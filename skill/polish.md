# 自动分支与子代理代码打磨提示词

先合并当前改动，随后不断开分支、反复开启子代理审查与优化代码。在保证性能不衰减的前提下，参考 `.agents/skills/rust_review/SKILL.md` 持续打磨，直到连续 3 次子代理独立审查均认为代码完美、无重复代码、无需要精简清理的死代码，且能自适应各种恶劣网络并逼近理论速度极限为止。

## 一、核心目标与原则

### 1. 性能第一
- 严禁任何导致吞吐下降或延迟增加的负优化。
- 充分发挥 `compio` 异步特性与系统零拷贝原语，消除热路径上的多余内存分配、锁竞争与阻塞拷贝。
- 结合离散事件仿真测试与真实链路基准评测验证，持续逼近理论吞吐极限。

### 2. 全网络谱系自适应（从数据中心到极限恶劣弱网）
- 拒绝面向单一网络写死固定超时、固定重传冷却或固定窗口上限；所有时间参数（握手重试、重传超时、尾部探测、失速恢复、缺失反馈周期、尾包挥手保持期、空闲断连）必须基于实测往返时延与时延抖动自适应伸缩。
- 全场景时延与带宽适配：覆盖亚毫秒内网千兆、百毫秒跨洋长肥浅队列链路、虚拟网卡与隧道小报文路径（自动探测或遇报文超限无损回退）、500 毫秒同步卫星、3 秒多跳卫星与蜂窝弱信号重传链路，直至 10 秒以上窄带卫星叠加深度排队膨胀（Bufferbloat）的极限高时延网络。
- 精确时延追踪与抗混叠：消除握手或数据重传引发的往返时延采样混叠，支持移动网络切换或路由重收敛时的双向基准时延更新，防止被历史过期样本锁死窗口或误判排队。
- 恶劣信道韧性：自适应应对突发连续丢包、剧烈时延抖动引发的乱序到达、反向确认通道丢包以及尾包确认丢失；乱序检测窗口随实测时延与伪重传反馈动态调节，接收端在收齐数据后按实测时延维持自适应挥手保持期并按需补发完成确认，杜绝尾确认丢失导致发送端超时失败。

### 3. 全方位离散事件仿真测试
- 状态机同源驱动：仿真测试必须直接驱动生产级收发状态机与拥塞控制核心，在虚拟时钟下毫秒级确定性跑完完整生命周期（含握手、慢启动、稳态传输、丢包恢复与尾部挥手退出）。
- 链路谱系覆盖：构建内网千兆、城域广域网、跨洋高带宽时延积专线、跨太平洋浅队列家用链路、边缘高丢包弱网、3 秒多跳卫星高时延链路、10 秒以上极限缓冲膨胀链路，以及传输中途带宽骤降或骤升的动态阶跃链路。
- 恶劣病理注入：仿真器不能只测单向均匀随机丢包与理想确认通道，必须同时注入突发连丢、传播抖动与包乱序、瓶颈路由器浅队列尾丢弃、反向确认包随机丢失，以及强制丢弃首轮尾包完成确认，验证极端弱网下零死锁、零过早退出、零断言崩溃。
- 理论极限对照：每个仿真场景均计算扣除协议头开销与信道丢包后的理论最大有效吞吐，断言实际有效吞吐利用率、重传开销与收敛时延达标且不发生性能回退。

### 4. 奥卡姆剃刀原则
- 让代码简洁、流程清晰、状态机闭环、调用拓扑扁平优雅。
- 协议与原语精简高效：可以用数字、定长字节、枚举或位掩码表示的，绝对不用字符串，消除字符串解析、格式化与堆分配开销。
- 拒绝过度设计与冗余包装：模块内部直接暴露必要字段，消除无意义的转发层与样板代码。

### 5. 单一事实来源与模块化复用
- 变量与常量一处定义：消除魔法数字，可在编译期计算的绝不放到运行时。
- 拆分独立 crate：将通用常量、协议原语、基础算法与拥塞控制下沉拆分为职责单一的 crate，方便跨模块与其他库复用。
- 清理重复与死代码：识别并删除未使用的死代码、废弃分支与冗余类型；将跨文件重复逻辑下沉为公共原语。

### 6. 务实安全加固（拒绝无意义的防御式编程）
- 先复现，再修复：安全问题必须先编写代码或测试用例复现确认，再去修复；严禁凭空猜测堆砌防御式编程导致代码臃肿或降低性能。
- 协议层防反射攻击：无连接协议在未验证对端地址前，严格限制回包字节倍率，阻断伪造源地址反射放大。
- 不加密模式不做防篡改：内网或不加密高速传输模式下，不在数据热路径做逐块防篡改校验，保持极速吞吐。

## 二、自动化循环流程

### 步骤 1：基线收敛
1. 运行 `./sh/clippy.sh` 与 `./test.sh`，确认当前工作区零警告且测试全过。
2. 将当前改动合并至主分支，保持主干干净。
3. 初始化连续完美计数 `clean_streak = 0`。

### 步骤 2：分支与子代理打磨循环（直至 `clean_streak == 3`）
当 `clean_streak < 3` 时，重复执行以下流程：

1. 创建隔离分支
   - 从主干最新提交切出独立优化分支（或为子代理分配独立 `branch` 工作树）。

2. 启动审查优化子代理
   - 子代理先阅读 `.agents/skills/rust_review/SKILL.md` 及本文件，对全仓代码进行审查与重构：
     - 清理未使用的死代码、冗余结构与废弃分支
     - 抽取并复用重复代码
     - 归口散落的常量与魔法数字，保持一处定义
     - 排查并消除写死的网络超时或窗口截断，确保全链路参数随实测时延与带宽自适应
     - 完善恶劣网络与极限高时延离散事件仿真测试，验证理论吞吐利用率与边界韧性
     - 优化 crate 拆分与调用拓扑
     - 将不必要的字符串原语替换为紧凑数值原语
     - 移除拖慢热路径的无意义防御式代码
     - 复现并修复协议反射放大等真实安全缺陷
     - 检查单文件行数上限、导入规范与 `compio` 特性运用

3. 验证与合流判定
   - 若子代理发现可优化项并完成修改（`STATUS: IMPROVED`）：
     1. 运行 `./sh/clippy.sh`（零警告，禁用 `allow` 掩盖）与 `./test.sh`（含全谱系恶劣网络仿真全量通过），验证性能不衰减。
     2. 提交改动并合并回主分支，清理临时分支。
     3. 重置计数 `clean_streak = 0`，进入下一轮审查。
   - 若子代理确认代码完美、无重复代码与死代码、自适应与仿真完备（`STATUS: CLEAN`）：
     1. 不做凑数的无意义改动。
     2. 丢弃临时分支，累加计数 `clean_streak += 1`。

4. 终止条件
   - 连续 3 次子代理审查均返回 `STATUS: CLEAN`（`clean_streak == 3`）时，结束循环并输出总结。
