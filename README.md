# sync0

`sync0` is a decentralized P2P file sharing, real-time synchronization and multi-source distribution tool used to replace `rsync` - the measured speed of transcontinental WAN is up to `rsync`'s **5.89×** (single point geometric average speed **2.67×**, P2P dual-source geometric average speed **3.16×**), and transoceanic high-latency link P2P acceleration is up to **7.68×** (Full-link 24-scenario comprehensive geometric mean speed **2.56×**).

Each machine is both a server and a client: no central server or public network address is required, automatic hole punching is performed based on distributed network public key addresses, supporting direct transfer between two machines, multi-sharing group permission hosting, on-demand multi-selection of subdirectories, millisecond-level real-time incremental synchronization, and P2P multi-source concurrent acceleration.

## Get started quickly

### 1. Zero-configuration direct transmission between two machines (`send` / `recv`)

No need to configure a sharing group, directly transfer files or directories between two machines at high speed:

**774.98**
# The receiving end listens on the port and writes to ./backup
sync0 recv 0.0.0.0:9000 ./backup

# Direct transmission from the sender (optional --delete mirror to clean up excess files, --rate 50MB speed limit)
sync0 send ./project 192.168.1.10:9000
For more link data and reproduction scripts, see [Performance Measurement Report](../../doc/zh/benchmark.md).

### 2. Post sharing and on-demand pull / upload (`share` / `pull` / `push`)

**774.98**
# Server: Publish the sharing group with one line of command (output the IP-free iroh node address after startup)
sync0 share dataset:./data

# Client: Pull the entire dataset sharing group to the local ./local_data
sync0 pull dataset:// ./local_data -p <node address>

# Client: Pull multiple selections on demand (only synchronize specified single files and subdirectories)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <node address>

# Client: Upload files or directories to authorized sharing groups
sync0 push dataset://releases/v1 ./build_output -p <node address>
For more link data and reproduction scripts, see [Performance Measurement Report](../../doc/zh/benchmark.md).

### 3. Real-time subscription seeding and multi-machine two-way synchronization (`sub` / `group`)

After establishing a persistent connection, whenever any file **creation, modification, deletion, permission (`mode`), or modification time (`mtime`) change** occurs on the remote end, the local directory is automatically updated in real time within milliseconds (creating/modifying large files only pulls differential blocks in place, deleting files automatically cleans up local files and empty directories, and modifying permissions or timestamps takes effect in place with zero data block transfer):

- **`sync0 sub` (One-way real-time mirror + automatic seeding)**: The local directory follows remote additions, deletions, and modifications in real time, while automatically serving as a P2P seed source to accelerate concurrent downloads for other nodes.
- **`sync0 group` (Multi-machine peer-to-peer two-way real-time synchronization)**: When any machine in the group adds, deletes, or modifies files, all other online nodes synchronize updates in real time and seed each other.

**774.98**
# Subscribe to the entire sharing group: remote additions, deletions, and modifications are synced locally in real time and seeded automatically
sync0 sub dataset:// ./local_mirror -p <node address>

# On-demand multi-select subscription: only sync and seed specified single files and subdirectories in real time
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <node address>

# Multi-machine peer group two-way real-time synchronization (also supports full or comma multi-select paths)
sync0 group team-docs:// ./docs -p <node address>
For more link data and reproduction scripts, see [Performance Measurement Report](../../doc/zh/benchmark.md).

### 4. Team multi-sharing group and member permission configuration (`.nt` configuration)

The default configuration directory is `~/.config/sync0` (can be switched via `-c <directory>`), using the minimalist [NestedText](https://nestedtext.org) (`.nt`) format:
- **Supports restricting public network reading (only authorized users can read)**: As long as the sharing group is configured with a `users:` member list (or the command line specifies `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`), the system **automatically turns on private authentication (`auth: true`)** and prohibits public network anonymous node enumeration or reading, and P2P Subscribing to seeding nodes will also inherit the whitelist simultaneously, allowing only authorized users to read; sharing groups that are not configured with `users` are public and read-only by default (if you want to be public and read-only and open to uploads only to specified members, you can explicitly set `auth: false`).
- **Fine-grained read-write and subdirectory delivery permissions**: Members are read-only by default (`r` does not need to be written explicitly), and support `r` (read-only), `w` (only write to the drop box, not readable), `rw` (read-write) and `write_prefix` (limit the subdirectory prefix allowed for uploading).

**Member configuration example (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (default read-only, speed limit 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
For more link data and reproduction scripts, see [Performance Measurement Report](../../doc/zh/benchmark.md).

id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob

```yaml
users_dir: ./users

groups:

    rate: 50MB

  # Configured users: automatically restrict public network reading (only alice and bob can read, charlie can only deliver and upload)

    users:
      - alice
      - bob
      - charlie

### Core product features

- **Public key addressing automatic hole punching**: No need for a central server and public network address, automatic NAT hole punching based on the distributed network public key address.
- **Millisecond-level real-time synchronization and metadata awareness**: Based on native file event monitoring (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), real-time push of file additions, deletions, POSIX permissions (`mode`) and millisecond-level modification time (`mtime`); zero data block transmission when only permissions or time are modified.
- **BT-style simultaneous download and upload and regional affinity scheduling**: The downloading node does not need to wait for the full amount to be downloaded. All the block intervals (`Op::Have`) that have passed the 128-bit hash check are immediately locked in the memory/temporary pool for other nodes to pull concurrently. Together with dynamic PEX node exchange and slow node half preemption (Work-Stealing), the cluster throughput is maximized.
- **Anti-malicious node tampering and cluster poisoning immunity**: authoritative source list `root_hash` Self-consistent locking + mandatory hardware acceleration `gxhash128` digest verification before each block is placed on the disk and externally seeded; if a tampered block is found, the millisecond-level circuit breaker will blackout the malicious node and automatically recover from the honest source.
- **FastCDC in-situ increment and small file aggregation**: Only differential blocks are transferred for partial modification of large files and placed on disk; massive small file memory packaging and prefix differential compression eliminate file-by-file round-trip overhead.
- **Self-healing after power outage and resumption after restart**: Redis-like RDB + AOF hybrid format (`.s0_subs.bin`) is used to persist the seeding status and file list, daily changes are appended in microseconds, and are automatically rewritten and organized regularly. After the server is restarted, offline changes are automatically pushed to the seeding node.

## Technical architecture and documentation

- **Dual plane decoupling protocol**:
  - **Control and real-time change plane (`iroh` QUIC / TCP, first byte `PROTO_VERSION` version handshake)**: Responsible for Ed25519 business card verification, permission verification, Swarm seed discovery, and support for `u64::MAX` level mass change streaming batching and `mzstd` compressed `SubPush` real-time push (`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` three primitives).
  - **Data distribution plane (native UDP + `compio` asynchronous I/O)**: 20B compact header, 18B TACK periodic feedback, BBRv3/Copa hybrid congestion control, RACK-TLP packet loss recovery, first-block Shannon entropy adaptive Zstd compression bypass, and `gxhash128` block end-to-end verification.
