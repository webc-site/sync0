# sync0

`sync0` は、`rsync` に代わる分散型 P2P ファイル共有、リアルタイム同期、およびマルチソース配信ツールです。大陸横断 WAN の測定速度は最大 `rsync` の **5.89×** (単一ポイントの幾何平均速度 **2.67×**、P2P デュアルソースの幾何平均速度 **3.16×**)、および大洋横断高遅延リンクです。 P2P 加速は最大 **7.68×** (フルリンク 24 シナリオの総合幾何平均速度 **2.56×**) です。

各マシンはサーバーとクライアントの両方です。中央サーバーやパブリック ネットワーク アドレスは必要ありません。自動ホール パンチは分散ネットワーク公開キー アドレスに基づいており、2 台のマシン間の直接送信、マルチ共有グループ権限ホスティング、オンデマンドでのサブディレクトリの複数選択、ミリ秒レベルのリアルタイム増分同期、および P2P マルチソース同時アクセラレーションをサポートしています。

## インストール

### 方法 1: 貨物の設置

```bash
cargo install sync0
```

### 方法 2: プリコンパイルされたバイナリをダウンロードする

[GitHub Releases](https://github.com/webc-site/sync0/releases) に移動して、システムに対応する `.tar.xz` 圧縮パッケージ (Linux、macOS、Windows、Android、iOS、FreeBSD をサポート) をダウンロードし、解凍して `PATH` に置きます。

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## すぐに始めましょう

### 1. 2 台のマシン間のゼロ構成の直接送信 (`send` / `recv`)

共有グループを構成する必要がなく、2 台のマシン間でファイルやディレクトリを高速に直接転送できます。

```bash
# 受信側はポートをリッスンし、./backup に書き込みます。
sync0 recv 0.0.0.0:9000 ./backup

# 送信者からの直接送信 (オプションの --delete ミラーで余分なファイルをクリーンアップ、 --rate 50MB の速度制限)
sync0 send ./project 192.168.1.10:9000
```

### 2. 投稿の共有とオンデマンドのプル/アップロード (`share` / `pull` / `push`)

```bash
# サーバー: 1 行のコマンドで共有グループを公開します (起動後に IP フリーの iroh ノード アドレスを出力します)。
sync0 share dataset:./data

# クライアント: データセット共有グループ全体をローカルの ./local_data にプルします。
sync0 pull dataset:// ./local_data -p <ノードアドレス>

# クライアント: オンデマンドで複数の選択をプルします (指定された単一のファイルとサブディレクトリのみを同期します)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <ノードアドレス>

# クライアント: 承認された共有グループにファイルまたはディレクトリをアップロードします。
sync0 Push dataset://releases/v1 ./build_output -p <ノード アドレス>
```

### 3. リアルタイムのサブスクリプション シーディングと複数マシンの双方向同期 (`sub` / `group`)

長期接続を確立した後、遠隔でファイルの**追加、変更、削除、権限や変更日時の変更**が発生すると、ローカルディレクトリはミリ秒単位でリアルタイムに同期更新されます（追加/変更された大きなファイルは差分ブロックだけを取得してインプレースで更新され、削除されたファイルはローカルのファイルや空ディレクトリも自動で削除され、権限やタイムスタンプの変更のみならデータブロックはゼロで直接適用されます）：

- **`sync0 sub`（一方向リアルタイムミラー + 自動シード）**：ローカルはリアルタイムで共有端の追加・削除・変更を追従し、同時に自動で P2P シード元として他の取得ノードに並行加速を提供します。
- **`sync0 group`（複数機器のピア間双方向リアルタイム同期）**：グループ内の任意の機器でファイルの追加・削除・変更が発生すると、他のすべてのオンラインノードもリアルタイムで同期更新され、互いにシードになります。

```bash
# 共有グループ全体を購読：遠隔の追加・削除・変更をローカルでリアルタイムに同期し、かつ自動的にシードします
sync0 サブ データセット:// ./local_mirror -p <ノード アドレス>

# オンデマンドの複数選択サブスクリプション: 指定された単一のファイルとサブディレクトリのみをリアルタイムで同期およびシードします
sync0 サブ データセット://models/llama.onnx,configs ./local_mirror -p <ノード アドレス>

# マルチマシンピアグループの双方向リアルタイム同期 (フルパスまたはカンマ複数選択パスもサポート)
sync0 グループ チーム-docs:// ./docs -p <ノード アドレス>
```

### 4. チームのマルチ共有グループとメンバー権限の構成 (`.nt` 構成)

デフォルトの構成ディレクトリは `~/.config/sync0` (`-c <directory>` で切り替え可能) で、最小限の [NestedText](https://nestedtext.org) (`.nt`) 形式が使用されます。
- **パブリック ネットワーク読み取りの制限をサポート (許可されたユーザーのみが読み取り可能)**: 共有グループが `users:` メンバー リストで構成されている限り (またはコマンド ラインで `--allow-r` / `--allow-rw` / `--allow-w` / `--auth` を指定している)、システムは **プライベート認証 (`auth: true`)** を自動的にオンにし、パブリック ネットワークの匿名ノードの列挙または読み取り、およびシードへの P2P サブスクライブを禁止します。ノードは同時にホワイトリストも継承し、許可されたユーザーのみが読み取りを許可します。 `users` で構成されていない共有グループは、デフォルトで公開および読み取り専用になります (公開および読み取り専用にして、指定したメンバーのみにアップロードを許可したい場合は、`auth: false` を明示的に設定できます)。
- **きめ細かい読み取り/書き込みおよびサブディレクトリ配信権限**: メンバーはデフォルトで読み取り専用 (`r` は明示的に書き込む必要はありません) で、`r` (読み取り専用)、`w` (ドロップ ボックスへの書き込みのみ。読み取り不可)、`rw` (読み取り/書き込み)、および `write_prefix` (アップロードに許可されるサブディレクトリ プレフィックスを制限します) をサポートします。

**メンバー構成例 (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (デフォルトは読み取り専用、速度制限は 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (読み取りおよび書き込み権限、指定されたサブディレクトリへのアップロードのみが許可されます)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (書き込み配信許可のみ、読み取り禁止)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**共有グループの構成例 (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # 未構成のユーザー: デフォルトのパブリック ネットワークは読み取り専用です
  dataset:
    path: ./data
    rate: 50MB

  # 設定されたユーザー: パブリック ネットワークの読み取りを自動的に制限します (アリスとボブのみが読み取り可能、チャーリーは配信とアップロードのみ可能)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

サービスを開始します (構成ファイルをロードするか、コマンド ライン パラメーターを直接使用して、パブリック ネットワークの読み取りを制限し、メンバーを承認します)。

```bash
# ~/.config/sync0/config.nt をロードして開始します
sync0 share --region SHA

# または、純粋なコマンド ラインを使用してプライベート共有グループを公開します ( --allow-* を指定すると、パブリック ネットワークの読み取りが自動的に制限され、許可されたユーザーのみがアクセスできるようになります)。
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. ノードアドレス、名刺、多言語対応

```bash
# ローカルの IP フリー ノード アドレスを表示します (キーは初回実行時に自動的に生成されます)。
sync0 id

# Ed25519 自己署名ノード名刺を生成 (ニックネーム、市外局番、電子メール、Web サイト、紹介文)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# 75 の組み込み言語があり、デフォルトではシステム言語に従い、環境変数を通じて切り替えることができます。
SYNC0_LANG=en sync0 --help
```

## パフォーマンスとコア機能

### 大陸横断WANの実測値（ 比較`rsync`）

実際の測定環境: 米国 `c1` → ヨーロッパ `n1` (RTT 65 ms)、データセットは Linux カーネル `linux-7.3.3`:

#### 1) アラカルト モード vs `rsync`

| データセット | サイズ | `sync0` シングルポイント<br>(Mbps) | `rsync`<br>(Mbps) | 高速化 (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(圧縮不可) | 155 MB | **236.48** | 108.74 | **2.17×** |
| `linux-7.3.3.tar`(圧縮可能) | 1.6 GB | **843.83** | 385.06 | **2.19×** |
| `linux-7.3.3.tar`(ローカル変更増分) | 1.6 GB | **8,014.15** | 1,361.72 | **5.89×** |
| `linux-7.3.3/` (95,979 個の小さいファイル) | 1.5 GB | **627.58** | 347.80 | **1.80×** |
| **幾何平均** | — | **1,000.91** | 375.26 | **2.67×** |

#### 2) P2P デュアルソース モードと `rsync`

| データセット | サイズ | `sync0` P2P デュアル ソース<br>(Mbps) | `rsync`<br>(Mbps) | 高速化 (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(圧縮不可) | 155 MB | **330.09** | 108.74 | **3.04×** |
| `linux-7.3.3.tar`(圧縮可能) | 1.6 GB | **1,551.86** | 385.06 | **4.03×** |
| `linux-7.3.3.tar`(ローカル変更増分) | 1.6 GB | **5,474.17** | 1,361.72 | **4.02×** |
| `linux-7.3.3/` (95,979 個の小さいファイル) | 1.5 GB | **706.56** | 347.80 | **2.03×** |
| **幾何平均** | — | **1,186.42** | 375.26 | **3.16×** |

> 注: P2P デュアルソース モードでは、 ヨーロッパのノード`s1`がシード処理のために連携し、大陸間のバックボーン RTT は 65 ミリ秒です。

### 製品のコア機能

- **公開キー アドレスによる自動ホール パンチ**: 中央サーバーやパブリック ネットワーク アドレスは不要で、分散ネットワーク公開キー アドレスに基づいた自動 NAT ホール パンチが可能です。
- **ミリ秒レベルのリアルタイム同期とメタデータ認識**: ネイティブ ファイル イベントの監視 (`FSEvents` / `inotify` / `ReadDirectoryChangesW`)、ファイルの追加、削除、POSIX 権限 (`mode`) およびミリ秒レベルの変更時間 (`mtime`) のリアルタイム プッシュに基づいています。権限または時間のみが変更される場合、ゼロ データ ブロック送信。
- **BT スタイルの同時ダウンロードとアップロード、およびリージョン アフィニティ スケジューリング**: ダウンロード ノードは、全量がダウンロードされるまで待つ必要はありません。 128 ビット ハッシュ チェックに合格したすべてのブロック インターバル (`Op::Have`) は、他のノードが同時にプルできるようにメモリ/一時プールに即座にロックされます。動的な PEX ノード交換と低速ノード ハーフ プリエンプション (ワーク スチール) を組み合わせることで、クラスターのスループットが最大化されます。
- **悪意のあるノードの改ざん対策とクラスター ポイズニングの免疫**: 信頼できるソース リストの`root_hash`自己一貫性ロック + 必須のハードウェア アクセラレーションによる`gxhash128`各ブロックがディスクに配置され外部にシードされる前のダイジェスト検証。改ざんされたブロックが見つかった場合、ミリ秒レベルのサーキット ブレーカーが悪意のあるノードを遮断し、正当なソースから自動的に回復します。
- **FastCDC のその場でのインクリメントと小規模ファイルの集約**: 大きなファイルの部分的な変更には差分ブロックのみが転送され、ディスク上に配置されます。大規模で小さなファイルのメモリ パッケージ化とプレフィックスの差分圧縮により、ファイルごとのラウンドトリップ オーバーヘッドが排除されます。
- **停電後の自己修復と再起動後の再開**: Redis のような RDB + AOF ハイブリッド形式 (`.s0_subs.bin`) を使用してシード状態とファイル リストが永続化され、毎日の変更がマイクロ秒単位で追加され、自動的に書き換えられて定期的に整理されます。サーバーが再起動されると、オフラインの変更がシード ノードに自動的にプッシュされます。

## 技術的なアーキテクチャとドキュメント

- **デュアルプレーンデカップリングプロトコル**:
  - **制御およびリアルタイム変更サーフェス (`iroh` QUIC / TCP、最初のバイト `PROTO_VERSION` バージョン ハンドシェイク) **: Ed25519 名刺検証、権限検証、Swarm シード検出、および `u64::MAX` レベルの大量変更ストリーミング バッチングと`mzstd` 圧縮された`SubPush` リアルタイム プッシュ (`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` の 3 つのサポート) を担当します。プリミティブ)。
  - ** データ配信サーフェス (ネイティブ UDP + `compio` 非同期 I/O) **: 20B コンパクト ヘッダー、18B TACK 定期フィードバック、BBRv3/Copa ハイブリッド輻輳制御、RACK-TLP パケット損失回復、ファーストブロック シャノン エントロピー適応 Zstd 圧縮バイパス、および`gxhash128` ブロック エンドツーエンド検証。
