# sync0

`sync0` は、Resilio Sync と競合するピアツーピア (P2P) ファイル共有およびマルチマシン同期ツールです。

各マシンはサーバーとクライアントの両方であり、どのノードでも複数のファイル共有グループを公開できます。他のノードが参加すると、利用可能なシード ノードをピア サーバーから自動的に取得し、複数のソースから同時にプルできます。同期が完了すると、ダウンロードを高速化するために、より多くのノードのシードが自動的に作成されます。

## 主要なハイライト

- **誰もがサーバーとクライアントの両方です**: Resilio Sync に似ていますが、中央サーバーへの依存はありません。どのノードでも複数のファイル共有グループを作成でき、他の人の共有グループに参加することもできます。ノードは自動的に利用可能なシード ノードを交換して取得し、複数のマシンの同時プルとリアルタイム同期を実現します。
- **IP フリー ノード アドレス**: デフォルトでは、ノード キーと`base64url`エンコードされた`iroh`アドレスが`~/.config/sync0`に自動的に生成され、パブリックIPを記憶したり公開したりする必要はありません。
- **オンデマンドの複数選択同期**: 共有グループ全体の同期をサポートし、同時に複数のファイルまたはサブディレクトリを選択することによるオンデマンドの同期もサポートします。
- **グループ メンバーの階層的アクセス許可とアップロード ディレクトリの制御**: 読み取り専用 (`ro`)、読み取り/書き込みアップロード (`rw`)、および管理 (`admin`) アクセス許可をサポートし、各メンバーがアップロードを許可されるパス プレフィックスを個別に指定できます (デフォルトでは、共有のルート ディレクトリへのアップロードが許可されます)。
- **ネットワーク全体でのフルスピードおよび増分同期**: 大きなファイルの同時送信、メモリ内の大量の小さなファイルの集約、およびファイルが部分的に変更された場合のみデータ ブロックを同期します。

| コードおよびアーカイブ パッケージ (`.tar`) | 10.0 MB | 増分同期 | 83.38 Mbps | 26.02 Mbps | 3.2x |

| ビデオ ファイル (`.mp4`) | 15.0 MB | 増分同期 | 216.83 Mbps | 21.51 Mbps | 10.1x |

## インストール

### 方法 1: Cargo 経由でインストールする

```bash
cargo install sync0
```

### 方法 2: プリコンパイルされたバイナリをダウンロードする

[GitHub Releases](https://github.com/webc-site/sync0/releases) に移動して、対応するシステム用の `.tar.xz` 圧縮パッケージ (Linux、macOS、Windows、Android、FreeBSD、NetBSD をサポート) をダウンロードし、解凍して `PATH` ディレクトリに置きます。

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## すぐに始めましょう

`sync0` は、デフォルトで `~/.config/sync0` を設定ディレクトリとして使用します (他のディレクトリに切り替える必要がある場合は、`-c <ディレクトリ>` を追加できます)。

### 1. ローカルノードアドレスと設定名刺の表示

```bash
# ローカル ノード アドレスを表示します (キーは初めて ~/.config/sync0 に自動的に生成されます)
sync0 id

# 個人ノードの名刺を生成します (ユーザー名、都市、電子メール、Web サイト、および 256 ワード以内の署名をサポート)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. 複数のファイル共有グループを公開し、グループメンバーの権限を設定します (`.nt` 構成)

`sync0` は、[NestedText](https://nestedtext.org) (`.nt`) 形式で構成されます。各ユーザーには個別の`.nt`設定ファイルがあります。 `config.nt` の `users_dir` を通じてユーザー プロファイル ディレクトリを指定できます (このディレクトリにはすべての `.nt` ファイルが自動的に含まれます)。アップロードが許可されているユーザーとパス プレフィックスは両方とも、順序なしリスト (`-`) を使用します。 **アップロード パスのプレフィックスが入力されていない場合、デフォルトで共有のルート ディレクトリへのアップロードが許可されます**。

1. `~/.config/sync0/users/` ディレクトリ内のメンバーごとに個別の `.nt` 構成ファイルを作成します。

`~/.config/sync0/users/alice.nt` (読み取り専用メンバー、レート制限のある `80MB`、`rate` は `GB`、`MB`、`KB` ユニットをサポートします):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (アップロードメンバーが制限されています: `uploads/bob` および `shared/common` ディレクトリへのアップロードのみが許可されます):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (デフォルトのメンバーアップロード: `write_prefix` が省略された場合、共有のルート ディレクトリへのアップロードがデフォルトで許可されます):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. `~/.config/sync0/config.nt` でユーザー ディレクトリと複数のファイル共有グループを構成します。

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

共有サービスを開始します。

```bash
# 直接起動 (~/.config/sync0/config.nt および users_dir ディレクトリ内のすべての .nt ユーザー構成を自動的にロードします)
sync0 share --region SHA

# または、複数の共有グループをすばやく公開し、コマンド ラインから直接グループ メンバーを承認します。
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. すべてのコンテンツを取得するか、複数のファイルとディレクトリを選択します (`sync0 pull`)

任意のピアノードに接続して、共有グループ内の利用可能なすべてのシード ノードを自動的に取得し、複数のシード ノードから同時にプルします。

```bash
# データセット共有グループ全体をローカルの ./local_data にプルします
sync0 pull dataset:// ./local_data -p <ノードアドレス>

# 複数選択の同期: 単一ファイル docs/readme.md とサブディレクトリのassets/icons、src/coreを同時にプルします。
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <ノードアドレス>
```

### 4. ファイルまたはディレクトリを共有グループにアップロードします (`sync0 push`)

アップロード権限 (`rw` または `admin`) を持つメンバーは、ローカル ファイルまたはディレクトリをリモート共有グループにアップロードできます。

```bash
# ルート ディレクトリのアップロード権限を持つメンバー: 共有ルート ディレクトリに直接アップロードします。
sync0 プッシュ チーム-vault:// ./new_release -p <ノード アドレス>

# 特定のプレフィックス (uploads/bob など) を許可されたメンバーのみ: 許可されたパス プレフィックスにアップロードします。
sync0 プッシュ チーム vault://uploads/bob/report.pdf ./report.pdf -p <ノード アドレス>
```

### 5. 自動同期とシードを購読する (`sync0 sub`)

特定のノードの共有グループに加入すると、ローカル サーバーは受信クライアントと新しいシード サーバーの両方になります。ソース ノード ファイルが更新されると、自動的に同期され、他のノードにチャンク ダウンロードが提供されます。

```bash
# 共有グループ全体をサブスクライブし、自動的にシードします
sync0 サブ データセット:// ./local_mirror -p <ノード アドレス>

# 指定したファイルとサブディレクトリをサブスクライブしてシードする場合のみ複数選択します
sync0 サブ データセット://models/llama.onnx,configs ./local_mirror -p <ノード アドレス>
```

### 6. マルチマシングループピア同期 (`sync0 group`)

複数のマシンが同じ共有グループに参加し、相互に利用可能なシード ノードを自動的に検出し、双方向の同期を維持します (完全同期またはファイルとディレクトリの複数選択をサポートします)。

```bash
# グループに完全に参加し、双方向同期します
sync0 グループ チーム-docs:// ./docs -p <ノード アドレス>

# 複数選択同期グループ内の wal ディレクトリと meta.json ファイルのみ
sync0 グループ チーム-docs://wal,meta.json ./docs -p <ノード アドレス>
```

### 7. 2 台のマシン間のポイントツーポイントの直接送信 (`send` / `recv`)

グループを事前に構成する必要はなく、2 台のマシン間でファイルまたはディレクトリを一時的に直接転送できます。

```bash
# 受信機モニタリング
sync0 recv 0.0.0.0:9000 ./backup

# 送信側はファイルまたはディレクトリを直接転送します (余分なファイルをクリーンアップするオプションの --delete ミラー、--rate 速度制限)
sync0 send ./project 192.168.1.10:9000
```

### 8. 多言語切り替え

`sync0` は 75 の言語をサポートしており、デフォルトではシステムの言語環境に応じて自動的に切り替わります。 `SYNC0_LANG` を使用して手動で指定することもできます。

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
