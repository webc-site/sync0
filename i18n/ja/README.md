# sync0

`sync0` は、ネットワーク間でのファイルの転送、ディレクトリの増分同期、複数のマシンへのデータの同時配布を行うためのコマンド ライン ツールです。

## 当初の設計意図

複数のマシンルーム、国、またはネットワーク遅延やパケット損失のある環境では、`rsync` や `scp` などのツールは単一の接続シーケンスの確認に基づいており、帯域幅の使用率が制限されます。複数のマシンが同じサーバーから同時にデータをプルすると、ソース サーバーのネットワーク カードがボトルネックになりやすくなります。

`sync0` の目標は、次の 2 つの問題を解決することです。

1. 2 台のマシン間のファイルとディレクトリの同期では物理帯域幅をフルに実行し、ファイルが部分的に変更された場合にのみ変更部分を転送します。
2. 同じディレクトリを同期するときに複数のマシンがデータ ブロックを相互に転送できるため、ソース サーバーの負荷が軽減され、全体の同期時間が短縮されます。

## rsyncとの速度比較

テスト環境: ヨーロッパ ノード $\leftrightarrow$ 北米ノード、往復遅延 86 ミリ秒、ディレクトリ スキャン、重複排除の比較、ネットワーク送信、ディスク配置の検証などの完全な時間を測定:

| 送信シナリオ | データサイズ | `sync0` | `rsync` | 複数 |
| :--- | :---: | :---: | :---: | :---: |
| 10,000 個の小さなファイル | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| コードおよびアーカイブ パッケージ (`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| ビデオ ファイル (`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| 増分同期 (1% コンテンツを変更) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## パフォーマンス改善方法

- **UDP 同時送信**: UDP 経由でデータ ブロックを送信し、失われたフラグメントのみを再送信して、後続のファイル転送をブロックする 1 つのパケット損失を回避します。
- **コンテンツのセグメント化と重複排除**: コンテンツに従ってファイルをデータ ブロックに分割し、チェック値を計算します。受信側にすでにある同じコンテンツは、ネットワークを複製することなく、ローカルで直接再利用されます。
- **ネットワーク速度に応じて圧縮を自動的に調整**: テキストやコードなどの圧縮可能なコンテンツの圧縮をオンにします。ビデオ、写真、圧縮パッケージ、または高速 LAN 環境では、圧縮を自動的にスキップして CPU 消費量を削減します。
- **近くの複数ノードのプル**: 複数のマシンが同じディレクトリをプルする場合、データ ブロックは同じ都市にあるダウンロードされたノードから同時にプルされるか、より低い遅延でプルされます。

## インストール

### 方法 1: Cargo 経由でインストールする

```bash
cargo install sync0
```

### 方法 2: プリコンパイルされたバイナリをダウンロードする

[GitHub Releases](https://github.com/webc-site/sync0/releases) に移動して、 対応するシステムの`.tar.xz`圧縮パッケージをダウンロードします (Linux x86_64/ARM64、macOS Apple Silicon/Intel、Windows x64/ARM64、Android ARM64/x86_64、FreeBSD、NetBSD をサポート)。解凍後、 `sync0` を `PATH` ディレクトリに配置します。

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## ユーザーガイド

### 1. 2 台のマシン間でファイルまたはディレクトリを直接転送する

受信側マシンで監視を開始し、受信および保存のパスを指定します。

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

送信側マシンから単一のファイルまたはディレクトリ全体を送信します。

```bash
sync0 send ./project 192.168.1.10:9000
```

一般的に使用されるパラメータ:

```bash
# 受信側には存在するが送信側には存在しない冗長ファイルを削除する（ミラー同期）
sync0 send ./project 192.168.1.10:9000 --delete

# 送信速度の制限 (単位: バイト/秒、例: 50 MB/秒)
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# サイレント モード (進行状況バーは表示されません)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. 共有ディレクトリのパブリッシュと複数のノードからのプル

共有ディレクトリ (`dataset` という名前) をオリジン サーバー上に公開します。

```bash
sync0 share dataset ./data --region SHA
```

他のマシン上の共有ディレクトリをプルします (同時にプルするには、カンマで区切って複数のノード アドレスを同時に入力できます)。

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

共有ディレクトリ内の特定のサブディレクトリのみをプルします。

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

ローカルの変更をリモートの共有ディレクトリにプッシュバックします。

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. カタログの自動更新を購読する

ソースノードの共有ディレクトリをサブスクライブします。ファイルがソース ディレクトリに追加または変更されると、そのファイルはローカル コンピュータに自動的に同期されます。同時に、ローカル マシンは、他のマシンがプルするためのノードとして自動的に機能します。

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. マルチマシングループの双方向同期

複数のマシンが同じグループ名に参加すると、ノード ディレクトリの変更はグループ内の他のノードに自動的に同期されます。

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. ノード ID と個人の名刺

各ノードは、ユーザー名、都市、電子メール、Web サイト、および個人用署名 (最大 256 文字) の設定をサポートし、ローカル秘密キー署名認証に合格します。

```bash
# ローカル公開キー ID を表示します (キーを永続化するための構成ディレクトリを指定します)。
sync0 id -c ~/.config/sync0

# パーソナライズされた署名付きのノード名刺を生成して表示する
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`、`pull`、`sub`、`group` は、次のプロファイル パラメータを使用して起動することもできます。

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. 多言語切り替え

`sync0` 75 の言語をサポートします。デフォルトでは、オペレーティング システムの言語環境に応じて、対応する言語のコマンド ライン ヘルプとプロンプトが自動的に表示されます。システム言語がサポートされているリストにない場合は、デフォルトで英語が使用されます。

言語を手動で指定するには、環境変数`SYNC0_LANG`を設定します。

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
