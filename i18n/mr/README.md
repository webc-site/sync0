# sync0

`sync0` हे नेटवर्कवर फाइल्स ट्रान्सफर करण्यासाठी, डिरेक्ट्रीजचे वाढीव सिंक्रोनाइझ करण्यासाठी आणि एकाच वेळी एकाधिक मशीनवर डेटा वितरित करण्यासाठी कमांड लाइन टूल आहे.

## मूळ डिझाइन हेतू

क्रॉस-मशीन रूम, देश किंवा नेटवर्क विलंब आणि पॅकेट लॉस असलेल्या वातावरणात, `rsync` आणि `scp` सारखी साधने सिंगल कनेक्शन अनुक्रम पुष्टीकरणावर आधारित असतात, जे बँडविड्थ वापर मर्यादित करते; जेव्हा एकाच वेळी अनेक मशीन एकाच सर्व्हरवरून डेटा काढतात, तेव्हा सोर्स सर्व्हर नेटवर्क कार्ड सहजपणे अडथळे बनू शकते.

`sync0` चे ध्येय दोन समस्या सोडवणे आहे:

1. दोन मशीनमधील फाइल आणि डिरेक्टरी सिंक्रोनाइझेशनला पूर्ण फिजिकल बँडविड्थ चालवू द्या आणि फाइल अर्धवट सुधारित केल्यावरच बदललेला भाग हस्तांतरित करा.
2. एकाच डिरेक्ट्री सिंक्रोनाइझ करताना, सोर्स सर्व्हरवरील भार कमी करून आणि एकूण सिंक्रोनाइझेशन वेळ कमी करताना एकाधिक मशीन्स डेटा ब्लॉक्स एकमेकांना हस्तांतरित करू शकतात.

## rsync सह वेगाची तुलना

चाचणी वातावरण: युरोपियन नोड $\leftrightarrow$ नॉर्थ अमेरिकन नोड, राउंड-ट्रिप विलंब 86 ms, निर्देशिका स्कॅनिंग, डुप्लिकेशन तुलना, नेटवर्क ट्रान्समिशन आणि डिस्क प्लेसमेंट सत्यापनासह संपूर्ण वेळ घेणारे मोजमाप:

| ट्रान्समिशन परिदृश्य | डेटा आकार | `sync0` | `rsync` | एकाधिक |
| :--- | :---: | :---: | :---: | :---: |
| 10,000 लहान फाइल्स | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| कोड आणि संग्रहण पॅकेजेस (`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| व्हिडिओ फाइल (`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| वाढीव सिंक्रोनाइझेशन (1% सामग्री सुधारित करा) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## कामगिरी सुधारण्याच्या पद्धती

- **UDP समवर्ती ट्रान्समिशन**: UDP द्वारे डेटा ब्लॉक्स पाठवा आणि त्यानंतरच्या फाइल ट्रान्सफरला ब्लॉक करणारी एकल पॅकेट लॉस टाळण्यासाठी फक्त हरवलेले तुकडे पुन्हा ट्रान्समिट करा.
- **सामग्री विभाजन आणि डुप्लिकेशन**: सामग्रीनुसार फाइलला डेटा ब्लॉकमध्ये विभाजित करा आणि चेक मूल्याची गणना करा. रिसीव्हिंग एंडवर आधीपासून असलेली समान सामग्री नेटवर्कची डुप्लिकेट न करता थेट स्थानिकरित्या पुन्हा वापरली जाते.
- **नेटवर्क गतीनुसार आपोआप कम्प्रेशन समायोजित करा**: मजकूर आणि कोड यासारख्या संकुचित करण्यायोग्य सामग्रीसाठी कॉम्प्रेशन चालू करा; CPU वापर कमी करण्यासाठी व्हिडिओ, चित्रे, संकुचित पॅकेजेस किंवा हाय-स्पीड LAN अंतर्गत कॉम्प्रेशन स्वयंचलितपणे वगळा.
- **मल्टी-नोड जवळील पुलिंग**: जेव्हा एकापेक्षा जास्त मशीन एकच डिरेक्टरी खेचतात, तेव्हा एकाच शहरातील डाउनलोड केलेल्या नोड्समधून किंवा कमी लेटन्सीसह डेटा ब्लॉक्स एकाच वेळी खेचले जातील.

## स्थापित करा

### पद्धत 1: कार्गो मार्गे स्थापित करा

```bash
cargo install sync0
```

### पद्धत 2: पूर्वसंकलित बायनरी डाउनलोड करा

संबंधित प्रणालीसाठी `.tar.xz` संकुचित पॅकेज डाउनलोड करण्यासाठी [GitHub Releases](https://github.com/webc-site/sync0/releases) वर जा (Linux x86_64/ARM64, macOS Apple Silicon/Intel, Windows x64/ARM64, Android ARM64/x86_64, FreeBSD, NetBSD ला समर्थन देते). अनझिप केल्यानंतर, `sync0` `PATH` निर्देशिकेत ठेवा:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## वापरकर्ता मार्गदर्शक

### 1. दोन मशीन्समध्ये थेट फाइल्स किंवा डिरेक्टरी हस्तांतरित करा

प्राप्त करणाऱ्या मशीनवर देखरेख सुरू करा आणि प्राप्त करण्याचा आणि जतन करण्याचा मार्ग निर्दिष्ट करा:

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

सेंडिंग मशीनवरून एकच फाइल किंवा संपूर्ण निर्देशिका पाठवा:

```bash
sync0 send ./project 192.168.1.10:9000
```

सामान्यतः वापरलेले पॅरामीटर्स:

```bash
# रिडंडंट फाइल्स हटवा ज्या रिसीव्हिंग एंडवर अस्तित्वात आहेत परंतु सेंडिंग एंडवर नाहीत (मिरर सिंक्रोनाइझेशन)
sync0 send ./project 192.168.1.10:9000 --delete

# पाठवण्याचा दर मर्यादित करा (युनिट: बाइट/सेकंद, उदाहरणार्थ ५० एमबी/से)
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# मूक मोड (कोणतीही प्रगती पट्टी दर्शविली नाही)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. सामायिक निर्देशिका प्रकाशित करणे आणि एकाधिक नोड्समधून खेचणे

मूळ सर्व्हरवर शेअर केलेली निर्देशिका (`dataset` नावाची) प्रकाशित करा:

```bash
sync0 share dataset ./data --region SHA
```

इतर मशीन्सवर शेअर केलेली डिरेक्टरी खेचा (आपण एकाच वेळी अनेक नोड पत्ते भरू शकता, एकाच वेळी खेचण्यासाठी स्वल्पविरामाने विभक्त केलेले):

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

सामायिक निर्देशिकेत फक्त एक विशिष्ट उपनिर्देशिका खेचा:

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

रिमोट शेअर केलेल्या निर्देशिकेत स्थानिक बदल परत पुश करा:

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. कॅटलॉग स्वयंचलित अद्यतनांची सदस्यता घ्या

स्त्रोत नोडच्या सामायिक निर्देशिकेची सदस्यता घ्या. जेव्हा एखादी फाइल स्त्रोत निर्देशिकेत जोडली जाते किंवा सुधारली जाते, तेव्हा ती स्वयंचलितपणे स्थानिक संगणकावर समक्रमित केली जाते. त्याच वेळी, स्थानिक मशीन स्वयंचलितपणे इतर मशीन्स खेचण्यासाठी नोड म्हणून काम करेल:

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. मल्टी-मशीन गटांचे द्वि-मार्ग सिंक्रोनाइझेशन

अनेक मशीन एकाच गटाच्या नावात सामील होतात आणि कोणत्याही नोड निर्देशिकेतील बदल गटातील इतर नोड्समध्ये आपोआप सिंक्रोनाइझ केले जातील:

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. नोड ओळख आणि वैयक्तिक व्यवसाय कार्ड

प्रत्येक नोड वापरकर्ता नाव, शहर, ईमेल, वेबसाइट आणि वैयक्तिक स्वाक्षरी (जास्तीत जास्त 256 वर्ण) सेट करण्यास समर्थन देतो आणि स्थानिक खाजगी की स्वाक्षरी प्रमाणीकरण पास करतो:

```bash
# स्थानिक सार्वजनिक की आयडी पहा (की कायम ठेवण्यासाठी कॉन्फिगरेशन निर्देशिका निर्दिष्ट करा)
sync0 id -c ~/.config/sync0

# वैयक्तिक स्वाक्षरीसह नोड व्यवसाय कार्ड तयार करा आणि प्रदर्शित करा
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`, `pull`, `sub`, `group` या प्रोफाइल पॅरामीटर्ससह देखील लॉन्च केले जाऊ शकतात:

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. बहु-भाषा स्विचिंग

`sync0` ७५ भाषांना सपोर्ट करते. डीफॉल्टनुसार, ऑपरेटिंग सिस्टमच्या भाषा वातावरणानुसार संबंधित भाषेतील कमांड लाइन मदत आणि प्रॉम्प्ट स्वयंचलितपणे प्रदर्शित केले जातात; जर सिस्टीमची भाषा समर्थित सूचीमध्ये नसेल, तर डीफॉल्टनुसार इंग्रजी वापरली जाते.

भाषा स्वहस्ते निर्दिष्ट करण्यासाठी, पर्यावरण व्हेरिएबल सेट करा `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
