# sync0

`sync0` विकेंद्रित P2P फाइल सामायिकरण, रिअल-टाइम सिंक्रोनाइझेशन आणि बहु-स्रोत वितरण साधन आहे जे `rsync` पुनर्स्थित करण्यासाठी वापरले जाते - ट्रान्सकॉन्टिनेंटल वाइड एरिया नेटवर्कची मोजलेली गती `rsync` च्या **6.95×** पर्यंत आहे (सिंगल-पॉइंट भौमितिक सरासरी वेग **2.01 2.01 2.01 मीटर सरासरी गती **3.33×**), आणि महासागरांवरील मोठ्या लहान फाइल्सचे सिंक्रोनाइझेशन **7.19×** इतके वेगवान आहे.

प्रत्येक मशीन सर्व्हर आणि क्लायंट दोन्ही आहे: मध्यवर्ती सर्व्हर किंवा सार्वजनिक नेटवर्क पत्त्याची आवश्यकता नाही, स्वयंचलित होल पंचिंग वितरित नेटवर्क सार्वजनिक की पत्त्यावर आधारित आहे, आणि ते दोन मशीन्समधील थेट प्रसारणास समर्थन देते, मल्टी-शेअरिंग गट परवानगी होस्टिंग, मागणीनुसार उपडिरेक्टरीजची एकाधिक निवड, मिलिसेकंद-स्तरीय रिअल-टाइम इन्क्रिमेंटल पीक्युरेंटल ऍक्युरेंटल ऍक्युरेंटल पी.

## स्थापित करा

### पद्धत 1: कार्गो स्थापना

```bash
cargo install sync0
```

### पद्धत 2: पूर्वसंकलित बायनरी डाउनलोड करा

सिस्टमशी संबंधित `.tar.xz` संकुचित पॅकेज डाउनलोड करण्यासाठी [GitHub Releases](https://github.com/webc-site/sync0/releases) वर जा (Linux, macOS, Windows, Android, iOS, FreeBSD चे समर्थन करते), अनझिप करा आणि `PATH` मध्ये टाका:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## लवकर सुरुवात करा

### 1. दोन मशीन्समध्ये शून्य-कॉन्फिगरेशन डायरेक्ट ट्रान्समिशन (`send` / `recv`)

शेअरिंग ग्रुप कॉन्फिगर करण्याची गरज नाही, दोन मशीन्समध्ये थेट फाइल्स किंवा डिरेक्टरी उच्च वेगाने हस्तांतरित करा:

```bash
# प्राप्त करणारा शेवट पोर्टवर ऐकतो आणि ./backup वर लिहितो
sync0 recv 0.0.0.0:9000 ./backup

# प्रेषकाकडून थेट प्रक्षेपण (पर्यायी --अतिरिक्त फायली साफ करण्यासाठी मिरर हटवा, --रेट 50MB गती मर्यादा)
sync0 send ./project 192.168.1.10:9000
```

### 2. पोस्ट शेअरिंग आणि मागणीनुसार पुल/अपलोड (`share` / `pull` / `push`)

```bash
# सर्व्हर: कमांडच्या एका ओळीने शेअरिंग ग्रुप प्रकाशित करा (स्टार्टअपनंतर आयपी-फ्री इरोह नोड ॲड्रेस आउटपुट करा)
sync0 share dataset:./data

# क्लायंट: संपूर्ण डेटासेट शेअरिंग गट स्थानिक ./local_data वर खेचा
sync0 पुल डेटासेट:// ./local_data -p <नोड पत्ता>

# क्लायंट: मागणीनुसार एकाधिक निवडी खेचा (केवळ निर्दिष्ट एकल फाइल्स आणि उपनिर्देशिका समक्रमित करा)
sync0 पुल डेटासेट://docs/readme.md,assets/icons,src/core ./local_data -p <नोड पत्ता>

# क्लायंट: अधिकृत सामायिकरण गटांमध्ये फायली किंवा निर्देशिका अपलोड करा
sync0 पुश डेटासेट://releases/v1 ./build_output -p <नोड पत्ता>
```

### 3. रिअल-टाइम सबस्क्रिप्शन सीडिंग आणि मल्टी-मशीन टू-वे सिंक्रोनाइझेशन (`sub` / `group`)

दीर्घ कनेक्शन स्थापित केल्यानंतर, रिमोट एंडवर कोणतीही फाइल **जोडणे, सुधारणे, हटवणे, परवानग्या बदलणे किंवा बदल करण्याची वेळ** आढळल्यास, स्थानिक निर्देशिका रिअल टाइममध्ये मिलिसेकंदांमध्ये समकालिकपणे अद्यतनित केली जाईल (नवीन/सुधारित मोठ्या फायली केवळ फरक ब्लॉक्स काढतील आणि त्या ठिकाणी अद्यतनित करतील, फाइल्स हटवतील किंवा डायरेक्टर फायली बदलतील आणि फक्त डायरेक्टर फायली बदलतील. ब्लॉक थेट):

- **`sync0 sub`(वन-वे रिअल-टाइम मिररिंग + ऑटोमॅटिक सीडिंग)**: स्थानिक रिअल-टाइम शेअरिंग एंडच्या जोडण्या, हटवणे आणि बदलांचे अनुसरण करते आणि इतर पुलिंग नोड्ससाठी समवर्ती प्रवेग प्रदान करण्यासाठी स्वयंचलितपणे P2P सीड स्त्रोत म्हणून कार्य करते.
- **`sync0 group`(मल्टी-मशीन पीअर-टू-पीअर टू-वे रिअल-टाइम सिंक्रोनाइझेशन)**: गटातील कोणत्याही मशीनवर फायली जोडल्या गेल्या, हटवल्या किंवा सुधारित केल्या गेल्या असल्यास, इतर सर्व ऑनलाइन नोड्स रिअल टाइममध्ये समकालिकपणे अद्यतनित केले जातील आणि एकमेकांसाठी सीड म्हणून काम करतील.

```bash
# संपूर्ण सामायिकरण गटाची सदस्यता घ्या: रिमोट जोडणे, हटवणे आणि बदल रिअल टाइममध्ये स्थानिकरित्या सिंक्रोनाइझ केले जातात आणि आपोआप सीड केले जातात
sync0 sub dataset:// ./local_mirror -p <नोड पत्ता>

# ऑन-डिमांड मल्टी-सिलेक्ट सबस्क्रिप्शन: रिअल टाइममध्ये फक्त सिंक्रोनाइझ करा आणि निर्दिष्ट केलेल्या एकल फाइल्स आणि उपनिर्देशिका सीड करा
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <नोड पत्ता>

# मल्टी-मशीन पीअर ग्रुप टू-वे रिअल-टाइम सिंक्रोनाइझेशन (पूर्ण किंवा स्वल्पविराम मल्टी-सिलेक्ट पथांना देखील समर्थन देते)
sync0 group team-docs:// ./docs -p <node address>
```

### 4. टीम मल्टी-शेअरिंग ग्रुप आणि सदस्य परवानगी कॉन्फिगरेशन (`.nt` कॉन्फिगरेशन)

डीफॉल्ट कॉन्फिगरेशन निर्देशिका `~/.config/sync0` आहे (`-c <directory>` द्वारे स्विच केली जाऊ शकते), मिनिमलिस्ट [NestedText](https://nestedtext.org) (`.nt`) फॉरमॅट वापरून:
- **सार्वजनिक नेटवर्क वाचन प्रतिबंधित करण्यास समर्थन देते (केवळ अधिकृत वापरकर्ते वाचू शकतात)**: जोपर्यंत सामायिकरण गट `users:` सदस्य सूचीसह कॉन्फिगर केलेला आहे (किंवा कमांड लाइन `--allow-r` / `--allow-rw` / `--allow-w` / `--auth` निर्दिष्ट करते तोपर्यंत, सिस्टम ** स्वयंचलितपणे चालू होते (`--auth`) ** स्वयंचलितपणे चालू होते (`--auth`). सार्वजनिक नेटवर्क निनावी नोड गणन किंवा वाचन प्रतिबंधित करते, आणि P2P सीडिंग नोड्सचे सदस्यत्व देखील एकाच वेळी श्वेतसूचीचा वारसा घेते, केवळ अधिकृत वापरकर्त्यांना वाचण्याची परवानगी देते; `users` सह कॉन्फिगर न केलेले सामायिकरण गट डीफॉल्टनुसार सार्वजनिक आणि केवळ-वाचनीय आहेत (जर तुम्हाला सार्वजनिक आणि केवळ वाचनीय व्हायचे असेल आणि केवळ निर्दिष्ट सदस्यांसाठी अपलोड करण्यासाठी खुले असेल, तर तुम्ही स्पष्टपणे `auth: false` सेट करू शकता).
- **सुरेख वाचन-लेखन आणि उपनिर्देशिका वितरण परवानग्या**: सदस्यांना डीफॉल्टनुसार केवळ वाचनीय आहे (`r` स्पष्टपणे लिहिण्याची आवश्यकता नाही), आणि समर्थन `r` (केवळ-वाचनीय), `w` (फक्त ड्रॉप बॉक्समध्ये लिहा, वाचण्यायोग्य नाही), `rw` (5) वाचन करा (5) उपडिरेक्ट्री उपसर्ग अपलोड करण्यास अनुमती आहे).

**सदस्य कॉन्फिगरेशनचे उदाहरण (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (डिफॉल्ट केवळ-वाचनीय, गती मर्यादा 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (वाचन आणि लिहिण्याची परवानगी, केवळ निर्दिष्ट उपनिर्देशिकेवर अपलोड करण्याची परवानगी)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (फक्त वितरण परवानगी लिहा, वाचन प्रतिबंधित आहे)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**शेअरिंग ग्रुप कॉन्फिगरेशनचे उदाहरण (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # कॉन्फिगर केलेले नाही वापरकर्ते: डीफॉल्ट सार्वजनिक नेटवर्क केवळ-वाचनीय
  dataset:
    path: ./data
    rate: 50MB

  # कॉन्फिगर केलेले वापरकर्ते: स्वयंचलितपणे सार्वजनिक नेटवर्क वाचन प्रतिबंधित करा (केवळ ॲलिस आणि बॉब वाचू शकतात, चार्ली फक्त वितरित आणि अपलोड करू शकतात)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

सेवा सुरू करा (कॉन्फिगरेशन फाइल लोड करा किंवा सार्वजनिक नेटवर्क वाचन प्रतिबंधित करण्यासाठी आणि सदस्यांना अधिकृत करण्यासाठी थेट कमांड लाइन पॅरामीटर्स वापरा):

```bash
# सुरू करण्यासाठी ~/.config/sync0/config.nt लोड करा
sync0 share --region SHA

# किंवा शुद्ध कमांड लाइनद्वारे खाजगी शेअरिंग गट प्रकाशित करा (सार्वजनिक नेटवर्क वाचन स्वयंचलितपणे प्रतिबंधित करण्यासाठी --allow-* निर्दिष्ट करा आणि केवळ अधिकृत वापरकर्ते त्यात प्रवेश करू शकतात)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. नोड पत्ता, व्यवसाय कार्ड आणि बहु-भाषा

```bash
# स्थानिक आयपी-फ्री नोड पत्ता पहा (की पहिल्या रनसाठी स्वयंचलितपणे तयार केली जाते)
sync0 id

# Ed25519 स्व-स्वाक्षरी केलेले नोड व्यवसाय कार्ड व्युत्पन्न करा (टोपणनाव, शहर कोड, ईमेल, वेबसाइट, परिचय)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# तेथे 75 अंगभूत भाषा आहेत, ज्या डीफॉल्टनुसार सिस्टम भाषेचे अनुसरण करतात आणि पर्यावरण व्हेरिएबल्सद्वारे स्विच केल्या जाऊ शकतात.
SYNC0_LANG=en sync0 --help
```

### मुख्य उत्पादन वैशिष्ट्ये

- **पब्लिक की ॲड्रेसिंग ऑटोमॅटिक होल पंचिंग**: सेंट्रल सर्व्हर आणि सार्वजनिक नेटवर्क ॲड्रेसची गरज नाही, वितरित नेटवर्क सार्वजनिक की ॲड्रेसवर आधारित ऑटोमॅटिक NAT होल पंचिंग.
- **मिलिसेकंद-स्तरीय रिअल-टाइम सिंक्रोनाइझेशन आणि मेटाडेटा जागरूकता**: नेटिव्ह फाइल इव्हेंट मॉनिटरिंगवर आधारित (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), फाइल जोडणे, हटवणे, POSIX परवानग्या (`mode`) आणि मिलिसेकंद वेळ (`mode`) आणि मिलिसेकंद वेळ (`mode`) रिअल-टाइम पुश; शून्य डेटा ब्लॉक ट्रान्समिशन जेव्हा फक्त परवानग्या किंवा वेळ सुधारित केले जातात.
- **BT-शैलीचे एकाचवेळी डाउनलोड आणि अपलोड आणि प्रादेशिक आत्मीयता शेड्युलिंग**: डाउनलोडिंग नोडला पूर्ण रक्कम डाउनलोड होण्याची प्रतीक्षा करण्याची आवश्यकता नाही. सर्व ब्लॉक अंतराल (`Op::Have`) ज्यांनी 128-बिट हॅश चेक उत्तीर्ण केले आहे ते इतर नोड्स एकाच वेळी खेचण्यासाठी मेमरी/तात्पुरत्या पूलमध्ये त्वरित लॉक केले जातात. डायनॅमिक PEX नोड एक्सचेंज आणि स्लो नोड हाफ प्रीम्प्शन (वर्क-स्टीलिंग) सोबत, क्लस्टर थ्रूपुट कमाल केले जाते.
- **अँटी-मॅलिशिअस नोड छेडछाड आणि क्लस्टर पॉइझनिंग इम्युनिटी**: अधिकृत स्त्रोत सूची `root_hash` सेल्फ-कॉन्सिस्टंट लॉकिंग + अनिवार्य हार्डवेअर प्रवेग `gxhash128` डिस्कवर प्रत्येक ब्लॉक ठेवण्यापूर्वी आणि बाहेरून सीड करण्यापूर्वी डायजेस्ट सत्यापन; छेडछाड केलेला ब्लॉक आढळल्यास, मिलिसेकंद-स्तरीय सर्किट ब्रेकर दुर्भावनायुक्त नोड ब्लॅकआउट करेल आणि प्रामाणिक स्त्रोताकडून आपोआप पुनर्प्राप्त होईल.
- **फास्टसीडीसी इन-सीटू इन्क्रिमेंट आणि लहान फाइल एकत्रीकरण**: मोठ्या फाइल्सच्या आंशिक बदलासाठी फक्त डिफरेंशियल ब्लॉक्स हस्तांतरित केले जातात आणि डिस्कवर ठेवले जातात; मोठ्या प्रमाणात लहान फाइल मेमरी पॅकेजिंग आणि उपसर्ग डिफरेंशियल कॉम्प्रेशन फाइल-बाय-फाइल राउंड-ट्रिप ओव्हरहेड काढून टाकते.
- **पॉवर आउटेज नंतर सेल्फ-हिलिंग आणि रीस्टार्ट केल्यानंतर पुन्हा सुरू करणे**: रेडिस-सारखे RDB + AOF हायब्रिड फॉरमॅट (`.s0_subs.bin`) सीडिंग स्थिती आणि फाइल सूची कायम ठेवण्यासाठी वापरला जातो, दैनंदिन बदल मायक्रोसेकंदमध्ये जोडले जातात, आणि स्वयंचलितपणे पुन्हा लिहले जातात आणि नियमितपणे व्यवस्थित केले जातात. सर्व्हर रीस्टार्ट केल्यानंतर, ऑफलाइन बदल आपोआप सीडिंग नोडवर ढकलले जातात.
