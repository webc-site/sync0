# sync0

`sync0` हे पीअर-टू-पीअर (P2P) फाइल शेअरिंग आणि मल्टी-मशीन सिंक्रोनाइझेशन टूल आहे जे Resilio Sync शी स्पर्धा करते.

प्रत्येक मशीन सर्व्हर आणि क्लायंट दोन्ही आहे: कोणताही नोड एकाधिक फाइल शेअरिंग गट प्रकाशित करू शकतो. इतर नोड्स सामील झाल्यानंतर, ते पीअर सर्व्हरवरून आपोआप उपलब्ध सीड नोड्स मिळवू शकतात आणि त्यांना एकाधिक स्त्रोतांकडून एकाच वेळी खेचू शकतात. सिंक्रोनाइझेशन पूर्ण झाल्यानंतर, डाउनलोडला गती देण्यासाठी अधिक नोड्ससाठी बिया स्वयंचलितपणे तयार केल्या जातील.

## कोर हायलाइट्स

- **प्रत्येकजण सर्व्हर आणि क्लायंट दोन्ही असतो**: रेसिलिओ सिंकशी तुलना करता येते, केंद्रीय सर्व्हर अवलंबित्व नाही. कोणताही नोड एकाधिक फाइल सामायिकरण गट तयार करू शकतो, आणि इतर लोकांच्या शेअरिंग गटांमध्ये देखील सामील होऊ शकतो; अनेक मशीन्सचे समवर्ती पुलिंग आणि रिअल-टाइम सिंक्रोनायझेशन साध्य करण्यासाठी नोड्स स्वयंचलितपणे एक्सचेंज करतात आणि उपलब्ध सीड नोड्स मिळवतात.
- **आयपी-फ्री नोड पत्ता**: डीफॉल्टनुसार, नोड की आणि `base64url` एन्कोड केलेला `iroh` पत्ता `~/.config/sync0` मध्ये सार्वजनिक IP लक्षात ठेवण्याची किंवा उघड न करता आपोआप जनरेट केला जातो.
- **मल्टी-सिलेक्ट सिंक्रोनाइझेशन ऑन डिमांड**: संपूर्ण शेअरिंग ग्रुपच्या सिंक्रोनाइझेशनला समर्थन देते आणि एकाच वेळी अनेक फाइल्स किंवा सबडिरेक्टरीज निवडून मागणीनुसार सिंक्रोनाइझेशनचे समर्थन करते.
- **समूह सदस्य श्रेणीबद्ध परवानग्या आणि अपलोड निर्देशिका नियंत्रण**: केवळ-वाचनीय (`ro`), वाचन-लेखन अपलोड (`rw`), आणि व्यवस्थापन (`admin`) परवानग्यांना समर्थन देते आणि प्रत्येक सदस्याला अपलोड करण्याची अनुमती असलेला पथ उपसर्ग वैयक्तिकरित्या निर्दिष्ट करू शकतो (डीफॉल्टनुसार, शेअर निर्देशिका अपलोड करण्यासाठी अनुमती आहे).
- **नेटवर्कवर पूर्ण-गती आणि वाढीव सिंक्रोनाइझेशन**: मोठ्या फायलींचे समवर्ती प्रसारण, मेमरीमधील मोठ्या लहान फायलींचे एकत्रीकरण आणि फाइल्स अंशतः सुधारित केल्यावरच डेटा ब्लॉक्स्चे समक्रमित केले जातात.

## स्थापित करा

### पद्धत 1: कार्गो मार्गे स्थापित करा

```bash
cargo install sync0
```

### पद्धत 2: पूर्वसंकलित बायनरी डाउनलोड करा

संबंधित प्रणालीसाठी (Linux, macOS, Windows, Android, FreeBSD, NetBSD ला सपोर्ट करते) साठी `.tar.xz` संकुचित पॅकेज डाउनलोड करण्यासाठी [GitHub Releases](https://github.com/webc-site/sync0/releases) वर जा, अनझिप करा आणि `PATH` निर्देशिकेत ठेवा:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## लवकर सुरुवात करा

`sync0` डीफॉल्टनुसार कॉन्फिगरेशन डिरेक्टरी म्हणून `~/.config/sync0` वापरते (तुम्हाला इतर डिरेक्टरीमध्ये स्विच करायचे असल्यास, तुम्ही `-c <directory>` जोडू शकता).

### 1. स्थानिक नोड पत्ता आणि व्यवसाय कार्ड सेटिंग पहा

```bash
# स्थानिक नोड पत्ता पहा (की प्रथमच ~/.config/sync0 मध्ये स्वयंचलितपणे तयार केली जाते)
sync0 id

# वैयक्तिक नोड व्यवसाय कार्ड व्युत्पन्न करा (वापरकर्ता नाव, शहर, ईमेल, वेबसाइट आणि स्वाक्षरी 256 शब्दांमध्ये समर्थित करते)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. एकाधिक फाइल शेअरिंग गट प्रकाशित करा आणि गट सदस्य परवानग्या सेट करा (`.nt` कॉन्फिगरेशन)

`sync0` [NestedText](https://nestedtext.org) (`.nt`) फॉरमॅटमध्ये कॉन्फिगर केले आहे. प्रत्येक वापरकर्त्याकडे स्वतंत्र `.nt` कॉन्फिगरेशन फाइल असते. तुम्ही वापरकर्ता प्रोफाइल निर्देशिका `users_dir` द्वारे `config.nt` मध्ये निर्दिष्ट करू शकता (ज्यात या निर्देशिकेतील सर्व `.nt` फाइल्स आपोआप समाविष्ट होतात). अपलोड करण्याची अनुमती असलेले वापरकर्ता आणि पथ उपसर्ग दोन्ही क्रमरहित सूची (`-`) वापरतात. **जेव्हा अपलोड पथ उपसर्ग भरला जात नाही, तेव्हा शेअरच्या मूळ निर्देशिकेवर अपलोड करण्याची परवानगी डीफॉल्टनुसार असते**.

1. `~/.config/sync0/users/` निर्देशिकेत प्रत्येक सदस्यासाठी स्वतंत्र `.nt` कॉन्फिगरेशन फाइल्स तयार करा:

`~/.config/sync0/users/alice.nt` (केवळ-वाचनीय सदस्य, दर मर्यादित `80MB`, `rate` `GB`, `MB`, `KB` युनिट्सना समर्थन देते):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (प्रतिबंधित अपलोड सदस्य: फक्त `uploads/bob` आणि `shared/common` निर्देशिकांवर अपलोड करण्याची परवानगी आहे):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (डीफॉल्ट सदस्य अपलोड: जेव्हा `write_prefix` वगळले जाते, तेव्हा शेअरच्या मूळ निर्देशिकेवर अपलोड करण्याची परवानगी डीफॉल्टनुसार असते):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. `~/.config/sync0/config.nt` मध्ये वापरकर्ता निर्देशिका आणि एकाधिक फाइल सामायिकरण गट कॉन्फिगर करा:

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

शेअरिंग सेवा सुरू करा:

```bash
# डायरेक्ट स्टार्टअप (~/.config/sync0/config.nt आणि user_dir निर्देशिकांमध्ये सर्व .nt वापरकर्ता कॉन्फिगरेशन स्वयंचलितपणे लोड करते)
sync0 share --region SHA

# किंवा एकाधिक सामायिकरण गट द्रुतपणे प्रकाशित करा आणि थेट कमांड लाइनद्वारे गट सदस्यांना अधिकृत करा
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. सर्व सामग्री काढा किंवा एकाधिक फाइल्स आणि निर्देशिका निवडा (`sync0 pull`)

शेअरिंग ग्रुपमधील सर्व उपलब्ध सीड नोड्स आपोआप मिळवण्यासाठी कोणत्याही पीअर नोडशी कनेक्ट करा आणि एकाच वेळी अनेक सीड नोड्समधून खेचून घ्या:

```bash
# संपूर्ण डेटासेट शेअरिंग गटाला स्थानिक ./local_data वर खेचा
sync0 पुल डेटासेट:// ./local_data -p <नोड पत्ता>

# मल्टी-सिलेक्ट सिंक्रोनाइझेशन: एकाच वेळी एकल फाइल docs/readme.md आणि उपनिर्देशिका मालमत्ता/चिन्ह, src/core खेचा
sync0 पुल डेटासेट://docs/readme.md,assets/icons,src/core ./local_data -p <नोड पत्ता>
```

### 4. शेअरिंग ग्रुपवर फाइल किंवा निर्देशिका अपलोड करा (`sync0 push`)

अपलोड परवानग्या असलेले सदस्य (`rw` किंवा `admin`) रिमोट शेअरिंग गटांमध्ये स्थानिक फाइल्स किंवा निर्देशिका अपलोड करू शकतात:

```bash
# रूट निर्देशिका अपलोड करण्याची परवानगी असलेले सदस्य: शेअर केलेल्या रूट डिरेक्ट्रीवर थेट अपलोड करा
sync0 push team-vault:// ./new_release -p <node address>

# केवळ विशिष्ट उपसर्ग (जसे की अपलोड/बॉब) साठी अधिकृत सदस्य: अनुमत पथ उपसर्गावर अपलोड करा
sync0 push team-vault://uploads/bob/report.pdf ./report.pdf -p <नोड पत्ता>
```

### 5. स्वयंचलित सिंक आणि सीडिंगची सदस्यता घ्या (`sync0 sub`)

ठराविक नोडच्या शेअरिंग ग्रुपची सदस्यता घेतल्यानंतर, स्थानिक सर्व्हर प्राप्त करणारा क्लायंट आणि नवीन सीडिंग सर्व्हर दोन्ही असतो; जेव्हा स्त्रोत नोड फाइल अद्यतनित केली जाते, तेव्हा ती स्वयंचलितपणे सिंक्रोनाइझ केली जाते आणि इतर नोड्ससाठी तुकडे केलेले डाउनलोड प्रदान करते:

```bash
# संपूर्ण शेअरिंग ग्रुपची सदस्यता घ्या आणि आपोआप सीड करा
sync0 sub dataset:// ./local_mirror -p <नोड पत्ता>

# निर्दिष्ट केलेल्या फाइल्स आणि उपडिरेक्टरीजचे सदस्यत्व घेण्यासाठी आणि त्यांना सीड करण्यासाठी फक्त मल्टी-सिलेक्ट करा
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <नोड पत्ता>
```

### 6. मल्टी-मशीन ग्रुप पीअर सिंक्रोनाइझेशन (`sync0 group`)

अनेक मशीन्स एकाच शेअरिंग ग्रुपमध्ये सामील होतात, एकमेकांना आपोआप उपलब्ध सीड नोड्स शोधतात आणि द्वि-मार्ग सिंक्रोनाइझेशन राखतात (संपूर्ण सिंक्रोनाइझेशन किंवा फायली आणि निर्देशिकांच्या एकाधिक निवडीला समर्थन देते):

```bash
# गट आणि द्वि-मार्ग समक्रमणात पूर्णपणे सामील व्हा
sync0 group team-docs:// ./docs -p <node address>

# मल्टी-सिलेक्ट सिंक्रोनाइझेशन ग्रुपमध्ये फक्त wal निर्देशिका आणि meta.json फाइल
sync0 group team-docs://wal,meta.json ./docs -p <node address>
```

### 7. दोन मशीनमधील पॉइंट-टू-पॉइंट डायरेक्ट ट्रान्समिशन (`send` / `recv`)

गट पूर्व-कॉन्फिगर करण्याची आवश्यकता नाही, आणि तुम्ही तात्पुरते फायली किंवा निर्देशिका थेट दोन मशीनमध्ये हस्तांतरित करू शकता:

```bash
# प्राप्तकर्ता निरीक्षण
sync0 recv 0.0.0.0:9000 ./backup

# सेंडिंग एंड थेट फाइल्स किंवा डिरेक्टरीज ट्रान्सफर करते (पर्यायी --अतिरिक्त फाइल्स साफ करण्यासाठी मिरर हटवा, --रेट स्पीड लिमिट)
sync0 send ./project 192.168.1.10:9000
```

### 8. बहु-भाषा स्विचिंग

`sync0` 75 भाषांना सपोर्ट करते, आणि डीफॉल्टनुसार सिस्टम भाषा वातावरणानुसार स्वयंचलितपणे स्विच होते; ते `SYNC0_LANG` द्वारे व्यक्तिचलितपणे देखील निर्दिष्ट केले जाऊ शकते:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
