# sync0

`sync0` — это одноранговый (P2P) инструмент для обмена файлами и синхронизации между несколькими компьютерами, конкурирующий с Resilio Sync.

Каждая машина является одновременно сервером и клиентом: любой узел может публиковать несколько групп обмена файлами. После присоединения других узлов они могут автоматически получать доступные начальные узлы с однорангового сервера и одновременно извлекать их из нескольких источников. После завершения синхронизации семена будут автоматически созданы для большего количества узлов для ускорения загрузки.

## Основные моменты

- **Каждый является и сервером, и клиентом**: аналогично Resilio Sync, нет зависимости от центрального сервера. Любой узел может создавать несколько групп общего доступа к файлам, а также может присоединяться к группам общего доступа других людей; узлы автоматически обмениваются и получают доступные начальные узлы для одновременного извлечения и синхронизации нескольких машин в реальном времени.
- **Адрес узла без IP**: по умолчанию ключ узла и `base64url` закодированный адрес `iroh` автоматически генерируются в `~/.config/sync0` без необходимости запоминать или раскрывать общедоступный IP-адрес.
- **Синхронизация с множественным выбором по требованию**: поддерживает синхронизацию всей группы общего доступа, а также поддерживает синхронизацию по требованию путем одновременного выбора нескольких файлов или подкаталогов.
- **Иерархические разрешения членов группы и управление каталогом загрузки**: поддерживаются разрешения только для чтения (`ro`), чтения и записи (`rw`) и управления (`admin`), а также можно индивидуально указать префикс пути, который каждому участнику разрешено загружать (по умолчанию разрешена загрузка в корневой каталог общего ресурса).
- **Полноскоростная и инкрементальная синхронизация между сетями**: одновременная передача больших файлов, агрегирование больших маленьких файлов в памяти и синхронизация блоков данных только при частичном изменении файлов.

## Установить

### Способ 1: установка через Cargo

```bash
cargo install sync0
```

### Способ 2. Загрузите предварительно скомпилированные двоичные файлы.

Перейдите в [GitHub Releases](https://github.com/webc-site/sync0/releases), чтобы загрузить сжатый пакет `.tar.xz` для соответствующей системы (поддерживает Linux, macOS, Windows, Android, FreeBSD, NetBSD), разархивируйте и поместите его в каталог `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Начинайте быстро

`sync0` использует `~/.config/sync0` в качестве каталога конфигурации по умолчанию (если вам нужно переключиться на другие каталоги, вы можете добавить `-c <directory>`).

### 1. Просмотр адреса локального узла и настройка визитной карточки

```bash
# Просмотрите адрес локального узла (ключ автоматически генерируется в ~/.config/sync0 в первый раз)
sync0 id

# Создайте визитную карточку личного узла (поддерживает имя пользователя, город, адрес электронной почты, веб-сайт и подпись в пределах 256 слов)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. Публикация нескольких групп общего доступа к файлам и установка разрешений для участников группы (конфигурация `.nt`)

`sync0` настроен в формате [NestedText](https://nestedtext.org) (`.nt`). У каждого пользователя есть отдельный файл конфигурации `.nt`. Вы можете указать каталог профиля пользователя с помощью `users_dir` в `config.nt` (который автоматически включает все файлы `.nt` в этот каталог). И пользователь, и префикс пути, разрешенный для загрузки, используют неупорядоченный список (`-`). **Если префикс пути загрузки не заполнен, загрузка в корневой каталог общего ресурса разрешена по умолчанию**.

1. Создайте отдельные файлы конфигурации `.nt` для каждого участника в каталоге `~/.config/sync0/users/`:

`~/.config/sync0/users/alice.nt` (член только для чтения, ограничение по скорости `80MB`, `rate` поддерживает единицы `GB`, `MB`, `KB`):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (участники с ограниченным доступом к загрузке: разрешена загрузка только в каталоги `uploads/bob` и `shared/common`):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (Загрузка элемента по умолчанию: если `write_prefix` опущен, загрузка в корневой каталог общего ресурса разрешена по умолчанию):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. Настройте каталог пользователя и несколько групп общего доступа к файлам в `~/.config/sync0/config.nt`:

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

Запустить сервис обмена:

```bash
# Прямой запуск (автоматически загружает все пользовательские конфигурации .nt в каталоги ~/.config/sync0/config.nt иusers_dir)
sync0 share --region SHA

# Или быстро опубликуйте несколько групп общего доступа и авторизуйте участников группы непосредственно через командную строку.
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. Извлеките все содержимое или выберите несколько файлов и каталогов (`sync0 pull`)

Подключитесь к любому одноранговому узлу, чтобы автоматически получить все доступные исходные узлы в группе общего доступа и одновременно получать данные из нескольких исходных узлов:

```bash
# Перенесите всю группу общего доступа к набору данных в локальный файл ./local_data.
sync0 pull dataset:// ./local_data -p <адрес узла>

# Синхронизация с множественным выбором: одновременно извлекайте один файл docs/readme.md и подкаталоги assets/icons, src/core.
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <адрес узла>
```

### 4. Загрузите файл или каталог в группу общего доступа (`sync0 push`)

Участники с разрешениями на загрузку (`rw` или `admin`) могут загружать локальные файлы или каталоги в удаленные группы общего доступа:

```bash
# Участники с разрешением на загрузку в корневой каталог: загрузка непосредственно в общий корневой каталог.
sync0 push team-vault:// ./new_release -p <адрес узла>

# Только участники, авторизованные по определенному префиксу (например, uploads/bob): загрузка по разрешенному префиксу пути.
sync0 push team-vault://uploads/bob/report.pdf ./report.pdf -p <адрес узла>
```

### 5. Подписаться на автоматическую синхронизацию и раздачу (`sync0 sub`)

После подписки на группу общего доступа определенного узла локальный сервер является одновременно принимающим клиентом и новым раздающим сервером; когда файл исходного узла обновляется, он автоматически синхронизируется и обеспечивает фрагментированную загрузку для других узлов:

```bash
# Подпишитесь на всю группу общего доступа и автоматически раздавайте
sync0 sub dataset:// ./local_mirror -p <адрес узла>

# Только множественный выбор, чтобы подписаться на указанные файлы и подкаталоги и заполнить их.
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <адрес узла>
```

### 6. Одноранговая синхронизация группы из нескольких компьютеров (`sync0 group`)

Несколько компьютеров присоединяются к одной и той же группе общего доступа, каждая из которых автоматически обнаруживает доступные исходные узлы и поддерживает двустороннюю синхронизацию (поддерживает полную синхронизацию или множественный выбор файлов и каталогов):

```bash
# Полное присоединение к группе и двусторонняя синхронизация
группа sync0 team-docs:// ./docs -p <адрес узла>

# Только каталог wal и файл Meta.json в группе синхронизации с множественным выбором.
группа sync0 team-docs://wal,meta.json ./docs -p <адрес узла>
```

### 7. Прямая передача «точка-точка» между двумя компьютерами (`send` / `recv`)

Нет необходимости предварительно настраивать группу, и вы можете временно передавать файлы или каталоги напрямую между двумя машинами:

```bash
# Мониторинг приемника
sync0 recv 0.0.0.0:9000 ./backup

# Отправляющая сторона напрямую передает файлы или каталоги (необязательно --delete зеркало для очистки лишних файлов, --rate ограничение скорости)
sync0 send ./project 192.168.1.10:9000
```

### 8. Многоязычное переключение

`sync0` поддерживает 75 языков и автоматически переключается в соответствии с языковой средой системы по умолчанию; его также можно указать вручную через `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
