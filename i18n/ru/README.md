# sync0

`sync0` — это децентрализованный инструмент обмена файлами P2P, синхронизации в реальном времени и распространения из нескольких источников, используемый для замены `rsync` – измеренная скорость трансконтинентальной глобальной сети достигает **5,89×** для `rsync` (средняя геометрическая скорость в одной точке **2,67×**, средняя геометрическая скорость P2P с двумя источниками **3,16×**) и трансокеанский канал с высокой задержкой. Ускорение P2P составляет до **7,68×** (средняя геометрическая скорость Full-link для 24 сценариев **2,56×**).

Каждая машина является одновременно и сервером, и клиентом: нет необходимости в центральном сервере или публичном сетевом адресе, автоматическое прокалывание дыр основано на адресе открытого ключа распределенной сети и поддерживает прямую передачу между двумя машинами, хостинг с разрешениями групп с несколькими общим доступом, множественный выбор подкаталогов по требованию, инкрементальную синхронизацию в реальном времени на уровне миллисекунд и одновременное ускорение P2P с несколькими источниками.

## Установить

### Способ 1: Установка груза

```bash
cargo install sync0
```

### Способ 2. Загрузите предварительно скомпилированные двоичные файлы.

Перейдите на страницу [GitHub Releases](https://github.com/webc-site/sync0/releases), чтобы загрузить сжатый пакет `.tar.xz`, соответствующий вашей системе (поддерживает Linux, macOS, Windows, Android, iOS, FreeBSD), разархивируйте и поместите в `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Начинайте быстро

### 1. Прямая передача без настройки между двумя машинами (`send` / `recv`)

Нет необходимости настраивать группу общего доступа, напрямую передавайте файлы или каталоги между двумя компьютерами на высокой скорости:

```bash
# Принимающая сторона прослушивает порт и записывает в ./backup.
sync0 recv 0.0.0.0:9000 ./backup

# Прямая передача от отправителя (опционально --delete зеркало для удаления лишних файлов, --rate ограничение скорости 50 МБ)
sync0 send ./project 192.168.1.10:9000
```

### 2. Обмен сообщениями и получение/загрузка по требованию (`share` / `pull` / `push`)

```bash
# Сервер: опубликуйте группу общего доступа с помощью одной командной строки (выведите адрес узла iroh без IP после запуска)
sync0 share dataset:./data

# Клиент: переместите всю группу общего доступа к набору данных в локальный файл ./local_data.
sync0 pull dataset:// ./local_data -p <адрес узла>

# Клиент: выбор нескольких вариантов по требованию (синхронизировать только указанные отдельные файлы и подкаталоги).
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <адрес узла>

# Клиент: загрузка файлов или каталогов в авторизованные группы общего доступа.
sync0 push dataset://releases/v1 ./build_output -p <адрес узла>
```

### 3. Заполнение подписки в реальном времени и двусторонняя синхронизация между несколькими компьютерами (`sub` / `group`)

После установления длительного соединения, если на удаленном конце происходит какое-либо **добавление, изменение, удаление, изменение разрешений или время модификации**, локальный каталог будет синхронно обновляться за миллисекунды в реальном времени (новые/измененные большие файлы будут только извлекать разностные блоки и обновлять их на месте, удаление файлов будет автоматически очищать локальные файлы и пустые каталоги, а также напрямую изменять разрешения или метки времени нулевых блоков данных):

- **`sync0 sub`(Одностороннее зеркалирование в реальном времени + автоматическое заполнение)**: Локальный режим реального времени следует за добавлениями, удалениями и изменениями конца совместного использования и автоматически служит источником начального P2P для обеспечения одновременного ускорения для других принимающих узлов.
- **`sync0 group`(одноранговая двусторонняя синхронизация в реальном времени на нескольких компьютерах)**: если файлы добавляются, удаляются или изменяются на любом компьютере в группе, все остальные онлайн-узлы будут обновляться синхронно в реальном времени и служить в качестве исходных файлов друг для друга.

```bash
# Подпишитесь на всю группу общего доступа: удаленные добавления, удаления и изменения синхронизируются локально в режиме реального времени и автоматически заполняются.
sync0 sub dataset:// ./local_mirror -p <адрес узла>

# Подписка с множественным выбором по требованию: синхронизируйте и заполняйте только указанные отдельные файлы и подкаталоги в режиме реального времени.
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <адрес узла>

# Двусторонняя синхронизация в реальном времени в группе из нескольких компьютеров (также поддерживает полный или запятый множественный выбор путей)
группа sync0 team-docs:// ./docs -p <адрес узла>
```

### 4. Группа коллективного доступа с несколькими пользователями и конфигурация разрешений участников (конфигурация `.nt`)

Каталог конфигурации по умолчанию — `~/.config/sync0` (можно переключить с помощью `-c <directory>`), используя минималистичный формат [NestedText](https://nestedtext.org) (`.nt`):
- **Поддерживает ограничение чтения в общедоступной сети (только авторизованные пользователи могут читать)**: если группа общего доступа настроена со списком участников `users:` (или в командной строке указано `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`), система **автоматически включает частную аутентификацию (`auth: true`)** и запрещает перечисление анонимных узлов в общедоступной сети или чтение и P2P-подписка на раздающие узлы также одновременно наследуют белый список, позволяя читать только авторизованным пользователям; группы общего доступа, которые не настроены с помощью `users`, по умолчанию являются общедоступными и доступны только для чтения (если вы хотите быть общедоступными, доступными только для чтения и открытыми для загрузки только указанным участникам, вы можете явно установить `auth: false`).
- **Детальные разрешения на чтение и запись, а также на доставку в подкаталог**: по умолчанию элементы доступны только для чтения (`r` не нужно указывать явно) и поддерживают `r` (только чтение), `w` (только запись в раскрывающийся ящик, не читается), `rw` (чтение и запись) и `write_prefix` (ограничивает разрешенный префикс подкаталога для загрузка).

**Пример конфигурации участника (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (по умолчанию только чтение, ограничение скорости 80 МБ)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (разрешения на чтение и запись, загрузка разрешена только в указанный подкаталог)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (разрешение только на доставку, чтение запрещено)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**Пример конфигурации группы общего доступа (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # Не настроенные пользователи: общедоступная сеть по умолчанию только для чтения.
  dataset:
    path: ./data
    rate: 50MB

  # Настроенные пользователи: автоматически ограничивать чтение в общедоступной сети (только Алиса и Боб могут читать, Чарли может только доставлять и загружать)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

Запустите службу (загрузите файл конфигурации или напрямую используйте параметры командной строки, чтобы ограничить чтение общедоступной сети и авторизовать участников):

```bash
# Загрузите ~/.config/sync0/config.nt для начала.
sync0 share --region SHA

# Или опубликуйте частную группу общего доступа с помощью чистой командной строки (укажите --allow-*, чтобы автоматически ограничить чтение общедоступной сети и доступ к ней смогут получить только авторизованные пользователи).
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. Адрес узла, визитная карточка и многоязычность

```bash
# Просмотр локального адреса узла без IP (ключ генерируется автоматически при первом запуске)
sync0 id

# Создать визитную карточку самоподписанного узла Ed25519 (псевдоним, код города, адрес электронной почты, веб-сайт, введение)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# Существует 75 встроенных языков, которые по умолчанию соответствуют языку системы и могут переключаться с помощью переменных среды.
SYNC0_LANG=en sync0 --help
```

## Производительность и основные функции

### Фактические измерения в межконтинентальной глобальной сети (сравнение `rsync`)

Фактическая среда измерения: США `c1` → Европа `n1` (RTT 65 мс), набор данных — ядро ​​Linux `linux-7.3.3`:

#### 1) Режим а-ля-карт по сравнению с `rsync`

| Набор данных | размер | `sync0` Одна точка<br>(Мбит/с) | `rsync`<br>(Mbps) | Ускорение (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(не сжимается) | 155 MB | **236.48** | 108.74 | **2,17×** |
| `linux-7.3.3.tar`(сжимаемый) | 1.6 GB | **843.83** | 385.06 | **2,19×** |
| `linux-7.3.3.tar`(шаг локального изменения) | 1.6 GB | **8,014.15** | 1,361.72 | **5,89×** |
| `linux-7.3.3/` (95 979 небольших файлов) | 1.5 GB | **627.58** | 347.80 | **1,80×** |
| **среднее геометрическое** | — | **1,000.91** | 375.26 | **2,67×** |

#### 2) Режим P2P с двумя источниками и `rsync`

| Набор данных | размер | `sync0` Двойной источник P2P<br>(Мбит/с) | `rsync`<br>(Mbps) | Ускорение (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(не сжимается) | 155 MB | **330.09** | 108.74 | **3,04×** |
| `linux-7.3.3.tar`(сжимаемый) | 1.6 GB | **1,551.86** | 385.06 | **4.03×** |
| `linux-7.3.3.tar`(шаг локального изменения) | 1.6 GB | **5,474.17** | 1,361.72 | **4.02×** |
| `linux-7.3.3/` (95 979 небольших файлов) | 1.5 GB | **706.56** | 347.80 | **2,03×** |
| **среднее геометрическое** | — | **1,186.42** | 375.26 | **3,16×** |

> Примечание. В режиме P2P с двумя источниками европейские узлы `s1` совместно распределяют трафик, а время RTT для межконтинентальной магистральной сети составляет 65 мс.

### Основные характеристики продукта

- **Автоматическая пробивка дырок при адресации открытого ключа**: нет необходимости в центральном сервере и адресе общедоступной сети, автоматическая пробивка дырок NAT на основе адреса открытого ключа распределенной сети.
- **Синхронизация в реальном времени на миллисекундном уровне и отслеживание метаданных**: на основе встроенного мониторинга событий файлов (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), добавления и удаления файлов в реальном времени, разрешений POSIX (`mode`) и времени изменения на уровне миллисекунд (`mtime`); передача нулевого блока данных, когда изменяются только разрешения или время.
- **Одновременная загрузка и выгрузка в стиле BT и планирование региональной привязки**: узлу загрузки не нужно ждать загрузки всего объема. Все интервалы блоков (`Op::Have`), прошедшие 128-битную хеш-проверку, немедленно блокируются в памяти/временном пуле, чтобы другие узлы могли одновременно получать данные. Вместе с динамическим обменом узлами PEX и медленным половинным вытеснением узлов (Work-Stealing) пропускная способность кластера максимизируется.
- **Защита от несанкционированного вмешательства в узлы и иммунитет к отравлению кластера**: авторитетный список источников `root_hash` Самосогласованная блокировка + обязательное аппаратное ускорение `gxhash128` проверка дайджеста перед размещением каждого блока на диске и внешним заполнением; если обнаружен подделанный блок, автоматический выключатель миллисекундного уровня отключит вредоносный узел и автоматически восстановит работу из честного источника.
- **Инкремент FastCDC на месте и агрегирование небольших файлов**: для частичной модификации больших файлов передаются только дифференциальные блоки, которые помещаются на диск; массивная упаковка небольших файлов в памяти и дифференциальное сжатие префиксов устраняют накладные расходы при передаче файлов туда и обратно.
- **Самовосстановление после отключения питания и возобновление работы после перезапуска**: гибридный формат RDB + AOF, подобный Redis (`.s0_subs.bin`), используется для сохранения статуса заполнения и списка файлов, ежедневные изменения добавляются за микросекунды, автоматически перезаписываются и систематизируются. После перезапуска сервера автономные изменения автоматически передаются на начальный узел.

## Техническая архитектура и документация

- **Протокол двухплоскостной развязки**:
  - **Панель управления и изменений в реальном времени (`iroh` QUIC / TCP, первый байт `PROTO_VERSION` рукопожатие версии) **: отвечает за проверку визитных карточек Ed25519, проверку разрешений, обнаружение исходного кода Swarm и поддержку пакетной потоковой передачи массовых изменений уровня `u64::MAX` и `mzstd` сжатого `SubPush` push-уведомления в реальном времени (`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` Три примитива).
  - **Поверхность распределения данных (собственный UDP + `compio` асинхронный ввод-вывод) **: компактный заголовок 20 байт, периодическая обратная связь TACK 18 байт, гибридный контроль перегрузки BBRv3/Copa, восстановление потерянных пакетов RACK-TLP, обход энтропийно-адаптивного сжатия Zstd первого блока и сквозная проверка блоков `gxhash128`.
