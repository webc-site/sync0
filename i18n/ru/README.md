# sync0

`sync0` — это инструмент командной строки для передачи файлов по сети, поэтапной синхронизации каталогов и одновременного распространения данных на несколько компьютеров.

## Оригинальный дизайнерский замысел

В комнатах с несколькими компьютерами, в странах или средах с задержками в сети и потерей пакетов такие инструменты, как `rsync` и `scp`, основаны на подтверждении одной последовательности подключений, что ограничивает использование полосы пропускания; Когда несколько компьютеров одновременно извлекают данные с одного и того же сервера, сетевая карта исходного сервера может легко стать узким местом.

Целью `sync0` является решение двух проблем:

1. Позвольте синхронизации файлов и каталогов между двумя компьютерами использовать полную физическую полосу пропускания и передавать измененную часть только тогда, когда файл частично изменен.
2. Несколько машин могут передавать блоки данных друг другу при синхронизации одного и того же каталога, что снижает нагрузку на исходный сервер и сокращает общее время синхронизации.

## Сравнение скорости с помощью rsync

Тестовая среда: европейский узел $\leftrightarrow$ Североамериканский узел, двусторонняя задержка 86 мс, измерение всех затрат времени, включая сканирование каталогов, сравнение дедупликации, передачу по сети и проверку размещения диска:

| Сценарий передачи | Размер данных | `sync0` | `rsync` | несколько |
| :--- | :---: | :---: | :---: | :---: |
| 10 000 небольших файлов | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| Пакеты кода и архива (`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| Видеофайл (`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| Инкрементальная синхронизация (изменить 1% контента) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## Методы повышения производительности

- **Одновременная передача по UDP**: отправляйте блоки данных через UDP и повторно передавайте только потерянные фрагменты, чтобы избежать потери одного пакета, блокирующей последующую передачу файлов.
- **Сегментация и дедупликация контента**. Разделите файл на блоки данных в соответствии с содержимым и рассчитайте проверочное значение. Тот же контент, который уже находится на принимающей стороне, повторно используется непосредственно локально без дублирования сети.
- **Автоматическая настройка сжатия в зависимости от скорости сети**. Включите сжатие для сжимаемого содержимого, такого как текст и код; автоматически пропускать сжатие видео, изображений, сжатых пакетов или в высокоскоростной локальной сети, чтобы снизить нагрузку на процессор.
- **Загрузка нескольких узлов поблизости**: когда несколько компьютеров извлекают один и тот же каталог, блоки данных будут извлекаться одновременно из загруженных узлов в одном городе или с меньшей задержкой.

## Установить

### Способ 1: установка через Cargo

```bash
cargo install sync0
```

### Способ 2. Загрузите предварительно скомпилированные двоичные файлы.

Перейдите на страницу [GitHub Releases](https://github.com/webc-site/sync0/releases), чтобы загрузить сжатый пакет `.tar.xz` для соответствующей системы (поддерживает Linux x86_64/ARM64, macOS Apple Silicon/Intel, Windows x64/ARM64, Android ARM64/x86_64, FreeBSD, NetBSD). После распаковки поместите `sync0` в каталог `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Руководство пользователя

### 1. Непосредственная передача файлов или каталогов между двумя компьютерами

Запустите мониторинг на принимающей машине и укажите путь получения и сохранения:

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

Отправьте один файл или весь каталог с отправляющего компьютера:

```bash
sync0 send ./project 192.168.1.10:9000
```

Часто используемые параметры:

```bash
# Удалите избыточные файлы, существующие на принимающей стороне, но не на отправляющей стороне (зеркальная синхронизация).
sync0 send ./project 192.168.1.10:9000 --delete

# Ограничить скорость отправки (единица измерения: байт/секунда, например 50 МБ/с).
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# Тихий режим (индикатор выполнения не отображается)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. Публикация общих каталогов и получение данных с нескольких узлов

Опубликуйте общий каталог (с именем `dataset`) на исходном сервере:

```bash
sync0 share dataset ./data --region SHA
```

Извлеките общий каталог на других машинах (вы можете одновременно указать несколько адресов узлов, разделенных запятыми, чтобы извлекать одновременно):

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

Извлекайте только определенный подкаталог в общем каталоге:

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

Отправьте локальные изменения обратно в удаленный общий каталог:

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. Подпишитесь на автоматические обновления каталога

Подпишитесь на общий каталог исходного узла. Когда файл добавляется или изменяется в исходном каталоге, он автоматически синхронизируется с локальным компьютером. В то же время локальная машина автоматически будет служить узлом для других машин:

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. Двусторонняя синхронизация групп из нескольких машин

Несколько компьютеров присоединяются к одной и той же группе, и изменения в любом каталоге узла будут автоматически синхронизированы с другими узлами в группе:

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. Удостоверение узла и личная визитная карточка

Каждый узел поддерживает настройку имени пользователя, города, электронной почты, веб-сайта и персонализированной подписи (максимум 256 символов) и передает аутентификацию подписи с помощью локального закрытого ключа:

```bash
# Просмотр идентификатора локального открытого ключа (укажите каталог конфигурации для сохранения ключа)
sync0 id -c ~/.config/sync0

# Создавайте и отображайте визитные карточки узлов с персонализированными подписями
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`, `pull`, `sub`, `group` также можно запустить со следующими параметрами профиля:

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. Многоязычное переключение

`sync0` Поддерживает 75 языков. По умолчанию справка и подсказки командной строки на соответствующем языке отображаются автоматически в соответствии с языковой средой операционной системы; если язык системы отсутствует в списке поддерживаемых, по умолчанию используется английский.

Чтобы указать язык вручную, установите переменную среды `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
