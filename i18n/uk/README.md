# sync0

`sync0` — це інструмент командного рядка для передачі файлів між мережами, поступової синхронізації каталогів і одночасного розподілу даних на кількох машинах.

## Оригінальний дизайнерський задум

У різних машинних приміщеннях, країнах або середовищах із мережевими затримками та втратою пакетів такі інструменти, як `rsync` і `scp`, базуються на підтвердженні однієї послідовності підключення, що обмежує використання пропускної здатності; коли кілька машин отримують дані з одного сервера одночасно, мережева карта вихідного сервера може легко стати вузьким місцем.

Метою `sync0` є вирішення двох проблем:

1. Дозвольте синхронізації файлів і каталогів між двома машинами виконувати повну фізичну пропускну здатність і передавати змінену частину лише тоді, коли файл частково змінено.
2. Кілька машин можуть передавати блоки даних одна одній під час синхронізації одного каталогу, зменшуючи навантаження на вихідний сервер і скорочуючи загальний час синхронізації.

## Порівняння швидкості з rsync

Тестове середовище: європейський вузол $\leftrightarrow$ північноамериканський вузол, затримка в обидві сторони 86 мс, вимірювання повного часу, включаючи сканування каталогу, порівняння дедуплікацій, мережеву передачу та перевірку розміщення диска:

| Сценарій передачі | Розмір даних | `sync0` | `rsync` | багаторазовий |
| :--- | :---: | :---: | :---: | :---: |
| 10 000 маленьких файлів | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| Пакунки коду та архіву (`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| Відеофайл (`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| Поступова синхронізація (змінити 1% вмісту) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## Методи підвищення продуктивності

- **Одночасна передача UDP**: надсилайте блоки даних через UDP і повторно передайте лише втрачені фрагменти, щоб уникнути блокування втратою одного пакета наступних передач файлів.
- **Сегментація вмісту та дедуплікація**: розділіть файл на блоки даних відповідно до вмісту та обчисліть контрольне значення. Той самий вміст, який уже знаходиться на приймальній стороні, повторно використовується безпосередньо локально без дублювання в мережі.
- **Автоматично регулюйте стиснення відповідно до швидкості мережі**: увімкніть стиснення для стиснутого вмісту, наприклад тексту та коду; автоматично пропускати стиснення для відео, зображень, стиснутих пакетів або під час високошвидкісної локальної мережі, щоб зменшити споживання ЦП.
- **Витягування кількох вузлів поблизу**: коли кілька машин завантажують той самий каталог, блоки даних витягуватимуться одночасно із завантажених вузлів у тому самому місті або з меншою затримкою.

## встановити

### Спосіб 1: встановлення через Cargo

```bash
cargo install sync0
```

### Спосіб 2. Завантажте попередньо скомпільовані двійкові файли

Перейдіть на [GitHub Releases](https://github.com/webc-site/sync0/releases), щоб завантажити стислий пакет `.tar.xz` для відповідної системи (підтримує Linux x86_64/ARM64, macOS Apple Silicon/Intel, Windows x64/ARM64, Android ARM64/x86_64, FreeBSD, NetBSD). Після розпакування помістіть `sync0` у каталог `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Посібник користувача

### 1. Пряма передача файлів або каталогів між двома машинами

Розпочніть моніторинг на приймальній машині та вкажіть шлях отримання та збереження:

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

Надішліть один файл або цілий каталог із машини-відправника:

```bash
sync0 send ./project 192.168.1.10:9000
```

Зазвичай використовувані параметри:

```bash
# Видалити зайві файли, які існують на стороні приймача, але не на стороні надсилання (дзеркальна синхронізація)
sync0 send ./project 192.168.1.10:9000 --delete

# Обмежити швидкість надсилання (одиниця вимірювання: байт/секунду, наприклад 50 МБ/с)
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# Тихий режим (індикатор прогресу не відображається)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. Публікація спільних каталогів і отримання з кількох вузлів

Опублікуйте спільний каталог (під назвою `dataset`) на вихідному сервері:

```bash
sync0 share dataset ./data --region SHA
```

Витягніть спільний каталог на інших машинах (ви можете заповнити кілька адрес вузлів одночасно, розділивши їх комами, щоб отримати одночасно):

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

Витягнути лише певний підкаталог у спільному каталозі:

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

Надішліть локальні зміни назад у віддалений спільний каталог:

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. Підпишіться на автоматичне оновлення каталогу

Підпишіться на спільний каталог вихідного вузла. Коли файл додається або змінюється у вихідному каталозі, він автоматично синхронізується з локальним комп’ютером. Водночас локальна машина автоматично слугуватиме вузлом для інших машин:

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. Двостороння синхронізація багатомашинних груп

Кілька машин приєднуються до однієї групи, і зміни в каталозі будь-якого вузла будуть автоматично синхронізовані з іншими вузлами в групі:

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. Посвідчення особи вузла та особиста візитна картка

Кожен вузол підтримує встановлення імені користувача, міста, електронної пошти, веб-сайту та персоналізованого підпису (максимум 256 символів), а також проходить автентифікацію підпису локального закритого ключа:

```bash
# Перегляньте ідентифікатор локального відкритого ключа (вкажіть каталог конфігурації, щоб зберегти ключ)
sync0 id -c ~/.config/sync0

# Створюйте та відображайте візитні картки вузлів із персональними підписами
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`, `pull`, `sub`, `group` також можна запускати з такими параметрами профілю:

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. Багатомовне перемикання

`sync0` Підтримує 75 мов. За замовчуванням довідка командного рядка та підказки відповідною мовою автоматично відображаються відповідно до мовного середовища операційної системи; якщо мови системи немає в списку підтримуваних, за замовчуванням використовується англійська.

Щоб вказати мову вручну, установіть змінну середовища `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
