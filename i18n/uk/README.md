# sync0

`sync0` – це децентралізований інструмент обміну файлами P2P, синхронізації в реальному часі та розповсюдження з кількох джерел, який використовується замість `rsync` - виміряна швидкість трансконтинентальної глобальної мережі `rsync` досягає **5,89×** (середня геометрична швидкість в одній точці **2,67×**, середня геометрична швидкість P2P з подвійним джерелом **3,16×**) і трансокеанське P2P-прискорення з високою затримкою досягає **7,68×** (повна середня геометрична швидкість 24-сценарію повного зв’язку **2,56×**).

Кожна машина є і сервером, і клієнтом: немає потреби в центральному сервері чи загальнодоступній мережевій адресі, автоматичне пробивання отворів базується на розподіленій адресі відкритого ключа мережі та підтримує пряму передачу між двома машинами, розміщення групових дозволів для спільного доступу, множинний вибір підкаталогів на вимогу, поступову синхронізацію в режимі реального часу на рівні мілісекунд і паралельне прискорення з кількох джерел P2P.

## встановити

### Спосіб 1: Вантажна установка

```bash
cargo install sync0
```

### Спосіб 2. Завантажте попередньо скомпільовані двійкові файли

Перейдіть до [GitHub Releases](https://github.com/webc-site/sync0/releases), щоб завантажити `.tar.xz` стислий пакет, що відповідає системі (підтримує Linux, macOS, Windows, Android, iOS, FreeBSD), розархівуйте та помістіть у `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Почніть швидше

### 1. Пряма передача без конфігурації між двома машинами (`send` / `recv`)

Немає необхідності налаштовувати групу спільного доступу, безпосередньо передавати файли або каталоги між двома машинами на високій швидкості:

```bash
# Приймаюча сторона прослуховує порт і записує в ./backup
sync0 recv 0.0.0.0:9000 ./backup

# Пряма передача від відправника (необов’язково --delete дзеркало, щоб очистити зайві файли, --rate 50MB обмеження швидкості)
sync0 send ./project 192.168.1.10:9000
```

### 2. Обмін дописами та отримання/завантаження на вимогу (`share` / `pull` / `push`)

```bash
# Сервер: опублікуйте групу спільного доступу за допомогою одного рядка команди (виведіть адресу вузла iroh без IP після запуску)
sync0 share dataset:./data

# Клієнт: перетягніть всю групу спільного доступу до набору даних до локального ./local_data
sync0 pull dataset:// ./local_data -p <адреса вузла>

# Клієнт: витягувати кілька виділених елементів на вимогу (синхронізувати лише певні окремі файли та підкаталоги)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <адреса вузла>

# Клієнт: завантажуйте файли або каталоги до авторизованих груп спільного доступу
sync0 push dataset://releases/v1 ./build_output -p <адреса вузла>
```

### 3. Посадка підписки в режимі реального часу та багатомашинна двостороння синхронізація (`sub` / `group`)

Після встановлення тривалого з’єднання, якщо будь-який файл **додає, змінює, видаляє, змінює дозволи або час модифікації** відбувається на віддаленому кінці, локальний каталог буде синхронно оновлено за мілісекунди в режимі реального часу (нові/змінені великі файли лише витягуватимуть блоки відмінностей і оновлюватимуть їх на місці, видалені файли автоматично очищатимуть локальні файли та порожні каталоги, а також змінюватимуть дозволи або напряму лише нульові блоки даних:

- **`sync0 sub`(Одностороннє віддзеркалення в реальному часі + автоматичне заповнення)**: локальний режим реального часу слідкує за додаваннями, видаленнями та змінами в кінці спільного доступу та автоматично служить початковим джерелом P2P, щоб забезпечити одночасне прискорення для інших вузлів, що витягують.
- **`sync0 group`(Багатомашинна однорангова двостороння синхронізація в режимі реального часу)**: якщо файли додаються, видаляються або змінюються на будь-якій машині в групі, усі інші онлайн-вузли оновлюватимуться синхронно в режимі реального часу та слугуватимуть один одному початковими.

```bash
# Підпишіться на всю групу спільного доступу: віддалені додавання, видалення та модифікації синхронізуються локально в реальному часі та автоматично заповнюються
sync0 sub dataset:// ./local_mirror -p <адреса вузла>

# Підписка з множинним вибором на вимогу: синхронізація та заповнення лише окремих файлів і підкаталогів у реальному часі
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <адреса вузла>

# Двостороння синхронізація в режимі реального часу для багатомашинної однорангової групи (також підтримує шляхи повного вибору або коми з множинним вибором)
sync0 group team-docs:// ./docs -p <адреса вузла>
```

### 4. Конфігурація груп спільного доступу та членів команди (конфігурація `.nt`)

Типовим каталогом конфігурації є `~/.config/sync0` (можна переключити за допомогою `-c <directory>`), використовуючи мінімалістичний формат [NestedText](https://nestedtext.org) (`.nt`):
- **Підтримується обмеження читання загальнодоступної мережі (тільки авторизовані користувачі можуть читати)**: якщо групу спільного доступу налаштовано зі списком учасників `users:` (або в командному рядку вказано `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`), система **автоматично вмикає приватну автентифікацію (`auth: true`)** і забороняє нумерацію або читання анонімних вузлів загальнодоступної мережі, а P2P-підписка на початкові вузли також успадкує білий список одночасно, дозволяючи читати лише авторизованим користувачам; Групи спільного доступу, для яких не налаштовано `users`, за замовчуванням є загальнодоступними та доступними лише для читання (якщо ви хочете бути загальнодоступними та доступними лише для читання та відкритими для завантажень лише для вказаних учасників, ви можете явно встановити `auth: false`).
- **Докладні дозволи на читання, запис і доставку підкаталогів**: учасники за замовчуванням доступні лише для читання (`r` не потрібно вказувати явно) і підтримують `r` (лише для читання), `w` (лише запис у вікно розвантаження, не читається), `rw` (читання-запис) і `write_prefix` (обмеження префікс підкаталогу, дозволений для завантаження).

**Приклад конфігурації члена (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (за умовчанням лише читання, обмеження швидкості 80 МБ)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (дозволи на читання та запис, дозволено лише завантажувати у вказаний підкаталог)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (лише дозвіл на доставку запису, читання заборонено)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**Приклад конфігурації групи спільного доступу (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # Неналаштовані користувачі: загальнодоступна мережа за умовчанням лише для читання
  dataset:
    path: ./data
    rate: 50MB

  # Налаштовані користувачі: автоматично обмежувати читання загальнодоступної мережі (лише Аліса та Боб можуть читати, Чарлі може лише доставляти та завантажувати)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

Запустіть службу (завантажте файл конфігурації або напряму скористайтеся параметрами командного рядка, щоб обмежити читання публічної мережі та авторизувати учасників):

```bash
# Завантажте ~/.config/sync0/config.nt для запуску
sync0 share --region SHA

# Або опублікуйте приватну групу спільного доступу через чистий командний рядок (вкажіть --allow-*, щоб автоматично обмежити читання загальнодоступної мережі, і лише авторизовані користувачі зможуть отримати до неї доступ)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. Адреса вузла, візитна картка та багатомовність

```bash
# Перегляньте адресу локального вузла без IP (ключ генерується автоматично для першого запуску)
sync0 id

# Створіть самопідписану візитну картку вузла Ed25519 (нік, код міста, електронна адреса, веб-сайт, вступ)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# Існує 75 вбудованих мов, які за замовчуванням відповідають системній мові, і їх можна перемикати за допомогою змінних середовища.
SYNC0_LANG=en sync0 --help
```

## Продуктивність і основні функції

### Фактичне вимірювання міжконтинентальної глобальної мережі (порівняння `rsync`)

Фактичне середовище вимірювання: США `c1` → Європа `n1` (RTT 65 мс), набором даних є ядро ​​Linux `linux-7.3.3`:

#### 1) Режим a la carte проти `rsync`

| Набір даних | розмір | `sync0` Одна точка<br>(Мбіт/с) | `rsync`<br>(Mbps) | Прискорення (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(не стискається) | 155 MB | **236.48** | 108.74 | **2,17×** |
| `linux-7.3.3.tar`(стискається) | 1.6 GB | **843.83** | 385.06 | **2,19×** |
| `linux-7.3.3.tar`(локальний крок зміни) | 1.6 GB | **8,014.15** | 1,361.72 | **5,89×** |
| `linux-7.3.3/` (95 979 малих файлів) | 1.5 GB | **627.58** | 347.80 | **1,80×** |
| **середнє геометричне** | — | **1,000.91** | 375.26 | **2,67×** |

#### 2) Режим подвійного джерела P2P проти `rsync`

| Набір даних | розмір | `sync0` Подвійне джерело P2P<br>(Мбіт/с) | `rsync`<br>(Mbps) | Прискорення (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(не стискається) | 155 MB | **330.09** | 108.74 | **3,04×** |
| `linux-7.3.3.tar`(стискається) | 1.6 GB | **1,551.86** | 385.06 | **4,03×** |
| `linux-7.3.3.tar`(локальний крок зміни) | 1.6 GB | **5,474.17** | 1,361.72 | **4,02×** |
| `linux-7.3.3/` (95 979 малих файлів) | 1.5 GB | **706.56** | 347.80 | **2,03×** |
| **середнє геометричне** | — | **1,186.42** | 375.26 | **3,16×** |

> Примітка. У режимі подвійного джерела P2P європейські вузли `s1` співпрацюють для заповнення, а міжконтинентальна магістраль RTT становить 65 мс.

### Основні характеристики продукту

- **Автоматичне пробивання отворів для адресації відкритих ключів**: немає потреби в центральному сервері та адресі загальнодоступної мережі, автоматичне пробивання отворів NAT на основі адреси відкритого ключа розподіленої мережі.
- **Синхронізація в режимі реального часу на рівні мілісекунд і обізнаність про метадані**: на основі власного моніторингу подій файлів (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), додавання файлів, видалення в реальному часі, дозволи POSIX (`mode`) і час модифікації на рівні мілісекунд (`mtime`); нульова передача блоку даних, коли змінюються лише дозволи або час.
- **Одночасне завантаження й завантаження в стилі BT і планування регіональної приналежності**: вузлу завантаження не потрібно чекати, поки буде завантажено повний обсяг. Усі інтервали блоків (`Op::Have`), які пройшли 128-бітну хеш-перевірку, негайно блокуються в пам’яті/тимчасовому пулі для одночасного отримання іншими вузлами. Разом із динамічним обміном вузлами PEX і повільним половинним випередженням вузла (викрадання роботи) пропускна здатність кластера максимізується.
- **Антишкідливий вузол та імунітет до отруєння кластера**: авторитетний список джерел `root_hash` Самоузгоджене блокування + обов’язкове апаратне прискорення `gxhash128` перевірка дайджесту перед тим, як кожен блок буде розміщено на диску та заповнено зовні; якщо виявлено пошкоджений блок, автоматичний вимикач на рівні мілісекунд відключає шкідливий вузол і автоматично відновлюється з чесного джерела.
- **FastCDC in-situ інкремент і агрегація невеликих файлів**: лише диференціальні блоки передаються для часткової модифікації великих файлів і розміщуються на диску; велике пакування пам’яті для невеликих файлів і диференціальне стиснення префіксів усувають накладні витрати на передачу файлів у обидва кінці.
- **Самовідновлення після відключення електроенергії та відновлення після перезапуску**: Redis-подібний гібридний формат RDB + AOF (`.s0_subs.bin`) використовується для збереження статусу заповнення та списку файлів, щоденні зміни додаються за мікросекунди та автоматично переписуються та регулярно впорядковуються. Після перезапуску сервера зміни в автономному режимі автоматично надсилаються до вузла заповнення.

## Технічна архітектура та документація

- **Протокол розв’язки подвійної площини**:
  - **Контроль і поверхня змін у реальному часі (`iroh` QUIC / TCP, перший байт `PROTO_VERSION` рукостискання версії) **: Відповідає за перевірку візитної картки Ed25519, перевірку дозволів, виявлення початкових даних Swarm і підтримку потокового пакетування масових змін на рівні `u64::MAX` і `mzstd` стисненого `SubPush` push-у реальному часі (`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` Три примітиви).
  - **Поверхня розподілу даних (власний UDP + `compio` асинхронний ввід-вивід) **: компактний заголовок 20B, періодичний зворотний зв’язок 18B TACK, гібридний контроль перевантажень BBRv3/Copa, відновлення втрачених пакетів RACK-TLP, обхід стиснення Zstd з адаптивним ентропієм Шеннона першого блоку та наскрізна перевірка блоку `gxhash128`.
