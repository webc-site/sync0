# sync0

`sync0` — це одноранговий (P2P) інструмент обміну файлами та багатомашинної синхронізації, який конкурує з Resilio Sync.

Кожна машина одночасно є сервером і клієнтом: будь-який вузол може публікувати кілька груп спільного доступу до файлів. Після приєднання інших вузлів вони можуть автоматично отримувати доступні вихідні вузли з однорангового сервера та одночасно отримувати їх із кількох джерел. Після завершення синхронізації для більшої кількості вузлів буде автоматично створено вихідні дані для прискорення завантажень.

## Основні моменти

- **Кожен є і сервером, і клієнтом**: порівнянно з Resilio Sync, немає залежності від центрального сервера. Будь-який вузол може створювати кілька груп спільного доступу до файлів, а також може приєднуватися до груп спільного доступу інших людей; вузли автоматично обмінюються та отримують доступні початкові вузли для досягнення одночасного залучення та синхронізації в реальному часі кількох машин.
- **Адреса вузла без IP**: за замовчуванням ключ вузла та `base64url` закодована адреса `iroh` автоматично генеруються в `~/.config/sync0` без необхідності запам’ятовувати чи відкривати загальнодоступну IP-адресу.
- **Синхронізація з кількома виборами на вимогу**: підтримує синхронізацію всієї групи спільного доступу, а також підтримує синхронізацію на вимогу шляхом вибору кількох файлів або підкаталогів одночасно.
- **Ієрархічні дозволи членів групи та керування каталогом завантаження**: підтримує дозволи лише для читання (`ro`), завантаження для читання й запису (`rw`) і керування (`admin`), а також може окремо вказати префікс шляху, який кожному учаснику дозволено завантажувати (за умовчанням дозволено завантаження в кореневий каталог спільного ресурсу).
- **Повношвидкісна та поступова синхронізація між мережами**: одночасна передача великих файлів, агрегація масивних малих файлів у пам’яті та лише синхронізовані блоки даних, коли файли частково змінені.

## встановити

### Спосіб 1: встановлення через Cargo

```bash
cargo install sync0
```

### Спосіб 2. Завантажте попередньо скомпільовані двійкові файли

Перейдіть до [GitHub Releases](https://github.com/webc-site/sync0/releases), щоб завантажити стислий пакет `.tar.xz` для відповідної системи (підтримує Linux, macOS, Windows, Android, FreeBSD, NetBSD), розпакуйте та помістіть його в каталог `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Почніть швидше

`sync0` за замовчуванням використовує `~/.config/sync0` як каталог конфігурації (якщо вам потрібно перейти до інших каталогів, ви можете додати `-c <directory>`).

### 1. Перегляньте адресу локального вузла та візитну картку налаштування

```bash
# Перегляньте адресу локального вузла (ключ автоматично генерується в ~/.config/sync0 вперше)
sync0 id

# Створіть особисту візитну картку вузла (підтримує ім’я користувача, місто, електронну адресу, веб-сайт і підпис у межах 256 слів)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. Публікація кількох груп спільного доступу до файлів і встановлення дозволів членів групи (`.nt` Конфігурація)

`sync0` налаштовано у форматі [NestedText](https://nestedtext.org) (`.nt`). Кожен користувач має окремий файл конфігурації `.nt`. Ви можете вказати каталог профілю користувача через `users_dir` в `config.nt` (що автоматично включає всі `.nt` файли в цьому каталозі). Як користувач, так і префікс шляху, який можна завантажити, використовують невпорядкований список (`-`). **Якщо префікс шляху завантаження не заповнений, завантаження в кореневий каталог спільного ресурсу дозволено за умовчанням**.

1. Створіть окремі файли конфігурації `.nt` для кожного члена в каталозі `~/.config/sync0/users/`:

`~/.config/sync0/users/alice.nt` (учасник лише для читання, швидкість обмежена `80MB`, `rate` підтримує одиниці `GB`, `MB`, `KB`):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (учасники з обмеженим доступом до завантаження: дозволено завантажувати лише до каталогів `uploads/bob` і `shared/common`):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (Завантаження учасників за умовчанням: якщо `write_prefix` опущено, завантаження до кореневого каталогу спільного ресурсу дозволено за замовчуванням):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. Налаштуйте каталог користувача та кілька груп спільного доступу до файлів у `~/.config/sync0/config.nt`:

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

Почати службу обміну:

```bash
# Прямий запуск (автоматично завантажує всі конфігурації користувача .nt у каталогах ~/.config/sync0/config.nt і users_dir)
sync0 share --region SHA

# Або швидко опублікуйте кілька груп спільного доступу та авторизуйте учасників групи безпосередньо через командний рядок
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. Витягніть весь вміст або виберіть кілька файлів і каталогів (`sync0 pull`)

Підключіться до будь-якого однорангового вузла, щоб автоматично отримати всі доступні початкові вузли в групі спільного доступу та отримати з кількох початкових вузлів одночасно:

```bash
# Перетягніть всю групу спільного доступу до набору даних до локального ./local_data
sync0 pull dataset:// ./local_data -p <адреса вузла>

# Синхронізація з множинним вибором: одночасно отримати один файл docs/readme.md і підкаталоги, іконки, src/core
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <адреса вузла>
```

### 4. Завантажте файл або каталог до групи спільного доступу (`sync0 push`)

Учасники з дозволами на завантаження (`rw` або `admin`) можуть завантажувати локальні файли або каталоги до груп віддаленого спільного доступу:

```bash
# Учасники з дозволом на завантаження в кореневий каталог: завантажуйте безпосередньо в спільний кореневий каталог
sync0 push team-vault:// ./new_release -p <адреса вузла>

# Лише учасники, авторизовані на певний префікс (наприклад, uploads/bob): завантажувати на дозволений префікс шляху
sync0 push team-vault://uploads/bob/report.pdf ./report.pdf -p <адреса вузла>
```

### 5. Підписатися на автоматичну синхронізацію та заповнення (`sync0 sub`)

Після підписки на групу спільного доступу певного вузла локальний сервер є одночасно клієнтом-одержувачем і новим сервером заповнення; коли файл вихідного вузла оновлюється, він автоматично синхронізується та забезпечує розділене завантаження для інших вузлів:

```bash
# Підпишіться на всю групу спільного доступу та автоматично запустіть її
sync0 sub dataset:// ./local_mirror -p <адреса вузла>

# Щоб підписатися на вказані файли та підкаталоги та заповнити їх, використовуйте лише кілька варіантів вибору
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <адреса вузла>
```

### 6. Багатомашинна групова однорангова синхронізація (`sync0 group`)

Кілька машин приєднуються до однієї групи спільного доступу, один з одним автоматично виявляє доступні початкові вузли та підтримує двосторонню синхронізацію (підтримується повна синхронізація або множинний вибір файлів і каталогів):

```bash
# Повне приєднання до групи і двостороння синхронізація
sync0 group team-docs:// ./docs -p <адреса вузла>

# Лише каталог wal і файл meta.json у групі синхронізації з множинним вибором
sync0 group team-docs://wal,meta.json ./docs -p <адреса вузла>
```

### 7. Пряма передача «точка-точка» між двома машинами (`send` / `recv`)

Немає необхідності попередньо налаштовувати групу, і ви можете тимчасово передавати файли або каталоги безпосередньо між двома машинами:

```bash
# Моніторинг приймача
sync0 recv 0.0.0.0:9000 ./backup

# Сторона-відправник безпосередньо передає файли або каталоги (необов’язково --delete дзеркало, щоб очистити зайві файли, --rate обмеження швидкості)
sync0 send ./project 192.168.1.10:9000
```

### 8. Багатомовне перемикання

`sync0` підтримує 75 мов і автоматично перемикається відповідно до мовного середовища системи за замовчуванням; його також можна вказати вручну через `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
