# sync0

`sync0` یک ابزار خط فرمان برای انتقال فایل ها در شبکه ها، همگام سازی تدریجی دایرکتوری ها و توزیع همزمان داده ها در چندین ماشین است.

## قصد طراحی اصلی

در اتاق‌ها، کشورها یا محیط‌های متقابل ماشینی با تأخیر شبکه و از دست دادن بسته‌ها، ابزارهایی مانند `rsync` و `scp` بر اساس تأیید توالی اتصال واحد هستند که استفاده از پهنای باند را محدود می‌کند. هنگامی که چندین ماشین به طور همزمان داده ها را از یک سرور می کشند، کارت شبکه سرور منبع به راحتی می تواند به یک گلوگاه تبدیل شود.

هدف `sync0` حل دو مشکل است:

1. اجازه دهید همگام سازی فایل و دایرکتوری بین دو ماشین، پهنای باند فیزیکی کامل را اجرا کند و تنها زمانی که فایل تا حدی اصلاح شده باشد، قسمت تغییر یافته را منتقل کنید.
2. چندین ماشین می‌توانند هنگام همگام‌سازی یک فهرست، بلوک‌های داده را به یکدیگر منتقل کنند، بار روی سرور منبع را کاهش داده و زمان کلی همگام‌سازی را کوتاه می‌کنند.

## مقایسه سرعت با rsync

محیط آزمایش: گره اروپایی $\leftrightarrow$ گره آمریکای شمالی، تاخیر رفت و برگشت 86 میلی‌ثانیه، اندازه‌گیری زمان‌بر کامل از جمله اسکن دایرکتوری، مقایسه تکراری، انتقال شبکه و تأیید قرار دادن دیسک:

| سناریوی انتقال | اندازه داده ها | `sync0` | `rsync` | چندگانه |
| :--- | :---: | :---: | :---: | :---: |
| 10000 فایل کوچک | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| بسته‌های کد و آرشیو (`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| فایل ویدیویی (`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| همگام سازی افزایشی (تغییر محتوای 1٪) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## روش های بهبود عملکرد

- **انتقال همزمان UDP**: بلوک های داده را از طریق UDP ارسال کنید و فقط قطعات گم شده را مجددا ارسال کنید تا از دست دادن بسته منفرد جلوگیری کنید که انتقال فایل های بعدی را مسدود کند.
- **تقسیم بندی محتوا و حذف مجدد**: فایل را بر اساس محتوا به بلوک های داده تقسیم کنید و مقدار چک را محاسبه کنید. همان محتوایی که قبلاً در انتهای گیرنده وجود دارد، مستقیماً به صورت محلی بدون تکرار شبکه مورد استفاده مجدد قرار می گیرد.
- **تنظیم خودکار فشرده سازی با توجه به سرعت شبکه**: فشرده سازی را برای محتوای قابل فشرده سازی مانند متن و کد روشن کنید. برای کاهش مصرف CPU، به طور خودکار از فشرده سازی برای فیلم ها، تصاویر، بسته های فشرده یا تحت شبکه LAN پرسرعت صرف نظر کنید.
- **کشش چند گره در نزدیکی**: وقتی چندین ماشین یک فهرست را می کشند، بلوک های داده همزمان از گره های دانلود شده در همان شهر یا با تأخیر کمتر کشیده می شوند.

## نصب کنید

### روش 1: نصب از طریق بار

```bash
cargo install sync0
```

### روش 2: باینری های از پیش کامپایل شده را دانلود کنید

برای دانلود بسته فشرده `.tar.xz` برای سیستم مربوطه (از Linux x86_64/ARM64، macOS Apple Silicon/Intel، Windows x64/ARM64، Android ARM64/x86_64، FreeBSD، NetBSD پشتیبانی می‌کند) به [GitHub Releases](https://github.com/webc-site/sync0/releases) بروید. پس از باز کردن، `sync0` را در فهرست `PATH` قرار دهید:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## راهنمای کاربر

### 1. انتقال مستقیم فایل ها یا دایرکتوری ها بین دو ماشین

نظارت را بر روی دستگاه دریافت کننده شروع کنید و مسیر دریافت و ذخیره را مشخص کنید:

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

ارسال یک فایل یا یک فهرست کامل از دستگاه فرستنده:

```bash
sync0 send ./project 192.168.1.10:9000
```

پارامترهای رایج:

```bash
# حذف فایل های اضافی که در انتهای گیرنده وجود دارد اما در انتهای ارسال وجود ندارد (همگام سازی آینه ای)
sync0 send ./project 192.168.1.10:9000 --delete

# محدود کردن سرعت ارسال (واحد: بایت در ثانیه، به عنوان مثال 50 مگابایت بر ثانیه)
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# حالت بی‌صدا (نوار پیشرفت نشان داده نمی‌شود)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. انتشار دایرکتوری های مشترک و بیرون کشیدن از چندین گره

یک فهرست مشترک (با نام `dataset`) در سرور مبدا منتشر کنید:

```bash
sync0 share dataset ./data --region SHA
```

دایرکتوری به اشتراک گذاشته شده را در ماشین های دیگر بکشید (می توانید آدرس های چند گره را به طور همزمان پر کنید که با کاما از هم جدا شده اند تا همزمان بکشید):

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

فقط یک زیر شاخه خاص را در فهرست مشترک بکشید:

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

تغییرات محلی را به دایرکتوری مشترک راه دور برگردانید:

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. مشترک شدن در به روز رسانی خودکار کاتالوگ

در دایرکتوری مشترک گره منبع مشترک شوید. هنگامی که یک فایل در فهرست منبع اضافه یا اصلاح می شود، به طور خودکار با رایانه محلی همگام می شود. در همان زمان، ماشین محلی به طور خودکار به عنوان یک گره برای ماشین های دیگر عمل می کند تا بکشند:

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. همگام سازی دو طرفه گروه های چند ماشینی

چندین ماشین به یک نام گروه ملحق می شوند و تغییرات در هر دایرکتوری گره به طور خودکار با سایر گره های گروه همگام می شوند:

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. شناسه گره و کارت ویزیت شخصی

هر گره از تنظیم نام کاربری، شهر، ایمیل، وب سایت و یک امضای شخصی (حداکثر 256 کاراکتر) پشتیبانی می کند و تأیید اعتبار امضای کلید خصوصی محلی را ارسال می کند:

```bash
# شناسه کلید عمومی محلی را مشاهده کنید (دایرکتوری پیکربندی را برای حفظ کلید مشخص کنید)
sync0 id -c ~/.config/sync0

# کارت ویزیت گره را با امضاهای شخصی سازی شده تولید و نمایش دهید
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`، `pull`، `sub`، `group` را نیز می‌توان با این پارامترهای نمایه راه‌اندازی کرد:

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. سوئیچینگ چند زبانه

`sync0` از 75 زبان پشتیبانی می کند. به طور پیش فرض، راهنمای خط فرمان و اعلان ها به زبان مربوطه به طور خودکار با توجه به محیط زبان سیستم عامل نمایش داده می شوند. اگر زبان سیستم در لیست پشتیبانی نشده باشد، انگلیسی به طور پیش فرض استفاده می شود.

برای تعیین زبان به صورت دستی، متغیر محیطی `SYNC0_LANG` را تنظیم کنید:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
