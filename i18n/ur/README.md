# sync0

`sync0` ایک پیئر ٹو پیئر (P2P) فائل شیئرنگ اور ملٹی مشین سنکرونائزیشن ٹول ہے جو Resilio Sync کا مقابلہ کرتا ہے۔

ہر مشین ایک سرور اور کلائنٹ دونوں ہے: کوئی بھی نوڈ متعدد فائل شیئرنگ گروپس شائع کرسکتا ہے۔ دوسرے نوڈس کے شامل ہونے کے بعد، وہ خود بخود پیئر سرور سے دستیاب سیڈ نوڈس حاصل کر سکتے ہیں اور انہیں متعدد ذرائع سے بیک وقت کھینچ سکتے ہیں۔ سنکرونائزیشن مکمل ہونے کے بعد، ڈاؤن لوڈز کو تیز کرنے کے لیے مزید نوڈس کے لیے بیج خود بخود بنائے جائیں گے۔

## بنیادی جھلکیاں

- **ہر کوئی سرور اور کلائنٹ دونوں ہوتا ہے**: ریسیلیو سنک سے موازنہ، کوئی مرکزی سرور پر انحصار نہیں۔ کوئی بھی نوڈ ایک سے زیادہ فائل شیئرنگ گروپ بنا سکتا ہے، اور دوسرے لوگوں کے شیئرنگ گروپس میں بھی شامل ہو سکتا ہے۔ نوڈس خود بخود تبادلہ اور دستیاب سیڈ نوڈس حاصل کرتے ہیں تاکہ ایک سے زیادہ مشینوں کی کنکرنٹ پلنگ اور ریئل ٹائم سنکرونائزیشن حاصل کی جا سکے۔
- **آئی پی فری نوڈ ایڈریس**: ڈیفالٹ کے طور پر، نوڈ کلید اور `base64url` انکوڈ شدہ `iroh` پتہ خود بخود `~/.config/sync0` میں عوامی IP کو یاد رکھنے یا ظاہر کرنے کی ضرورت کے بغیر تیار ہو جاتے ہیں۔
- **ڈیمانڈ پر ملٹی سلیکٹ سنکرونائزیشن**: پورے شیئرنگ گروپ کی ہم وقت سازی کی حمایت کرتا ہے، اور ایک ہی وقت میں متعدد فائلوں یا ذیلی ڈائرکٹریز کو منتخب کرکے ڈیمانڈ پر سنکرونائزیشن کی حمایت کرتا ہے۔
- **گروپ ممبر کی درجہ بندی کی اجازتیں اور اپ لوڈ ڈائرکٹری کنٹرول**: صرف پڑھنے کے لیے (`ro`)، پڑھنے لکھنے کے اپ لوڈ (`rw`)، اور انتظام (`admin`) کی اجازتوں کی حمایت کرتا ہے، اور انفرادی طور پر اس راستے کے سابقہ ​​کی وضاحت کرسکتا ہے جسے ہر رکن کو اپ لوڈ کرنے کی اجازت ہے (بطور ڈیفالٹ، شیئر ڈائرکٹری کو اپ لوڈ کرنے کی اجازت ہے)۔
- **مکمل رفتار اور بڑھتے ہوئے ہم آہنگی پورے نیٹ ورکس میں**: بڑی فائلوں کی ایک ساتھ منتقلی، میموری میں بڑے پیمانے پر چھوٹی فائلوں کا مجموعہ، اور صرف مطابقت پذیر ڈیٹا بلاکس جب فائلوں کو جزوی طور پر تبدیل کیا جاتا ہے۔

## انسٹال کریں۔

### طریقہ 1: کارگو کے ذریعے انسٹال کریں۔

```bash
cargo install sync0
```

### طریقہ 2: پہلے سے مرتب شدہ بائنریز ڈاؤن لوڈ کریں۔

متعلقہ سسٹم کے لیے `.tar.xz` کمپریسڈ پیکج ڈاؤن لوڈ کرنے کے لیے [GitHub Releases](https://github.com/webc-site/sync0/releases) پر جائیں (Linux، macOS، Windows، Android، FreeBSD، NetBSD کو سپورٹ کرتا ہے)، ان زپ کریں اور اسے `PATH` ڈائریکٹری میں ڈالیں:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## جلدی شروع کریں۔

`sync0` `~/.config/sync0` کو بطور ڈیفالٹ کنفیگریشن ڈائرکٹری استعمال کرتا ہے (اگر آپ کو دوسری ڈائرکٹریز پر جانے کی ضرورت ہے تو آپ `-c <directory>` شامل کر سکتے ہیں)۔

### 1. مقامی نوڈ کا پتہ اور بزنس کارڈ کی ترتیب دیکھیں

```bash
# مقامی نوڈ ایڈریس دیکھیں (کلید پہلی بار ~/.config/sync0 میں خود بخود تیار ہوتی ہے)
sync0 id

# ایک ذاتی نوڈ بزنس کارڈ بنائیں (256 الفاظ کے اندر صارف کا نام، شہر، ای میل، ویب سائٹ اور دستخط کی حمایت کرتا ہے)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. متعدد فائل شیئرنگ گروپس شائع کریں اور گروپ ممبر کی اجازتیں سیٹ کریں (`.nt` کنفیگریشن)

`sync0` کو [NestedText](https://nestedtext.org) (`.nt`) فارمیٹ میں کنفیگر کیا گیا ہے۔ ہر صارف کے پاس ایک الگ `.nt` کنفیگریشن فائل ہوتی ہے۔ آپ صارف پروفائل ڈائرکٹری کو `users_dir` کے ذریعے `config.nt` میں بتا سکتے ہیں (جس میں اس ڈائرکٹری کی تمام `.nt` فائلیں خود بخود شامل ہوجاتی ہیں)۔ استعمال کنندہ اور پاتھ کے سابقہ ​​دونوں کو اپ لوڈ کرنے کی اجازت غیر ترتیب شدہ فہرست (`-`) کا استعمال کرتی ہے۔ **جب اپ لوڈ پاتھ کا سابقہ ​​نہیں بھرا جاتا ہے، تو شیئر کی روٹ ڈائرکٹری پر اپ لوڈ کرنے کی اجازت بطور ڈیفالٹ ہوتی ہے**۔

1. `~/.config/sync0/users/` ڈائرکٹری میں ہر رکن کے لیے الگ الگ `.nt` کنفیگریشن فائلیں بنائیں:

`~/.config/sync0/users/alice.nt` (صرف پڑھنے کے لیے ممبر، ریٹ محدود `80MB`، `rate` سپورٹ `GB`، `MB`، `KB` یونٹس):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (اپ لوڈ کے محدود ارکان: صرف `uploads/bob` اور `shared/common` ڈائریکٹریز پر اپ لوڈ کرنے کی اجازت ہے):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (پہلے سے طے شدہ ممبر اپ لوڈ: جب `write_prefix` کو چھوڑ دیا جاتا ہے، تو شیئر کی روٹ ڈائرکٹری پر اپ لوڈ کرنے کی اجازت بطور ڈیفالٹ ہے):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. `~/.config/sync0/config.nt` میں صارف کی ڈائرکٹری اور متعدد فائل شیئرنگ گروپس کو ترتیب دیں:

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

شیئرنگ سروس شروع کریں:

```bash
# براہ راست آغاز (~/.config/sync0/config.nt اور user_dir ڈائریکٹریز میں تمام .nt صارف کنفیگریشنز کو خودکار طور پر لوڈ کرتا ہے)
sync0 share --region SHA

# یا فوری طور پر ایک سے زیادہ شیئرنگ گروپس شائع کریں اور گروپ ممبران کو کمانڈ لائن کے ذریعے براہ راست اجازت دیں۔
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. تمام مواد کھینچیں یا متعدد فائلیں اور ڈائریکٹریز منتخب کریں (`sync0 pull`)

شیئرنگ گروپ میں تمام دستیاب سیڈ نوڈس کو خود بخود حاصل کرنے کے لیے کسی بھی پیر نوڈ سے جڑیں، اور ایک سے زیادہ سیڈ نوڈس سے بیک وقت کھینچیں:

```bash
# پورے ڈیٹاسیٹ شیئرنگ گروپ کو مقامی ./local_data پر کھینچیں۔
sync0 pull dataset:// ./local_data -p <node address>

# ملٹی سلیکٹ سنکرونائزیشن: بیک وقت سنگل فائل docs/readme.md اور ذیلی ڈائرکٹریز اثاثوں/ شبیہیں، src/core کو کھینچیں۔
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <node address>
```

### 4. شیئرنگ گروپ میں فائل یا ڈائرکٹری اپ لوڈ کریں (`sync0 push`)

اپ لوڈ کی اجازت والے ممبران (`rw` یا `admin`) ریموٹ شیئرنگ گروپس میں مقامی فائلیں یا ڈائریکٹریز اپ لوڈ کر سکتے ہیں:

```bash
# روٹ ڈائرکٹری اپ لوڈ کرنے کی اجازت کے ساتھ ممبران: مشترکہ روٹ ڈائرکٹری میں براہ راست اپ لوڈ کریں۔
sync0 push team-vault:// ./new_release -p <node address>

# صرف ایک مخصوص سابقہ ​​کے لیے مجاز اراکین (جیسے اپ لوڈز/بوب): اجازت شدہ پاتھ کے سابقہ ​​پر اپ لوڈ کریں
sync0 push team-vault://uploads/bob/report.pdf ./report.pdf -p <node address>
```

### 5. خودکار مطابقت پذیری اور سیڈنگ کو سبسکرائب کریں (`sync0 sub`)

ایک مخصوص نوڈ کے شیئرنگ گروپ کو سبسکرائب کرنے کے بعد، مقامی سرور وصول کرنے والا کلائنٹ اور نیا سیڈنگ سرور دونوں ہوتا ہے۔ جب سورس نوڈ فائل کو اپ ڈیٹ کیا جاتا ہے، تو یہ خود بخود ہم آہنگ ہو جاتا ہے اور دوسرے نوڈس کے لیے chunked ڈاؤن لوڈ فراہم کرتا ہے:

```bash
# پورے شیئرنگ گروپ کو سبسکرائب کریں اور خود بخود سیڈ کریں۔
sync0 sub dataset:// ./local_mirror -p <node address>

# مخصوص فائلوں اور ذیلی ڈائرکٹریوں کو سبسکرائب کرنے کے لیے صرف ملٹی سلیکٹ کریں اور انہیں سیڈ کریں۔
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <node address>
```

### 6. ملٹی مشین گروپ پیئر سنکرونائزیشن (`sync0 group`)

متعدد مشینیں ایک ہی شیئرنگ گروپ میں شامل ہوتی ہیں، ایک دوسرے کو خود بخود دستیاب سیڈ نوڈس کا پتہ چلتا ہے اور دو طرفہ ہم آہنگی کو برقرار رکھتا ہے (مکمل مطابقت پذیری یا فائلوں اور ڈائریکٹریوں کے متعدد انتخاب کی حمایت کرتا ہے):

```bash
# مکمل طور پر گروپ اور دو طرفہ ہم آہنگی میں شامل ہوں۔
sync0 group team-docs:// ./docs -p <node address>

# ملٹی سلیکٹ سنکرونائزیشن گروپ میں صرف wal ڈائریکٹری اور meta.json فائل
sync0 group team-docs://wal,meta.json ./docs -p <node address>
```

### 7. دو مشینوں کے درمیان پوائنٹ ٹو پوائنٹ ڈائریکٹ ٹرانسمیشن (`send` / `recv`)

کسی گروپ کو پہلے سے ترتیب دینے کی ضرورت نہیں ہے، اور آپ عارضی طور پر فائلوں یا ڈائریکٹریز کو براہ راست دو مشینوں کے درمیان منتقل کر سکتے ہیں۔

```bash
# وصول کنندہ کی نگرانی
sync0 recv 0.0.0.0:9000 ./backup

# بھیجنے کا اختتام براہ راست فائلوں یا ڈائریکٹریوں کو منتقل کرتا ہے (اختیاری --ڈیلیٹ آئینہ اضافی فائلوں کو صاف کرنے کے لئے، --ریٹ رفتار کی حد)
sync0 send ./project 192.168.1.10:9000
```

### 8. ملٹی لینگویج سوئچنگ

`sync0` 75 زبانوں کو سپورٹ کرتا ہے، اور خود بخود سسٹم لینگویج کے ماحول کے مطابق بطور ڈیفالٹ سوئچ ہوجاتا ہے۔ اسے `SYNC0_LANG` کے ذریعے دستی طور پر بھی بیان کیا جا سکتا ہے:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
