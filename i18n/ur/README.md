# sync0

`sync0` ایک ڈی سینٹرلائزڈ P2P فائل شیئرنگ، ریئل ٹائم سنکرونائزیشن اور ملٹی سورس ڈسٹری بیوشن ٹول ہے جسے تبدیل کرنے کے لیے استعمال کیا جاتا ہے `rsync` - ٹرانس کانٹینینٹل وائڈ ایریا نیٹ ورک کی پیمائش شدہ رفتار `rsync` کے **6.95×** تک ہے **3.33×**)، اور سمندروں میں بڑے پیمانے پر چھوٹی فائلوں کی مطابقت پذیری **7.19×** جتنی تیز ہے۔

ہر مشین ایک سرور اور کلائنٹ دونوں ہے: مرکزی سرور یا پبلک نیٹ ورک ایڈریس کی ضرورت نہیں ہے، خودکار ہول پنچنگ تقسیم شدہ نیٹ ورک کے پبلک کلید ایڈریس پر مبنی ہے، اور یہ دو مشینوں کے درمیان براہ راست ٹرانسمیشن، ملٹی شیئرنگ گروپ پرمیشن ہوسٹنگ، ڈیمانڈ پر سب ڈائرکٹریز کا ایک سے زیادہ انتخاب، ملی سیکنڈ لیول ریئل ٹائم انکریمنٹل Piccurronation Pc-Synchronation-

## انسٹال کریں۔

### طریقہ 1: کارگو کی تنصیب

```bash
cargo install sync0
```

### طریقہ 2: پہلے سے مرتب شدہ بائنریز ڈاؤن لوڈ کریں۔

سسٹم سے متعلقہ `.tar.xz` کمپریسڈ پیکج کو ڈاؤن لوڈ کرنے کے لیے [GitHub Releases](https://github.com/webc-site/sync0/releases) پر جائیں (Linux، macOS، Windows، Android، iOS، FreeBSD کو سپورٹ کرتا ہے)، ان زپ کریں اور `PATH` میں ڈالیں:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## جلدی شروع کریں۔

### 1. دو مشینوں کے درمیان زیرو کنفیگریشن ڈائریکٹ ٹرانسمیشن (`send` / `recv`)

شیئرنگ گروپ کو ترتیب دینے کی ضرورت نہیں، تیز رفتاری سے دو مشینوں کے درمیان فائلیں یا ڈائریکٹریز کو براہ راست منتقل کرنا:

```bash
# وصول کنندہ پورٹ پر سنتا ہے اور ./backup پر لکھتا ہے۔
sync0 recv 0.0.0.0:9000 ./backup

# بھیجنے والے سے براہ راست ٹرانسمیشن (اختیاری -- اضافی فائلوں کو صاف کرنے کے لیے آئینہ حذف کریں، --50MB رفتار کی حد کی شرح کریں)
sync0 send ./project 192.168.1.10:9000
```

### 2. پوسٹ شیئرنگ اور آن ڈیمانڈ پل/اپ لوڈ (`share` / `pull` / `push`)

```bash
# سرور: شیئرنگ گروپ کو ایک لائن آف کمانڈ کے ساتھ شائع کریں (آؤٹ پٹ آئی پی فری آئروہ نوڈ ایڈریس اسٹارٹ اپ کے بعد)
sync0 share dataset:./data

# کلائنٹ: پورے ڈیٹاسیٹ شیئرنگ گروپ کو مقامی ./local_data پر کھینچیں۔
sync0 pull dataset:// ./local_data -p <node address>

# کلائنٹ: طلب پر متعدد انتخاب کو کھینچیں (صرف مخصوص واحد فائلوں اور ذیلی ڈائریکٹریوں کو ہم آہنگ کریں)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <node address>

# کلائنٹ: مجاز شیئرنگ گروپس میں فائلیں یا ڈائریکٹریز اپ لوڈ کریں۔
sync0 push dataset://releases/v1 ./build_output -p <node address>
```

### 3. ریئل ٹائم سبسکرپشن سیڈنگ اور ملٹی مشین ٹو وے سنکرونائزیشن (`sub` / `group`)

ایک لمبا کنکشن قائم کرنے کے بعد، اگر کوئی فائل ** شامل کرنا، ترمیم کرنا، حذف کرنا، اجازتیں تبدیل کرنا یا ترمیم کا وقت** ہوتا ہے تو مقامی ڈائرکٹری کو حقیقی وقت میں ملی سیکنڈ میں مطابقت پذیری سے اپ ڈیٹ کیا جائے گا (نئی/ ترمیم شدہ بڑی فائلیں صرف فرق بلاکس کو کھینچیں گی اور ان کو اپ ڈیٹ کریں گی، فائلوں کو حذف کرنے سے خود بخود مقامی فائلوں کو صاف کیا جائے گا اور صرف ڈائرکٹر فائلوں کو ڈیلیٹ کیا جائے گا اور ڈائرکٹری ڈیٹا کو تبدیل کیا جائے گا۔ براہ راست بلاکس):

- **`sync0 sub`(ایک طرفہ ریئل ٹائم مررنگ + آٹومیٹک سیڈنگ)**: مقامی ریئل ٹائم شیئرنگ اینڈ کے اضافے، حذف اور ترمیم کی پیروی کرتا ہے، اور خود بخود P2P بیج کے ذریعہ کے طور پر کام کرتا ہے تاکہ دوسرے پلنگ نوڈس کے لیے ہم آہنگی کی رفتار فراہم کرے۔
- **`sync0 group`(ملٹی مشین پیئر ٹو پیئر ٹو وے ریئل ٹائم سنکرونائزیشن)**: اگر گروپ میں کسی بھی مشین پر فائلیں شامل، ڈیلیٹ، یا ترمیم کی جاتی ہیں، تو باقی تمام آن لائن نوڈس ریئل ٹائم میں ہم آہنگی سے اپ ڈیٹ ہوں گے اور ایک دوسرے کے لیے بیج کے طور پر کام کریں گے۔

```bash
# پورے شیئرنگ گروپ کو سبسکرائب کریں: ریموٹ اضافے، حذف، اور ترمیمات مقامی طور پر حقیقی وقت میں مطابقت پذیر ہوتے ہیں اور خود بخود سیڈ ہوتے ہیں۔
sync0 sub dataset:// ./local_mirror -p <node address>

# آن ڈیمانڈ ملٹی سلیکٹ سبسکرپشن: ریئل ٹائم میں صرف ہم وقت سازی اور مخصوص کردہ سنگل فائلز اور سب ڈائرکٹریاں
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <node address>

# ملٹی مشین پیئر گروپ دو طرفہ ریئل ٹائم سنکرونائزیشن (مکمل یا کوما ملٹی سلیکٹ راستوں کو بھی سپورٹ کرتا ہے)
sync0 group team-docs:// ./docs -p <node address>
```

### 4. ٹیم ملٹی شیئرنگ گروپ اور ممبر پرمیشن کنفیگریشن (`.nt` کنفیگریشن)

ڈیفالٹ کنفیگریشن ڈائرکٹری ہے `~/.config/sync0` (`-c <directory>` کے ذریعے تبدیل کیا جا سکتا ہے)، minimalist [NestedText](https://nestedtext.org) (`.nt`) فارمیٹ کا استعمال کرتے ہوئے:
- **پبلک نیٹ ورک ریڈنگ کو محدود کرنے کی حمایت کرتا ہے (صرف مجاز صارفین ہی پڑھ سکتے ہیں)**: جب تک شیئرنگ گروپ کو `users:` ممبر لسٹ کے ساتھ کنفیگر کیا جاتا ہے (یا کمانڈ لائن `--allow-r` / `--allow-rw` / `--allow-w` / `--auth` کی وضاحت کرتی ہے)، سسٹم ** خود بخود id="6" کو آن کر دیتا ہے اور <b id=" کو خود بخود آن کر دیتا ہے۔ عوامی نیٹ ورک کے گمنام نوڈ کی گنتی یا پڑھنے سے منع کرتا ہے، اور P2P سیڈنگ نوڈس کو سبسکرائب کرنے سے بھی بیک وقت وائٹ لسٹ وراثت میں ملے گی، صرف مجاز صارفین کو پڑھنے کی اجازت ہوگی۔ شیئرنگ گروپس جو `users` کے ساتھ کنفیگر نہیں ہیں عوامی اور صرف پڑھنے کے لیے ڈیفالٹ ہیں (اگر آپ عوامی اور صرف پڑھنے کے لیے چاہتے ہیں اور صرف مخصوص ممبران کے لیے اپ لوڈز کے لیے کھلے ہیں، تو آپ واضح طور پر `auth: false` سیٹ کر سکتے ہیں)۔
- **فائن گرینڈ ریڈ رائٹ اور سب ڈائرکٹری ڈیلیوری کی اجازتیں**: ممبران صرف پڑھنے کے لیے بطور ڈیفالٹ ہوتے ہیں (`r` کو واضح طور پر لکھنے کی ضرورت نہیں ہے)، اور سپورٹ `r` (صرف پڑھنے کے لیے)، `w` (صرف ڈراپ باکس میں لکھیں، پڑھنے کے قابل نہیں)، <b-id="limit">5> (5) ذیلی ڈائرکٹری کا سابقہ اپ لوڈ کرنے کی اجازت ہے)۔

**ممبر کنفیگریشن کی مثال (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (پہلے سے طے شدہ صرف پڑھنے، رفتار کی حد 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (پڑھنے اور لکھنے کی اجازت، صرف مخصوص ذیلی ڈائرکٹری پر اپ لوڈ کرنے کی اجازت ہے)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (صرف ترسیل کی اجازت لکھیں، پڑھنا ممنوع ہے)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**شیئرنگ گروپ کنفیگریشن مثال (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # کنفیگر نہیں کیے گئے صارفین: ڈیفالٹ پبلک نیٹ ورک صرف پڑھنے کے لیے
  dataset:
    path: ./data
    rate: 50MB

  # کنفیگرڈ صارفین: پبلک نیٹ ورک ریڈنگ کو خود بخود محدود کریں (صرف ایلس اور باب پڑھ سکتے ہیں، چارلی صرف ڈیلیور اور اپ لوڈ کر سکتے ہیں)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

سروس شروع کریں (کنفیگریشن فائل لوڈ کریں یا پبلک نیٹ ورک کی ریڈنگ کو محدود کرنے اور ممبران کو اجازت دینے کے لیے براہ راست کمانڈ لائن پیرامیٹرز استعمال کریں):

```bash
# شروع کرنے کے لیے ~/.config/sync0/config.nt لوڈ کریں۔
sync0 share --region SHA

# یا خالص کمانڈ لائن کے ذریعے نجی شیئرنگ گروپ شائع کریں (عوامی نیٹ ورک کے پڑھنے کو خود بخود محدود کرنے کے لیے --allow-* کی وضاحت کریں اور صرف مجاز صارفین ہی اس تک رسائی حاصل کر سکتے ہیں)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. نوڈ ایڈریس، بزنس کارڈ اور کثیر زبان

```bash
# مقامی آئی پی فری نوڈ ایڈریس دیکھیں (کلید پہلے رن کے لیے خود بخود تیار ہوتی ہے)
sync0 id

# Ed25519 خود دستخط شدہ نوڈ بزنس کارڈ بنائیں (عرفی نام، شہر کا کوڈ، ای میل، ویب سائٹ، تعارف)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# 75 بلٹ ان زبانیں ہیں، جو سسٹم لینگویج کو بطور ڈیفالٹ فالو کرتی ہیں اور ماحولیاتی متغیرات کے ذریعے تبدیل کی جا سکتی ہیں۔
SYNC0_LANG=en sync0 --help
```

## کارکردگی اور بنیادی خصوصیات

### کراس براعظمی WAN اصل پیمائش (موازنہ `rsync`)

اصل پیمائش کا ماحول: ریاستہائے متحدہ `c1` → یورپ `n1` (RTT 65 ms)، ڈیٹا سیٹ لینکس کرنل ہے `linux-7.3.3`:

#### 1) اے لا کارٹ موڈ بمقابلہ `rsync`

| ڈیٹا سیٹ | سائز | `sync0` سنگل پوائنٹ<br>(Mbps) | `rsync`<br>(Mbps) | اسپیڈ اپ (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(کمپریسیبل نہیں) | 155 MB | **121.07** | 107.89 | **1.12×** |
| `linux-7.3.3.tar`(کمپریس ایبل) | 1.6 GB | **442.07** | 506.62 | **0.87×** |
| `linux-7.3.3.tar`(مقامی تبدیلی میں اضافہ) | 1.6 GB | **8,123.87** | 1,169.49 | **6.95×** |
| `linux-7.3.3/` (95,979 چھوٹی فائلیں) | 1.5 GB | **565.49** | 235.27 | **2.40×** |
| ** جیومیٹرک وسط** | - | **704.17** | 350.19 | **2.01×** |

#### 2) P2P ڈوئل سورس موڈ بمقابلہ `rsync`

| ڈیٹا سیٹ | سائز | `sync0` P2P دوہری ماخذ<br>(Mbps) | `rsync`<br>(Mbps) | اسپیڈ اپ (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(کمپریسیبل نہیں) | 155 MB | **466.85** | 107.89 | **4.33×** |
| `linux-7.3.3.tar`(کمپریس ایبل) | 1.6 GB | **992.17** | 506.62 | **1.96×** |
| `linux-7.3.3.tar`(مقامی تبدیلی میں اضافہ) | 1.6 GB | **5,666.84** | 1,169.49 | **4.85×** |
| `linux-7.3.3/` (95,979 چھوٹی فائلیں) | 1.5 GB | **703.30** | 235.27 | **2.99×** |
| ** جیومیٹرک وسط** | - | **1,165.63** | 350.19 | **3.33×** |

> نوٹ: P2P ڈوئل سورس موڈ میں، یورپی نوڈس `s1` سیڈنگ کے لیے تعاون کرتے ہیں، اور کراس کانٹینینٹل بیک بون RTT 65 ms ہے۔

### مصنوعات کی بنیادی خصوصیات

- **پبلک کی ایڈریسنگ آٹومیٹک ہول پنچنگ**: سینٹرل سرور اور پبلک نیٹ ورک ایڈریس کی ضرورت نہیں، تقسیم شدہ نیٹ ورک پبلک کی ایڈریس کی بنیاد پر خودکار NAT ہول پنچنگ۔
- **ملی سیکنڈ لیول ریئل ٹائم سنکرونائزیشن اور میٹا ڈیٹا آگاہی**: مقامی فائل ایونٹ مانیٹرنگ (`FSEvents` / `inotify` / `ReadDirectoryChangesW` پر مبنی، فائلوں کے اضافے، حذف کرنے، POSIX اجازتوں (`mode`) اور ملی سیکنڈ کے وقت (`mode`) اور ملی سیکنڈ کے وقت (`mode`) صفر ڈیٹا بلاک ٹرانسمیشن جب صرف اجازت یا وقت میں ترمیم کی جاتی ہے۔
- **BT طرز کا بیک وقت ڈاؤن لوڈ اور اپ لوڈ اور علاقائی وابستگی کا شیڈولنگ**: ڈاؤن لوڈنگ نوڈ کو پوری رقم کے ڈاؤن لوڈ ہونے کا انتظار کرنے کی ضرورت نہیں ہے۔ تمام بلاک وقفے (`Op::Have`) جنہوں نے 128 بٹ ہیش چیک کو پاس کیا ہے، دوسرے نوڈس کو بیک وقت کھینچنے کے لیے فوری طور پر میموری/عارضی پول میں بند کر دیا جاتا ہے۔ متحرک PEX نوڈ ایکسچینج اور سست نوڈ ہاف پریمپشن (ورک اسٹیلنگ) کے ساتھ، کلسٹر تھرو پٹ کو زیادہ سے زیادہ کیا جاتا ہے۔
- **مخالف نوڈ ٹمپرنگ اور کلسٹر پوائزننگ امیونٹی**: مستند ماخذ کی فہرست `root_hash` سیلف کنسسٹنٹ لاکنگ + لازمی ہارڈویئر ایکسلریشن `gxhash128` ڈائجسٹ کی توثیق اس سے پہلے کہ ہر بلاک کو ڈسک پر رکھا جائے اور بیرونی طور پر سیڈ کیا جائے؛ اگر چھیڑ چھاڑ والا بلاک پایا جاتا ہے تو، ملی سیکنڈ لیول کا سرکٹ بریکر نقصان دہ نوڈ کو بلیک آؤٹ کر دے گا اور خود بخود ایماندار ذریعہ سے بازیافت ہو جائے گا۔
- **فاسٹ سی ڈی سی ان سیٹو انکریمنٹ اور چھوٹی فائل ایگریگیشن**: بڑی فائلوں کی جزوی ترمیم کے لیے صرف ڈیفرینشل بلاکس کو منتقل کیا جاتا ہے اور ڈسک پر رکھا جاتا ہے۔ بڑے پیمانے پر چھوٹی فائل میموری پیکیجنگ اور پریفکس ڈیفرینشل کمپریشن فائل بہ فائل راؤنڈ ٹرپ اوور ہیڈ کو ختم کرتا ہے۔
- **بجلی کی بندش کے بعد خود کو ٹھیک کرنا اور دوبارہ شروع ہونے کے بعد دوبارہ شروع کرنا**: ریڈیس جیسا RDB + AOF ہائبرڈ فارمیٹ (`.s0_subs.bin`) بیج کی حیثیت اور فائل کی فہرست کو برقرار رکھنے کے لیے استعمال کیا جاتا ہے، روزانہ کی تبدیلیاں مائیکرو سیکنڈز میں شامل کی جاتی ہیں، اور خود بخود دوبارہ لکھی جاتی ہیں اور باقاعدگی سے ترتیب دی جاتی ہیں۔ سرور کے دوبارہ شروع ہونے کے بعد، آف لائن تبدیلیاں خود بخود سیڈنگ نوڈ پر پہنچ جاتی ہیں۔
