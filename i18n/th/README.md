# sync0

`sync0` เป็นเครื่องมือบรรทัดคำสั่งสำหรับการถ่ายโอนไฟล์ข้ามเครือข่าย การซิงโครไนซ์ไดเร็กทอรีแบบเพิ่มหน่วย และการกระจายข้อมูลไปยังเครื่องหลายเครื่องพร้อมกัน

## ความตั้งใจในการออกแบบดั้งเดิม

ในห้องเครื่องข้ามเครื่อง ประเทศ หรือสภาพแวดล้อมที่มีความล่าช้าของเครือข่ายและการสูญเสียแพ็กเก็ต เครื่องมือเช่น `rsync` และ `scp` จะขึ้นอยู่กับการยืนยันลำดับการเชื่อมต่อเดี่ยว ซึ่งจะจำกัดการใช้แบนด์วิดท์ เมื่อเครื่องหลายเครื่องดึงข้อมูลจากเซิร์ฟเวอร์เดียวกันในเวลาเดียวกัน การ์ดเครือข่ายเซิร์ฟเวอร์ต้นทางอาจกลายเป็นคอขวดได้อย่างง่ายดาย

เป้าหมายของ `sync0` คือการแก้ปัญหาสองข้อ:

1. ปล่อยให้ไฟล์และไดเร็กทอรีซิงโครไนซ์ระหว่างเครื่องทั้งสองเครื่องเรียกใช้แบนด์วิธทางกายภาพเต็มรูปแบบ และถ่ายโอนเฉพาะส่วนที่เปลี่ยนแปลงเมื่อไฟล์ได้รับการแก้ไขบางส่วนเท่านั้น
2. เครื่องหลายเครื่องสามารถถ่ายโอนบล็อกข้อมูลระหว่างกันเมื่อซิงโครไนซ์ไดเร็กทอรีเดียวกัน ช่วยลดภาระบนเซิร์ฟเวอร์ต้นทาง และลดระยะเวลาการซิงโครไนซ์โดยรวมให้สั้นลง

## การเปรียบเทียบความเร็วด้วย rsync

สภาพแวดล้อมการทดสอบ: โหนดยุโรป $\leftrightarrow$ โหนดอเมริกาเหนือ ความล่าช้าไปกลับ 86 ms การวัดการใช้เวลานานทั้งหมด รวมถึงการสแกนไดเรกทอรี การเปรียบเทียบการขจัดข้อมูลซ้ำซ้อน การส่งผ่านเครือข่าย และการตรวจสอบตำแหน่งของดิสก์:

| สถานการณ์การส่งสัญญาณ | ขนาดข้อมูล | `sync0` | `rsync` | หลายรายการ |
| :--- | :---: | :---: | :---: | :---: |
| ไฟล์ขนาดเล็ก 10,000 ไฟล์ | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| รหัสและแพ็คเกจการเก็บถาวร (`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| ไฟล์วิดีโอ (`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| การซิงโครไนซ์แบบเพิ่มหน่วย (แก้ไขเนื้อหา 1%) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## วิธีการปรับปรุงประสิทธิภาพ

- **การส่งข้อมูล UDP พร้อมกัน**: ส่งบล็อกข้อมูลผ่าน UDP และส่งเฉพาะแฟรกเมนต์ที่สูญหายไปอีกครั้งเท่านั้น เพื่อหลีกเลี่ยงการสูญเสียแพ็กเก็ตเดียวที่ขัดขวางการถ่ายโอนไฟล์ในภายหลัง
- **การแบ่งส่วนเนื้อหาและการขจัดข้อมูลซ้ำซ้อน**: แยกไฟล์ออกเป็นบล็อกข้อมูลตามเนื้อหาและคำนวณค่าตรวจสอบ เนื้อหาเดียวกันที่ปลายทางการรับจะถูกนำมาใช้ซ้ำโดยตรงในเครื่องโดยไม่ต้องทำซ้ำเครือข่าย
- **ปรับการบีบอัดอัตโนมัติตามความเร็วเครือข่าย**: เปิดการบีบอัดสำหรับเนื้อหาที่บีบอัดได้ เช่น ข้อความและโค้ด ข้ามการบีบอัดวิดีโอ รูปภาพ แพ็คเกจที่บีบอัด หรือภายใต้ LAN ความเร็วสูงโดยอัตโนมัติ เพื่อลดการใช้ CPU
- **การดึงหลายโหนดใกล้เคียง**: เมื่อเครื่องหลายเครื่องดึงไดเร็กทอรีเดียวกัน บล็อกข้อมูลจะถูกดึงพร้อมกันจากโหนดที่ดาวน์โหลดในเมืองเดียวกันหรือด้วยเวลาแฝงที่ต่ำกว่า

## ติดตั้ง

### วิธีที่ 1: ติดตั้งผ่าน Cargo

```bash
cargo install sync0
```

### วิธีที่ 2: ดาวน์โหลดไบนารีที่คอมไพล์แล้ว

ไปที่ [GitHub Releases](https://github.com/webc-site/sync0/releases) เพื่อดาวน์โหลดแพ็คเกจบีบอัด `.tar.xz` สำหรับระบบที่เกี่ยวข้อง (รองรับ Linux x86_64/ARM64, macOS Apple Silicon/Intel, Windows x64/ARM64, Android ARM64/x86_64, FreeBSD, NetBSD) หลังจากคลายซิปแล้ว ให้วาง `sync0` ลงในไดเร็กทอรี `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## คู่มือการใช้งาน

### 1. ถ่ายโอนไฟล์หรือไดเร็กทอรีระหว่างสองเครื่องโดยตรง

เริ่มการตรวจสอบบนเครื่องรับและระบุเส้นทางการรับและการบันทึก:

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

ส่งไฟล์เดียวหรือทั้งไดเร็กทอรีจากเครื่องส่ง:

```bash
sync0 send ./project 192.168.1.10:9000
```

พารามิเตอร์ที่ใช้กันทั่วไป:

```bash
# ลบไฟล์ซ้ำซ้อนที่มีอยู่ในฝั่งรับแต่ไม่ได้อยู่ที่ฝั่งส่ง (การซิงโครไนซ์มิเรอร์)
sync0 send ./project 192.168.1.10:9000 --delete

# จำกัดอัตราการส่ง (หน่วย: ไบต์/วินาที เช่น 50 MB/s)
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# โหมดเงียบ (ไม่แสดงแถบความคืบหน้า)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. การเผยแพร่ไดเร็กทอรีที่ใช้ร่วมกันและดึงข้อมูลจากหลายโหนด

เผยแพร่ไดเรกทอรีที่ใช้ร่วมกัน (ชื่อ `dataset`) บนเซิร์ฟเวอร์ต้นทาง:

```bash
sync0 share dataset ./data --region SHA
```

ดึงไดเร็กทอรีที่แชร์บนเครื่องอื่น (คุณสามารถกรอกที่อยู่โหนดหลายรายการพร้อมกัน โดยคั่นด้วยเครื่องหมายจุลภาคเพื่อดึงพร้อมกัน):

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

ดึงเฉพาะไดเร็กทอรีย่อยบางรายการในไดเร็กทอรีที่แชร์:

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

พุชการเปลี่ยนแปลงในเครื่องกลับไปยังไดเร็กทอรีที่แชร์ระยะไกล:

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. สมัครสมาชิกเพื่ออัพเดตแคตตาล็อกอัตโนมัติ

สมัครสมาชิกไดเรกทอรีที่ใช้ร่วมกันของโหนดต้นทาง เมื่อมีการเพิ่มหรือแก้ไขไฟล์ในไดเร็กทอรีต้นทาง ไฟล์นั้นจะถูกซิงโครไนซ์กับเครื่องคอมพิวเตอร์โดยอัตโนมัติ ในเวลาเดียวกัน เครื่องท้องถิ่นจะทำหน้าที่เป็นโหนดเพื่อให้เครื่องอื่นดึงโดยอัตโนมัติ:

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. การซิงโครไนซ์สองทางของกลุ่มเครื่องหลายเครื่อง

เครื่องหลายเครื่องรวมชื่อกลุ่มเดียวกัน และการเปลี่ยนแปลงในไดเร็กทอรีโหนดใด ๆ จะถูกซิงโครไนซ์กับโหนดอื่น ๆ ในกลุ่มโดยอัตโนมัติ:

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. ข้อมูลระบุตัวตนของโหนดและนามบัตรส่วนบุคคล

แต่ละโหนดรองรับการตั้งค่าชื่อผู้ใช้ เมือง อีเมล เว็บไซต์ และลายเซ็นส่วนบุคคล (สูงสุด 256 อักขระ) และส่งผ่านการตรวจสอบลายเซ็นคีย์ส่วนตัวในเครื่อง:

```bash
# ดูรหัสสาธารณะคีย์ในเครื่อง (ระบุไดเร็กทอรีการกำหนดค่าเพื่อคงคีย์ไว้)
sync0 id -c ~/.config/sync0

# สร้างและแสดงนามบัตรโหนดพร้อมลายเซ็นส่วนตัว
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`, `pull`, `sub`, `group` ยังสามารถเปิดใช้งานได้ด้วยพารามิเตอร์โปรไฟล์เหล่านี้:

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. การสลับหลายภาษา

`sync0` รองรับ 75 ภาษา ตามค่าเริ่มต้น วิธีใช้บรรทัดคำสั่งและพรอมต์ในภาษาที่เกี่ยวข้องจะแสดงโดยอัตโนมัติตามสภาพแวดล้อมภาษาของระบบปฏิบัติการ หากภาษาของระบบไม่อยู่ในรายการที่รองรับ ระบบจะใช้ภาษาอังกฤษเป็นค่าเริ่มต้น

หากต้องการระบุภาษาด้วยตนเอง ให้ตั้งค่าตัวแปรสภาพแวดล้อม `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
