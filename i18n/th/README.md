# sync0

`sync0` เป็นการแชร์ไฟล์ P2P แบบกระจายอำนาจ การซิงโครไนซ์แบบเรียลไทม์ และเครื่องมือการกระจายหลายแหล่งที่ใช้เพื่อแทนที่ `rsync` - ความเร็วที่วัดได้ของ WAN ข้ามทวีปสูงถึง `rsync`'s **5.89×** (ความเร็วเฉลี่ยเรขาคณิตจุดเดียว **2.67×**, ความเร็วเฉลี่ยทางเรขาคณิตแบบสองแหล่งที่มา P2P **3.16×**) และการเร่งความเร็ว P2P ลิงก์เวลาแฝงสูงข้ามมหาสมุทร สูงถึง **7.68×** (ความเร็วเฉลี่ยเรขาคณิตที่ครอบคลุม 24 สถานการณ์แบบเต็มลิงก์ **2.56×**)

แต่ละเครื่องเป็นทั้งเซิร์ฟเวอร์และไคลเอนต์: ไม่จำเป็นต้องมีเซิร์ฟเวอร์กลางหรือที่อยู่เครือข่ายสาธารณะ การเจาะรูอัตโนมัติจะขึ้นอยู่กับที่อยู่คีย์สาธารณะของเครือข่ายแบบกระจาย และรองรับการส่งข้อมูลโดยตรงระหว่างเครื่องสองเครื่อง การโฮสต์การอนุญาตกลุ่มการแบ่งปันหลายรายการ การเลือกไดเร็กทอรีย่อยหลายรายการตามความต้องการ การซิงโครไนซ์ส่วนเพิ่มตามเวลาจริงระดับมิลลิวินาที และการเร่งความเร็วพร้อมกันหลายแหล่ง P2P

## ติดตั้ง

### วิธีที่ 1: การติดตั้งสินค้า

```bash
cargo install sync0
```

### วิธีที่ 2: ดาวน์โหลดไบนารีที่คอมไพล์แล้ว

ไปที่ [GitHub Releases](https://github.com/webc-site/sync0/releases) เพื่อดาวน์โหลดแพ็คเกจบีบอัด `.tar.xz` ที่สอดคล้องกับระบบ (รองรับ Linux, macOS, Windows, Android, iOS, FreeBSD) แตกไฟล์และใส่ลงใน `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## เริ่มต้นได้อย่างรวดเร็ว

### 1. การส่งข้อมูลโดยตรงแบบไม่มีการกำหนดค่าระหว่างสองเครื่อง (`send` / `recv`)

ไม่จำเป็นต้องกำหนดค่ากลุ่มการแชร์ ถ่ายโอนไฟล์หรือไดเร็กทอรีระหว่างเครื่องสองเครื่องโดยตรงด้วยความเร็วสูง:

```bash
# ส่วนรับจะฟังพอร์ตและเขียนไปที่ ./backup
sync0 recv 0.0.0.0:9000 ./backup

# การส่งโดยตรงจากผู้ส่ง (ตัวเลือก --ลบมิเรอร์เพื่อล้างไฟล์ส่วนเกิน --rate จำกัดความเร็ว 50MB)
sync0 send ./project 192.168.1.10:9000
```

### 2. การแชร์โพสต์และการดึง/อัปโหลดตามความต้องการ (`share` / `pull` / `push`)

```bash
# เซิร์ฟเวอร์: เผยแพร่กลุ่มการแบ่งปันด้วยคำสั่งหนึ่งบรรทัด (ส่งออกที่อยู่โหนด iroh ที่ไม่มี IP หลังจากเริ่มต้นระบบ)
sync0 share dataset:./data

# ลูกค้า: ดึงกลุ่มการแชร์ชุดข้อมูลทั้งหมดไปที่ ./local_data ในเครื่อง
sync0 ดึงชุดข้อมูล:// ./local_data -p <ที่อยู่โหนด>

# ลูกค้า: ดึงตัวเลือกหลายรายการตามความต้องการ (ซิงโครไนซ์เฉพาะไฟล์เดียวและไดเรกทอรีย่อยที่ระบุ)
sync0 ดึงชุดข้อมูล://docs/readme.md,assets/icons,src/core ./local_data -p <ที่อยู่โหนด>

# ลูกค้า: อัปโหลดไฟล์หรือไดเร็กทอรีไปยังกลุ่มการแชร์ที่ได้รับอนุญาต
sync0 push dataset://releases/v1 ./build_output -p <ที่อยู่โหนด>
```

### 3. การเริ่มการสมัครสมาชิกแบบเรียลไทม์และการซิงโครไนซ์สองทางหลายเครื่อง (`sub` / `group`)

หลังจากสร้างการเชื่อมต่อที่ยาวนาน หากไฟล์ใดๆ **เพิ่ม แก้ไข ลบ เปลี่ยนแปลงสิทธิ์หรือเวลาแก้ไข** เกิดขึ้นที่ระยะไกล ไดเร็กทอรีในเครื่องจะได้รับการอัปเดตพร้อมกันในหน่วยมิลลิวินาทีแบบเรียลไทม์ (ไฟล์ขนาดใหญ่ใหม่/แก้ไขจะดึงบล็อกส่วนต่างเท่านั้นและอัปเดตให้เข้าที่ ไฟล์ที่ถูกลบจะล้างไฟล์ในเครื่องและไดเร็กทอรีว่างโดยอัตโนมัติ และเปลี่ยนเฉพาะการอนุญาตหรือประทับเวลาเป็นศูนย์บล็อกข้อมูลโดยตรง):

- **`sync0 sub`(การมิเรอร์แบบเรียลไทม์ทางเดียว + การเริ่มข้อมูลอัตโนมัติ)**: เรียลไทม์ในพื้นที่ติดตามการเพิ่ม การลบ และการแก้ไขของการแชร์ และทำหน้าที่เป็นแหล่งที่มาเริ่มต้น P2P โดยอัตโนมัติเพื่อให้การเร่งความเร็วพร้อมกันสำหรับโหนดการดึงอื่นๆ
- **`sync0 group`(การซิงโครไนซ์แบบเรียลไทม์แบบสองทางแบบเพียร์ทูเพียร์หลายเครื่อง)**: หากมีการเพิ่ม ลบ หรือแก้ไขไฟล์บนเครื่องใด ๆ ในกลุ่ม โหนดออนไลน์อื่น ๆ ทั้งหมดจะได้รับการอัปเดตพร้อมกันแบบเรียลไทม์และทำหน้าที่เป็นเมล็ดพันธุ์สำหรับกันและกัน

```bash
# สมัครสมาชิกกลุ่มการแชร์ทั้งหมด: การเพิ่ม การลบ และการแก้ไขจากระยะไกลจะถูกซิงโครไนซ์แบบเรียลไทม์และเริ่มต้นโดยอัตโนมัติ
ชุดข้อมูลย่อย sync0:// ./local_mirror -p <ที่อยู่โหนด>

# การสมัครสมาชิกแบบเลือกได้หลายรายการตามความต้องการ: ซิงโครไนซ์และเริ่มต้นไฟล์เดียวและไดเร็กทอรีย่อยที่ระบุแบบเรียลไทม์
ชุดข้อมูลย่อย sync0: //models/llama.onnx,configs ./local_mirror -p <ที่อยู่โหนด>

# การซิงโครไนซ์แบบเรียลไทม์แบบสองทางของกลุ่มเพียร์หลายเครื่อง (ยังรองรับเส้นทางแบบเลือกหลายรายการแบบเต็มหรือเครื่องหมายจุลภาค)
กลุ่ม sync0 team-docs:// ./docs -p <ที่อยู่โหนด>
```

### 4. การกำหนดค่ากลุ่มการแชร์หลายทีมและการกำหนดค่าสิทธิ์ของสมาชิก (การกำหนดค่า `.nt`)

ไดเร็กทอรีการกำหนดค่าเริ่มต้นคือ `~/.config/sync0` (สามารถสลับผ่าน `-c <directory>`) โดยใช้รูปแบบมินิมอล [NestedText](https://nestedtext.org) (`.nt`) รูปแบบ:
- **รองรับการจำกัดการอ่านเครือข่ายสาธารณะ (เฉพาะผู้ใช้ที่ได้รับอนุญาตเท่านั้นที่สามารถอ่านได้)**: ตราบใดที่กลุ่มการแชร์ได้รับการกำหนดค่าด้วยรายชื่อสมาชิก `users:` (หรือบรรทัดคำสั่งระบุ `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`) ระบบ **จะเปิดการตรวจสอบสิทธิ์ส่วนตัวโดยอัตโนมัติ (`auth: true`)** และห้ามมิให้มีการแจงนับหรืออ่านโหนดที่ไม่ระบุตัวตนของเครือข่ายสาธารณะ และ P2P การสมัครรับ seeding node จะสืบทอด whitelist ไปพร้อมๆ กัน โดยอนุญาตให้เฉพาะผู้ใช้ที่ได้รับอนุญาตเท่านั้นที่จะอ่านได้ กลุ่มการแบ่งปันที่ไม่ได้กำหนดค่าด้วย `users` จะเป็นสาธารณะและอ่านอย่างเดียวตามค่าเริ่มต้น (หากคุณต้องการให้เป็นสาธารณะและอ่านอย่างเดียว และเปิดให้อัปโหลดเฉพาะสมาชิกที่ระบุ คุณสามารถตั้งค่า `auth: false` ได้อย่างชัดเจน)
- **สิทธิ์ในการอ่าน-เขียนและการส่งไดเร็กทอรีย่อยแบบละเอียด**: สมาชิกเป็นแบบอ่านอย่างเดียวโดยค่าเริ่มต้น (`r` ไม่จำเป็นต้องเขียนอย่างชัดเจน) และรองรับ `r` (อ่านอย่างเดียว), `w` (เขียนลงในดรอปบ็อกซ์เท่านั้น ไม่สามารถอ่านได้), `rw` (อ่าน-เขียน) และ `write_prefix` (จำกัดคำนำหน้าไดเรกทอรีย่อยที่อนุญาตสำหรับการอัปโหลด)

**ตัวอย่างการกำหนดค่าสมาชิก (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (ค่าเริ่มต้นอ่านอย่างเดียว จำกัดความเร็ว 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (สิทธิ์ในการอ่านและเขียน อนุญาตให้อัปโหลดไปยังไดเรกทอรีย่อยที่ระบุเท่านั้น)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (เฉพาะสิทธิ์ในการเขียนเท่านั้น ห้ามอ่าน)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**ตัวอย่างการกำหนดค่ากลุ่มการแชร์ (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # ผู้ใช้ที่ไม่ได้กำหนดค่า: เครือข่ายสาธารณะเริ่มต้นแบบอ่านอย่างเดียว
  dataset:
    path: ./data
    rate: 50MB

  # ผู้ใช้ที่กำหนดค่า: จำกัดการอ่านเครือข่ายสาธารณะโดยอัตโนมัติ (เฉพาะอลิซและบ๊อบเท่านั้นที่สามารถอ่านได้ ชาร์ลีสามารถส่งและอัปโหลดเท่านั้น)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

เริ่มบริการ (โหลดไฟล์การกำหนดค่าหรือใช้พารามิเตอร์บรรทัดคำสั่งโดยตรงเพื่อจำกัดการอ่านเครือข่ายสาธารณะและอนุญาตสมาชิก):

```bash
# โหลด ~/.config/sync0/config.nt เพื่อเริ่มต้น
sync0 share --region SHA

# หรือเผยแพร่กลุ่มการแบ่งปันส่วนตัวผ่านบรรทัดคำสั่งล้วนๆ (ระบุ --allow-* เพื่อจำกัดการอ่านเครือข่ายสาธารณะโดยอัตโนมัติ และมีเพียงผู้ใช้ที่ได้รับอนุญาตเท่านั้นที่สามารถเข้าถึงได้)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. ที่อยู่โหนด นามบัตร และหลายภาษา

```bash
# ดูที่อยู่โหนดที่ไม่มี IP ในเครื่อง (คีย์จะถูกสร้างขึ้นโดยอัตโนมัติสำหรับการรันครั้งแรก)
sync0 id

# สร้างนามบัตรโหนดที่ลงนามด้วยตนเอง Ed25519 (ชื่อเล่น รหัสเมือง อีเมล เว็บไซต์ บทนำ)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# มีภาษาในตัว 75 ภาษา ซึ่งเป็นไปตามภาษาของระบบตามค่าเริ่มต้น และสามารถสลับผ่านตัวแปรสภาพแวดล้อมได้
SYNC0_LANG=en sync0 --help
```

## ประสิทธิภาพและคุณสมบัติหลัก

### การวัดจริง WAN ข้ามทวีป (การเปรียบเทียบ `rsync`)

สภาพแวดล้อมการวัดจริง: สหรัฐอเมริกา `c1` → ยุโรป `n1` (RTT 65 ms) ชุดข้อมูลคือ Linux kernel `linux-7.3.3`:

#### 1) โหมดอาหารตามสั่ง vs `rsync`

| ชุดข้อมูล | ขนาด | `sync0` จุดเดียว<br>(Mbps) | `rsync`<br>(Mbps) | เร่งความเร็ว (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(ไม่สามารถบีบอัดได้) | 155 MB | **236.48** | 108.74 | **2.17×** |
| `linux-7.3.3.tar`(บีบอัดได้) | 1.6 GB | **843.83** | 385.06 | **2.19×** |
| `linux-7.3.3.tar`(การเพิ่มการเปลี่ยนแปลงในเครื่อง) | 1.6 GB | **8,014.15** | 1,361.72 | **5.89×** |
| `linux-7.3.3/` (95,979 ไฟล์ขนาดเล็ก) | 1.5 GB | **627.58** | 347.80 | **1.80×** |
| **ค่าเฉลี่ยเรขาคณิต** | — | **1,000.91** | 375.26 | **2.67×** |

#### 2) โหมดแหล่งคู่ P2P เทียบกับ `rsync`

| ชุดข้อมูล | ขนาด | `sync0` P2P ดูอัลซอร์ส<br>(Mbps) | `rsync`<br>(Mbps) | เร่งความเร็ว (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(ไม่สามารถบีบอัดได้) | 155 MB | **330.09** | 108.74 | **3.04×** |
| `linux-7.3.3.tar`(บีบอัดได้) | 1.6 GB | **1,551.86** | 385.06 | **4.03×** |
| `linux-7.3.3.tar`(การเพิ่มการเปลี่ยนแปลงในเครื่อง) | 1.6 GB | **5,474.17** | 1,361.72 | **4.02×** |
| `linux-7.3.3/` (95,979 ไฟล์ขนาดเล็ก) | 1.5 GB | **706.56** | 347.80 | **2.03×** |
| **ค่าเฉลี่ยเรขาคณิต** | — | **1,186.42** | 375.26 | **3.16×** |

> หมายเหตุ: ในโหมดแหล่งที่มาคู่ P2P โหนดยุโรป `s1` ทำงานร่วมกันในการเริ่มต้น และแกนหลัก RTT ข้ามทวีปคือ 65 มิลลิวินาที

### คุณสมบัติหลักของผลิตภัณฑ์

- **การจัดการคีย์สาธารณะที่เจาะรูอัตโนมัติ**: ไม่จำเป็นต้องมีเซิร์ฟเวอร์กลางและที่อยู่เครือข่ายสาธารณะ การเจาะรู NAT อัตโนมัติตามที่อยู่คีย์สาธารณะของเครือข่ายแบบกระจาย
- **การซิงโครไนซ์แบบเรียลไทม์ระดับมิลลิวินาทีและการรับรู้ข้อมูลเมตา**: อิงตามการตรวจสอบเหตุการณ์ไฟล์ดั้งเดิม (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), การเพิ่มไฟล์แบบเรียลไทม์, การลบ, สิทธิ์ POSIX (`mode`) และเวลาแก้ไขระดับมิลลิวินาที (`mtime`); การส่งบล็อกข้อมูลเป็นศูนย์เมื่อมีการแก้ไขสิทธิ์หรือเวลาเท่านั้น
- **การดาวน์โหลดและอัปโหลดพร้อมกันสไตล์ BT และการกำหนดเวลาความสัมพันธ์ในระดับภูมิภาค**: โหนดการดาวน์โหลดไม่จำเป็นต้องรอให้ดาวน์โหลดเต็มจำนวน ช่วงเวลาบล็อกทั้งหมด (`Op::Have`) ที่ผ่านการตรวจสอบแฮช 128 บิตจะถูกล็อคทันทีในหน่วยความจำ/พูลชั่วคราวเพื่อให้โหนดอื่นดึงพร้อมกัน เมื่อใช้ร่วมกับการแลกเปลี่ยนโหนด PEX แบบไดนามิกและการสงวนโหนดครึ่งหนึ่งที่ช้า (การขโมยงาน) ปริมาณงานของคลัสเตอร์จะถูกขยายให้สูงสุด
- **การต่อต้านการปลอมแปลงโหนดที่เป็นอันตรายและภูมิคุ้มกันพิษของคลัสเตอร์**: รายการแหล่งที่มาที่เชื่อถือได้ `root_hash` การล็อคที่สอดคล้องกันในตัวเอง + การเร่งด้วยฮาร์ดแวร์ที่บังคับ `gxhash128` การตรวจสอบการแยกย่อยก่อนที่แต่ละบล็อกจะถูกวางบนดิสก์และเริ่มต้นจากภายนอก หากพบบล็อกที่ถูกงัดแงะ เซอร์กิตเบรกเกอร์ระดับมิลลิวินาทีจะปิดโหนดที่เป็นอันตรายและกู้คืนจากแหล่งที่มาที่ซื่อสัตย์โดยอัตโนมัติ
- **การเพิ่ม FastCDC ในแหล่งกำเนิดและการรวมไฟล์ขนาดเล็ก**: เฉพาะบล็อกส่วนต่างเท่านั้นที่ถูกถ่ายโอนสำหรับการแก้ไขไฟล์ขนาดใหญ่บางส่วนและวางลงบนดิสก์ แพคเกจหน่วยความจำไฟล์ขนาดเล็กขนาดใหญ่และการบีบอัดส่วนนำหน้าช่วยลดค่าใช้จ่ายในการเดินทางไปกลับแบบไฟล์ต่อไฟล์
- **การรักษาตัวเองหลังจากไฟฟ้าดับและการเริ่มต้นใหม่หลังจากรีสตาร์ท**: รูปแบบไฮบริด RDB + AOF ที่คล้ายกับ Redis (`.s0_subs.bin`) ใช้เพื่อคงสถานะการ seeding และรายการไฟล์ การเปลี่ยนแปลงรายวันจะถูกผนวกในหน่วยไมโครวินาที และจะถูกเขียนใหม่และจัดระเบียบโดยอัตโนมัติเป็นประจำ หลังจากรีสตาร์ทเซิร์ฟเวอร์แล้ว การเปลี่ยนแปลงออฟไลน์จะถูกพุชไปยังโหนดเริ่มต้นโดยอัตโนมัติ

## สถาปัตยกรรมทางเทคนิคและเอกสารประกอบ

- **โปรโตคอลการแยกระนาบคู่**:
  - **พื้นผิวการควบคุมและการเปลี่ยนแปลงแบบเรียลไทม์ (`iroh` QUIC / TCP, ไบต์แรก `PROTO_VERSION` เวอร์ชันแฮนด์เชค) **: รับผิดชอบในการตรวจสอบนามบัตร Ed25519, การตรวจสอบสิทธิ์, การค้นพบ Swarm seed และการสนับสนุนสำหรับ `u64::MAX` การสตรีมชุดการเปลี่ยนแปลงจำนวนมากในระดับและ `mzstd` การบีบอัด `SubPush` การพุชแบบเรียลไทม์ (`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` สามพื้นฐาน)
  - **พื้นผิวการกระจายข้อมูล (UDP ดั้งเดิม + `compio` I/O แบบอะซิงโครนัส) **: ส่วนหัวขนาดกะทัดรัด 20B, การตอบสนองเป็นระยะ 18B TACK, การควบคุมความแออัดแบบไฮบริด BBRv3/Copa, การกู้คืนการสูญเสียแพ็คเก็ต RACK-TLP, บายพาสการบีบอัด Zstd แบบปรับตัวเอนโทรปีของ Shannon บล็อกแรก และ `gxhash128` บล็อกการตรวจสอบจากต้นทางถึงปลายทาง
