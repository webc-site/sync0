# sync0

`sync0` คือการแชร์ไฟล์แบบ peer-to-peer (P2P) และเครื่องมือการซิงโครไนซ์หลายเครื่องที่แข่งขันกับ Resilio Sync

แต่ละเครื่องเป็นทั้งเซิร์ฟเวอร์และไคลเอนต์: โหนดใด ๆ สามารถเผยแพร่กลุ่มการแบ่งปันไฟล์ได้หลายกลุ่ม หลังจากที่โหนดอื่นเข้าร่วม โหนดเหล่านั้นจะสามารถรับโหนดเริ่มต้นที่มีอยู่จากเซิร์ฟเวอร์เพียร์ได้โดยอัตโนมัติ และดึงโหนดเหล่านั้นจากหลายแหล่งพร้อมกัน หลังจากการซิงโครไนซ์เสร็จสิ้น เมล็ดจะถูกสร้างขึ้นโดยอัตโนมัติสำหรับโหนดเพิ่มเติมเพื่อเร่งการดาวน์โหลด

## จุดเด่นหลัก

- **ทุกคนเป็นทั้งเซิร์ฟเวอร์และไคลเอนต์**: เทียบได้กับ Resilio Sync ไม่มีการพึ่งพาเซิร์ฟเวอร์ส่วนกลาง โหนดใดๆ สามารถสร้างกลุ่มการแชร์ไฟล์ได้หลายกลุ่ม และยังสามารถเข้าร่วมกลุ่มการแชร์ของผู้อื่นได้ โหนดจะแลกเปลี่ยนและรับโหนดเริ่มต้นที่มีอยู่โดยอัตโนมัติเพื่อให้สามารถดึงข้อมูลพร้อมกันและการซิงโครไนซ์แบบเรียลไทม์ของเครื่องจักรหลายเครื่อง
- **ที่อยู่โหนดที่ไม่มี IP**: ตามค่าเริ่มต้น คีย์โหนดและที่อยู่ `base64url` ที่เข้ารหัส `iroh` จะถูกสร้างขึ้นโดยอัตโนมัติใน `~/.config/sync0` โดยไม่จำเป็นต้องจดจำหรือเปิดเผย IP สาธารณะ
- **การซิงโครไนซ์แบบเลือกหลายรายการตามความต้องการ**: รองรับการซิงโครไนซ์ของกลุ่มการแชร์ทั้งหมด และยังรองรับการซิงโครไนซ์ตามความต้องการโดยการเลือกหลายไฟล์หรือไดเรกทอรีย่อยพร้อมกัน
- **สิทธิ์แบบลำดับชั้นของสมาชิกกลุ่มและการควบคุมไดเรกทอรีการอัปโหลด**: รองรับสิทธิ์การอัปโหลดแบบอ่านอย่างเดียว (`ro`), การอัปโหลดแบบอ่าน-เขียน (`rw`) และสิทธิ์การจัดการ (`admin`) และสามารถระบุคำนำหน้าเส้นทางที่สมาชิกแต่ละคนได้รับอนุญาตให้อัปโหลดเป็นรายบุคคล (โดยค่าเริ่มต้น จะอนุญาตให้อัปโหลดไปยังไดเร็กทอรีรากของการแชร์)
- **การซิงโครไนซ์ความเร็วเต็มที่และการซิงโครไนซ์แบบเพิ่มหน่วยผ่านเครือข่าย**: การส่งไฟล์ขนาดใหญ่พร้อมกัน การรวมไฟล์ขนาดเล็กจำนวนมากในหน่วยความจำ และบล็อกข้อมูลซิงโครไนซ์เฉพาะเมื่อมีการแก้ไขไฟล์เพียงบางส่วน

## ติดตั้ง

### วิธีที่ 1: ติดตั้งผ่าน Cargo

```bash
cargo install sync0
```

### วิธีที่ 2: ดาวน์โหลดไบนารีที่คอมไพล์แล้ว

ไปที่ [GitHub Releases](https://github.com/webc-site/sync0/releases) เพื่อดาวน์โหลดแพ็คเกจบีบอัด `.tar.xz` สำหรับระบบที่เกี่ยวข้อง (รองรับ Linux, macOS, Windows, Android, FreeBSD, NetBSD) คลายซิปและวางลงในไดเร็กทอรี `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## เริ่มต้นได้อย่างรวดเร็ว

`sync0` ใช้ `~/.config/sync0` เป็นไดเร็กทอรีการกำหนดค่าตามค่าเริ่มต้น (หากคุณต้องการสลับไปยังไดเร็กทอรีอื่น คุณสามารถเพิ่ม `-c <directory>`)

### 1. ดูที่อยู่โหนดในเครื่องและการตั้งค่านามบัตร

```bash
# ดูที่อยู่โหนดในเครื่อง (คีย์จะถูกสร้างขึ้นโดยอัตโนมัติใน ~/.config/sync0 เป็นครั้งแรก)
sync0 id

# สร้างนามบัตรโหนดส่วนบุคคล (รองรับชื่อผู้ใช้ เมือง อีเมล เว็บไซต์ และลายเซ็นภายใน 256 คำ)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. เผยแพร่กลุ่มการแชร์ไฟล์หลายกลุ่มและตั้งค่าสิทธิ์ของสมาชิกกลุ่ม (`.nt` การกำหนดค่า)

`sync0` ได้รับการกำหนดค่าในรูปแบบ [NestedText](https://nestedtext.org) (`.nt`) ผู้ใช้แต่ละคนมีไฟล์การกำหนดค่า `.nt` แยกต่างหาก คุณสามารถระบุไดเร็กทอรีโปรไฟล์ผู้ใช้ผ่าน `users_dir` ใน `config.nt` (ซึ่งจะรวมไฟล์ `.nt` ทั้งหมดในไดเร็กทอรีนี้โดยอัตโนมัติ) ทั้งผู้ใช้และคำนำหน้าเส้นทางที่ได้รับอนุญาตให้อัปโหลดใช้รายการที่ไม่เรียงลำดับ (`-`) **เมื่อไม่ได้กรอกคำนำหน้าเส้นทางการอัปโหลด การอัปโหลดไปยังไดเร็กทอรีรากของการแชร์จะได้รับอนุญาตตามค่าเริ่มต้น**

1. สร้างไฟล์การกำหนดค่า `.nt` แยกกันสำหรับสมาชิกแต่ละคนในไดเร็กทอรี `~/.config/sync0/users/`:

`~/.config/sync0/users/alice.nt` (สมาชิกแบบอ่านอย่างเดียว อัตราจำกัด `80MB`, `rate` รองรับหน่วย `GB`, `MB`, `KB`):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (จำกัดการอัปโหลดสมาชิก: อนุญาตให้อัปโหลดไปยังไดเร็กทอรี `uploads/bob` และ `shared/common` เท่านั้น):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (การอัปโหลดสมาชิกเริ่มต้น: เมื่อละเว้น `write_prefix` การอัปโหลดไปยังไดเร็กทอรีรากของการแชร์จะได้รับอนุญาตตามค่าเริ่มต้น):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. กำหนดค่าไดเร็กทอรีผู้ใช้และกลุ่มการแชร์ไฟล์หลายกลุ่มใน `~/.config/sync0/config.nt`:

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

เริ่มบริการแบ่งปัน:

```bash
# เริ่มต้นโดยตรง (โหลดการกำหนดค่าผู้ใช้ .nt ทั้งหมดโดยอัตโนมัติในไดเร็กทอรี ~/.config/sync0/config.nt และ users_dir)
sync0 share --region SHA

# หรือเผยแพร่กลุ่มการแบ่งปันหลายกลุ่มอย่างรวดเร็วและอนุญาตสมาชิกกลุ่มโดยตรงผ่านบรรทัดคำสั่ง
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. ดึงเนื้อหาทั้งหมดหรือเลือกหลายไฟล์และไดเร็กทอรี (`sync0 pull`)

เชื่อมต่อกับโหนดเพียร์ใดก็ได้เพื่อรับโหนดเริ่มต้นที่มีอยู่ทั้งหมดในกลุ่มการแบ่งปันโดยอัตโนมัติ และดึงจากโหนดเริ่มต้นหลายโหนดพร้อมกัน:

```bash
# ดึงกลุ่มการแชร์ชุดข้อมูลทั้งหมดไปที่ ./local_data ในเครื่อง
sync0 ดึงชุดข้อมูล:// ./local_data -p <ที่อยู่โหนด>

# การซิงโครไนซ์แบบเลือกหลายรายการ: ดึงไฟล์เดียว docs/readme.md และสินทรัพย์/ไอคอนไดเรกทอรีย่อย src/core พร้อมกัน
sync0 ดึงชุดข้อมูล://docs/readme.md,assets/icons,src/core ./local_data -p <ที่อยู่โหนด>
```

### 4. อัปโหลดไฟล์หรือไดเร็กทอรีไปยังกลุ่มการแบ่งปัน (`sync0 push`)

สมาชิกที่มีสิทธิ์การอัปโหลด (`rw` หรือ `admin`) สามารถอัปโหลดไฟล์หรือไดเร็กทอรีในเครื่องไปยังกลุ่มการแชร์ระยะไกล:

```bash
# สมาชิกที่มีสิทธิ์อัปโหลดไดเรกทอรีราก: อัปโหลดโดยตรงไปยังไดเรกทอรีรากที่แชร์
sync0 push team-vault:// ./new_release -p <ที่อยู่โหนด>

# เฉพาะสมาชิกที่ได้รับอนุญาตให้ใช้คำนำหน้าเฉพาะ (เช่น uploads/bob): อัปโหลดไปยังคำนำหน้าเส้นทางที่อนุญาต
sync0 push team-vault://uploads/bob/report.pdf ./report.pdf -p <ที่อยู่โหนด>
```

### 5. สมัครสมาชิกการซิงค์และการเพาะอัตโนมัติ (`sync0 sub`)

หลังจากสมัครสมาชิกกลุ่มการแบ่งปันของโหนดใดโหนดหนึ่งแล้ว เซิร์ฟเวอร์ภายในเครื่องจะเป็นทั้งไคลเอนต์ที่รับและเซิร์ฟเวอร์เริ่มต้นใหม่ เมื่อไฟล์โหนดต้นทางได้รับการอัปเดต ไฟล์นั้นจะถูกซิงโครไนซ์โดยอัตโนมัติและให้การดาวน์โหลดแบบก้อนสำหรับโหนดอื่นๆ:

```bash
# สมัครสมาชิกกลุ่มการแบ่งปันทั้งหมดและเริ่มต้นโดยอัตโนมัติ
ชุดข้อมูลย่อย sync0:// ./local_mirror -p <ที่อยู่โหนด>

# เฉพาะการเลือกหลายรายการเพื่อสมัครรับไฟล์และไดเร็กทอรีย่อยที่ระบุและเริ่มต้นไฟล์เหล่านั้น
ชุดข้อมูลย่อย sync0: //models/llama.onnx,configs ./local_mirror -p <ที่อยู่โหนด>
```

### 6. การซิงโครไนซ์เพียร์กลุ่มหลายเครื่อง (`sync0 group`)

เครื่องหลายเครื่องเข้าร่วมกลุ่มการแบ่งปันเดียวกัน โดยแต่ละเครื่องจะค้นหาโหนดเริ่มต้นที่มีอยู่โดยอัตโนมัติ และรักษาการซิงโครไนซ์แบบสองทาง (รองรับการซิงโครไนซ์แบบเต็มหรือการเลือกไฟล์และไดเร็กทอรีหลายรายการ):

```bash
# เข้าร่วมกลุ่มอย่างเต็มที่และการซิงโครไนซ์สองทาง
กลุ่ม sync0 team-docs:// ./docs -p <ที่อยู่โหนด>

# เฉพาะไดเร็กทอรี wal และไฟล์ meta.json ในกลุ่มการซิงโครไนซ์แบบเลือกหลายรายการ
กลุ่ม sync0 team-docs://wal,meta.json ./docs -p <ที่อยู่โหนด>
```

### 7. การส่งข้อมูลโดยตรงแบบจุดต่อจุดระหว่างสองเครื่อง (`send` / `recv`)

ไม่จำเป็นต้องกำหนดค่ากลุ่มล่วงหน้า และคุณสามารถถ่ายโอนไฟล์หรือไดเร็กทอรีโดยตรงระหว่างเครื่องสองเครื่องได้ชั่วคราว:

```bash
# การตรวจสอบผู้รับ
sync0 recv 0.0.0.0:9000 ./backup

# จุดสิ้นสุดการส่งจะถ่ายโอนไฟล์หรือไดเร็กทอรีโดยตรง (ตัวเลือก --delete มิเรอร์เพื่อล้างไฟล์ส่วนเกิน --rate ความเร็วจำกัด)
sync0 send ./project 192.168.1.10:9000
```

### 8. การสลับหลายภาษา

`sync0` รองรับ 75 ภาษา และสลับโดยอัตโนมัติตามสภาพแวดล้อมภาษาของระบบตามค่าเริ่มต้น นอกจากนี้ยังสามารถระบุได้ด้วยตนเองผ่าน `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
