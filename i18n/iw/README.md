# sync0

`sync0` הוא כלי שיתוף קבצים מבוזר P2P, סנכרון בזמן אמת והפצה מרובת מקורות המשמש להחלפת `rsync` - המהירות הנמדדת של רשת המרחב הטרנס-יבשתית היא עד **6.95×** של `rsync` (מהירות ממוצעת גיאומטרית חד-נקודתית **2.01×3.** מהירות גיאומטרית ממוצעת **2.01×3.**, P2. הסנכרון של קבצים קטנים ומסיביים על פני אוקיינוסים הוא מהיר כמו **7.19×**.

כל מכונה היא גם שרת וגם לקוח: אין צורך בשרת מרכזי או בכתובת רשת ציבורית, ניקוב חורים אוטומטי מבוסס על כתובת המפתח הציבורי של הרשת המבוזרת, והיא תומכת בשידור ישיר בין שני מכונות, אירוח הרשאות קבוצות מרובות שיתוף, בחירה מרובה של ספריות משנה לפי דרישה, סנכרון מצטבר בזמן אמת בזמן אמת והאצת P2P מרובה מקורות.

## לְהַתְקִין

### שיטה 1: התקנת מטען

```bash
cargo install sync0
```

### שיטה 2: הורד קבצים בינאריים מהודרים מראש

עבור אל [GitHub Releases](https://github.com/webc-site/sync0/releases) כדי להוריד את החבילה הדחוסה `.tar.xz` התואמת למערכת (תומך ב-Linux, macOS, Windows, Android, iOS, FreeBSD), פתח את הדחוס והכנס לתוך `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## התחל מהר

### 1. שידור ישיר בתצורת אפס בין שני מכונות (`send` / `recv`)

אין צורך להגדיר קבוצת שיתוף, להעביר ישירות קבצים או ספריות בין שני מכונות במהירות גבוהה:

```bash
# הצד המקבל מאזין ביציאה וכותב ל-./backup
sync0 recv 0.0.0.0:9000 ./backup

# שידור ישיר מהשולח (אופציונלי --מחק מראה כדי לנקות קבצים עודפים, --קצב הגבלת מהירות של 50MB)
sync0 send ./project 192.168.1.10:9000
```

### 2. שיתוף פוסטים ומשיכה/העלאה לפי דרישה (`share` / `pull` / `push`)

```bash
# שרת: פרסם את קבוצת השיתוף עם שורת פקודה אחת (הצא את כתובת ה-iroh node ללא IP לאחר ההפעלה)
sync0 share dataset:./data

# לקוח: משוך את כל קבוצת השיתוף של מערך הנתונים אל ה-./local_data המקומי
sync0 pull dataset:// ./local_data -p <כתובת צומת>

# לקוח: משוך מספר בחירות לפי דרישה (סנכרן רק קבצים בודדים וספריות משנה)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <כתובת צומת>

# לקוח: העלה קבצים או ספריות לקבוצות שיתוף מורשות
sync0 push dataset://releases/v1 ./build_output -p <כתובת צומת>
```

### 3. הזנת מנויים בזמן אמת וסנכרון דו-כיווני מרובה מכונות (`sub` / `group`)

לאחר יצירת חיבור ארוך, אם קובץ כלשהו **הוספה, שינוי, מחיקה, שינוי הרשאות או זמן שינוי** מתרחש בקצה המרוחק, הספרייה המקומית תתעדכן באופן סינכרוני באלפיות שניות בזמן אמת (קבצים גדולים חדשים/שונו רק ימשכו את בלוקי ההפרש ויעדכנו אותם במקום, מחיקת קבצים תנקה אוטומטית קבצים מקומיים וספריות ריקות של קבצים ריקים בלבד):

- **`sync0 sub`(שיקוף בזמן אמת חד-כיווני + זריעה אוטומטית)**: הזמן האמיתי המקומי עוקב אחר התוספות, המחיקות והשינויים של קצה השיתוף, ומשמש אוטומטית כמקור זרע P2P כדי לספק האצה במקביל לצמתי משיכה אחרים.
- **`sync0 group`(סנכרון דו-כיווני בזמן אמת בין מחשבים לעמית)**: אם קבצים יתווספו, יימחקו או ישונו בכל מכונה בקבוצה, כל שאר הצמתים המקוונים יעודכנו באופן סינכרוני בזמן אמת וישמשו כ-seed זה עבור זה.

```bash
# הירשם לכל קבוצת השיתוף: תוספות, מחיקות ושינויים מרחוק מסונכרנים באופן מקומי בזמן אמת ומוזרמים אוטומטית
sync0 sub dataset:// ./local_mirror -p <כתובת צומת>

# מנוי מרובה בחירה לפי דרישה: רק סנכרון והטמעה של קבצים בודדים וספריות משנה שצוינו בזמן אמת
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <כתובת צומת>

# סנכרון דו-כיווני בזמן אמת של קבוצת עמיתים מרובת מכונות (תומך גם בנתיבים מרובים מלאים או פסיקים)
sync0 group team-docs:// ./docs -p <כתובת צומת>
```

### 4. קבוצת ריבוי שיתוף ותצורה של הרשאות חברים (`.nt` תצורה)

ספריית התצורה המוגדרת כברירת מחדל היא `~/.config/sync0` (ניתן להחליף באמצעות `-c <directory>`), באמצעות הפורמט המינימליסטי [NestedText](https://nestedtext.org) (`.nt`):
- **תומך בהגבלת קריאת רשת ציבורית (רק משתמשים מורשים יכולים לקרוא)**: כל עוד קבוצת השיתוף מוגדרת עם `users:` רשימת חברים (או שורת הפקודה מציינת `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`), המערכת **תפעיל אוטומטית רשתות אנונימיות (<) אנונימיות ואנונימיות (<) ** אותנטיות ציבוריות. ספירת צמתים או קריאה, ו-P2P הרשמה לצמתי זריעה תירש גם את הרשימה הלבנה בו-זמנית, ותאפשר רק למשתמשים מורשים לקרוא; קבוצות שיתוף שאינן מוגדרות עם `users` הן ציבוריות וקריאה בלבד כברירת מחדל (אם ברצונך להיות ציבורית וקריאה בלבד ופתוחות להעלאות רק לחברים שצוינו, תוכל להגדיר במפורש `auth: false`).
- **הרשאות קריאה-כתיבה ומסירה של ספריות משנה**: חברים הם לקריאה בלבד כברירת מחדל (`r` אין צורך לכתוב במפורש), ותומכים ב`r` (לקריאה בלבד), `w` (כתוב רק לתיבת ה-Drop Box, לא קריא), `rw` (מותר להגביל את ה-read-writ עבור המשנה) מעלה).

**דוגמה לתצורת חבר (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (ברירת מחדל לקריאה בלבד, הגבלת מהירות 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (הרשאות קריאה וכתיבה, מותר רק להעלות לספריית משנה שצוינה)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (רק הרשאת כתיבה, קריאה אסורה)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**דוגמה לתצורת קבוצת שיתוף (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # משתמשים לא מוגדרים: ברירת המחדל של רשת ציבורית לקריאה בלבד
  dataset:
    path: ./data
    rate: 50MB

  # משתמשים מוגדרים: הגבל אוטומטית את קריאת הרשת הציבורית (רק אליס ובוב יכולים לקרוא, צ'רלי יכול רק לשלוח ולהעלות)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

הפעל את השירות (טען את קובץ התצורה או השתמש ישירות בפרמטרים של שורת הפקודה כדי להגביל את קריאת הרשת הציבורית ולהעניק הרשאה לחברים):

```bash
# טען ~/.config/sync0/config.nt כדי להתחיל
sync0 share --region SHA

# או פרסם קבוצת שיתוף פרטית באמצעות שורת פקודה טהורה (ציין --allow-* כדי להגביל אוטומטית קריאת רשת ציבורית ורק משתמשים מורשים יכולים לגשת אליה)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. כתובת צומת, כרטיס ביקור ורב שפות

```bash
# הצג את כתובת הצומת המקומית נטולת ה-IP (המפתח נוצר אוטומטית להפעלה הראשונה)
sync0 id

# צור כרטיס ביקור לצומת בחתימה עצמית של Ed25519 (כינוי, קוד עיר, דוא"ל, אתר אינטרנט, מבוא)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# ישנן 75 שפות מובנות, העוקבות אחר שפת המערכת כברירת מחדל וניתנות להחלפה באמצעות משתני סביבה.
SYNC0_LANG=en sync0 --help
```

## ביצועים ותכונות ליבה

### מדידה ממשית של WAN חוצה יבשות (השוואה `rsync`)

סביבת מדידה בפועל: ארצות הברית `c1` → אירופה `n1` (RTT 65 ms), מערך הנתונים הוא ליבת לינוקס `linux-7.3.3`:

| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(לא ניתן לדחיסה) | 155 MB | **121.07** | 107.89 | **1.12×** |
| `linux-7.3.3.tar`(ניתן לדחיסה) | 1.6 GB | **442.07** | 506.62 | **0.87×** |
| `linux-7.3.3.tar`(תוספת שינוי מקומי) | 1.6 GB | **8,123.87** | 1,169.49 | **6.95×** |
| `linux-7.3.3/` (95,979 קבצים קטנים) | 1.5 GB | **565.49** | 235.27 | **2.40×** |
| **ממוצע גיאומטרי** | — | **704.17** | 350.19 | **2.01×** |

### תכונות ליבה של המוצר

- **מפתח פומבי הנותן מענה לחורים אוטומטיים**: אין צורך בשרת מרכזי ובכתובת רשת ציבורית, ניקוב חורים אוטומטי ב-NAT המבוסס על כתובת המפתח הציבורי של הרשת המבוזרת.
- **סנכרון בזמן אמת ברמת אלפית השנייה ומודעות למטא-נתונים**: מבוסס על ניטור אירועי קבצים מקוריים (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), דחיפה בזמן אמת של תוספות קבצים, מחיקות, הרשאות POSIX (`mode`) וזמן שינוי אלפית השנייה (`mtime`); שידור בלוק נתונים אפס כאשר רק הרשאות או זמן משתנים.
- **הורדה והעלאה סימולטנית בסגנון BT ותזמון זיקה אזורית**: צומת ההורדה לא צריך לחכות להורדת הסכום המלא. כל מרווחי החסימה (`Op::Have`) שעברו את בדיקת ה-hash של 128 סיביות ננעלות מיד בזיכרון/הבריכה הזמנית כדי שצמתים אחרים יוכלו למשוך בו זמנית. יחד עם חילופי צומת PEX דינמיים והקדמת חצי צומת אטית (גניבת עבודה), התפוקה של האשכולות מוגדלת.
- **חסינות נגד צמתים נגד זדוניות וחסינות הרעלת אשכול**: רשימת מקורות סמכותית `root_hash` נעילה עקבית + האצת חומרה חובה `gxhash128` אימות עיכול לפני שכל בלוק מונח בדיסק ומוזרם חיצונית; אם נמצא בלוק מבולבל, מפסק המעגל ברמת אלפית השנייה יכפיל את הצומת הזדוני ויתאושש אוטומטית מהמקור הישר.
- **הגדלה של FastCDC במקום וצבירת קבצים קטנים**: רק בלוקים דיפרנציאליים מועברים לשינוי חלקי של קבצים גדולים וממוקמים בדיסק; אריזת זיכרון מאסיבית של קבצים קטנים ודחיסת קידומת דיפרנציאלית מבטלת את התקורה של קובץ אחר קובץ הלוך ושוב.
- **ריפוי עצמי לאחר הפסקת חשמל וחידוש לאחר הפעלה מחדש**: פורמט RDB + AOF היברידי דמוי Redis (`.s0_subs.bin`) משמש לשמירה על מצב הזריעה ורשימת הקבצים, שינויים יומיים מתווספים במיקרו-שניות, ונכתבים מחדש ומאורגנים באופן אוטומטי באופן קבוע. לאחר הפעלה מחדש של השרת, שינויים לא מקוונים נדחפים אוטומטית לצומת הזריעה.

## ארכיטקטורה טכנית ותיעוד

- **פרוטוקול ניתוק מישור כפול**:
  - **משטח בקרה ושינוי בזמן אמת (`iroh` QUIC / TCP, לחיצת יד בגרסה הראשונה של `PROTO_VERSION` **: אחראי על אימות כרטיס ביקור Ed25519, אימות הרשאות, גילוי זרעי Swarm ותמיכה ב-`u64::MAX` זרימה של שינוי המוני ברמה ו`mzstd` דחיפה בזמן אמת. id="6"> / `FsOp::Remove` / `FsOp::Meta` שלושה פרימיטיביים).
  - **משטח הפצת נתונים (מקורי UDP + `compio` I/O אסינכרוני) **: כותרת קומפקטית של 20B, משוב תקופתי של 18B TACK, בקרת גודש היברידית BBRv3/Copa, שחזור אובדן מנות RACK-TLP, מעקף דחיסה Zstd אדפטיבית אנטרופיה בלוק ראשון של Shannon ו-<b id.
