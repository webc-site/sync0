# sync0

`sync0` - орталықтандырылмаған P2P файлдарын ортақ пайдалану, нақты уақыттағы синхрондау және `rsync` ауыстыру үшін пайдаланылатын көп көзді тарату құралы - трансконтиненттік кең аумақтық желінің өлшенген жылдамдығы `rsync` **6,95×** дейін (бір нүктелік геометриялық орташа жылдамдық **2,01 геометриялық бастапқы көз**- P2,01 геометриялық жылдамдық**-) **3,33×**) және мұхиттар арқылы үлкен шағын файлдарды синхрондау **7,19×** жылдам.

Әрбір машина бір мезгілде сервер және клиент болып табылады: орталық сервер немесе жалпы желі мекенжайы қажет емес, автоматты түрде тесілген желі жалпы кілтінің мекенжайына негізделген және ол екі машина арасында тікелей жіберуді, көп бөлісетін топтық рұқсатты хостингті, сұраныс бойынша ішкі каталогтарды бірнеше таңдауды, миллисекунд деңгейіндегі нақты уақыттағы қосымша синхронизацияны және көпкөзді аккредиттеуді қолдайды.

## Орнату

### 1-әдіс: Жүкті орнату

```bash
cargo install sync0
```

### 2-әдіс: Алдын ала құрастырылған екілік файлдарды жүктеп алыңыз

Жүйеге сәйкес келетін (Linux, macOS, Windows, Android, iOS, FreeBSD жүйелеріне қолдау көрсетеді) `.tar.xz` қысылған буманы жүктеп алу үшін [GitHub шығарылымдары](https://github.com/webc-site/sync0/releases) бөліміне өтіңіз, разрядты ашыңыз және `PATH` ішіне салыңыз:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Тез бастаңыз

### 1. Екі машина арасындағы нөлдік конфигурациялы тікелей жіберу (`send` / `recv`)

Ортақ топты конфигурациялаудың қажеті жоқ, файлдарды немесе каталогтарды екі машина арасында жоғары жылдамдықпен тікелей тасымалдау:

```bash
# Қабылдаушы жақ портты тыңдайды және ./backup файлына жазады
sync0 recv 0.0.0.0:9000 ./backup

# Жіберушіден тікелей жіберу (қосымша - артық файлдарды тазалау үшін айнаны жою, --50 МБ жылдамдықты шектеу)
sync0 send ./project 192.168.1.10:9000
```

### 2. Постты бөлісу және сұраныс бойынша тарту/жүктеп салу (`share` / `pull` / `push`)

```bash
# Сервер: бір пәрмен жолы арқылы бөлісу тобын жариялау (іске қосылғаннан кейін IP-сіз iroh түйінінің мекенжайын шығару)
sync0 share dataset:./data

# Клиент: бүкіл деректер жиынын ортақ пайдалану тобын жергілікті ./local_data файлына тартыңыз
sync0 тарту деректер жинағы:// ./local_data -p <түйін мекенжайы>

# Клиент: сұраныс бойынша бірнеше таңдауды тартыңыз (тек көрсетілген жеке файлдар мен ішкі каталогтарды синхрондаңыз)
sync0 тарту деректер жинағы://docs/readme.md,assets/icons,src/core ./local_data -p <түйін мекенжайы>

# Клиент: файлдарды немесе каталогтарды рұқсат етілген бөлісу топтарына жүктеп салыңыз
sync0 push деректер жинағы://releases/v1 ./build_output -p <түйін мекенжайы>
```

### 3. Нақты уақыттағы жазылымды себу және көп машиналы екі жақты синхрондау (`sub` / `group`)

Ұзақ қосылымды орнатқаннан кейін, қашықтағы ұшта кез келген файл **қосу, өзгерту, жою, рұқсаттарды өзгерту немесе өзгерту уақыты** орын алса, жергілікті каталог нақты уақытта миллисекундтарда синхронды түрде жаңартылады (жаңа/өзгертілген үлкен файлдар тек айырмашылық блоктарын алып, оларды орнында жаңартады, файлдарды жою жергілікті файлдарды автоматты түрде тазартады және тек бос каталогтар уақытын өзгертеді):

- **`sync0 sub`(Бір жақты нақты уақытта шағылыстыру + автоматты себу)**: Жергілікті нақты уақыт бөлісу соңындағы қосуларды, жоюларды және өзгертулерді бақылайды және басқа тарту түйіндері үшін бір мезгілде жеделдетуді қамтамасыз ету үшін автоматты түрде P2P тұқым көзі ретінде қызмет етеді.
- **`sync0 group`(Көп машиналы тең-теңімен екі жақты нақты уақытта синхрондау)**: Топтағы кез келген құрылғыда файлдар қосылса, жойылса немесе өзгертілсе, барлық басқа онлайн түйіндер нақты уақытта синхронды түрде жаңартылады және бір-біріне тұқым ретінде қызмет етеді.

```bash
# Бүкіл бөлісу тобына жазылыңыз: қашықтағы қосулар, жоюлар және өзгертулер нақты уақытта жергілікті түрде синхрондалады және автоматты түрде себіледі.
sync0 ішкі деректер жинағы:// ./local_mirror -p <түйін мекенжайы>

# Сұраныс бойынша көп таңдаулы жазылым: нақты уақыт режимінде тек көрсетілген жалғыз файлдар мен ішкі каталогтарды синхрондаңыз және тұқымдаңыз
sync0 ішкі деректер жинағы://models/llama.onnx,configs ./local_mirror -p <түйін мекенжайы>

# Нақты уақыттағы екі жақты синхрондау (толық немесе үтірмен көп таңдау жолдарын да қолдайды) көп машиналық тең топтар.
sync0 group team-docs:// ./docs -p <түйін мекенжайы>
```

### 4. Топтық көп бөлісу тобы және мүше рұқсатының конфигурациясы (`.nt` конфигурациясы)

Әдепкі конфигурация каталогы `~/.config/sync0` (`-c <каталогы>` арқылы ауыстырылады), минималистік [NestedText](https://nestedtext.org) (`.nt`) пішімін пайдаланады:
- **Жалпы желіні оқуды шектеуді қолдайды (тек рұқсаты бар пайдаланушылар оқи алады)**: ортақ пайдалану тобы `users:` мүшелер тізімімен конфигурацияланған кезде (немесе пәрмен жолы `--allow-r` / `--allow-rw` / `--allow-w` / `--auth` көрсетеді), жүйе автоматты түрде қосылады (құпияланған пайдаланушылар ғана оқи алады) **құпиялылық<b>6) және жалпы желідегі анонимді түйіндерді санауға немесе оқуға тыйым салады және P2P септік түйіндеріне жазылу ақ тізімді бір уақытта иеленіп, тек рұқсаты бар пайдаланушыларға оқуға мүмкіндік береді; `users` параметрімен конфигурацияланбаған ортақ пайдалану топтары әдепкі бойынша жалпыға ортақ және тек оқуға арналған (егер сіз жалпыға ортақ және тек оқуға арналған және тек көрсетілген мүшелерге жүктеп салуға ашық болғыңыз келсе, `auth: false` параметрін анық орнатуға болады).
- **Жақсартылған оқу-жазу және ішкі каталогты жеткізу рұқсаттары**: мүшелер әдепкі бойынша тек оқуға арналған (`r` анық жазылуы қажет емес) және `r` (тек оқу үшін), `w` (тек тастау жолағына жазу, оқылмайды), <b) id="-re"> `write_prefix` және <b) id="-4"> қолдау көрсетеді. (жүктеп салуға рұқсат етілген ішкі каталог префиксін шектеңіз).

**Мүше конфигурациясының мысалы (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (әдепкі тек оқуға арналған, жылдамдық шегі 80 МБ)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (оқу және жазу рұқсаттары, тек көрсетілген ішкі каталогқа жүктеп салуға рұқсат етілген)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (тек жеткізу рұқсатын жазу, оқуға тыйым салынады)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**Ортақ топ конфигурациясының мысалы (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # Конфигурацияланбаған пайдаланушылар: әдепкі жалпы желі тек оқуға арналған
  dataset:
    path: ./data
    rate: 50MB

  # Конфигурацияланған пайдаланушылар: жалпы желіні оқуды автоматты түрде шектейді (тек Алиса мен Боб оқи алады, Чарли тек жеткізе алады және жүктей алады)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

Қызметті іске қосыңыз (конфигурация файлын жүктеңіз немесе жалпы желіні оқуды шектеу және мүшелерді авторизациялау үшін пәрмен жолы параметрлерін тікелей пайдаланыңыз):

```bash
# Бастау үшін ~/.config/sync0/config.nt жүктеңіз
sync0 share --region SHA

# Немесе жеке бөлісу тобын таза пәрмен жолы арқылы жариялаңыз (қоғамдық желіні оқуды автоматты түрде шектеу үшін --allow-* көрсетіңіз және оған тек рұқсаты бар пайдаланушылар қол жеткізе алады)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. Түйін мекенжайы, визитка және көп тілді

```bash
# Жергілікті IP-сіз түйін мекенжайын көру (кілт бірінші іске қосу үшін автоматты түрде жасалады)
sync0 id

# Ed25519 өздігінен қол қойылған түйін визиткасын жасаңыз (лақап аты, қала коды, электрондық пошта, веб-сайт, кіріспе)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# Әдепкі бойынша жүйелік тілге сәйкес келетін және орта айнымалылары арқылы ауысуға болатын 75 кірістірілген тіл бар.
SYNC0_LANG=en sync0 --help
```

| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(сығымдалмайды) | 155 MB | **121.07** | 107.89 | **1,12×** |
| `linux-7.3.3.tar`(сығымдалатын) | 1.6 GB | **442.07** | 506.62 | **0,87×** |

### Өнімнің негізгі ерекшеліктері

- **Ашық кілт мекенжайы бойынша саңылауларды автоматты түрде ашу**: орталық сервер мен жалпы желі мекенжайын қажет етпейді, таратылған желідегі ашық кілт мекенжайы негізінде автоматты NAT тесігі.
- **Миллисекунд деңгейіндегі нақты уақытта синхрондау және метадеректер туралы хабардарлық**: жергілікті файл оқиғасын бақылау негізінде (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), нақты уақыттағы файлдарды қосу, жою, POSIX рұқсаттары (`mode`) және миллисекундтық модификация уақыты="-le" (<b); тек рұқсаттар немесе уақыт өзгертілген кезде деректер блогының нөлдік берілуі.
- **BT стиліндегі бір уақытта жүктеп алу мен жүктеп салу және аймақтық ұқсастықты жоспарлау**: Жүктеп алу түйіні толық көлемде жүктеп алынғанша күтудің қажеті жоқ. 128-биттік хэшті тексеруден өткен барлық блок аралықтары (`Op::Have`) басқа түйіндердің бір уақытта тартуы үшін жад/уақытша пулда дереу құлыпталады. Динамикалық PEX түйін алмасуымен және баяу түйіннің жартылай алдын-алуымен (жұмыс-ұрлау) кластердің өткізу қабілеті барынша жоғарылайды.
- **Зияндық түйінді бұзуға және кластерді улануға қарсы иммунитет**: беделді көздер тізімі `root_hash` Өзін-өзі дәйекті құлыптау + міндетті аппараттық жеделдету `gxhash128` әр блокты дискіге орналастырып, сырттан себу алдында дайджестті тексеру; егер бұзылған блок табылса, миллисекундтық деңгейдегі автоматты ажыратқыш зиянды түйінді өшіреді және автоматты түрде шынайы көзден қалпына келтіреді.
- **FastCDC in-situ өсімі және шағын файлдарды біріктіру**: Үлкен файлдарды ішінара өзгерту үшін тек дифференциалдық блоктар тасымалданады және дискіге орналастырылады; ауқымды шағын файл жады орамасы және префиксті дифференциалды қысу файлдан файлға айналу шығындарын жояды.
- **Қуат өшірілгеннен кейін өзін-өзі емдеу және қайта қосудан кейін қайта қосу**: Redis тәрізді RDB + AOF гибридті пішімі (`.s0_subs.bin`) себу күйі мен файлдар тізімін сақтау үшін пайдаланылады, күнделікті өзгерістер микросекундтарда қосылады және автоматты түрде қайта жазылады және жүйелі түрде ұйымдастырылады. Сервер қайта іске қосылғаннан кейін желіден тыс өзгерістер автоматты түрде септік түйініне жіберіледі.
