# sync0

`sync0` عبارة عن أداة لامركزية لمشاركة ملفات P2P ومزامنة في الوقت الفعلي وتوزيع متعدد المصادر تستخدم لتحل محل `rsync` - السرعة المقاسة للشبكة واسعة النطاق العابرة للقارات تصل إلى **6.95×** من `rsync` (متوسط السرعة الهندسية لنقطة واحدة **2.01×**، متوسط السرعة الهندسية ثنائية المصدر P2P **3.33×**)، ومزامنة الملفات الصغيرة الضخمة عبر المحيطات بسرعة **7.19×**.

كل جهاز عبارة عن خادم وعميل في نفس الوقت: ليست هناك حاجة إلى خادم مركزي أو عنوان شبكة عامة، ويعتمد التثقيب التلقائي على عنوان المفتاح العام للشبكة الموزعة، ويدعم النقل المباشر بين جهازين، واستضافة إذن مجموعة المشاركة المتعددة، والاختيار المتعدد للأدلة الفرعية عند الطلب، والمزامنة التزايدية في الوقت الفعلي على مستوى المللي ثانية، والتسريع المتزامن متعدد المصادر P2P.

## ثَبَّتَ

### الطريقة الأولى: تركيب البضائع

```bash
cargo install sync0
```

### الطريقة الثانية: تنزيل الثنائيات المترجمة مسبقًا

انتقل إلى [إصدارات GitHub](https://github.com/webc-site/sync0/releases) لتنزيل الحزمة المضغوطة `.tar.xz` المطابقة للنظام (تدعم Linux وmacOS وWindows وAndroid وiOS وFreeBSD)، ثم قم بفك الضغط ووضعها في `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## ابدأ بسرعة

### 1. نقل مباشر بدون تكوين بين جهازين (`send` / `recv`)

لا حاجة لتكوين مجموعة مشاركة، أو نقل الملفات أو الأدلة مباشرة بين جهازين بسرعة عالية:

```bash
# يستمع الطرف المتلقي إلى المنفذ ويكتب إلى ./backup
sync0 recv 0.0.0.0:9000 ./backup

# الإرسال المباشر من المرسل (اختياري - حذف المرآة لتنظيف الملفات الزائدة - الحد الأقصى للسرعة 50 ميجابايت)
sync0 send ./project 192.168.1.10:9000
```

### 2. مشاركة المنشورات والسحب/التحميل عند الطلب (`share` / `pull` / `push`)

```bash
# الخادم: نشر مجموعة المشاركة بسطر أوامر واحد (إخراج عنوان عقدة iroh الخالية من IP بعد بدء التشغيل)
sync0 share dataset:./data

# العميل: اسحب مجموعة مشاركة مجموعة البيانات بأكملها إلى ./local_data المحلي
sync0 سحب مجموعة البيانات::// ./local_data -p <عنوان العقدة>

# العميل: سحب تحديدات متعددة عند الطلب (فقط قم بمزامنة الملفات الفردية والأدلة الفرعية المحددة)
sync0 سحب مجموعة البيانات://docs/readme.md,assets/icons,src/core ./local_data -p <عنوان العقدة>

# العميل: تحميل الملفات أو الدلائل إلى مجموعات المشاركة المعتمدة
sync0 دفع مجموعة البيانات://releases/v1 ./build_output -p <عنوان العقدة>
```

### 3. زرع الاشتراكات في الوقت الفعلي والمزامنة ثنائية الاتجاه للأجهزة المتعددة (`sub` / `group`)

بعد إنشاء اتصال طويل، إذا حدث أي ملف **إضافة أو تعديل أو حذف أو تغيير الأذونات أو وقت التعديل** على الطرف البعيد، فسيتم تحديث الدليل المحلي بشكل متزامن بالمللي ثانية في الوقت الفعلي (ستقوم الملفات الكبيرة الجديدة/المعدلة فقط بسحب كتل الاختلاف وتحديثها في مكانها، وسيؤدي حذف الملفات تلقائيًا إلى تنظيف الملفات المحلية والأدلة الفارغة، وتغيير الأذونات أو كتل البيانات ذات الطابع الزمني الصفري فقط مباشرة):

- **`sync0 sub`(النسخ المتطابق في الوقت الفعلي في اتجاه واحد + البذر التلقائي)**: يتبع الوقت الفعلي المحلي الإضافات والحذف والتعديلات لنهاية المشاركة، ويعمل تلقائيًا كمصدر أولي P2P لتوفير تسريع متزامن لعقد السحب الأخرى.
- **`sync0 group`(مزامنة متعددة الأجهزة من نظير إلى نظير في الوقت الفعلي في اتجاهين)**: إذا تمت إضافة ملفات أو حذفها أو تعديلها على أي جهاز في المجموعة، فسيتم تحديث جميع العقد الأخرى عبر الإنترنت بشكل متزامن في الوقت الفعلي وتكون بمثابة بذور لبعضها البعض.

```bash
# الاشتراك في مجموعة المشاركة بأكملها: تتم مزامنة الإضافات والحذف والتعديلات عن بعد محليًا في الوقت الفعلي ويتم تصنيفها تلقائيًا
sync0 مجموعة البيانات الفرعية: // ./local_mirror -p <عنوان العقدة>

# الاشتراك متعدد التحديد عند الطلب: فقط قم بمزامنة الملفات الفردية والأدلة الفرعية المحددة وزرعها في الوقت الفعلي
مجموعة البيانات الفرعية sync0://models/llama.onnx,configs ./local_mirror -p <عنوان العقدة>

# مزامنة في الوقت الفعلي لمجموعة نظيرة متعددة الأجهزة في اتجاهين (يدعم أيضًا المسارات الكاملة أو متعددة التحديد بفاصلة)
sync0 group team-docs:// ./docs -p <عنوان العقدة>
```

### 4. تكوين أذونات مجموعة المشاركة المتعددة للفريق والأعضاء (`.nt` التكوين)

دليل التكوين الافتراضي هو `~/.config/sync0` (يمكن تبديله عبر `-c <directory>`)، باستخدام تنسيق [NestedText](https://nestedtext.org) (`.nt`) البسيط:
- ** يدعم تقييد قراءة الشبكة العامة (يمكن للمستخدمين المصرح لهم فقط القراءة) **: طالما تم تكوين مجموعة المشاركة بقائمة أعضاء `users:` (أو يحدد سطر الأوامر `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`)، يقوم النظام ** تلقائيًا بتشغيل المصادقة الخاصة (`auth: true`) ** ويحظر تعداد العقدة المجهولة للشبكة العامة أو القراءة، والاشتراك في عقد البذر P2P سوف يرث أيضًا القائمة البيضاء في وقت واحد، مما يسمح للمستخدمين المصرح لهم فقط بالقراءة؛ مجموعات المشاركة التي لم يتم تكوينها باستخدام `users` تكون عامة ومخصصة للقراءة فقط بشكل افتراضي (إذا كنت تريد أن تكون عامة ومخصصة للقراءة فقط ومفتوحة للتحميلات لأعضاء محددين فقط، فيمكنك تعيين `auth: false` بشكل صريح).
- **أذونات القراءة والكتابة الدقيقة وتسليم الدليل الفرعي**: الأعضاء للقراءة فقط بشكل افتراضي (`r` لا يلزم كتابتهم بشكل صريح)، ويدعمون `r` (للقراءة فقط)، `w` (الكتابة فقط في صندوق الإسقاط، غير قابل للقراءة)، `rw` (للقراءة والكتابة) و`write_prefix` (الحد من بادئة الدليل الفرعي المسموح بها لـ التحميل).

**مثال لتكوين العضو (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (القراءة الافتراضية فقط، الحد الأقصى للسرعة هو 80 ميجابايت)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (أذونات القراءة والكتابة، يُسمح فقط بالتحميل إلى دليل فرعي محدد)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (فقط كتابة إذن التسليم، القراءة محظورة)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**مثال لتكوين مجموعة المشاركة (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # المستخدمون الذين لم يتم تكوينهم: الشبكة العامة الافتراضية للقراءة فقط
  dataset:
    path: ./data
    rate: 50MB

  # المستخدمون الذين تم تكوينهم: تقييد قراءة الشبكة العامة تلقائيًا (يمكن لأليس وبوب فقط القراءة، ويمكن لتشارلي فقط التسليم والتحميل)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

ابدأ الخدمة (قم بتحميل ملف التكوين أو استخدم معلمات سطر الأوامر مباشرةً لتقييد قراءة الشبكة العامة وتفويض الأعضاء):

```bash
# قم بتحميل ~/.config/sync0/config.nt للبدء
sync0 share --region SHA

# أو قم بنشر مجموعة مشاركة خاصة من خلال سطر الأوامر فقط (حدد --allow-* لتقييد قراءة الشبكة العامة تلقائيًا ولا يمكن الوصول إليها إلا للمستخدمين المصرح لهم فقط)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. عنوان العقدة وبطاقة العمل ومتعددة اللغات

```bash
# عرض عنوان العقدة المحلية الخالية من IP (يتم إنشاء المفتاح تلقائيًا للتشغيل الأول)
sync0 id

# إنشاء بطاقة عمل عقدة موقعة ذاتيًا Ed25519 (الاسم المستعار ورمز المدينة والبريد الإلكتروني والموقع الإلكتروني والمقدمة)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# هناك 75 لغة مدمجة تتبع لغة النظام بشكل افتراضي ويمكن التبديل بينها من خلال متغيرات البيئة.
SYNC0_LANG=en sync0 --help
```

## الأداء والميزات الأساسية

### القياس الفعلي لشبكة WAN عبر القارات (المقارنة `rsync`)

بيئة القياس الفعلية: الولايات المتحدة `c1` → أوروبا `n1` (RTT 65 مللي ثانية)، مجموعة البيانات هي Linux kernel `linux-7.3.3`:

| مجموعة البيانات | مقاس | `sync0` نقطة واحدة<br>(ميغابت في الثانية) | `rsync`<br>(Mbps) | التسريع (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(غير قابل للضغط) | 155 MB | **121.07** | 107.89 | **1.12×** |
| `linux-7.3.3.tar`(قابل للضغط) | 1.6 GB | **442.07** | 506.62 | **0.87×** |
| `linux-7.3.3.tar`(زيادة التغيير المحلي) | 1.6 GB | **8,123.87** | 1,169.49 | **6.95×** |
| `linux-7.3.3/` (95,979 ملفًا صغيرًا) | 1.5 GB | **565.49** | 235.27 | **2.40×** |
| **المتوسط ​​الهندسي** | — | **704.17** | 350.19 | **2.01×** |

#### 2) وضع المصدر المزدوج P2P مقابل `rsync`

| مجموعة البيانات | مقاس | `sync0` مصدر ثنائي P2P<br>(ميغابت في الثانية) | `rsync`<br>(Mbps) | التسريع (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(غير قابل للضغط) | 155 MB | **466.85** | 107.89 | **4.33×** |

### ميزات المنتج الأساسية

- **الثقب التلقائي لعنوان المفتاح العام**: لا حاجة لخادم مركزي وعنوان شبكة عامة، فالثقب التلقائي لـ NAT يعتمد على عنوان المفتاح العام للشبكة الموزعة.
- **المزامنة في الوقت الفعلي على مستوى المللي ثانية والوعي بالبيانات الوصفية**: استنادًا إلى مراقبة أحداث الملف الأصلية (`FSEvents` / `inotify` / `ReadDirectoryChangesW`)، والدفع في الوقت الفعلي لإضافات الملفات وعمليات الحذف وأذونات POSIX (`mode`) ووقت التعديل على مستوى المللي ثانية (`mtime`)؛ نقل كتلة البيانات صفر عندما يتم تعديل الأذونات أو الوقت فقط.
- ** التنزيل والتحميل المتزامن بأسلوب BT وجدولة التقارب الإقليمي **: لا تحتاج عقدة التنزيل إلى انتظار تنزيل المبلغ بالكامل. يتم قفل جميع فترات الكتلة (`Op::Have`) التي اجتازت فحص التجزئة 128 بت على الفور في تجمع الذاكرة/المؤقت حتى تتمكن العقد الأخرى من السحب بشكل متزامن. جنبًا إلى جنب مع التبادل الديناميكي لعقدة PEX واستباق نصف العقدة البطيئة (سرقة العمل)، يتم تعظيم إنتاجية المجموعة إلى الحد الأقصى.
- ** مكافحة التلاعب بالعقدة الضارة ومناعة التسمم العنقودي **: قائمة المصادر الموثوقة `root_hash` قفل متسق ذاتيًا + تسريع إلزامي للأجهزة `gxhash128` التحقق من الملخص قبل وضع كل كتلة على القرص وزرعها خارجيًا؛ إذا تم العثور على كتلة تم العبث بها، فإن قاطع الدائرة على مستوى المللي ثانية سوف يحجب العقدة الضارة ويتعافى تلقائيًا من المصدر الصادق.
- **زيادة FastCDC في الموقع وتجميع الملفات الصغيرة**: يتم نقل الكتل التفاضلية فقط للتعديل الجزئي للملفات الكبيرة ووضعها على القرص؛ تعمل تعبئة ذاكرة الملفات الصغيرة الضخمة والضغط التفاضلي للبادئة على التخلص من الحمل ذهابًا وإيابًا لكل ملف على حدة.
- **الشفاء الذاتي بعد انقطاع التيار الكهربائي والاستئناف بعد إعادة التشغيل**: يتم استخدام تنسيق RDB + AOF الهجين المشابه لـ Redis (`.s0_subs.bin`) للاستمرار في حالة البذر وقائمة الملفات، ويتم إلحاق التغييرات اليومية بالميكروثانية، وتتم إعادة كتابتها وتنظيمها تلقائيًا بانتظام. بعد إعادة تشغيل الخادم، يتم دفع التغييرات دون اتصال تلقائيًا إلى عقدة البذر.

## الهندسة المعمارية والتوثيق الفني

- **بروتوكول فصل المستوى المزدوج**:
  - ** سطح التحكم والتغيير في الوقت الفعلي (`iroh` QUIC / TCP، البايت الأول `PROTO_VERSION` مصافحة الإصدار) **: مسؤول عن التحقق من بطاقة العمل Ed25519، والتحقق من الأذونات، واكتشاف بذور السرب، ودعم `u64::MAX` تجميع تدفق التغيير الشامل على المستوى و `mzstd` المضغوط `SubPush` الدفع في الوقت الفعلي (`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` ثلاثة عناصر أولية).
  - **سطح توزيع البيانات (UDP الأصلي + `compio` الإدخال/الإخراج غير المتزامن) **: رأس مضغوط 20B، وملاحظات دورية 18B TACK، والتحكم في الازدحام المختلط BBRv3/Copa، واسترداد فقدان حزم RACK-TLP، وتجاوز ضغط Zstd التكيفي لإنتروبيا شانون، و`gxhash128` التحقق الشامل.
