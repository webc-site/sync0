# sync0

`sync0` is a decentralized P2P file sharing, real-time synchronization and multi-source distribution tool used to replace `rsync` - the measured speed of transcontinental WAN is up to `rsync`'s **5.89×** (single point geometric average speed **2.67×**, P2P dual-source geometric average speed **3.16×**), and ການເລັ່ງຄວາມໄວຂອງການເຊື່ອມຕໍ່ transoceanic ສູງ P2P ແມ່ນສູງເຖິງ **7.68×** (ຄວາມໄວສະເລ່ຍຂອງ geometric ທີ່ສົມບູນແບບ 24-link ສະຖານະການ **2.56×**).

ແຕ່ລະເຄື່ອງແມ່ນທັງເຊີຟເວີແລະລູກຄ້າ: ບໍ່ຈໍາເປັນຕ້ອງມີເຄື່ອງແມ່ຂ່າຍກາງຫຼືທີ່ຢູ່ເຄືອຂ່າຍສາທາລະນະ, ການເຈາະຮູອັດຕະໂນມັດແມ່ນອີງໃສ່ທີ່ຢູ່ລະຫັດສາທາລະນະຂອງເຄືອຂ່າຍທີ່ແຈກຢາຍ, ແລະມັນສະຫນັບສະຫນູນການສົ່ງໂດຍກົງລະຫວ່າງສອງເຄື່ອງຈັກ, ການແບ່ງປັນການອະນຸຍາດຂອງກຸ່ມຫຼາຍ, ການຄັດເລືອກ subdirectories ຕາມຄວາມຕ້ອງການ, ການ synchronization ເພີ່ມຂຶ້ນໃນເວລາທີ່ແທ້ຈິງ millisecond ແລະ P2P multi-source concurrent.

## ຕິດຕັ້ງ

### ວິທີການ 1: ການຕິດຕັ້ງສິນຄ້າ

```bash
cargo install sync0
```

### ວິທີທີ່ 2: ດາວໂຫລດ binary precompiled

ໄປ​ທີ່ [GitHub Releases](https://github.com/webc-site/sync0/releases) ເພື່ອ​ດາວ​ໂຫລດ `.tar.xz`ຊຸດ​ບີບ​ອັດ​ທີ່​ສອດ​ຄ້ອງ​ກັບ​ລະ​ບົບ (ສະ​ຫນັບ​ສະ​ຫນູນ Linux, macOS, Windows, Android, iOS, FreeBSD), unzip ແລະ​ເອົາ​ໃສ່​ໃນ `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## ເລີ່ມຕົ້ນໄວ

### 1. ສູນການສົ່ງໂດຍກົງລະຫວ່າງສອງເຄື່ອງ (`send` / `recv`)

ບໍ່​ຈໍາ​ເປັນ​ຕ້ອງ​ກໍາ​ນົດ​ການ​ແບ່ງ​ປັນ​ກຸ່ມ​, ການ​ໂອນ​ໄຟລ​໌​ໂດຍ​ກົງ​ຫຼື​ລະ​ຫວ່າງ​ສອງ​ເຄື່ອງ​ທີ່​ມີ​ຄວາມ​ໄວ​ສູງ​:

```bash
# ໃນຕອນທ້າຍທີ່ໄດ້ຮັບຟັງຢູ່ໃນພອດແລະຂຽນໃສ່ ./backup
sync0 recv 0.0.0.0:9000 ./backup

# ການສົ່ງໂດຍກົງຈາກຜູ້ສົ່ງ (ທາງເລືອກ --delete mirror ເພື່ອເຮັດຄວາມສະອາດໄຟລ໌ເກີນ, --rate ຄວາມໄວຈໍາກັດ 50MB)
sync0 send ./project 192.168.1.10:9000
```

### 2. ການແບ່ງປັນໂພສ ແລະດຶງ/ອັບໂຫຼດຕາມຄວາມຕ້ອງການ (`share` / `pull` / `push`)

```bash
# ເຊີບເວີ: ເຜີຍແພ່ກຸ່ມແບ່ງປັນດ້ວຍຄຳສັ່ງໜຶ່ງແຖວ (ສົ່ງທີ່ຢູ່ IP ທີ່ບໍ່ມີ iroh node ຫຼັງຈາກການເລີ່ມຕົ້ນ)
sync0 share dataset:./data

# ລູກຄ້າ: ດຶງກຸ່ມແບ່ງປັນຊຸດຂໍ້ມູນທັງໝົດໄປທີ່ ./local_data
sync0 pull dataset:// ./local_data -p <node address>

# ລູກ​ຄ້າ​: ດຶງ​ເອົາ​ການ​ຄັດ​ເລືອກ​ຫຼາຍ​ຕາມ​ຄວາມ​ຕ້ອງ​ການ (ພຽງ​ແຕ່ synchronize ໄຟລ​໌​ດຽວ​ທີ່​ລະ​ບຸ​ໄວ້​ແລະ subdirectories​)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <node address>

# ລູກຄ້າ: ອັບໂຫຼດໄຟລ໌ ຫຼືໄດເລກະທໍລີໄປຫາກຸ່ມແບ່ງປັນທີ່ໄດ້ຮັບອະນຸຍາດ
sync0 push dataset://releases/v1 ./build_output -p <node address>
```

### 3. ການຈັດລຽງແບບສະສົມແບບສົດໆ ແລະ ການຊິງໂຄຣໄນແບບສອງທາງຫຼາຍເຄື່ອງ (`sub` / `group`)

ຫຼັງຈາກການສ້າງການເຊື່ອມຕໍ່ທີ່ຍາວນານ, ຖ້າໄຟລ໌ໃດ ** ເພີ່ມ, ແກ້ໄຂ, ລຶບ, ການປ່ຽນແປງການອະນຸຍາດຫຼືເວລາການດັດແກ້ ** ເກີດຂື້ນໃນປາຍທາງຫ່າງໄກສອກຫຼີກ, ໄດເລກະທໍລີທ້ອງຖິ່ນຈະຖືກປັບປຸງ synchronously ເປັນ milliseconds ໃນເວລາຈິງ (ໄຟລ໌ຂະຫນາດໃຫຍ່ໃຫມ່ / ດັດແກ້ພຽງແຕ່ດຶງຄວາມແຕກຕ່າງແລະປັບປຸງໃຫ້ເຂົາເຈົ້າຢູ່ໃນສະຖານທີ່, ລຶບໄຟລ໌ຈະເຮັດຄວາມສະອາດໄຟລ໌ທ້ອງຖິ່ນອັດຕະໂນມັດແລະຂໍ້ມູນລາຍຊື່ເປົ່າຫວ່າງເປົ່າ), ແລະພຽງແຕ່ປ່ຽນເວລາອະນຸຍາດໂດຍກົງ.

- **`sync0 sub`(ການສະທ້ອນແບບສົດໆທາງດຽວ + ການກ້າແກ່ນແບບອັດຕະໂນມັດ)**: ເວລາຈິງໃນທ້ອງຖິ່ນປະຕິບັດຕາມການເພີ່ມ, ການລຶບ ແລະການແກ້ໄຂສ່ວນສິ້ນສຸດຂອງການແບ່ງປັນ, ແລະເຮັດໜ້າທີ່ເປັນແຫຼ່ງແກ່ນ P2P ໂດຍອັດຕະໂນມັດເພື່ອສະໜອງການເລັ່ງພ້ອມກັນສໍາລັບໂນດດຶງອື່ນໆ.
- **`sync0 group`(ການ​ຊິງ​ໂຄຣ​ໄນ​ແບບ​ຈິງ​ສອງ​ທາງ​ແບບ​ດຽວ​ກັບ​ໝູ່​ຫຼາຍ​ເຄື່ອງ)**: ຖ້າ​ຫາກ​ວ່າ​ໄຟລ​໌​ໄດ້​ຖືກ​ເພີ່ມ​, ລຶບ​, ຫຼື​ການ​ແກ້​ໄຂ​ໃນ​ເຄື່ອງ​ໃດ​ຫນຶ່ງ​ໃນ​ກຸ່ມ​, ຂໍ້​ມູນ​ອອນ​ໄລ​ນ​໌​ອື່ນໆ​ທັງ​ຫມົດ​ຈະ​ໄດ້​ຮັບ​ການ​ປັບ​ປຸງ synchronously ໃນ​ເວ​ລາ​ທີ່​ແທ້​ຈິງ​ແລະ​ເປັນ​ແກ່ນ​ສໍາ​ລັບ​ເຊິ່ງ​ກັນ​ແລະ​ກັນ​.

```bash
# ສະໝັກສະມາຊິກກຸ່ມແບ່ງປັນທັງໝົດ: ການເພີ່ມ, ການລຶບ, ແລະການດັດແກ້ຈາກໄລຍະໄກແມ່ນ synchronized ຢູ່ໃນທ້ອງຖິ່ນໃນເວລາຈິງ ແລະແກ່ນອັດຕະໂນມັດ.
sync0 sub dataset:// ./local_mirror -p <node address>

# ການສະໝັກສະມາຊິກແບບຫຼາຍທາງເລືອກຕາມຄວາມຕ້ອງການ: ພຽງແຕ່ synchronize ແລະ seed ໄຟລ໌ດຽວແລະ subdirectories ໃນເວລາທີ່ແທ້ຈິງ
sync0 sub dataset://models/llama.onnx,config ./local_mirror -p <node address>

# ການ​ຊິງ​ຄ໌​ຣອນ​ໃນ​ເວ​ລາ​ທີ່​ແທ້​ຈິງ​ຂອງ​ກຸ່ມ​ເຄື່ອງ​ຈັກ​ຫຼາຍ​ເຄື່ອງ (ຍັງ​ສະ​ຫນັບ​ສະ​ຫນູນ​ເຕັມ​ຫຼື​ເຄື່ອງ​ຫມາຍ​ຈຸດ​ຫຼາຍ​ເສັ້ນ​ທາງ​ເລືອກ​)
sync0 ກຸ່ມ team-docs:// ./docs -p <node address>
```

### 4. ກຸ່ມການແບ່ງປັນຫຼາຍທີມ ແລະການຕັ້ງຄ່າການອະນຸຍາດສະມາຊິກ (`.nt`ການຕັ້ງຄ່າ)

ໄດເຣັກທໍຣີການຕັ້ງຄ່າເລີ່ມຕົ້ນແມ່ນ `~/.config/sync0` (ສາມາດປ່ຽນໄດ້ຜ່ານ `-c <directory>`), ໂດຍໃຊ້ຮູບແບບ [NestedText](https://nestedtext.org) (`.nt`):
- **ຮອງຮັບການຈຳກັດການອ່ານເຄືອຂ່າຍສາທາລະນະ (ສະເພາະຜູ້ໃຊ້ທີ່ໄດ້ຮັບອະນຸຍາດເທົ່ານັ້ນສາມາດອ່ານໄດ້)**: ຕາບໃດທີ່ກຸ່ມການແບ່ງປັນຖືກກຳນົດຄ່າດ້ວຍ `users:`ລາຍຊື່ສະມາຊິກ (ຫຼືເສັ້ນຄຳສັ່ງລະບຸ `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`, ລະບົບ ** ເປີດໃຊ້ການຕັ້ງເຄືອຂ່າຍສາທາລະນະ (6) ອັດຕະໂນມັດ ແລະ ຫ້າມບໍ່ໃຫ້ນຳໃຊ້** anonymous node enumeration ຫຼື ການອ່ານ, ແລະ P2P ສະໝັກໃຊ້ seeding nodes ຍັງຈະສືບທອດບັນຊີຂາວໄປພ້ອມໆກັນ, ໃຫ້ຜູ້ໃຊ້ທີ່ໄດ້ຮັບອະນຸຍາດເທົ່ານັ້ນທີ່ຈະອ່ານ; ກຸ່ມການແບ່ງປັນທີ່ບໍ່ໄດ້ກຳນົດຄ່າດ້ວຍ `users`ແມ່ນສາທາລະນະ ແລະອ່ານເທົ່ານັ້ນຕາມຄ່າເລີ່ມຕົ້ນ (ຖ້າທ່ານຕ້ອງການເປັນສາທາລະນະ ແລະອ່ານຢ່າງດຽວ ແລະເປີດໃຫ້ອັບໂຫລດສະເພາະສະມາຊິກທີ່ລະບຸ, ທ່ານສາມາດຕັ້ງ `auth: false`ຢ່າງຈະແຈ້ງໄດ້).
- **ການອະນຸຍາດການອ່ານ-ຂຽນແບບລະອຽດ ແລະລະບົບຍ່ອຍຍ່ອຍ**: ສະມາຊິກແມ່ນອ່ານໄດ້ຢ່າງດຽວຕາມຄ່າເລີ່ມຕົ້ນ (`r`ບໍ່ຈຳເປັນຕ້ອງຂຽນຢ່າງຈະແຈ້ງ), ແລະຮອງຮັບ `r` (ອ່ານເທົ່ານັ້ນ), `w` (ພຽງແຕ່ຂຽນໃສ່ກ່ອງເລື່ອນ, ບໍ່ສາມາດອ່ານໄດ້), `rw` (ອ່ານໄດ້ຢ່າງດຽວ), `rw` (direct-writing) ຄໍານໍາຫນ້າອະນຸຍາດໃຫ້ອັບໂຫລດ).

**ຕົວຢ່າງການຕັ້ງຄ່າສະມາຊິກ (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (ຄ່າເລີ່ມຕົ້ນອ່ານເທົ່ານັ້ນ, ຈຳກັດຄວາມໄວ 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (ສິດອະນຸຍາດອ່ານ ແລະຂຽນ, ພຽງແຕ່ອະນຸຍາດໃຫ້ອັບໂຫລດໄປຍັງໄດເລກະທໍລີຍ່ອຍທີ່ລະບຸ)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (ພຽງແຕ່ຂຽນການອະນຸຍາດການຈັດສົ່ງ, ການອ່ານຖືກຫ້າມ)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**ການ​ແບ່ງ​ປັນ​ຕົວ​ຢ່າງ​ການ​ຕັ້ງ​ຄ່າ​ກຸ່ມ (`~/.config/sync0/config.nt`):**


### ລັກສະນະຜະລິດຕະພັນຫຼັກ

- ** ລະຫັດສາທາລະນະທີ່ແກ້ໄຂບັນຫາການເຈາະຮູອັດຕະໂນມັດ **: ບໍ່ຈໍາເປັນຕ້ອງມີເຄື່ອງແມ່ຂ່າຍກາງແລະທີ່ຢູ່ເຄືອຂ່າຍສາທາລະນະ, ການເຈາະຮູ NAT ອັດຕະໂນມັດໂດຍອີງໃສ່ທີ່ຢູ່ກະແຈສາທາລະນະຂອງເຄືອຂ່າຍທີ່ແຈກຢາຍ.
- **ການຊິ້ງຂໍ້ມູນເວລາຈິງລະດັບ Millisecond ແລະການຮັບຮູ້ເມຕາເດຕາ**: ອີງໃສ່ການຕິດຕາມເຫດການໄຟລ໌ພື້ນເມືອງ (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), ການຊຸກຍູ້ການເພີ່ມໄຟລ໌, ການລຶບ, ການອະນຸຍາດ POSIX (`mode`) ແລະເວລາດັດແກ້ລະດັບ millisecond (<b); ການ​ສົ່ງ​ຂໍ້​ມູນ​ຕັນ​ສູນ​ໃນ​ເວ​ລາ​ທີ່​ມີ​ພຽງ​ແຕ່​ການ​ອະ​ນຸ​ຍາດ​ຫຼື​ເວ​ລາ​ທີ່​ມີ​ການ​ແກ້​ໄຂ​.
- **ການດາວໂຫຼດ ແລະ ອັບໂຫຼດພ້ອມໆກັນແບບ BT ແລະການກຳນົດເວລາຄວາມສຳພັນໃນພາກພື້ນ**: ໂນດດາວໂຫຼດບໍ່ຈຳເປັນຕ້ອງລໍຖ້າໃຫ້ດາວໂຫຼດເຕັມຈຳນວນ. ຊ່ວງເວລາບລັອກທັງໝົດ (`Op::Have`) ທີ່ຜ່ານການກວດສອບ 128-bit hash ຈະຖືກລັອກທັນທີໃນໜ່ວຍຄວາມຈຳ/ຊົ່ວຄາວເພື່ອໃຫ້ໂນດອື່ນດຶງພ້ອມກັນ. ຮ່ວມກັນກັບການແລກປ່ຽນ node PEX ແບບເຄື່ອນໄຫວແລະການ preemption ເຄິ່ງ node ຊ້າ (Work-Stealing), ການສົ່ງຜ່ານຂອງກຸ່ມແມ່ນສູງສຸດ.
- **ການຕໍ່ຕ້ານ node tampering malicious and cluster poisoning immunity**: authoritative source list `root_hash`ການລັອກຕົວມັນເອງ + ການເລັ່ງຮາດແວທີ່ບັງຄັບ `gxhash128`ການພິສູດການຍ່ອຍກ່ອນທີ່ແຕ່ລະ block ຈະຖືກວາງໄວ້ໃນແຜ່ນ ແລະແກ່ນພາຍນອກ; ຖ້າພົບຕັນທີ່ຖືກລົບກວນ, ຕົວຕັດວົງຈອນລະດັບ millisecond ຈະ blackout node ທີ່ເປັນອັນຕະລາຍແລະຈະຟື້ນຕົວອັດຕະໂນມັດຈາກແຫຼ່ງທີ່ຊື່ສັດ.
- **FastCDC in-site increment ແລະການຮວບຮວມໄຟລ໌ຂະໜາດນ້ອຍ**: ມີພຽງແຕ່ບລັອກທີ່ແຕກຕ່າງເທົ່ານັ້ນທີ່ຖືກໂອນຍ້າຍສຳລັບການດັດແກ້ບາງສ່ວນຂອງໄຟລ໌ຂະໜາດໃຫຍ່ ແລະວາງໄວ້ໃນແຜ່ນ; ການຫຸ້ມຫໍ່ຫນ່ວຍຄວາມຈໍາໄຟລ໌ຂະຫນາດນ້ອຍຂະຫນາດໃຫຍ່ແລະການບີບອັດສ່ວນຄໍານໍາຫນ້າຈະລົບລ້າງໄຟລ໌ໂດຍໄຟລ໌ຕະຫຼອດການເດີນທາງ.
- ** ການປິ່ນປົວດ້ວຍຕົນເອງຫຼັງຈາກໄຟຟ້າຢຸດແລະເລີ່ມຕົ້ນໃຫມ່ພາຍຫຼັງການເລີ່ມຕົ້ນໃຫມ່ **: ຮູບແບບປະສົມ Redis ຄ້າຍຄື RDB + AOF (`.s0_subs.bin`) ຖືກໃຊ້ເພື່ອສືບຕໍ່ສະຖານະການແກ່ນແລະລາຍການໄຟລ໌, ການປ່ຽນແປງປະຈໍາວັນຈະຖືກຕໍ່ທ້າຍໃນ microseconds, ແລະຖືກຂຽນໃຫມ່ໂດຍອັດຕະໂນມັດແລະຈັດລະບຽບເປັນປົກກະຕິ. ຫຼັງຈາກເຊີບເວີຣີສະຕາດແລ້ວ, ການປ່ຽນແປງແບບອອບໄລນ໌ຈະຖືກກົດດັນໃສ່ຈຸດແກ່ນພັນໂດຍອັດຕະໂນມັດ.

- ** ອະນຸສັນຍາ decoupling ຍົນຄູ່ **:
