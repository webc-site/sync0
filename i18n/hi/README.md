# sync0

`sync0` एक पीयर-टू-पीयर (पी2पी) फ़ाइल शेयरिंग और मल्टी-मशीन सिंक्रोनाइज़ेशन टूल है जो रेसिलियो सिंक के साथ प्रतिस्पर्धा करता है।

प्रत्येक मशीन एक सर्वर और क्लाइंट दोनों है: कोई भी नोड एकाधिक फ़ाइल साझाकरण समूह प्रकाशित कर सकता है। अन्य नोड्स जुड़ने के बाद, वे स्वचालित रूप से पीयर सर्वर से उपलब्ध बीज नोड्स प्राप्त कर सकते हैं और उन्हें कई स्रोतों से एक साथ खींच सकते हैं। सिंक्रोनाइज़ेशन पूरा होने के बाद, डाउनलोड में तेजी लाने के लिए अधिक नोड्स के लिए बीज स्वचालित रूप से बनाए जाएंगे।

## मुख्य हाइलाइट्स

- **हर कोई सर्वर और क्लाइंट दोनों है**: रेसिलियो सिंक की तुलना में, कोई केंद्रीय सर्वर निर्भरता नहीं। कोई भी नोड एकाधिक फ़ाइल साझाकरण समूह बना सकता है, और अन्य लोगों के साझाकरण समूहों में भी शामिल हो सकता है; नोड्स स्वचालित रूप से आदान-प्रदान करते हैं और कई मशीनों के समवर्ती खींचने और वास्तविक समय सिंक्रनाइज़ेशन को प्राप्त करने के लिए उपलब्ध बीज नोड्स प्राप्त करते हैं।
- **आईपी-मुक्त नोड पता**: डिफ़ॉल्ट रूप से, नोड कुंजी और `base64url` एन्कोडेड `iroh` पता सार्वजनिक आईपी को याद रखने या उजागर करने की आवश्यकता के बिना स्वचालित रूप से `~/.config/sync0` में उत्पन्न होता है।
- **मांग पर बहु-चयन सिंक्रनाइज़ेशन**: संपूर्ण साझाकरण समूह के सिंक्रनाइज़ेशन का समर्थन करता है, और एक ही समय में एकाधिक फ़ाइलों या उपनिर्देशिकाओं का चयन करके मांग पर सिंक्रनाइज़ेशन का भी समर्थन करता है।
- **समूह सदस्य पदानुक्रमित अनुमतियाँ और अपलोड निर्देशिका नियंत्रण**: केवल पढ़ने के लिए (`ro`), पढ़ने-लिखने के लिए अपलोड (`rw`), और प्रबंधन (`admin`) अनुमतियों का समर्थन करता है, और व्यक्तिगत रूप से पथ उपसर्ग निर्दिष्ट कर सकता है जिसे प्रत्येक सदस्य को अपलोड करने की अनुमति है (डिफ़ॉल्ट रूप से, शेयर की रूट निर्देशिका पर अपलोड करने की अनुमति है)।
- **नेटवर्क में पूर्ण-गति और वृद्धिशील सिंक्रनाइज़ेशन**: बड़ी फ़ाइलों का समवर्ती प्रसारण, मेमोरी में बड़ी छोटी फ़ाइलों का एकत्रीकरण, और फ़ाइलों को आंशिक रूप से संशोधित होने पर केवल सिंक्रनाइज़ डेटा ब्लॉक।

## स्थापित करना

### विधि 1: कार्गो के माध्यम से स्थापित करें

```bash
cargo install sync0
```

### विधि 2: पूर्व संकलित बायनेरिज़ डाउनलोड करें

संबंधित सिस्टम के लिए संपीड़ित पैकेज डाउनलोड करने के लिए [GitHub रिलीज़](https://github.com/webc-site/sync0/releases) पर जाएं (लिनक्स, मैकओएस, विंडोज, एंड्रॉइड, फ्रीबीएसडी, नेटबीएसडी का समर्थन करता है), अनज़िप करें और इसे <बी आईडी = "3"> निर्देशिका में डालें:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## जल्दी से आरंभ करें

`sync0` डिफ़ॉल्ट रूप से कॉन्फ़िगरेशन निर्देशिका के रूप में `~/.config/sync0` का उपयोग करता है (यदि आपको अन्य निर्देशिकाओं पर स्विच करने की आवश्यकता है, तो आप <b class='CODE'>-c <directory>` जोड़ सकते हैं)।

### 1. स्थानीय नोड पता और सेटिंग व्यवसाय कार्ड देखें

```bash
# स्थानीय नोड पता देखें (कुंजी पहली बार ~/.config/sync0 में स्वचालित रूप से उत्पन्न होती है)
sync0 id

# एक व्यक्तिगत नोड व्यवसाय कार्ड बनाएं (256 शब्दों के भीतर उपयोगकर्ता नाम, शहर, ईमेल, वेबसाइट और हस्ताक्षर का समर्थन करता है)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. एकाधिक फ़ाइल साझाकरण समूह प्रकाशित करें और समूह सदस्य अनुमतियाँ सेट करें (`.nt` कॉन्फ़िगरेशन)

`sync0` को [NestedText](https://nestedtext.org) (`.nt`) प्रारूप में कॉन्फ़िगर किया गया है। प्रत्येक उपयोगकर्ता के पास एक अलग `.nt` कॉन्फ़िगरेशन फ़ाइल होती है। आप उपयोगकर्ता प्रोफ़ाइल निर्देशिका को `users_dir` के माध्यम से `config.nt` में निर्दिष्ट कर सकते हैं (जिसमें स्वचालित रूप से इस निर्देशिका में सभी `.nt` फ़ाइलें शामिल होती हैं)। उपयोगकर्ता और अपलोड किए जाने वाले पथ उपसर्ग दोनों एक अव्यवस्थित सूची (`-`) का उपयोग करते हैं। **जब अपलोड पथ उपसर्ग नहीं भरा जाता है, तो शेयर की रूट निर्देशिका पर अपलोड करने की डिफ़ॉल्ट रूप से अनुमति होती है**।

1. `~/.config/sync0/users/` निर्देशिका में प्रत्येक सदस्य के लिए अलग-अलग `.nt` कॉन्फ़िगरेशन फ़ाइलें बनाएं:

`~/.config/sync0/users/alice.nt` (केवल पढ़ने के लिए सदस्य, दर सीमित `80MB`, `rate` `GB`, `MB`, `KB` इकाइयों का समर्थन करता है):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (प्रतिबंधित अपलोड सदस्य: केवल `uploads/bob` और `shared/common` निर्देशिकाओं पर अपलोड करने की अनुमति):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (डिफ़ॉल्ट सदस्य अपलोड: जब `write_prefix` को हटा दिया जाता है, तो शेयर की मूल निर्देशिका में अपलोड करने की अनुमति डिफ़ॉल्ट रूप से होती है):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. `~/.config/sync0/config.nt` में उपयोगकर्ता निर्देशिका और एकाधिक फ़ाइल साझाकरण समूह कॉन्फ़िगर करें:

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

साझाकरण सेवा प्रारंभ करें:

```bash
# डायरेक्ट स्टार्टअप (स्वचालित रूप से सभी .nt उपयोगकर्ता कॉन्फ़िगरेशन को ~/.config/sync0/config.nt और user_dir निर्देशिकाओं में लोड करता है)
sync0 share --region SHA

# या एकाधिक साझाकरण समूहों को शीघ्रता से प्रकाशित करें और समूह सदस्यों को सीधे कमांड लाइन के माध्यम से अधिकृत करें
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. सभी सामग्री खींचें या एकाधिक फ़ाइलों और निर्देशिकाओं का चयन करें (`sync0 pull`)

साझाकरण समूह में सभी उपलब्ध बीज नोड्स को स्वचालित रूप से प्राप्त करने के लिए किसी भी सहकर्मी नोड से कनेक्ट करें, और एक साथ कई बीज नोड्स से खींचें:

```bash
# संपूर्ण डेटासेट साझाकरण समूह को स्थानीय ./local_data पर खींचें
सिंक0 पुल डेटासेट:// ./local_data -p <नोड पता>

# बहु-चयन सिंक्रनाइज़ेशन: एक साथ एकल फ़ाइल docs/readme.md और उपनिर्देशिका संपत्ति/आइकन, src/core खींचें
सिंक0 पुल डेटासेट://docs/readme.md,assets/icons,src/core ./local_data -p <नोड पता>
```

### 4. किसी साझाकरण समूह में फ़ाइल या निर्देशिका अपलोड करें (`sync0 push`)

अपलोड अनुमति वाले सदस्य (`rw` या `admin`) दूरस्थ साझाकरण समूहों में स्थानीय फ़ाइलें या निर्देशिका अपलोड कर सकते हैं:

```bash
# रूट निर्देशिका अपलोड अनुमति वाले सदस्य: सीधे साझा रूट निर्देशिका पर अपलोड करें
सिंक0 पुश टीम-वॉल्ट:// ./new_release -p <नोड पता>

# केवल विशिष्ट उपसर्ग (जैसे अपलोड/बॉब) के लिए अधिकृत सदस्य: अनुमत पथ उपसर्ग पर अपलोड करें
सिंक0 पुश टीम-वॉल्ट: //uploads/bob/report.pdf ./report.pdf -p <नोड पता>
```

### 5. स्वचालित सिंक और सीडिंग की सदस्यता लें (`sync0 sub`)

एक निश्चित नोड के साझाकरण समूह की सदस्यता लेने के बाद, स्थानीय सर्वर एक प्राप्तकर्ता क्लाइंट और एक नया सीडिंग सर्वर दोनों है; जब स्रोत नोड फ़ाइल अद्यतन की जाती है, तो यह स्वचालित रूप से सिंक्रनाइज़ हो जाती है और अन्य नोड्स के लिए खंडित डाउनलोड प्रदान करती है:

```bash
# संपूर्ण साझाकरण समूह की सदस्यता लें और स्वचालित रूप से बीजारोपण करें
sync0 उप डेटासेट:// ./local_mirror -p <नोड पता>

# निर्दिष्ट फ़ाइलों और उपनिर्देशिकाओं की सदस्यता लेने और उन्हें सीड करने के लिए केवल बहु-चयन करें
sync0 उप डेटासेट://मॉडल/llama.onnx,configs ./local_mirror -p <नोड पता>
```

### 6. मल्टी-मशीन ग्रुप पीयर सिंक्रोनाइज़ेशन (`sync0 group`)

एकाधिक मशीनें एक ही साझाकरण समूह में शामिल होती हैं, एक-दूसरे स्वचालित रूप से उपलब्ध बीज नोड्स की खोज करते हैं और दो-तरफ़ा सिंक्रनाइज़ेशन बनाए रखते हैं (पूर्ण सिंक्रनाइज़ेशन या फ़ाइलों और निर्देशिकाओं के एकाधिक चयन का समर्थन करते हैं):

```bash
# समूह में पूरी तरह से शामिल हों और दोतरफा समन्वयन करें
सिंक0 समूह टीम-दस्तावेज़:// ./docs -p <नोड पता>

# बहु-चयन सिंक्रनाइज़ेशन समूह में केवल wal निर्देशिका और मेटा.json फ़ाइल
सिंक0 समूह टीम-डॉक्स://वाल,मेटा.जेसन ./docs -p <नोड पता>
```

### 7. दो मशीनों के बीच प्वाइंट-टू-प्वाइंट सीधा प्रसारण (`send` / `recv`)

किसी समूह को पूर्व-कॉन्फ़िगर करने की कोई आवश्यकता नहीं है, और आप सीधे दो मशीनों के बीच फ़ाइलों या निर्देशिकाओं को अस्थायी रूप से स्थानांतरित कर सकते हैं:

```bash
# रिसीवर की निगरानी
sync0 recv 0.0.0.0:9000 ./backup

# भेजने वाला अंत सीधे फ़ाइलों या निर्देशिकाओं को स्थानांतरित करता है (वैकल्पिक - अतिरिक्त फ़ाइलों को साफ़ करने के लिए मिरर हटाएं, गति सीमा निर्धारित करें)
sync0 send ./project 192.168.1.10:9000
```

### 8. बहुभाषी स्विचिंग

`sync0` 75 भाषाओं का समर्थन करता है, और डिफ़ॉल्ट रूप से सिस्टम भाषा वातावरण के अनुसार स्वचालित रूप से स्विच करता है; इसे `SYNC0_LANG` के माध्यम से मैन्युअल रूप से भी निर्दिष्ट किया जा सकता है:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
