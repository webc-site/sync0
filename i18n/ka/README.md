# sync0

`sync0` არის დეცენტრალიზებული P2P ფაილების გაზიარების, რეალურ დროში სინქრონიზაციისა და მრავალ წყაროს განაწილების ხელსაწყო, რომელიც გამოიყენება `rsync`-ის ჩანაცვლებისთვის - ტრანსკონტინენტური WAN-ის გაზომილი სიჩქარე არის `rsync`-მდე **5.89×** (ერთი წერტილის საშუალო გეომეტრიული საშუალო სიჩქარე **-2,62P×** **3.16×**), ხოლო ტრანსოკეანური მაღალი ლატენტური კავშირის P2P აჩქარება **7.68×**-მდეა (სრული ბმული 24 სცენარის ყოვლისმომცველი გეომეტრიული საშუალო სიჩქარე **2.56×**).

თითოეული მანქანა არის როგორც სერვერი, ასევე კლიენტი: არ არის საჭირო ცენტრალური სერვერის ან საჯარო ქსელის მისამართი, ხვრელის ავტომატური პუნქცია ეფუძნება განაწილებული ქსელის საჯარო გასაღების მისამართს და მხარს უჭერს პირდაპირ გადაცემას ორ მანქანას შორის, მრავალჯერადი გაზიარების ჯგუფის ნებართვის ჰოსტინგი, ქვედირექტორიების მრავალჯერადი შერჩევა მოთხოვნისამებრ, მილიწამის დონის რეალურ დროში მულტიკულტურული სინქრონიზაცია და P2.

## დააინსტალირეთ

### მეთოდი 1: ტვირთის მონტაჟი

```bash
cargo install sync0
```

### მეთოდი 2: ჩამოტვირთეთ წინასწარ კომპილირებული ბინარები

გადადით [GitHub Releases](https://github.com/webc-site/sync0/releases) სისტემის შესაბამისი `.tar.xz` შეკუმშული პაკეტის ჩამოსატვირთად (მხარდაჭერილია Linux, macOS, Windows, Android, iOS, FreeBSD), გახსენით და ჩადეთ `PATH`-ში:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## დაიწყეთ სწრაფად

### 1. ნულოვანი კონფიგურაციის პირდაპირი გადაცემა ორ მანქანას შორის (`send` / `recv`)

არ არის საჭირო გაზიარების ჯგუფის კონფიგურაცია, ფაილების ან დირექტორიების პირდაპირ გადაცემა ორ მანქანას შორის მაღალი სიჩქარით:

```bash
# მიმღები უსმენს პორტს და წერს ./backup-ზე
sync0 recv 0.0.0.0:9000 ./backup

# პირდაპირი გადაცემა გამგზავნისგან (სურვილისამებრ -- წაშალეთ სარკე ზედმეტი ფაილების გასასუფთავებლად, -- სიჩქარის 50 მბ სიჩქარის ლიმიტი)
sync0 send ./project 192.168.1.10:9000
```

### 2. პოსტის გაზიარება და მოთხოვნით გაყვანა/ატვირთვა (`share` / `pull` / `push`)

```bash
# სერვერი: გამოაქვეყნეთ გაზიარების ჯგუფი ბრძანების ერთი ხაზით (გამოიტანეთ IP-უფასო iroh კვანძის მისამართი გაშვების შემდეგ)
sync0 share dataset:./data

# კლიენტი: გაიყვანეთ მონაცემთა გაზიარების მთელი ჯგუფი ადგილობრივ ./local_data-ზე
sync0 pull database:// ./local_data -p <კვანძის მისამართი>

# კლიენტი: მოთხოვნისამებრ გაიყვანეთ მრავალი არჩევანი (მხოლოდ მითითებული ცალკეული ფაილების და ქვედირექტორიების სინქრონიზაცია)
sync0 pull მონაცემთა ნაკრები://docs/readme.md,assets/icons,src/core ./local_data -p <კვანძის მისამართი>

# კლიენტი: ატვირთეთ ფაილები ან დირექტორიები ავტორიზებულ გაზიარების ჯგუფებში
sync0 push database://releases/v1 ./build_output -p <კვანძის მისამართი>
```

### 3. რეალურ დროში გამოწერის დათესვა და მრავალ მანქანით ორმხრივი სინქრონიზაცია (`sub` / `group`)

ხანგრძლივი კავშირის დამყარების შემდეგ, თუ რომელიმე ფაილის **დამატების, შეცვლა, წაშლა, ნებართვების შეცვლა ან შეცვლის დრო** მოხდება დისტანციურ ბოლოში, ლოკალური დირექტორია სინქრონულად განახლდება მილიწამებში რეალურ დროში (ახალი/შეცვლილი დიდი ფაილები მხოლოდ განსხვავებულ ბლოკებს ამოიღებს და განაახლებს მათ ადგილზე, ფაილების წაშლა ავტომატურად ასუფთავებს მონაცემებს და ცვლის მხოლოდ ადგილობრივ ფაილებს და ცარიელ დირექტორს).

- **`sync0 sub`(ცალმხრივი რეალურ დროში ასახვა + ავტომატური დათესვა)**: ადგილობრივი რეალურ დროში მიჰყვება გაზიარების დასასრულის დამატებებს, წაშლას და მოდიფიკაციას და ავტომატურად ემსახურება როგორც P2P სათესლე წყაროს, რათა უზრუნველყოს ერთდროული აჩქარება სხვა გამწევი კვანძებისთვის.
- **`sync0 group`(მრავალმანქანიანი peer-to-peer ორმხრივი რეალურ დროში სინქრონიზაცია)**: თუ ფაილები დაემატება, წაიშლება ან შეიცვლება ჯგუფის რომელიმე მოწყობილობაზე, ყველა სხვა ონლაინ კვანძი სინქრონულად განახლდება რეალურ დროში და იქნება ერთმანეთის სათავე.

```bash
# გამოიწერეთ გაზიარების მთელი ჯგუფი: დისტანციური დამატებები, წაშლა და ცვლილებები სინქრონიზებულია ადგილობრივად რეალურ დროში და ავტომატურად დათესილია
sync0 ქვე მონაცემთა ნაკრები:// ./local_mirror -p <კვანძის მისამართი>

# მრავალჯერადი შერჩევის გამოწერა მოთხოვნით: მხოლოდ სინქრონიზაცია და დათესვა მითითებული ცალკეული ფაილების და ქვეცნობარების რეალურ დროში
sync0 ქვე მონაცემთა ნაკრები://models/llama.onnx,configs ./local_mirror -p <კვანძის მისამართი>

# მრავალმანქანიანი თანატოლების ჯგუფის ორმხრივი რეალურ დროში სინქრონიზაცია (ასევე მხარს უჭერს სრულ ან მძიმით მრავალ არჩევის ბილიკებს)
sync0 ჯგუფი team-docs:// ./docs -p <კვანძის მისამართი>
```

### 4. გუნდის მრავალჯერადი გაზიარების ჯგუფი და წევრის ნებართვის კონფიგურაცია (`.nt` კონფიგურაცია)

ნაგულისხმევი კონფიგურაციის დირექტორია არის `~/.config/sync0` (შეიძლება გადართვა `-c <directory>` მეშვეობით), მინიმალისტური [NestedText](https://nestedtext.org) (`.nt`) ფორმატის გამოყენებით:
- **მხარდაჭერილია საჯარო ქსელის წაკითხვის შეზღუდვისთვის (მხოლოდ ავტორიზებულ მომხმარებლებს შეუძლიათ წაიკითხონ)**: სანამ გაზიარების ჯგუფი კონფიგურირებულია `users:` წევრების სიით (ან ბრძანების სტრიქონში მითითებულია `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`), სისტემა ჩართულია კერძო (b id="5">) id="6">)** და კრძალავს საჯარო ქსელის ანონიმური კვანძების ჩამოთვლას ან კითხვას, და P2P გამოწერა დათესილი კვანძების ასევე მემკვიდრეობით მიიღებს თეთრ სიას ერთდროულად, რაც მხოლოდ უფლებამოსილ მომხმარებლებს საშუალებას მისცემს წაიკითხონ; გაზიარებული ჯგუფები, რომლებიც არ არის კონფიგურირებული `users`-ით, ნაგულისხმევად არის საჯარო და მხოლოდ წაკითხვადი (თუ გსურთ იყოთ საჯარო და მხოლოდ წაკითხვადი და ღია ატვირთვისთვის მხოლოდ მითითებული წევრებისთვის, შეგიძლიათ ცალსახად დააყენოთ `auth: false`).
- ** წვრილმარცვლოვანი წაკითხვის-ჩაწერის და ქვედირექტორის მიწოდების ნებართვები**: წევრები ნაგულისხმევად მხოლოდ წაკითხვადია (`r` არ საჭიროებს ცალსახად დაწერას) და მხარს უჭერს `r` (მხოლოდ წასაკითხად), `w` (მხოლოდ ჩაწერა ჩამოსაშლელ ყუთში, არ იკითხება), <b>re <id="1"> (შეზღუდეთ ასატვირთად დაშვებული ქვეცნობარის პრეფიქსი).

**წევრის კონფიგურაციის მაგალითი (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (ნაგულისხმევი მხოლოდ წაკითხვადი, სიჩქარის ლიმიტი 80 მბ)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (კითხვისა და ჩაწერის ნებართვები, ნებადართულია ატვირთვა მხოლოდ მითითებულ ქვედირექტორიაში)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (მხოლოდ ჩაწერის მიწოდების ნებართვა, კითხვა აკრძალულია)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**ჯგუფის კონფიგურაციის გაზიარების მაგალითი (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # არაკონფიგურირებული მომხმარებლები: ნაგულისხმევი საჯარო ქსელი მხოლოდ წასაკითხად
  dataset:
    path: ./data
    rate: 50MB

  # კონფიგურირებული მომხმარებლები: ავტომატურად ზღუდავს საჯარო ქსელის კითხვას (მხოლოდ ალისს და ბობს შეუძლიათ წაკითხვა, ჩარლის შეუძლია მხოლოდ მიწოდება და ატვირთვა)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

დაიწყეთ სერვისი (ჩატვირთეთ კონფიგურაციის ფაილი ან პირდაპირ გამოიყენეთ ბრძანების ხაზის პარამეტრები საჯარო ქსელის წაკითხვის შეზღუდვისა და წევრების ავტორიზაციისთვის):

```bash
# ჩატვირთეთ ~/.config/sync0/config.nt დასაწყებად
sync0 share --region SHA

# ან გამოაქვეყნეთ პირადი გაზიარების ჯგუფი სუფთა ბრძანების ხაზის მეშვეობით (მიუთითეთ --allow-* ავტომატურად შეზღუდოს საჯარო ქსელის კითხვა და მხოლოდ ავტორიზებულ მომხმარებლებს შეუძლიათ მასზე წვდომა)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. კვანძის მისამართი, სავიზიტო ბარათი და მრავალენოვანი

```bash
# იხილეთ ადგილობრივი IP-უფასო კვანძის მისამართი (გასაღები ავტომატურად გენერირებულია პირველი გაშვებისთვის)
sync0 id

# შექმენით Ed25519 ხელმოწერილი კვანძის სავიზიტო ბარათი (მეტსახელი, ქალაქის კოდი, ელფოსტა, ვებსაიტი, შესავალი)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# არის 75 ჩაშენებული ენა, რომლებიც ნაგულისხმევად მიჰყვება სისტემის ენას და მათი გადართვა შესაძლებელია გარემოს ცვლადების საშუალებით.
SYNC0_LANG=en sync0 --help
```

### პროდუქტის ძირითადი მახასიათებლები

- **საჯარო გასაღების მისამართის ავტომატური ხვრელის დარტყმა**: არ არის საჭირო ცენტრალური სერვერის და საზოგადოებრივი ქსელის მისამართი, NAT ხვრელის ავტომატური პუნქცია განაწილებული ქსელის საჯარო გასაღების მისამართზე დაყრდნობით.
- **მილიწამის დონის რეალურ დროში სინქრონიზაცია და მეტამონაცემების ინფორმირებულობა**: ფაილების მოვლენის მონიტორინგზე (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), რეალურ დროში ფაილების დამატებების, წაშლის, POSIX ნებართვების (`mode`) და მილიფების მოდიფიკაციის (`mode`) და millisecon-ის დროზე (`mode`) დაფუძნებაზე; ნულოვანი მონაცემთა ბლოკის გადაცემა, როდესაც მხოლოდ ნებართვები ან დრო იცვლება.
- **BT სტილის ერთდროული ჩამოტვირთვა და ატვირთვა და რეგიონალური აფინურობის დაგეგმვა **: ჩამოტვირთვის კვანძს არ სჭირდება ლოდინი სრული თანხის ჩამოტვირთვისთვის. ყველა ბლოკის ინტერვალი (`Op::Have`), რომლებმაც გაიარეს 128-ბიტიანი ჰეშის შემოწმება, დაუყოვნებლივ იკეტება მეხსიერებაში/დროებით აუზში, რათა სხვა კვანძებმა ერთდროულად გაიყვანონ. დინამიურ PEX კვანძის გაცვლასთან და ნელი კვანძის ნახევრად პრემპტირებასთან ერთად (სამუშაო-ქურდობა), კლასტერის გამტარუნარიანობა მაქსიმალურად არის გაზრდილი.
- ** მავნე კვანძების დარღვევისა და კასეტური მოწამვლის იმუნიტეტი **: ავტორიტეტული წყაროების სია `root_hash` თვითმმართველობის თანმიმდევრული ჩაკეტვა + ტექნიკის სავალდებულო აჩქარება `gxhash128` დაიჯესტის შემოწმება ყოველი ბლოკის დისკზე განთავსებამდე და გარედან დათესვამდე; თუ დაზიანებული ბლოკი აღმოჩნდება, მილიწამის დონის ამომრთველი ჩააქრობს მავნე კვანძს და ავტომატურად აღდგება პატიოსანი წყაროდან.
- **FastCDC in-situ ზრდა და მცირე ფაილების აგრეგაცია**: მხოლოდ დიფერენციალური ბლოკები გადადის დიდი ფაილების ნაწილობრივი მოდიფიკაციისთვის და მოთავსებულია დისკზე; მასიური პატარა ფაილების მეხსიერების შეფუთვა და პრეფიქსის დიფერენციალური შეკუმშვა გამორიცხავს ფაილ-ფაილის მრგვალი მოგზაურობის ზედნადებს.
- **თვითგანკურნება ელექტროენერგიის გათიშვის შემდეგ და განახლება გადატვირთვის შემდეგ**: Redis-ის მსგავსი RDB + AOF ჰიბრიდული ფორმატი (`.s0_subs.bin`) გამოიყენება დათესვის სტატუსისა და ფაილების სიის შესანარჩუნებლად, ყოველდღიური ცვლილებები ემატება მიკროწამებში და ავტომატურად ხელახლა იწერება და რეგულარულად ორგანიზებულია. სერვერის გადატვირთვის შემდეგ, ოფლაინ ცვლილებები ავტომატურად გადადის სათესლე კვანძში.
