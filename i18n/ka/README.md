# sync0

`sync0` არის Peer-to-peer (P2P) ფაილების გაზიარებისა და მრავალ მანქანით სინქრონიზაციის ინსტრუმენტი, რომელიც კონკურენციას უწევს Resilio Sync-ს.

თითოეული მანქანა არის სერვერიც და კლიენტიც: ნებისმიერ კვანძს შეუძლია ფაილების გაზიარების მრავალი ჯგუფის გამოქვეყნება. მას შემდეგ, რაც სხვა კვანძები შეუერთდებიან, მათ შეუძლიათ ავტომატურად მიიღონ ხელმისაწვდომი სათესლე კვანძები თანატოლების სერვერიდან და გაიყვანონ ისინი ერთდროულად მრავალი წყაროდან. სინქრონიზაციის დასრულების შემდეგ, თესლები ავტომატურად შეიქმნება მეტი კვანძისთვის, ჩამოტვირთვის დასაჩქარებლად.

## ძირითადი მაჩვენებლები

- **ყველა არის როგორც სერვერი, ასევე კლიენტი**: შედარებულია Resilio Sync-თან, არ არის დამოკიდებული ცენტრალური სერვერზე. ნებისმიერ კვანძს შეუძლია შექმნას მრავალი ფაილის გაზიარების ჯგუფი და ასევე შეუერთდეს სხვა ადამიანების გაზიარების ჯგუფებს; კვანძები ავტომატურად ცვლიან და იღებენ ხელმისაწვდომ სათესლე კვანძებს, რათა მიაღწიონ მრავალჯერადი მანქანების ერთდროულად მოზიდვას და რეალურ დროში სინქრონიზაციას.
- **IP-ის გარეშე კვანძის მისამართი**: ნაგულისხმევად, კვანძის გასაღები და `base64url` კოდირებული `iroh` მისამართი ავტომატურად გენერირდება `~/.config/sync0`-ში საჯარო IP-ის დამახსოვრების ან გამოვლენის საჭიროების გარეშე.
- **მრავალარჩევანი სინქრონიზაცია მოთხოვნით**: მხარს უჭერს მთელი გაზიარების ჯგუფის სინქრონიზაციას და ასევე მხარს უჭერს სინქრონიზაციას მოთხოვნისამებრ რამდენიმე ფაილის ან ქვეცნობარის ერთდროულად არჩევით.
- **ჯგუფის წევრების იერარქიული ნებართვები და ატვირთვის დირექტორიას კონტროლი**: მხარს უჭერს მხოლოდ წაკითხვის (`ro`), წაკითხვა-ჩაწერის ატვირთვის (`rw`) და მართვის (`admin`) ნებართვებს და შეუძლია ინდივიდუალურად მიუთითოს ბილიკის პრეფიქსი, რომლის ატვირთვის უფლება აქვს თითოეულ წევრს (ნაგულისხმევად, ატვირთვა არის root დირექტორიაში).
- **სრული სიჩქარით და დამატებითი სინქრონიზაცია ქსელებში**: დიდი ფაილების ერთდროული გადაცემა, მასიური მცირე ფაილების აგრეგაცია მეხსიერებაში და მხოლოდ სინქრონიზებული მონაცემთა ბლოკები, როდესაც ფაილები ნაწილობრივ შეცვლილია.

## დააინსტალირეთ

### მეთოდი 1: ინსტალაცია Cargo-ს მეშვეობით

```bash
cargo install sync0
```

### მეთოდი 2: ჩამოტვირთეთ წინასწარ კომპილირებული ბინარები

გადადით [GitHub Releases](https://github.com/webc-site/sync0/releases) `.tar.xz` შეკუმშული პაკეტის ჩამოსატვირთად შესაბამისი სისტემისთვის (მხარდაჭერილია Linux, macOS, Windows, Android, FreeBSD, NetBSD), გახსენით და ჩადეთ `PATH` დირექტორიაში:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## დაიწყეთ სწრაფად

`sync0` ნაგულისხმევად იყენებს `~/.config/sync0` კონფიგურაციის დირექტორიად (თუ სხვა დირექტორიებზე გადასვლა გჭირდებათ, შეგიძლიათ დაამატოთ `-c <directory>`).

### 1. ნახეთ ადგილობრივი კვანძის მისამართი და დაყენების სავიზიტო ბარათი

```bash
# ლოკალური კვანძის მისამართის ნახვა (გასაღები ავტომატურად გენერირებულია ~/.config/sync0-ში პირველად)
sync0 id

# შექმენით პირადი კვანძის სავიზიტო ბარათი (მხარდაჭერილია მომხმარებლის სახელი, ქალაქი, ელფოსტა, ვებსაიტი და ხელმოწერა 256 სიტყვის ფარგლებში)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. ფაილების გაზიარების მრავალი ჯგუფის გამოქვეყნება და ჯგუფის წევრების ნებართვების დაყენება (`.nt` კონფიგურაცია)

`sync0` კონფიგურირებულია [NestedText](https://nestedtext.org) (`.nt`) ფორმატში. თითოეულ მომხმარებელს აქვს ცალკე `.nt` კონფიგურაციის ფაილი. შეგიძლიათ მიუთითოთ მომხმარებლის პროფილის დირექტორია `users_dir` `config.nt`-ში (რომელიც ავტომატურად მოიცავს ყველა `.nt` ფაილს ამ დირექტორიაში). როგორც მომხმარებელი, ასევე ატვირთვის ნებადართული ბილიკის პრეფიქსი იყენებს შეუკვეთებელ სიას (`-`). **როცა ატვირთვის ბილიკის პრეფიქსი არ არის შევსებული, ნაგულისხმევად ნებადართულია ატვირთვა წილის root დირექტორიაში**.

1. შექმენით ცალკე `.nt` კონფიგურაციის ფაილები თითოეული წევრისთვის `~/.config/sync0/users/` დირექტორიაში:

`~/.config/sync0/users/alice.nt` (მხოლოდ წაკითხვადი წევრი, მაჩვენებელი შეზღუდული `80MB`, `rate` მხარს უჭერს `GB`, `MB`, `KB` ერთეულებს):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (ატვირთვის შეზღუდული წევრები: ნებადართულია მხოლოდ `uploads/bob` და `shared/common` დირექტორიაში ატვირთვა):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (ნაგულისხმევი წევრის ატვირთვა: როდესაც `write_prefix` გამოტოვებულია, ნაგულისხმევად ნებადართულია გაზიარების root დირექტორიაში ატვირთვა):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. დააკონფიგურირეთ მომხმარებლის დირექტორია და ფაილების გაზიარების მრავალი ჯგუფი `~/.config/sync0/config.nt`-ში:

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

დაიწყეთ გაზიარების სერვისი:

```bash
# პირდაპირი გაშვება (ავტომატურად იტვირთება .nt მომხმარებლის ყველა კონფიგურაცია ~/.config/sync0/config.nt და users_dir დირექტორიებში)
sync0 share --region SHA

# ან სწრაფად გამოაქვეყნეთ მრავალი გაზიარების ჯგუფი და მიეცით ჯგუფის წევრების ავტორიზაცია პირდაპირ ბრძანების ხაზის მეშვეობით
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. გაიყვანეთ მთელი შინაარსი ან აირჩიეთ მრავალი ფაილი და დირექტორია (`sync0 pull`)

დაუკავშირდით ნებისმიერ თანატოლ კვანძს, რათა ავტომატურად მიიღოთ ყველა ხელმისაწვდომი სათესლე კვანძი გაზიარების ჯგუფში და ამოიღეთ რამდენიმე სათესლე კვანძიდან ერთდროულად:

```bash
# გაიყვანეთ მონაცემთა გაზიარების მთელი ჯგუფი ადგილობრივ ./local_data-ზე
sync0 pull database:// ./local_data -p <კვანძის მისამართი>

# მრავალჯერადი სინქრონიზაცია: ერთდროულად ამოიღეთ ერთი ფაილი docs/readme.md და ქვედირექტორიების აქტივები/ხატები, src/core
sync0 pull მონაცემთა ნაკრები://docs/readme.md,assets/icons,src/core ./local_data -p <კვანძის მისამართი>
```

### 4. ატვირთეთ ფაილი ან დირექტორია გაზიარების ჯგუფში (`sync0 push`)

წევრებს ატვირთვის ნებართვით (`rw` ან `admin`) შეუძლიათ ატვირთონ ადგილობრივი ფაილები ან დირექტორიები დისტანციური გაზიარების ჯგუფებში:

```bash
# წევრები root დირექტორიაში ატვირთვის ნებართვით: ატვირთეთ პირდაპირ გაზიარებულ root დირექტორიაში
sync0 push team-vault:// ./new_release -p <კვანძის მისამართი>

# მხოლოდ კონკრეტული პრეფიქსის (როგორიცაა ატვირთვები/ბობ) უფლებამოსილი წევრები: ატვირთეთ დაშვებული ბილიკის პრეფიქსი
sync0 push team-vault://uploads/bob/report.pdf ./report.pdf -p <კვანძის მისამართი>
```

### 5. გამოიწერეთ ავტომატური სინქრონიზაცია და დათესვა (`sync0 sub`)

გარკვეული კვანძის გაზიარების ჯგუფში გამოწერის შემდეგ, ლოკალური სერვერი არის როგორც მიმღები კლიენტი, ასევე ახალი სათესლე სერვერი; როდესაც წყაროს კვანძის ფაილი განახლდება, ის ავტომატურად სინქრონიზდება და უზრუნველყოფს სხვა კვანძების ჩამოტვირთვებს:

```bash
# გამოიწერეთ მთელი გაზიარების ჯგუფი და ავტომატურად დათესეთ
sync0 ქვე მონაცემთა ნაკრები:// ./local_mirror -p <კვანძის მისამართი>

# მხოლოდ მრავალჯერ აირჩიეთ, რათა გამოიწეროთ მითითებული ფაილები და ქვეცნობარები და დათესოთ ისინი
sync0 ქვე მონაცემთა ნაკრები://models/llama.onnx,configs ./local_mirror -p <კვანძის მისამართი>
```

### 6. მრავალმანქანიანი ჯგუფის თანატოლების სინქრონიზაცია (`sync0 group`)

მრავალი მანქანა უერთდება იმავე გაზიარების ჯგუფს, ერთმანეთი ავტომატურად აღმოაჩენს ხელმისაწვდომ სათესლე კვანძებს და ინარჩუნებს ორმხრივ სინქრონიზაციას (მხარდაჭერილია სრულ სინქრონიზაციას ან ფაილებისა და დირექტორიების მრავალჯერადი შერჩევას):

```bash
# სრულად შეუერთდით ჯგუფს და ორმხრივ სინქრონიზაციას
sync0 ჯგუფი team-docs:// ./docs -p <კვანძის მისამართი>

# მხოლოდ wal დირექტორია და meta.json ფაილი მრავალჯერადი სინქრონიზაციის ჯგუფში
sync0 ჯგუფი team-docs://wal,meta.json ./docs -p <კვანძის მისამართი>
```

### 7. წერტილიდან წერტილამდე პირდაპირი გადაცემა ორ მანქანას შორის (`send` / `recv`)

არ არის საჭირო ჯგუფის წინასწარი კონფიგურაცია და შეგიძლიათ დროებით გადაიტანოთ ფაილები ან დირექტორიები პირდაპირ ორ მანქანას შორის:

```bash
# მიმღების მონიტორინგი
sync0 recv 0.0.0.0:9000 ./backup

# გაგზავნის ბოლო პირდაპირ გადასცემს ფაილებს ან დირექტორიებს (სურვილისამებრ - წაშალეთ სარკე ზედმეტი ფაილების გასასუფთავებლად, - სიჩქარის შეზღუდვა)
sync0 send ./project 192.168.1.10:9000
```

### 8. მრავალენოვანი გადართვა

`sync0` მხარს უჭერს 75 ენას და ავტომატურად იცვლება სისტემის ენის გარემოს მიხედვით ნაგულისხმევად; ის ასევე შეიძლება ხელით მიუთითოთ `SYNC0_LANG`-ით:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
