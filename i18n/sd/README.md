# sync0

`sync0` هڪ غير مرڪزي P2P فائل شيئرنگ، حقيقي وقت جي هم وقت سازي ۽ ملٽي سورس ورهائڻ وارو اوزار آهي جيڪو بدلائڻ لاءِ استعمال ڪيو ويندو آهي `rsync` - ٽرانسڪنٽيننٽل وان جي ماپي رفتار `rsync` جي **5.89×** تائين آهي (سنگل پوائنٽ جاميٽري اوسط رفتار **2.67P × getric اوسط رفتار **2.67P×al**- **3.16×**)، ۽ transoceanic High-Letency Link P2P ايڪسلريشن **7.68×** تائين آهي (مڪمل لنڪ 24-منظر جامع جاميٽري مطلب جي رفتار **2.56×**).

هر مشين هڪ سرور ۽ ڪلائنٽ ٻئي آهي: مرڪزي سرور يا عوامي نيٽ ورڪ ايڊريس جي ڪا ضرورت ناهي، خودڪار سوراخ پنچنگ ورهايل نيٽ ورڪ پبلڪ ڪيئي ايڊريس تي مبني آهي، ۽ اها ٻن مشينن جي وچ ۾ سڌي ٽرانسميشن کي سپورٽ ڪري ٿي، ملٽي شيئرنگ گروپ جي اجازت هوسٽنگ، مطالبن تي ذيلي ڊائريڪٽرن جي گهڻن چونڊ، مليسيڪنڊ-سطح ريئل-ٽائم انڪريمينٽل-ايڪسيل-ايڪسيلر-سائينچائيشن ملٽي-سيڪنڊ-سطح.

## انسٽال ڪريو

### طريقو 1: سامان لڳائڻ

```bash
cargo install sync0
```

### طريقو 2: ڊائون لوڊ ڪريو اڳ ۾ ٺهيل بائنري

ڏانهن وڃو [GitHub Releases](https://github.com/webc-site/sync0/releases) ڊائون لوڊ ڪرڻ لاءِ `.tar.xz` ڪمپريس ٿيل پيڪيج جيڪو سسٽم سان لاڳاپيل آهي (لينڪس، ميڪوس، ونڊوز، اينڊرائيڊ، iOS، فري بي ايس ڊي کي سپورٽ ڪري ٿو)، ان زپ ڪريو ۽ ان ۾ وجھو `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## جلدي شروع ڪريو

### 1. ٻن مشينن جي وچ ۾ زيرو ترتيب واري سڌي ٽرانسميشن (`send` / `recv`)

شيئرنگ گروپ کي ترتيب ڏيڻ جي ڪا ضرورت ناهي، سڌو سنئون فائلون يا ڊائريڪٽريون ٻن مشينن جي وچ ۾ تيز رفتار تي منتقل ڪريو:

```bash
# وصول ڪندڙ آخر بندرگاهه تي ٻڌي ٿو ۽ لکي ٿو ./backup
sync0 recv 0.0.0.0:9000 ./backup

# موڪليندڙ کان سڌو ٽرانسميشن (اختياري - اضافي فائلن کي صاف ڪرڻ لاء آئيني کي حذف ڪريو، 50MB رفتار جي حد جي شرح)
sync0 send ./project 192.168.1.10:9000
```

### 2. پوسٽ شيئرنگ ۽ آن ڊيمانڊ پل/اپلوڊ (`share` / `pull` / `push`)

```bash
# سرور: ڪمانڊ جي ھڪڙي لائن سان شيئرنگ گروپ کي شايع ڪريو (شروع ٿيڻ کانپوءِ IP-free iroh node address output)
sync0 share dataset:./data

# ڪلائنٽ: پوري ڊيٽا سيٽ شيئرنگ گروپ کي مقامي ./local_data ڏانهن ڇڪيو
sync0 pull dataset:// ./local_data -p <node address>

# ڪلائنٽ: مطالبن تي گھڻن انتخابن کي ڇڪيو (صرف مخصوص واحد فائلن ۽ ذيلي ڊائريڪٽريز کي هم وقت سازي ڪريو)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <node address>

# ڪلائنٽ: اپلوڊ ڪريو فائلون يا ڊائريڪٽريون بااختيار شيئرنگ گروپن ڏانهن
sync0 push dataset://releases/v1 ./build_output -p <node address>
```

### 3. ريئل ٽائيم سبسڪرپشن سيڊنگ ۽ ملٽي مشين ٻه طرفي هم وقت سازي (`sub` / `group`)

ڊگھي ڪنيڪشن قائم ڪرڻ کان پوءِ، جيڪڏهن ڪا به فائل ** شامل ڪرڻ، تبديل ڪرڻ، حذف ڪرڻ، اجازتن کي تبديل ڪرڻ يا ترميم ڪرڻ وقت** ريموٽ جي آخر ۾ ٿئي ٿي، مقامي ڊاريڪٽري کي حقيقي وقت ۾ مليس سيڪنڊن ۾ هم وقت سازي سان اپڊيٽ ڪيو ويندو (نئون/ تبديل ٿيل وڏيون فائلون صرف فرق بلاڪ کي ڇڪينديون ۽ انهن کي اپ ڊيٽ ڪنديون، فائلون ڊليٽ ڪنديون ۽ مقامي فائلن کي پاڻمرادو صاف ڪنديون، ڊائريڪٽري فائلن کي مٽائيندي ۽ صرف ڊاريڪٽري فائلن کي تبديل ڪندي. بلاڪ سڌو):

- **`sync0 sub`(هڪ طرفي حقيقي وقت آئيني + خودڪار سيڊنگ)**: مقامي حقيقي وقت شيئرنگ جي آخر ۾ اضافو، حذف ڪرڻ ۽ ترميمن جي پيروي ڪري ٿو، ۽ خودڪار طريقي سان ڪم ڪري ٿو P2P ٻج ماخذ جي طور تي ٻين ڇڪڻ واري نوڊس لاء هموار تيز رفتار مهيا ڪرڻ لاء.
- **`sync0 group`(Multi-machine peer-to-peer two-way real-time synchronization)**: جيڪڏهن فائلون شامل ڪيون وڃن، ڊليٽ ڪيون وڃن، يا گروپ ۾ ڪنهن به مشين تي تبديل ڪيون وڃن، باقي سڀئي آن لائين نوڊس هم وقت سازي سان اپڊيٽ ڪيا ويندا ۽ هڪ ٻئي لاءِ ٻج طور ڪم ڪندا.

```bash
# پوري شيئرنگ گروپ جي رڪنيت حاصل ڪريو: ريموٽ اضافو، حذف ڪرڻ، ۽ تبديليون مقامي طور تي حقيقي وقت ۾ هم وقت سازي ٿينديون آهن ۽ خودڪار طريقي سان ترتيب ڏني وينديون آهن
sync0 sub dataset:// ./local_mirror -p <node address>

# آن ڊيمانڊ ملٽي سليڪٽ سبسڪرپشن: صرف هم وقت سازي ۽ ٻج مخصوص ٿيل واحد فائلون ۽ ذيلي ڊائريڪٽريون اصل وقت ۾
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <node address>

# ملٽي مشين پير گروپ ٻه طرفي حقيقي وقت جي هم وقت سازي (پڻ مڪمل يا ڪاما گھڻن چونڊيل رستن کي سپورٽ ڪري ٿو)
sync0 group team-docs:// ./docs -p <node address>
```

### 4. ٽيم ملٽي شيئرنگ گروپ ۽ ميمبرن جي اجازت جي ترتيب (`.nt` ترتيب)

ڊفالٽ ڪنفيگريشن ڊاريڪٽري آهي `~/.config/sync0` (`-c <directory>` ذريعي تبديل ڪري سگھجي ٿو)، استعمال ڪندي minimalist [NestedText](https://nestedtext.org) (`.nt`) فارميٽ:
- ** عوامي نيٽ ورڪ جي پڙھڻ کي محدود ڪرڻ جي حمايت ڪري ٿو (صرف بااختيار استعمال ڪندڙ پڙھي سگھن ٿا)**: جيستائين شيئرنگ گروپ کي ترتيب ڏنل آھي `users:` ميمبرن جي فهرست سان (يا ڪمانڊ لائن وضاحت ڪري ٿي `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`)، سسٽم ** خودڪار طور تي چالو ٿئي ٿو. عوامي نيٽ ورڪ گمنام نوڊ جي ڳڻپ يا پڙهڻ کان منع ڪري ٿو، ۽ P2P سبسڪرائب ڪرڻ سان سيڊنگ نوڊس پڻ هڪ ئي وقت وائيٽ لسٽ کي ورثي ۾ آڻيندو، صرف بااختيار صارفين کي پڙهڻ جي اجازت ڏيندو؛ شيئرنگ گروپس جيڪي ترتيب ڏنل نه آهن `users` سان ترتيب ڏنل آهن عوامي ۽ صرف پڙهڻ لاءِ ڊفالٽ (جيڪڏهن توهان چاهيو ٿا ته عوامي ۽ صرف پڙهڻ لاءِ ۽ صرف مخصوص ميمبرن لاءِ اپ لوڊ ڪرڻ لاءِ، توهان واضح طور تي سيٽ ڪري سگهو ٿا `auth: false`).
- **فائن-گرينڊ پڙهڻ-لکڻ ۽ ذيلي ڊاريڪٽري ترسيل اجازتون**: ميمبر صرف پڙهڻ لاءِ آهن ڊفالٽ (`r` واضح طور تي لکڻ جي ضرورت ناهي)، ۽ سپورٽ `r` (صرف پڙهڻ لاءِ)، `w` (صرف ڊراپ باڪس ڏانهن لکو، پڙهڻ لائق نه)، <b-id="4) > <b-id="4"> اپلوڊ ڪرڻ جي اجازت ڏني وئي ذيلي ڊائريڪٽري پريفڪس).

**ميمبر جي ٺاھ جوڙ جو مثال (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (صرف پڙهڻ لاءِ ڊفالٽ، رفتار جي حد 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (پڙهڻ ۽ لکڻ جي اجازت، صرف مخصوص سب ڊاريڪٽري تي اپلوڊ ڪرڻ جي اجازت آهي)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (صرف ترسيل جي اجازت لکڻ، پڙهڻ ممنوع آهي)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

** شيئرنگ گروپ ٺاھڻ جو مثال (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # نه ترتيب ڏنل استعمال ڪندڙ: ڊفالٽ عوامي نيٽ ورڪ صرف پڙهڻ لاءِ
  dataset:
    path: ./data
    rate: 50MB

  # ترتيب ڏنل استعمال ڪندڙ: خودڪار طريقي سان عوامي نيٽ ورڪ پڙهڻ کي محدود ڪريو (صرف ايلس ۽ باب پڙهي سگھن ٿا، چارلي صرف پهچائي ۽ اپلوڊ ڪري سگھن ٿا)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

خدمت شروع ڪريو (ڪانفيگريشن فائل لوڊ ڪريو يا سڌو استعمال ڪريو ڪمانڊ لائن پيٽرولر عوامي نيٽ ورڪ جي پڙھڻ کي محدود ڪرڻ ۽ ميمبرن کي اختيار ڏيڻ لاءِ):

```bash
# شروع ڪرڻ لاءِ ~/.config/sync0/config.nt لوڊ ڪريو
sync0 share --region SHA

# يا خالص ڪمانڊ لائن ذريعي پرائيويٽ شيئرنگ گروپ کي شايع ڪريو (وضاحت ڪريو --allow-* خود بخود عوامي نيٽ ورڪ جي پڙھڻ کي محدود ڪرڻ ۽ صرف بااختيار صارف ان تائين رسائي ڪري سگھن ٿا)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. نوڊ ايڊريس، ڪاروباري ڪارڊ ۽ گھڻائي ٻولي

```bash
# مقامي IP-مفت نوڊ ايڊريس ڏسو (ڪي پهرين رن لاءِ پاڻمرادو ٺاهي وئي آهي)
sync0 id

# ٺاھيو Ed25519 خود دستخط ٿيل نوڊ بزنس ڪارڊ (نڪ نالو، شھر جو ڪوڊ، اي ميل، ويب سائيٽ، تعارف)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# هتي 75 ٺاهيل ٻوليون آهن، جيڪي سسٽم جي ٻولي کي ڊفالٽ جي پيروي ڪندا آهن ۽ ماحول جي تبديلين ذريعي تبديل ڪري سگھجن ٿيون.
SYNC0_LANG=en sync0 --help
```

## ڪارڪردگي ۽ بنيادي خاصيتون

### ڪراس براعظمي WAN حقيقي ماپ (مقابلي `rsync`)

اصل ماپي ماحول: آمريڪا `c1` → يورپ `n1` (RTT 65 ms)، ڊيٽا سيٽ آهي لينڪس ڪرنل `linux-7.3.3`:

#### 1) هڪ لا ڪارٽ موڊ بمقابله `rsync`

| ڊيٽا سيٽ | ماپ | `sync0` سنگل پوائنٽ<br>(Mbps) | `rsync`<br>(Mbps) | اسپيڊ اپ (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(دٻائڻ لائق نه) | 155 MB | **236.48** | 108.74 | **2.17×** |
| `linux-7.3.3.tar`(دٻائڻ لائق) | 1.6 GB | **843.83** | 385.06 | **2.19×** |
| `linux-7.3.3.tar`(مقامي تبديلي واڌارو) | 1.6 GB | **8,014.15** | 1,361.72 | **5.89×** |
| `linux-7.3.3/` (95,979 ننڍيون فائلون) | 1.5 GB | **627.58** | 347.80 | **1.80×** |
| ** جاميٽري مطلب** | - | **1,000.91** | 375.26 | **2.67×** |

#### 2) P2P ڊبل سورس موڊ بمقابله `rsync`

| ڊيٽا سيٽ | ماپ | `sync0` P2P ٻٽي ماخذ<br>(Mbps) | `rsync`<br>(Mbps) | اسپيڊ اپ (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(دٻائڻ لائق نه) | 155 MB | **330.09** | 108.74 | **3.04×** |
| `linux-7.3.3.tar`(دٻائڻ لائق) | 1.6 GB | **1,551.86** | 385.06 | **4.03×** |
| `linux-7.3.3.tar`(مقامي تبديلي واڌارو) | 1.6 GB | **5,474.17** | 1,361.72 | **4.02×** |
| `linux-7.3.3/` (95,979 ننڍيون فائلون) | 1.5 GB | **706.56** | 347.80 | **2.03×** |
| ** جاميٽري مطلب** | - | **1,186.42** | 375.26 | **3.16×** |

> نوٽ: P2P ڊبل سورس موڊ ۾، يورپي نوڊس `s1` ٻج پوکڻ لاءِ تعاون ڪن ٿا، ۽ ڪراس براعظمي پس منظر RTT 65 ms آهي.

### بنيادي پيداوار جون خاصيتون

- **عوامي ڪيئي ايڊريسنگ آٽوميٽڪ هول پنچنگ**: مرڪزي سرور ۽ پبلڪ نيٽ ورڪ ايڊريس جي ڪا ضرورت ناهي، ورهايل نيٽ ورڪ پبلڪ ڪي ائڊريس جي بنياد تي خودڪار NAT هول پنچنگ.
- **ملي سيڪنڊ-سطح حقيقي وقت جي هم وقت سازي ۽ ميٽا ڊيٽا جي آگاهي**: اصلي فائل جي واقعن جي نگراني جي بنياد تي (`FSEvents` / `inotify` / `ReadDirectoryChangesW`)، فائل شامل ڪرڻ، حذف ڪرڻ، POSIX اجازتون (`mode`) ۽ مليسيڪنڊ وقت (`mode`) ۽ ملائي سيڪنڊ ="5"> صفر ڊيٽا بلاڪ ٽرانسميشن جڏهن صرف اجازتون يا وقت تبديل ٿيل آهن.
- **BT طرز هڪ ئي وقت ۾ ڊائون لوڊ ۽ اپلوڊ ۽ علائقائي لاڳاپن جي شيڊولنگ**: ڊائون لوڊ ڪرڻ واري نوڊ کي ڊائون لوڊ ٿيڻ لاءِ مڪمل رقم جو انتظار ڪرڻ جي ضرورت ناهي. سڀئي بلاڪ وقفا (`Op::Have`) جيڪي 128-bit هيش چيڪ پاس ڪيا آهن انهن کي فوري طور تي بند ڪيو ويو آهي ميموري/عارضي تلاءَ ۾ ٻين نوڊس کي گڏ ڪرڻ لاءِ. گڏو گڏ متحرڪ PEX نوڊ ايڪسچينج ۽ سست نوڊ اڌ پريمپشن (ڪم-چوري) سان گڏ، ڪلستر جي ذريعي وڌ ۾ وڌ ڪيو ويو آهي.
- **مخالف نوڊ ٽمپرنگ ۽ ڪلسٽر پوائزننگ اميونٽي**: مستند ماخذ لسٽ `root_hash` Self-consistent locking + mandatory Hardware acceleration `gxhash128` هضم جي تصديق ان کان اڳ جو هر بلاڪ کي ڊسڪ تي رکيو وڃي ۽ خارجي طور تي سيڊ ڪيو وڃي. جيڪڏهن هڪ ڇڪيل بلاڪ مليو آهي، مليسيڪنڊ-سطح سرڪٽ برڪر بدڪار نوڊ کي بليڪ آئوٽ ڪري ڇڏيندو ۽ خود بخود ايماندار ذريعن کان بحال ٿي ويندو.
- **FastCDC in-situ increment and small file aggregation**: وڏي فائلن جي جزوي ترميم لاءِ صرف ڊفرنشل بلاڪ منتقل ڪيا ويا آهن ۽ ڊسڪ تي رکيا ويا آهن. وڏي پئماني تي ننڍي فائل ميموري پيڪنگنگ ۽ پريفڪس ڊفرنشل ڪمپريشن کي ختم ڪري فائل بائي فائل گول ٽرپ اوور هيڊ.
- **بجلي جي بندش کان پوءِ پاڻ کي شفا ڏيڻ ۽ ٻيهر شروع ٿيڻ کان پوءِ ٻيهر شروع ڪرڻ**: ريڊس جهڙو RDB + AOF هائبرڊ فارميٽ (`.s0_subs.bin`) استعمال ڪيو ويندو آهي ٻج جي حالت ۽ فائل لسٽ کي برقرار رکڻ لاءِ، روزاني تبديليون مائڪرو سيڪنڊن ۾ شامل ڪيون وينديون آهن، ۽ خودڪار طريقي سان ٻيهر لکجي ۽ منظم ٿينديون آهن. سرور جي ٻيهر شروع ٿيڻ کان پوء، آف لائن تبديليون خودڪار طور تي ٻج جي نوڊ ڏانهن ڌڪي وينديون آهن.

## ٽيڪنيڪل فن تعمير ۽ دستاويز
