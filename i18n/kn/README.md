# sync0

`sync0` ಎಂಬುದು ವಿಕೇಂದ್ರೀಕೃತ P2P ಫೈಲ್ ಹಂಚಿಕೆ, ನೈಜ-ಸಮಯದ ಸಿಂಕ್ರೊನೈಸೇಶನ್ ಮತ್ತು ಬಹು-ಮೂಲ ವಿತರಣಾ ಸಾಧನವಾಗಿದೆ `rsync` ಅನ್ನು ಬದಲಿಸಲು ಬಳಸಲಾಗುತ್ತದೆ - ಟ್ರಾನ್ಸ್ಕಾಂಟಿನೆಂಟಲ್ ವೈಡ್ ಏರಿಯಾ ನೆಟ್‌ವರ್ಕ್‌ನ ಅಳತೆಯ ವೇಗವು `rsync` ನ **6.95×** ವರೆಗೆ ಇರುತ್ತದೆ (ಏಕ-ಪಾಯಿಂಟ್ P2P 2.0 ಮೂಲ ಸರಾಸರಿ ವೇಗ *** 2.0 ಜ್ಯಾಮಿತೀಯ ಸರಾಸರಿ ವೇಗ ವೇಗ **3.33×**), ಮತ್ತು ಸಾಗರಗಳಾದ್ಯಂತ ಬೃಹತ್ ಸಣ್ಣ ಫೈಲ್‌ಗಳ ಸಿಂಕ್ರೊನೈಸೇಶನ್ **7.19×** ವೇಗವಾಗಿರುತ್ತದೆ.

ಪ್ರತಿಯೊಂದು ಯಂತ್ರವು ಸರ್ವರ್ ಮತ್ತು ಕ್ಲೈಂಟ್ ಎರಡೂ ಆಗಿದೆ: ಕೇಂದ್ರ ಸರ್ವರ್ ಅಥವಾ ಸಾರ್ವಜನಿಕ ನೆಟ್‌ವರ್ಕ್ ವಿಳಾಸದ ಅಗತ್ಯವಿಲ್ಲ, ಸ್ವಯಂಚಾಲಿತ ರಂಧ್ರ ಪಂಚಿಂಗ್ ವಿತರಿಸಿದ ನೆಟ್‌ವರ್ಕ್ ಸಾರ್ವಜನಿಕ ಕೀ ವಿಳಾಸವನ್ನು ಆಧರಿಸಿದೆ ಮತ್ತು ಇದು ಎರಡು ಯಂತ್ರಗಳ ನಡುವೆ ನೇರ ಪ್ರಸರಣವನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ, ಬಹು-ಹಂಚಿಕೆ ಗುಂಪು ಅನುಮತಿ ಹೋಸ್ಟಿಂಗ್, ಬೇಡಿಕೆಯ ಮೇರೆಗೆ ಉಪ ಡೈರೆಕ್ಟರಿಗಳ ಬಹು ಆಯ್ಕೆ, ಮಿಲಿಸೆಕೆಂಡ್-ಮಟ್ಟದ ನೈಜ-ಸಮಯದ ಬಹು-ಮೂಲ ಸಿಂಕ್ರೊನೈಸೇಶನ್ ಮತ್ತು P.2P.

## ಸ್ಥಾಪಿಸಿ

### ವಿಧಾನ 1: ಸರಕು ಸ್ಥಾಪನೆ

```bash
cargo install sync0
```

### ವಿಧಾನ 2: ಪೂರ್ವ ಕಂಪೈಲ್ ಮಾಡಿದ ಬೈನರಿಗಳನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡಿ

ಸಿಸ್ಟಮ್‌ಗೆ ಸಂಬಂಧಿಸಿದ `.tar.xz` ಸಂಕುಚಿತ ಪ್ಯಾಕೇಜ್ ಅನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡಲು [GitHub ಬಿಡುಗಡೆಗಳು](https://github.com/webc-site/sync0/releases) ಗೆ ಹೋಗಿ (Linux, macOS, Windows, Android, iOS, FreeBSD ಅನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ), ಅನ್ಜಿಪ್ ಮಾಡಿ ಮತ್ತು `PATH` ಗೆ ಹಾಕಿ:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## ತ್ವರಿತವಾಗಿ ಪ್ರಾರಂಭಿಸಿ

### 1. ಎರಡು ಯಂತ್ರಗಳ ನಡುವೆ ಶೂನ್ಯ ಸಂರಚನೆ ನೇರ ಪ್ರಸರಣ (`send` / `recv`)

ಹಂಚಿಕೆ ಗುಂಪನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡುವ ಅಗತ್ಯವಿಲ್ಲ, ಹೆಚ್ಚಿನ ವೇಗದಲ್ಲಿ ಎರಡು ಯಂತ್ರಗಳ ನಡುವೆ ಫೈಲ್‌ಗಳು ಅಥವಾ ಡೈರೆಕ್ಟರಿಗಳನ್ನು ನೇರವಾಗಿ ವರ್ಗಾಯಿಸಿ:

```bash
# ಸ್ವೀಕರಿಸುವ ತುದಿಯು ಪೋರ್ಟ್‌ನಲ್ಲಿ ಆಲಿಸುತ್ತದೆ ಮತ್ತು ./backup ಗೆ ಬರೆಯುತ್ತದೆ
sync0 recv 0.0.0.0:9000 ./backup

# ಕಳುಹಿಸುವವರಿಂದ ನೇರ ಪ್ರಸರಣ (ಐಚ್ಛಿಕ --ಹೆಚ್ಚುವರಿ ಫೈಲ್‌ಗಳನ್ನು ಸ್ವಚ್ಛಗೊಳಿಸಲು ಕನ್ನಡಿಯನ್ನು ಅಳಿಸಿ, --ರೇಟ್ 50MB ವೇಗದ ಮಿತಿ)
sync0 send ./project 192.168.1.10:9000
```

### 2. ಪೋಸ್ಟ್ ಹಂಚಿಕೆ ಮತ್ತು ಬೇಡಿಕೆಯ ಮೇರೆಗೆ ಪುಲ್/ಅಪ್‌ಲೋಡ್ (`share` / `pull` / `push`)

```bash
# ಸರ್ವರ್: ಒಂದು ಸಾಲಿನ ಆದೇಶದೊಂದಿಗೆ ಹಂಚಿಕೆ ಗುಂಪನ್ನು ಪ್ರಕಟಿಸಿ (ಪ್ರಾರಂಭದ ನಂತರ IP-ಮುಕ್ತ iroh ನೋಡ್ ವಿಳಾಸವನ್ನು ಔಟ್ಪುಟ್ ಮಾಡಿ)
sync0 share dataset:./data

# ಕ್ಲೈಂಟ್: ಸಂಪೂರ್ಣ ಡೇಟಾಸೆಟ್ ಹಂಚಿಕೆ ಗುಂಪನ್ನು ಸ್ಥಳೀಯ ./local_data ಗೆ ಎಳೆಯಿರಿ
sync0 pull dataset:// ./local_data -p <ನೋಡ್ ವಿಳಾಸ>

# ಕ್ಲೈಂಟ್: ಬೇಡಿಕೆಯ ಮೇರೆಗೆ ಬಹು ಆಯ್ಕೆಗಳನ್ನು ಎಳೆಯಿರಿ (ನಿರ್ದಿಷ್ಟ ಏಕ ಫೈಲ್‌ಗಳು ಮತ್ತು ಉಪ ಡೈರೆಕ್ಟರಿಗಳನ್ನು ಮಾತ್ರ ಸಿಂಕ್ರೊನೈಸ್ ಮಾಡಿ)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <ನೋಡ್ ವಿಳಾಸ>

# ಗ್ರಾಹಕ: ಅಧಿಕೃತ ಹಂಚಿಕೆ ಗುಂಪುಗಳಿಗೆ ಫೈಲ್‌ಗಳು ಅಥವಾ ಡೈರೆಕ್ಟರಿಗಳನ್ನು ಅಪ್‌ಲೋಡ್ ಮಾಡಿ
sync0 ಪುಶ್ ಡೇಟಾಸೆಟ್://releases/v1 ./build_output -p <ನೋಡ್ ವಿಳಾಸ>
```

### 3. ನೈಜ-ಸಮಯದ ಚಂದಾದಾರಿಕೆ ಸೀಡಿಂಗ್ ಮತ್ತು ಬಹು-ಯಂತ್ರ ದ್ವಿಮುಖ ಸಿಂಕ್ರೊನೈಸೇಶನ್ (`sub` / `group`)

ದೀರ್ಘ ಸಂಪರ್ಕವನ್ನು ಸ್ಥಾಪಿಸಿದ ನಂತರ, ಯಾವುದೇ ಫೈಲ್ **ಸೇರಿಸುವುದು, ಮಾರ್ಪಡಿಸುವುದು, ಅಳಿಸುವುದು, ಅನುಮತಿಗಳನ್ನು ಬದಲಾಯಿಸುವುದು ಅಥವಾ ಮಾರ್ಪಾಡು ಮಾಡುವ ಸಮಯ** ರಿಮೋಟ್ ಎಂಡ್‌ನಲ್ಲಿ ಸಂಭವಿಸಿದರೆ, ಸ್ಥಳೀಯ ಡೈರೆಕ್ಟರಿಯನ್ನು ನೈಜ ಸಮಯದಲ್ಲಿ ಮಿಲಿಸೆಕೆಂಡ್‌ಗಳಲ್ಲಿ ಸಿಂಕ್ರೊನಸ್ ಆಗಿ ನವೀಕರಿಸಲಾಗುತ್ತದೆ (ಹೊಸ/ಮಾರ್ಪಡಿಸಿದ ದೊಡ್ಡ ಫೈಲ್‌ಗಳು ವ್ಯತ್ಯಾಸ ಬ್ಲಾಕ್‌ಗಳನ್ನು ಮಾತ್ರ ಎಳೆಯುತ್ತವೆ ಮತ್ತು ಅವುಗಳನ್ನು ಸ್ಥಳದಲ್ಲಿ ನವೀಕರಿಸುತ್ತವೆ, ಫೈಲ್‌ಗಳನ್ನು ಅಳಿಸುತ್ತದೆ ನೇರವಾಗಿ ಬ್ಲಾಕ್ಗಳು):

- **`sync0 sub`(ಒನ್-ವೇ ರಿಯಲ್-ಟೈಮ್ ಮಿರರಿಂಗ್ + ಸ್ವಯಂಚಾಲಿತ ಸೀಡಿಂಗ್)**: ಸ್ಥಳೀಯ ನೈಜ-ಸಮಯವು ಹಂಚಿಕೆಯ ಅಂತ್ಯದ ಸೇರ್ಪಡೆಗಳು, ಅಳಿಸುವಿಕೆಗಳು ಮತ್ತು ಮಾರ್ಪಾಡುಗಳನ್ನು ಅನುಸರಿಸುತ್ತದೆ ಮತ್ತು ಇತರ ಎಳೆಯುವ ನೋಡ್‌ಗಳಿಗೆ ಏಕಕಾಲೀನ ವೇಗವರ್ಧಕವನ್ನು ಒದಗಿಸಲು ಸ್ವಯಂಚಾಲಿತವಾಗಿ P2P ಸೀಡ್ ಮೂಲವಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.
- **`sync0 group`(ಮಲ್ಟಿ-ಮೆಷಿನ್ ಪೀರ್-ಟು-ಪೀರ್ ಟು-ವೇ ನೈಜ-ಸಮಯದ ಸಿಂಕ್ರೊನೈಸೇಶನ್)**: ಗುಂಪಿನಲ್ಲಿ ಯಾವುದೇ ಗಣಕದಲ್ಲಿ ಫೈಲ್‌ಗಳನ್ನು ಸೇರಿಸಿದರೆ, ಅಳಿಸಿದರೆ ಅಥವಾ ಮಾರ್ಪಡಿಸಿದರೆ, ಎಲ್ಲಾ ಇತರ ಆನ್‌ಲೈನ್ ನೋಡ್‌ಗಳನ್ನು ನೈಜ ಸಮಯದಲ್ಲಿ ಸಿಂಕ್ರೊನಸ್ ಆಗಿ ನವೀಕರಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಪರಸ್ಪರ ಬೀಜಗಳಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ.

```bash
# ಸಂಪೂರ್ಣ ಹಂಚಿಕೆ ಗುಂಪಿಗೆ ಚಂದಾದಾರರಾಗಿ: ರಿಮೋಟ್ ಸೇರ್ಪಡೆಗಳು, ಅಳಿಸುವಿಕೆಗಳು ಮತ್ತು ಮಾರ್ಪಾಡುಗಳನ್ನು ನೈಜ ಸಮಯದಲ್ಲಿ ಸ್ಥಳೀಯವಾಗಿ ಸಿಂಕ್ರೊನೈಸ್ ಮಾಡಲಾಗುತ್ತದೆ ಮತ್ತು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸೀಡ್ ಮಾಡಲಾಗುತ್ತದೆ
sync0 ಉಪ ಡೇಟಾಸೆಟ್:// ./local_mirror -p <ನೋಡ್ ವಿಳಾಸ>

# ಬೇಡಿಕೆಯ ಬಹು-ಆಯ್ಕೆಯ ಚಂದಾದಾರಿಕೆ: ನೈಜ ಸಮಯದಲ್ಲಿ ನಿರ್ದಿಷ್ಟಪಡಿಸಿದ ಏಕ ಫೈಲ್‌ಗಳು ಮತ್ತು ಉಪ ಡೈರೆಕ್ಟರಿಗಳನ್ನು ಮಾತ್ರ ಸಿಂಕ್ರೊನೈಸ್ ಮಾಡಿ ಮತ್ತು ಬೀಜ ಮಾಡಿ
sync0 ಉಪ ಡೇಟಾಸೆಟ್://models/llama.onnx,configs ./local_mirror -p <ನೋಡ್ ವಿಳಾಸ>

# ಬಹು-ಯಂತ್ರ ಪೀರ್ ಗುಂಪು ಎರಡು-ಮಾರ್ಗ ನೈಜ-ಸಮಯದ ಸಿಂಕ್ರೊನೈಸೇಶನ್ (ಪೂರ್ಣ ಅಥವಾ ಅಲ್ಪವಿರಾಮ ಬಹು-ಆಯ್ಕೆ ಮಾರ್ಗಗಳನ್ನು ಸಹ ಬೆಂಬಲಿಸುತ್ತದೆ)
sync0 group team-docs:// ./docs -p <ನೋಡ್ ವಿಳಾಸ>
```

### 4. ತಂಡದ ಬಹು-ಹಂಚಿಕೆ ಗುಂಪು ಮತ್ತು ಸದಸ್ಯರ ಅನುಮತಿ ಕಾನ್ಫಿಗರೇಶನ್ (`.nt` ಕಾನ್ಫಿಗರೇಶನ್)

ಡೀಫಾಲ್ಟ್ ಕಾನ್ಫಿಗರೇಶನ್ ಡೈರೆಕ್ಟರಿಯು `~/.config/sync0` ಆಗಿದೆ (`-c <directory>` ಮೂಲಕ ಬದಲಾಯಿಸಬಹುದು), ಕನಿಷ್ಠವಾದ [NestedText](https://nestedtext.org) (`.nt`) ಫಾರ್ಮ್ಯಾಟ್ ಬಳಸಿ:
- **ಸಾರ್ವಜನಿಕ ನೆಟ್‌ವರ್ಕ್ ಓದುವಿಕೆಯನ್ನು ನಿರ್ಬಂಧಿಸುವುದನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ (ಅಧಿಕೃತ ಬಳಕೆದಾರರು ಮಾತ್ರ ಓದಬಹುದು)**: ಹಂಚಿಕೊಳ್ಳುವ ಗುಂಪನ್ನು `users:` ಸದಸ್ಯರ ಪಟ್ಟಿಯೊಂದಿಗೆ ಕಾನ್ಫಿಗರ್ ಮಾಡುವವರೆಗೆ (ಅಥವಾ ಆಜ್ಞಾ ಸಾಲಿನ `--allow-r` / `--allow-rw` / `--allow-w` / `--auth` ಅನ್ನು ನಿರ್ದಿಷ್ಟಪಡಿಸುತ್ತದೆ, ಅದು ಸಂಪೂರ್ಣವಾಗಿ ಖಾಸಗಿಯಾಗಿ ಆನ್ ಆಗುತ್ತದೆ (ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಆನ್ ಆಗಿದೆ). id="6">)** ಮತ್ತು ಸಾರ್ವಜನಿಕ ನೆಟ್‌ವರ್ಕ್ ಅನಾಮಧೇಯ ನೋಡ್ ಎಣಿಕೆ ಅಥವಾ ಓದುವಿಕೆಯನ್ನು ನಿಷೇಧಿಸುತ್ತದೆ, ಮತ್ತು P2P ಸೀಡಿಂಗ್ ನೋಡ್‌ಗಳಿಗೆ ಚಂದಾದಾರರಾಗುವುದು ಸಹ ಶ್ವೇತಪಟ್ಟಿಯನ್ನು ಏಕಕಾಲದಲ್ಲಿ ಆನುವಂಶಿಕವಾಗಿ ಪಡೆಯುತ್ತದೆ, ಇದು ಅಧಿಕೃತ ಬಳಕೆದಾರರಿಗೆ ಮಾತ್ರ ಓದಲು ಅನುವು ಮಾಡಿಕೊಡುತ್ತದೆ; `users` ನೊಂದಿಗೆ ಕಾನ್ಫಿಗರ್ ಮಾಡದಿರುವ ಹಂಚಿಕೆ ಗುಂಪುಗಳು ಸಾರ್ವಜನಿಕವಾಗಿರುತ್ತವೆ ಮತ್ತು ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಓದಲು ಮಾತ್ರ (ನೀವು ಸಾರ್ವಜನಿಕ ಮತ್ತು ಓದಲು-ಮಾತ್ರ ಮತ್ತು ನಿರ್ದಿಷ್ಟಪಡಿಸಿದ ಸದಸ್ಯರಿಗೆ ಮಾತ್ರ ಅಪ್‌ಲೋಡ್‌ಗಳಿಗೆ ತೆರೆಯಲು ಬಯಸಿದರೆ, ನೀವು ಸ್ಪಷ್ಟವಾಗಿ `auth: false` ಅನ್ನು ಹೊಂದಿಸಬಹುದು).
- **ಉತ್ತಮವಾದ ಓದು-ಬರಹ ಮತ್ತು ಉಪ ಡೈರೆಕ್ಟರಿ ವಿತರಣಾ ಅನುಮತಿಗಳು**: ಸದಸ್ಯರು ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಓದಲು-ಮಾತ್ರ (`r` ಅನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಬರೆಯುವ ಅಗತ್ಯವಿಲ್ಲ), ಮತ್ತು ಬೆಂಬಲ `r` (ಓದಲು-ಮಾತ್ರ), `w` (ಡ್ರಾಪ್ ಬಾಕ್ಸ್‌ಗೆ ಮಾತ್ರ ಬರೆಯಿರಿ ಮತ್ತು <b id-4"> ಮತ್ತು <b id-4"> rite (read-4) id="5"> (ಅಪ್‌ಲೋಡ್ ಮಾಡಲು ಅನುಮತಿಸಲಾದ ಉಪ ಡೈರೆಕ್ಟರಿ ಪೂರ್ವಪ್ರತ್ಯಯವನ್ನು ಮಿತಿಗೊಳಿಸಿ).

**ಸದಸ್ಯ ಕಾನ್ಫಿಗರೇಶನ್ ಉದಾಹರಣೆ (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (ಡೀಫಾಲ್ಟ್ ಓದಲು-ಮಾತ್ರ, ವೇಗ ಮಿತಿ 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (ಓದಲು ಮತ್ತು ಬರೆಯಲು ಅನುಮತಿಗಳು, ನಿರ್ದಿಷ್ಟಪಡಿಸಿದ ಉಪ ಡೈರೆಕ್ಟರಿಗೆ ಮಾತ್ರ ಅಪ್‌ಲೋಡ್ ಮಾಡಲು ಅನುಮತಿಸಲಾಗಿದೆ)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (ಬರೆಯುವ ಅನುಮತಿಯನ್ನು ಮಾತ್ರ ಬರೆಯಿರಿ, ಓದುವುದನ್ನು ನಿಷೇಧಿಸಲಾಗಿದೆ)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**ಹಂಚಿಕೆ ಗುಂಪು ಕಾನ್ಫಿಗರೇಶನ್ ಉದಾಹರಣೆ (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # ಕಾನ್ಫಿಗರ್ ಮಾಡದ ಬಳಕೆದಾರರು: ಡೀಫಾಲ್ಟ್ ಸಾರ್ವಜನಿಕ ನೆಟ್‌ವರ್ಕ್ ಓದಲು-ಮಾತ್ರ
  dataset:
    path: ./data
    rate: 50MB

  # ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಬಳಕೆದಾರರು: ಸಾರ್ವಜನಿಕ ನೆಟ್‌ವರ್ಕ್ ಓದುವಿಕೆಯನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ನಿರ್ಬಂಧಿಸಿ (ಆಲಿಸ್ ಮತ್ತು ಬಾಬ್ ಮಾತ್ರ ಓದಬಹುದು, ಚಾರ್ಲಿ ಮಾತ್ರ ತಲುಪಿಸಬಹುದು ಮತ್ತು ಅಪ್‌ಲೋಡ್ ಮಾಡಬಹುದು)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

ಸೇವೆಯನ್ನು ಪ್ರಾರಂಭಿಸಿ (ಕಾನ್ಫಿಗರೇಶನ್ ಫೈಲ್ ಅನ್ನು ಲೋಡ್ ಮಾಡಿ ಅಥವಾ ಸಾರ್ವಜನಿಕ ನೆಟ್‌ವರ್ಕ್ ಓದುವಿಕೆಯನ್ನು ನಿರ್ಬಂಧಿಸಲು ಮತ್ತು ಸದಸ್ಯರನ್ನು ಅಧಿಕೃತಗೊಳಿಸಲು ಆಜ್ಞಾ ಸಾಲಿನ ನಿಯತಾಂಕಗಳನ್ನು ನೇರವಾಗಿ ಬಳಸಿ):

```bash
# ಪ್ರಾರಂಭಿಸಲು ~/.config/sync0/config.nt ಅನ್ನು ಲೋಡ್ ಮಾಡಿ
sync0 share --region SHA

# ಅಥವಾ ಶುದ್ಧ ಆಜ್ಞಾ ಸಾಲಿನ ಮೂಲಕ ಖಾಸಗಿ ಹಂಚಿಕೆ ಗುಂಪನ್ನು ಪ್ರಕಟಿಸಿ (ಸಾರ್ವಜನಿಕ ನೆಟ್‌ವರ್ಕ್ ಓದುವಿಕೆಯನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ನಿರ್ಬಂಧಿಸಲು --ಅನುಮತಿಸಿ-* ಅನ್ನು ನಿರ್ದಿಷ್ಟಪಡಿಸಿ ಮತ್ತು ಅಧಿಕೃತ ಬಳಕೆದಾರರು ಮಾತ್ರ ಅದನ್ನು ಪ್ರವೇಶಿಸಬಹುದು)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### ಕ್ರಾಸ್-ಕಾಂಟಿನೆಂಟಲ್ WAN ನಿಜವಾದ ಮಾಪನ (ಹೋಲಿಕೆ `rsync`)

### ಪ್ರಮುಖ ಉತ್ಪನ್ನ ವೈಶಿಷ್ಟ್ಯಗಳು

- **ಸಾರ್ವಜನಿಕ ಕೀ ವಿಳಾಸ ಸ್ವಯಂಚಾಲಿತ ರಂಧ್ರ ಪಂಚಿಂಗ್**: ಕೇಂದ್ರ ಸರ್ವರ್ ಮತ್ತು ಸಾರ್ವಜನಿಕ ನೆಟ್‌ವರ್ಕ್ ವಿಳಾಸದ ಅಗತ್ಯವಿಲ್ಲ, ವಿತರಿಸಿದ ನೆಟ್‌ವರ್ಕ್ ಸಾರ್ವಜನಿಕ ಕೀ ವಿಳಾಸದ ಆಧಾರದ ಮೇಲೆ ಸ್ವಯಂಚಾಲಿತ NAT ರಂಧ್ರ ಪಂಚಿಂಗ್.
- **ಮಿಲಿಸೆಕೆಂಡ್-ಮಟ್ಟದ ನೈಜ-ಸಮಯದ ಸಿಂಕ್ರೊನೈಸೇಶನ್ ಮತ್ತು ಮೆಟಾಡೇಟಾ ಜಾಗೃತಿ**: ಸ್ಥಳೀಯ ಫೈಲ್ ಈವೆಂಟ್ ಮಾನಿಟರಿಂಗ್ (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), ಫೈಲ್ ಸೇರ್ಪಡೆಗಳ ನೈಜ-ಸಮಯದ ಪುಶ್, ಅಳಿಸುವಿಕೆಗಳು, POSIX ಅನುಮತಿಗಳು (`mode`) ಮತ್ತು millisecond (`mode`) ಮತ್ತು millisecond; ಅನುಮತಿಗಳು ಅಥವಾ ಸಮಯವನ್ನು ಮಾತ್ರ ಮಾರ್ಪಡಿಸಿದಾಗ ಶೂನ್ಯ ಡೇಟಾ ಪ್ರಸರಣವನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತದೆ.
- **BT-ಶೈಲಿಯ ಏಕಕಾಲಿಕ ಡೌನ್‌ಲೋಡ್ ಮತ್ತು ಅಪ್‌ಲೋಡ್ ಮತ್ತು ಪ್ರಾದೇಶಿಕ ಸಂಬಂಧದ ವೇಳಾಪಟ್ಟಿ**: ಡೌನ್‌ಲೋಡ್ ಮಾಡುವ ನೋಡ್ ಪೂರ್ಣ ಮೊತ್ತವನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡಲು ಕಾಯುವ ಅಗತ್ಯವಿಲ್ಲ. 128-ಬಿಟ್ ಹ್ಯಾಶ್ ಚೆಕ್ ಅನ್ನು ರವಾನಿಸಿದ ಎಲ್ಲಾ ಬ್ಲಾಕ್ ಮಧ್ಯಂತರಗಳು (`Op::Have`) ಇತರ ನೋಡ್‌ಗಳು ಏಕಕಾಲದಲ್ಲಿ ಎಳೆಯಲು ಮೆಮೊರಿ/ತಾತ್ಕಾಲಿಕ ಪೂಲ್‌ನಲ್ಲಿ ತಕ್ಷಣವೇ ಲಾಕ್ ಆಗುತ್ತವೆ. ಡೈನಾಮಿಕ್ PEX ನೋಡ್ ವಿನಿಮಯ ಮತ್ತು ನಿಧಾನ ನೋಡ್ ಅರ್ಧ ಪೂರ್ವಭಾವಿ (ವರ್ಕ್-ಸ್ಟೀಲಿಂಗ್) ಜೊತೆಗೆ, ಕ್ಲಸ್ಟರ್ ಥ್ರೋಪುಟ್ ಅನ್ನು ಗರಿಷ್ಠಗೊಳಿಸಲಾಗುತ್ತದೆ.
- **ವಿರೋಧಿ-ದುರುದ್ದೇಶಪೂರಿತ ನೋಡ್ ಟ್ಯಾಂಪರಿಂಗ್ ಮತ್ತು ಕ್ಲಸ್ಟರ್ ವಿಷದ ಪ್ರತಿರಕ್ಷೆ**: ಅಧಿಕೃತ ಮೂಲ ಪಟ್ಟಿ `root_hash` ಸ್ವಯಂ-ಸ್ಥಿರವಾದ ಲಾಕ್ + ಕಡ್ಡಾಯ ಹಾರ್ಡ್‌ವೇರ್ ವೇಗವರ್ಧನೆ `gxhash128` ಪ್ರತಿ ಬ್ಲಾಕ್ ಅನ್ನು ಡಿಸ್ಕ್‌ನಲ್ಲಿ ಇರಿಸುವ ಮೊದಲು ಮತ್ತು ಬಾಹ್ಯವಾಗಿ ಸೀಡ್ ಮಾಡುವ ಪರಿಶೀಲನೆ; ಟ್ಯಾಂಪರ್ಡ್ ಬ್ಲಾಕ್ ಕಂಡುಬಂದರೆ, ಮಿಲಿಸೆಕೆಂಡ್-ಮಟ್ಟದ ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ ದುರುದ್ದೇಶಪೂರಿತ ನೋಡ್ ಅನ್ನು ಬ್ಲ್ಯಾಕ್ಔಟ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಪ್ರಾಮಾಣಿಕ ಮೂಲದಿಂದ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಚೇತರಿಸಿಕೊಳ್ಳುತ್ತದೆ.
- **ಫಾಸ್ಟ್‌ಸಿಡಿಸಿ ಇನ್-ಸಿಟು ಇನ್‌ಕ್ರಿಮೆಂಟ್ ಮತ್ತು ಸಣ್ಣ ಫೈಲ್ ಒಟ್ಟುಗೂಡಿಸುವಿಕೆ**: ದೊಡ್ಡ ಫೈಲ್‌ಗಳ ಭಾಗಶಃ ಮಾರ್ಪಾಡುಗಾಗಿ ಡಿಫರೆನ್ಷಿಯಲ್ ಬ್ಲಾಕ್‌ಗಳನ್ನು ಮಾತ್ರ ವರ್ಗಾಯಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಡಿಸ್ಕ್‌ನಲ್ಲಿ ಇರಿಸಲಾಗುತ್ತದೆ; ಬೃಹತ್ ಸಣ್ಣ ಫೈಲ್ ಮೆಮೊರಿ ಪ್ಯಾಕೇಜಿಂಗ್ ಮತ್ತು ಪೂರ್ವಪ್ರತ್ಯಯ ಡಿಫರೆನ್ಷಿಯಲ್ ಕಂಪ್ರೆಷನ್ ಫೈಲ್-ಬೈ-ಫೈಲ್ ರೌಂಡ್-ಟ್ರಿಪ್ ಓವರ್ಹೆಡ್ ಅನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ.
- **ವಿದ್ಯುತ್ ಕಡಿತದ ನಂತರ ಸ್ವಯಂ-ಗುಣಪಡಿಸುವಿಕೆ ಮತ್ತು ಮರುಪ್ರಾರಂಭದ ನಂತರ ಪುನರಾರಂಭ**: ಸೀಡಿಂಗ್ ಸ್ಥಿತಿ ಮತ್ತು ಫೈಲ್ ಪಟ್ಟಿಯನ್ನು ಮುಂದುವರಿಸಲು Redis-ರೀತಿಯ RDB + AOF ಹೈಬ್ರಿಡ್ ಸ್ವರೂಪವನ್ನು (`.s0_subs.bin`) ಬಳಸಲಾಗುತ್ತದೆ, ದೈನಂದಿನ ಬದಲಾವಣೆಗಳನ್ನು ಮೈಕ್ರೋಸೆಕೆಂಡ್‌ಗಳಲ್ಲಿ ಸೇರಿಸಲಾಗುತ್ತದೆ ಮತ್ತು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಪುನಃ ಬರೆಯಲಾಗುತ್ತದೆ ಮತ್ತು ನಿಯಮಿತವಾಗಿ ಆಯೋಜಿಸಲಾಗುತ್ತದೆ. ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿದ ನಂತರ, ಆಫ್‌ಲೈನ್ ಬದಲಾವಣೆಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸೀಡಿಂಗ್ ನೋಡ್‌ಗೆ ತಳ್ಳಲಾಗುತ್ತದೆ.

## ತಾಂತ್ರಿಕ ವಾಸ್ತುಶಿಲ್ಪ ಮತ್ತು ದಾಖಲಾತಿ

- **ಡ್ಯುಯಲ್ ಪ್ಲೇನ್ ಡಿಕೌಪ್ಲಿಂಗ್ ಪ್ರೋಟೋಕಾಲ್**:
  - **ನಿಯಂತ್ರಣ ಮತ್ತು ನೈಜ-ಸಮಯದ ಬದಲಾವಣೆ ಮೇಲ್ಮೈ (`iroh` QUIC / TCP, ಮೊದಲ ಬೈಟ್ `PROTO_VERSION` ಆವೃತ್ತಿ ಹ್ಯಾಂಡ್‌ಶೇಕ್) **: Ed25519 ವ್ಯಾಪಾರ ಕಾರ್ಡ್ ಪರಿಶೀಲನೆ, ಅನುಮತಿ ಪರಿಶೀಲನೆ, ಸ್ವಾರ್ಮ್ ಸೀಡ್ ಅನ್ವೇಷಣೆ ಮತ್ತು `u64::MAX` ಮಟ್ಟದ ಮಾಸ್ ಚೇಂಜ್> ಸ್ಟ್ರೀಮಿಂಗ್ ಬ್ಯಾಚಿಂಗ್ ಮತ್ತು <b>comid batched" 4 ಗೆ ಬೆಂಬಲ ನೈಜ-ಸಮಯದ ಪುಶ್ (`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` ಮೂರು ಮೂಲಗಳು).
  - **ಡೇಟಾ ವಿತರಣಾ ಮೇಲ್ಮೈ (ಸ್ಥಳೀಯ UDP + `compio` ಅಸಮಕಾಲಿಕ I/O) **: 20B ಕಾಂಪ್ಯಾಕ್ಟ್ ಹೆಡರ್, 18B TACK ನಿಯತಕಾಲಿಕ ಪ್ರತಿಕ್ರಿಯೆ, BBRv3/Copa ಹೈಬ್ರಿಡ್ ದಟ್ಟಣೆ ನಿಯಂತ್ರಣ, RACK-TLP ಪ್ಯಾಕೆಟ್ ನಷ್ಟ ಚೇತರಿಕೆ, ಮೊದಲ-ಬ್ಲಾಕ್ ಝ್ಸ್ಟ್‌ಟ್ರೊಪಿ ಮತ್ತು ಸಂಕೋಚನದ ಮೂಲಕ ಅಡಾಪ್ಶನ್ id="2"> ಎಂಡ್-ಟು-ಎಂಡ್ ಪರಿಶೀಲನೆಯನ್ನು ನಿರ್ಬಂಧಿಸಿ.
