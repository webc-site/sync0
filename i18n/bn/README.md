# sync0

`sync0` হল একটি বিকেন্দ্রীভূত P2P ফাইল শেয়ারিং, রিয়েল-টাইম সিঙ্ক্রোনাইজেশন এবং মাল্টি-সোর্স ডিস্ট্রিবিউশন টুল যা `rsync` প্রতিস্থাপন করতে ব্যবহৃত হয় - ট্রান্সকন্টিনেন্টাল WAN-এর পরিমাপিত গতি `rsync`-এর **5.89×** (একক বিন্দু জ্যামিতিক গড় গতি **2.67 পিএস-উৎস গড় গতি **2.67xal**) পর্যন্ত **3.16×**), এবং ট্রান্সওসেনিক হাই-লেটেন্সি লিঙ্ক P2P ত্বরণ **7.68×** পর্যন্ত (সম্পূর্ণ-লিঙ্ক 24-সিনেরিও ব্যাপক জ্যামিতিক গড় গতি **2.56×**)।

প্রতিটি মেশিন একটি সার্ভার এবং একটি ক্লায়েন্ট উভয়ই: একটি কেন্দ্রীয় সার্ভার বা একটি পাবলিক নেটওয়ার্ক ঠিকানার কোন প্রয়োজন নেই, স্বয়ংক্রিয় হোল পাঞ্চিং বিতরণ করা নেটওয়ার্ক পাবলিক কী ঠিকানার উপর ভিত্তি করে, এবং এটি দুটি মেশিনের মধ্যে সরাসরি ট্রান্সমিশন সমর্থন করে, মাল্টি-শেয়ারিং গ্রুপ অনুমতি হোস্টিং, চাহিদা অনুযায়ী সাবডিরেক্টরির একাধিক নির্বাচন, মিলিসেকেন্ড-লেভেল রিয়েল-টাইম ইনক্রিমেন্টাল অ্যাকরিমেন্টাল অ্যাকসেল 2 সিঙ্ক এবং পিসি 2 সিঙ্ক।

## ইনস্টল করুন

### পদ্ধতি 1: কার্গো ইনস্টলেশন

```bash
cargo install sync0
```

### পদ্ধতি 2: প্রি-কম্পাইল করা বাইনারি ডাউনলোড করুন

সিস্টেমের সাথে সম্পর্কিত `.tar.xz` সংকুচিত প্যাকেজ ডাউনলোড করতে [GitHub Releases](https://github.com/webc-site/sync0/releases) এ যান (লিনাক্স, macOS, Windows, Android, iOS, FreeBSD সমর্থন করে), আনজিপ করুন এবং `PATH` এ রাখুন:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## দ্রুত শুরু করুন

### 1. দুটি মেশিনের মধ্যে জিরো-কনফিগারেশন সরাসরি ট্রান্সমিশন (`send` / `recv`)

একটি শেয়ারিং গ্রুপ কনফিগার করার প্রয়োজন নেই, উচ্চ গতিতে দুটি মেশিনের মধ্যে সরাসরি ফাইল বা ডিরেক্টরি স্থানান্তর করুন:

```bash
# রিসিভিং এন্ড পোর্টে শোনে এবং ./backup-এ লেখে
sync0 recv 0.0.0.0:9000 ./backup

# প্রেরকের কাছ থেকে সরাসরি ট্রান্সমিশন (ঐচ্ছিক --অতিরিক্ত ফাইল পরিষ্কার করার জন্য মিরর মুছে ফেলুন, --রেট 50MB গতি সীমা)
sync0 send ./project 192.168.1.10:9000
```

### 2. পোস্ট শেয়ারিং এবং অন-ডিমান্ড টান/আপলোড (`share` / `pull` / `push`)

```bash
# সার্ভার: কমান্ডের এক লাইন দিয়ে শেয়ারিং গ্রুপ প্রকাশ করুন (স্টার্টআপের পরে আইপি-মুক্ত ইরো নোড ঠিকানা আউটপুট করুন)
sync0 share dataset:./data

# ক্লায়েন্ট: সমগ্র ডেটাসেট শেয়ারিং গ্রুপটিকে স্থানীয় ./local_data-এ টেনে আনুন
sync0 pull dataset:// ./local_data -p <নোড ঠিকানা>

# ক্লায়েন্ট: চাহিদা অনুযায়ী একাধিক নির্বাচন টানুন (শুধুমাত্র নির্দিষ্ট একক ফাইল এবং সাবডিরেক্টরিগুলি সিঙ্ক্রোনাইজ করুন)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <নোড ঠিকানা>

# ক্লায়েন্ট: অনুমোদিত শেয়ারিং গ্রুপে ফাইল বা ডিরেক্টরি আপলোড করুন
sync0 push dataset://releases/v1 ./build_output -p <নোড ঠিকানা>
```

### 3. রিয়েল-টাইম সাবস্ক্রিপশন সিডিং এবং মাল্টি-মেশিন টু-ওয়ে সিঙ্ক্রোনাইজেশন (`sub` / `group`)

একটি দীর্ঘ সংযোগ স্থাপনের পর, দূরবর্তী প্রান্তে কোনো ফাইল **সংযোজন, পরিবর্তন, মুছে ফেলা, অনুমতি পরিবর্তন বা পরিবর্তনের সময়** ঘটলে, স্থানীয় ডিরেক্টরিটি রিয়েল টাইমে মিলিসেকেন্ডে সিঙ্ক্রোনাসভাবে আপডেট করা হবে (নতুন/পরিবর্তিত বড় ফাইলগুলি শুধুমাত্র পার্থক্য ব্লকগুলিকে টেনে আনবে এবং সেগুলিকে আপডেট করবে, ফাইলগুলিকে স্বয়ংক্রিয়ভাবে পরিষ্কার করবে এবং শুধুমাত্র স্থানীয় ফাইলগুলিকে ক্লিন আপ করবে এবং শুধুমাত্র ডিরেক্টর ফাইলগুলিকে পরিবর্তন করবে। সরাসরি ব্লক):

- **`sync0 sub`(ওয়ান-ওয়ে রিয়েল-টাইম মিররিং + স্বয়ংক্রিয় সিডিং)**: স্থানীয় রিয়েল-টাইম শেয়ারিং এন্ডের সংযোজন, মুছে ফেলা এবং পরিবর্তনগুলি অনুসরণ করে এবং স্বয়ংক্রিয়ভাবে অন্যান্য পুলিং নোডগুলির জন্য সমবর্তী ত্বরণ প্রদানের জন্য একটি P2P বীজ উত্স হিসাবে কাজ করে৷
- **`sync0 group`(মাল্টি-মেশিন পিয়ার-টু-পিয়ার টু-ওয়ে রিয়েল-টাইম সিঙ্ক্রোনাইজেশন)**: যদি গ্রুপের কোনো মেশিনে ফাইলগুলি যোগ করা, মুছে ফেলা বা পরিবর্তন করা হয়, তবে অন্য সমস্ত অনলাইন নোডগুলি রিয়েল টাইমে সিঙ্ক্রোনাস আপডেট করা হবে এবং একে অপরের জন্য বীজ হিসাবে পরিবেশন করা হবে।

```bash
# সমগ্র শেয়ারিং গ্রুপে সদস্যতা নিন: দূরবর্তী সংযোজন, মুছে ফেলা এবং পরিবর্তনগুলি স্থানীয়ভাবে রিয়েল টাইমে সিঙ্ক্রোনাইজ করা হয় এবং স্বয়ংক্রিয়ভাবে বীজ হয়
sync0 সাব ডেটাসেট:// ./local_mirror -p <নোড ঠিকানা>

# অন-ডিমান্ড মাল্টি-সিলেক্ট সাবস্ক্রিপশন: রিয়েল টাইমে শুধুমাত্র সিঙ্ক্রোনাইজ করুন এবং নির্দিষ্ট একক ফাইল এবং সাবডিরেক্টরি বীজ করুন
sync0 সাব ডেটাসেট://models/llama.onnx,configs ./local_mirror -p <নোড ঠিকানা>

# মাল্টি-মেশিন পিয়ার গ্রুপ টু-ওয়ে রিয়েল-টাইম সিঙ্ক্রোনাইজেশন (এছাড়াও পূর্ণ বা কমা মাল্টি-সিলেক্ট পাথ সমর্থন করে)
sync0 group team-docs:// ./docs -p <node address>
```

### 4. টিম মাল্টি-শেয়ারিং গ্রুপ এবং সদস্যদের অনুমতি কনফিগারেশন (`.nt` কনফিগারেশন)

ডিফল্ট কনফিগারেশন ডিরেক্টরি হল `~/.config/sync0` (`-c <directory>` এর মাধ্যমে সুইচ করা যেতে পারে), মিনিমালিস্ট [NestedText](https://nestedtext.org) (`.nt`) ফর্ম্যাট ব্যবহার করে:
- **পাবলিক নেটওয়ার্ক রিডিং সীমিত করা সমর্থন করে (শুধুমাত্র অনুমোদিত ব্যবহারকারীরা পড়তে পারেন)**: যতক্ষণ শেয়ারিং গ্রুপটি `users:` সদস্য তালিকার সাথে কনফিগার করা থাকে (অথবা কমান্ড লাইন `--allow-r` / `--allow-rw` / `--allow-w` / `--auth` উল্লেখ করে), সিস্টেম ** স্বয়ংক্রিয়ভাবে চালু হয় এবং `--auth` <b> ** স্বয়ংক্রিয়ভাবে চালু হয়ে যায় পাবলিক নেটওয়ার্ক বেনামী নোড গণনা বা পড়া নিষিদ্ধ করে, এবং P2P সিডিং নোডগুলিতে সাবস্ক্রাইব করা একই সাথে সাদা তালিকার উত্তরাধিকারী হবে, শুধুমাত্র অনুমোদিত ব্যবহারকারীদের পড়তে অনুমতি দেবে; শেয়ারিং গোষ্ঠীগুলি যেগুলি `users` এর সাথে কনফিগার করা নেই সেগুলি ডিফল্টরূপে সর্বজনীন এবং শুধুমাত্র পঠনযোগ্য (যদি আপনি সর্বজনীন এবং শুধুমাত্র পঠনযোগ্য হতে চান এবং শুধুমাত্র নির্দিষ্ট সদস্যদের জন্য আপলোডের জন্য উন্মুক্ত করতে চান তবে আপনি স্পষ্টভাবে `auth: false` সেট করতে পারেন)।
- **সূক্ষ্মভাবে পড়া-লেখা এবং সাব-ডিরেক্টরি ডেলিভারি অনুমতি**: সদস্যরা ডিফল্টরূপে শুধুমাত্র পঠনযোগ্য (`r` স্পষ্টভাবে লেখার প্রয়োজন নেই), এবং সমর্থন `r` (শুধুমাত্র পঠনযোগ্য), `w` (শুধুমাত্র ড্রপ বক্সে লিখুন, পঠনযোগ্য নয়), `rw`> <b-id="4">> (5) সাবডিরেক্টরি উপসর্গ আপলোড করার জন্য অনুমোদিত)।

**সদস্য কনফিগারেশন উদাহরণ (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (ডিফল্ট শুধুমাত্র পঠন, গতি সীমা 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (পড়ুন এবং লেখার অনুমতি, শুধুমাত্র নির্দিষ্ট সাবডিরেক্টরিতে আপলোড করার অনুমতি)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (শুধুমাত্র বিতরণের অনুমতি লিখুন, পড়া নিষিদ্ধ)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

** শেয়ারিং গ্রুপ কনফিগারেশন উদাহরণ (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # কনফিগার করা ব্যবহারকারীরা নয়: ডিফল্ট পাবলিক নেটওয়ার্ক শুধুমাত্র পঠনযোগ্য
  dataset:
    path: ./data
    rate: 50MB

  # কনফিগার করা ব্যবহারকারী: স্বয়ংক্রিয়ভাবে পাবলিক নেটওয়ার্ক রিডিং সীমাবদ্ধ করুন (শুধুমাত্র এলিস এবং বব পড়তে পারে, চার্লি শুধুমাত্র বিতরণ এবং আপলোড করতে পারে)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

পরিষেবা শুরু করুন (কনফিগারেশন ফাইল লোড করুন বা সর্বজনীন নেটওয়ার্ক পড়া সীমাবদ্ধ করতে এবং সদস্যদের অনুমোদন করতে সরাসরি কমান্ড লাইন প্যারামিটার ব্যবহার করুন):

```bash
# শুরু করতে ~/.config/sync0/config.nt লোড করুন
sync0 share --region SHA

# অথবা বিশুদ্ধ কমান্ড লাইনের মাধ্যমে একটি ব্যক্তিগত শেয়ারিং গোষ্ঠী প্রকাশ করুন (পাবলিক নেটওয়ার্ক রিডিং স্বয়ংক্রিয়ভাবে সীমাবদ্ধ করতে --অনুমতি-* নির্দিষ্ট করুন এবং শুধুমাত্র অনুমোদিত ব্যবহারকারীরা এটি অ্যাক্সেস করতে পারবেন)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
```

### মূল পণ্য বৈশিষ্ট্য

- **পাবলিক কী অ্যাড্রেসিং স্বয়ংক্রিয় হোল পাঞ্চিং**: একটি কেন্দ্রীয় সার্ভার এবং পাবলিক নেটওয়ার্ক ঠিকানার প্রয়োজন নেই, বিতরণ করা নেটওয়ার্ক পাবলিক কী ঠিকানার উপর ভিত্তি করে স্বয়ংক্রিয় NAT হোল পাঞ্চিং।
- **মিলিসেকেন্ড-স্তরের রিয়েল-টাইম সিঙ্ক্রোনাইজেশন এবং মেটাডেটা সচেতনতা**: নেটিভ ফাইল ইভেন্ট মনিটরিং (`FSEvents` / `inotify` / `ReadDirectoryChangesW` এর উপর ভিত্তি করে, ফাইল সংযোজন, মুছে ফেলা, POSIX অনুমতি (`mode`) এবং মিলিসেকেন্ড-সময় (`mode`) এবং মিলিসেকেন্ড-সময় (5) এর রিয়েল-টাইম পুশ শূন্য ডেটা ব্লক ট্রান্সমিশন যখন শুধুমাত্র অনুমতি বা সময় পরিবর্তন করা হয়।
- **BT-শৈলী একযোগে ডাউনলোড এবং আপলোড এবং আঞ্চলিক অ্যাফিনিটি শিডিউলিং**: ডাউনলোডিং নোডকে সম্পূর্ণ পরিমাণ ডাউনলোড করার জন্য অপেক্ষা করতে হবে না। সমস্ত ব্লক ব্যবধান (`Op::Have`) যেগুলি 128-বিট হ্যাশ চেক পাস করেছে তা অবিলম্বে মেমরি/অস্থায়ী পুলে অন্যান্য নোডগুলিকে একযোগে টানতে লক করা হয়। ডাইনামিক PEX নোড এক্সচেঞ্জ এবং স্লো নোড হাফ প্রিম্পশন (ওয়ার্ক-স্টিলিং) সহ, ক্লাস্টার থ্রুপুট সর্বাধিক করা হয়।
- **অ্যান্টি-ম্যালিসিয়াস নোড টেম্পারিং এবং ক্লাস্টার পয়জনিং ইমিউনিটি**: প্রামাণিক উত্স তালিকা `root_hash` স্ব-সংগতিশীল লকিং + বাধ্যতামূলক হার্ডওয়্যার ত্বরণ `gxhash128` ডিস্কে প্রতিটি ব্লক স্থাপন করার আগে এবং বাহ্যিকভাবে বীজযুক্ত হওয়ার আগে ডাইজেস্ট যাচাইকরণ; যদি একটি টেম্পারড ব্লক পাওয়া যায়, মিলিসেকেন্ড-লেভেল সার্কিট ব্রেকার দূষিত নোডটিকে ব্ল্যাকআউট করবে এবং সৎ উৎস থেকে স্বয়ংক্রিয়ভাবে পুনরুদ্ধার করবে।
- **ফাস্টসিডিসি ইন-সিটু ইনক্রিমেন্ট এবং ছোট ফাইল অ্যাগ্রিগেশন**: বড় ফাইলের আংশিক পরিবর্তনের জন্য শুধুমাত্র ডিফারেনশিয়াল ব্লক স্থানান্তর করা হয় এবং ডিস্কে স্থাপন করা হয়; বিশাল ছোট ফাইল মেমরি প্যাকেজিং এবং প্রিফিক্স ডিফারেনশিয়াল কম্প্রেশন ফাইল-বাই-ফাইল রাউন্ড-ট্রিপ ওভারহেড দূর করে।
- **বিদ্যুত বিভ্রাটের পরে স্ব-নিরাময় এবং পুনরায় চালু করার পরে পুনরায় চালু করা**: রেডিস-এর মতো RDB + AOF হাইব্রিড ফরম্যাট (`.s0_subs.bin`) বীজের স্থিতি এবং ফাইল তালিকা বজায় রাখতে ব্যবহৃত হয়, দৈনিক পরিবর্তনগুলি মাইক্রোসেকেন্ডে যুক্ত করা হয়, এবং স্বয়ংক্রিয়ভাবে পুনরায় লিখিত এবং নিয়মিতভাবে সংগঠিত হয়। সার্ভার পুনরায় চালু হওয়ার পরে, অফলাইন পরিবর্তনগুলি স্বয়ংক্রিয়ভাবে সিডিং নোডে পুশ করা হয়।
