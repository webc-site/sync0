# sync0

`sync0`은 네트워크를 통해 파일을 전송하고, 디렉토리를 점진적으로 동기화하며, 동시에 여러 시스템에 데이터를 배포하기 위한 명령줄 도구입니다.

## 원래 디자인 의도

네트워크 지연 및 패킷 손실이 있는 교차 기계실, 국가 또는 환경에서 `rsync` 및 `scp`와 같은 도구는 대역폭 활용을 제한하는 단일 연결 시퀀스 확인을 기반으로 합니다. 여러 시스템이 동시에 동일한 서버에서 데이터를 가져오면 원본 서버 네트워크 카드가 쉽게 병목 현상을 일으킬 수 있습니다.

`sync0`의 목표는 두 가지 문제를 해결하는 것입니다.

1. 두 시스템 간의 파일 및 디렉터리 동기화가 전체 물리적 대역폭을 실행하도록 하고 파일이 부분적으로 수정된 경우에만 변경된 부분을 전송합니다.
2. 여러 시스템이 동일한 디렉터리를 동기화할 때 서로 데이터 블록을 전송할 수 있으므로 원본 서버의 부하가 줄어들고 전체 동기화 시간이 단축됩니다.

## rsync와의 속도 비교

테스트 환경: 유럽 노드 $\leftrightarrow$ 북미 노드, 왕복 지연 86ms, 디렉터리 검색, 중복 제거 비교, 네트워크 전송 및 디스크 배치 확인을 포함하여 전체 시간 소모 측정:

| 전송 시나리오 | 데이터 크기 | `sync0` | `rsync` | 다수의 |
| :--- | :---: | :---: | :---: | :---: |
| 작은 파일 10,000개 | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| 코드 및 아카이브 패키지(`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| 비디오 파일(`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| 증분 동기화(1% 콘텐츠 수정) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## 성능 개선 방법

- **UDP 동시 전송**: UDP를 통해 데이터 블록을 전송하고 손실된 조각만 재전송하여 후속 파일 전송을 차단하는 단일 패킷 손실을 방지합니다.
- **콘텐츠 분할 및 중복 제거**: 콘텐츠에 따라 파일을 데이터 블록으로 분할하고 검사 값을 계산합니다. 이미 수신 측에 있는 동일한 콘텐츠는 네트워크를 복제하지 않고 로컬에서 직접 재사용됩니다.
- **네트워크 속도에 따라 자동으로 압축 조정**: 텍스트, 코드 등 압축 가능한 콘텐츠에 대한 압축을 켭니다. CPU 소비를 줄이기 위해 비디오, 사진, 압축 패키지 또는 고속 LAN에서 자동으로 압축을 건너뜁니다.
- **인근 다중 노드 가져오기**: 여러 시스템이 동일한 디렉터리를 가져오는 경우 동일한 도시에 있거나 더 낮은 대기 시간으로 다운로드된 노드에서 데이터 블록을 동시에 가져옵니다.

## 설치하다

### 방법 1: Cargo를 통해 설치

```bash
cargo install sync0
```

### 방법 2: 미리 컴파일된 바이너리 다운로드

[GitHub 릴리스](https://github.com/webc-site/sync0/releases)로 이동하여 해당 시스템(Linux x86_64/ARM64, macOS Apple Silicon/Intel, Windows x64/ARM64, Android ARM64/x86_64, FreeBSD, NetBSD 지원)에 대한 `.tar.xz` 압축 패키지를 다운로드하세요. 압축을 푼 후 `sync0`를 `PATH` 디렉터리에 넣습니다.

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## 사용자 가이드

### 1. 두 컴퓨터 간에 파일이나 디렉터리를 직접 전송

수신 시스템에서 모니터링을 시작하고 수신 및 저장 경로를 지정합니다.

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

보내는 시스템에서 단일 파일 또는 전체 디렉터리를 보냅니다.

```bash
sync0 send ./project 192.168.1.10:9000
```

일반적으로 사용되는 매개변수:

```bash
# 수신측에는 존재하지만 송신측에는 존재하지 않는 중복 파일 삭제(미러동기화)
sync0 send ./project 192.168.1.10:9000 --delete

# 전송 속도 제한(단위: 바이트/초, 예: 50MB/s)
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# 자동 모드(진행률 표시줄이 표시되지 않음)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. 공유 디렉터리 게시 및 여러 노드에서 가져오기

원본 서버에 공유 디렉터리(`dataset`라는 이름)를 게시합니다.

```bash
sync0 share dataset ./data --region SHA
```

다른 머신에서 공유 디렉터리를 가져옵니다(동시에 가져오려면 쉼표로 구분하여 여러 노드 주소를 채울 수 있습니다).

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

공유 디렉터리에서 특정 하위 디렉터리만 가져옵니다.

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

로컬 변경 사항을 원격 공유 디렉터리로 다시 푸시합니다.

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. 카탈로그 자동 업데이트 구독

소스 노드의 공유 디렉터리를 구독합니다. 원본 디렉터리에 파일이 추가되거나 수정되면 자동으로 로컬 컴퓨터에 동기화됩니다. 동시에 로컬 머신은 자동으로 다른 머신이 다음을 가져올 수 있는 노드 역할을 합니다.

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. 다중 시스템 그룹의 양방향 동기화

여러 시스템이 동일한 그룹 이름에 참여하고 노드 디렉터리의 변경 사항은 그룹의 다른 노드에 자동으로 동기화됩니다.

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. 노드 ID 및 개인 명함

각 노드는 사용자 이름, 도시, 이메일, 웹사이트 및 개인화된 서명(최대 256자) 설정을 지원하고 로컬 개인 키 서명 인증을 전달합니다.

```bash
# 로컬 공개 키 ID 보기(키를 유지하려면 구성 디렉터리 지정)
sync0 id -c ~/.config/sync0

# 개인화된 서명이 포함된 노드 명함 생성 및 표시
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`, `pull`, `sub`, `group`는 다음 프로필 매개변수를 사용하여 시작할 수도 있습니다.

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. 다중 언어 전환

`sync0` 75개 언어를 지원합니다. 기본적으로 해당 언어의 명령줄 도움말과 프롬프트는 운영 체제의 언어 환경에 따라 자동으로 표시됩니다. 시스템 언어가 지원 목록에 없으면 기본적으로 영어가 사용됩니다.

언어를 수동으로 지정하려면 `SYNC0_LANG` 환경 변수를 설정하세요.

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
