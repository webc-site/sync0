# sync0

`sync0`은 `rsync`를 대체하는 데 사용되는 분산형 P2P 파일 공유, 실시간 동기화 및 다중 소스 배포 도구입니다. 대륙 횡단 WAN의 측정 속도는 최대 `rsync`의 **5.89×**(단일 지점 기하 평균 속도 **2.67×**, P2P 이중 소스 기하 평균 속도 **3.16×**) 및 대양 횡단 높은 대기 시간 링크 P2P 가속입니다. 최대 **7.68×**(풀 링크 24 시나리오 종합 기하 평균 속도 **2.56×**)입니다.

각 시스템은 서버이자 클라이언트입니다. 중앙 서버나 공용 네트워크 주소가 필요 없으며 자동 홀 펀칭은 분산 네트워크 공개 키 주소를 기반으로 하며 두 시스템 간의 직접 전송, 다중 공유 그룹 권한 호스팅, 요청 시 하위 디렉터리 다중 선택, 밀리초 수준의 실시간 증분 동기화 및 P2P 다중 소스 동시 가속을 지원합니다.

## 설치하다

### 방법 1: 화물 설치

```bash
cargo install sync0
```

### 방법 2: 미리 컴파일된 바이너리 다운로드

[GitHub 릴리스](https://github.com/webc-site/sync0/releases)로 이동하여 시스템(Linux, macOS, Windows, Android, iOS, FreeBSD 지원)에 해당하는 `.tar.xz` 압축 패키지를 다운로드하고 압축을 풀고 `PATH`에 넣습니다.

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## 빨리 시작하세요

### 1. 두 시스템 간의 제로 구성 직접 전송(`send` / `recv`)

공유 그룹을 구성할 필요가 없으며 두 시스템 간에 파일이나 디렉터리를 고속으로 직접 전송할 수 있습니다.

```bash
# 수신측은 포트에서 수신 대기하고 ./backup에 씁니다.
sync0 recv 0.0.0.0:9000 ./backup

# 발신자로부터 직접 전송(과도한 파일을 정리하기 위한 옵션 --delete 미러, --rate 50MB 속도 제한)
sync0 send ./project 192.168.1.10:9000
```

### 2. 게시물 공유 및 주문형 가져오기/업로드(`share` / `pull` / `push`)

```bash
# 서버: 한 줄의 명령으로 공유 그룹 게시(시작 후 IP가 없는 iroh 노드 주소 출력)
sync0 share dataset:./data

# 클라이언트: 전체 데이터 세트 공유 그룹을 로컬 ./local_data로 가져옵니다.
sync0 풀 데이터세트:// ./local_data -p <노드 주소>

# 클라이언트: 요청 시 여러 선택 항목 가져오기(지정된 단일 파일 및 하위 디렉터리만 동기화)
sync0 풀 데이터 세트://docs/readme.md,assets/icons,src/core ./local_data -p <노드 주소>

# 클라이언트: 승인된 공유 그룹에 파일 또는 디렉터리 업로드
sync0 푸시 데이터 세트://releases/v1 ./build_output -p <노드 주소>
```

### 3. 실시간 구독 시딩 및 다중 시스템 양방향 동기화(`sub` / `group`)

긴 연결을 설정한 후 원격 측에서 파일 **추가, 수정, 삭제, 권한 변경 또는 수정 시간**이 발생하면 로컬 디렉터리는 실시간으로 밀리초 단위로 동기식으로 업데이트됩니다. (새/수정된 대용량 파일은 차이 블록만 가져와서 제자리에 업데이트하고, 삭제 파일은 자동으로 로컬 파일과 빈 디렉터리를 정리하고 권한 또는 타임스탬프가 0인 데이터 블록만 직접 변경합니다.)

- **`sync0 sub`(단방향 실시간 미러링 + 자동 시딩)**: 로컬 실시간은 공유 측의 추가, 삭제 및 수정을 따르고 자동으로 P2P 시드 소스 역할을 하여 다른 풀링 노드에 동시 가속을 제공합니다.
- **`sync0 group`(다중 컴퓨터 P2P 양방향 실시간 동기화)**: 그룹의 컴퓨터에서 파일이 추가, 삭제 또는 수정되면 다른 모든 온라인 노드는 실시간으로 동기식 업데이트되어 서로의 시드 역할을 합니다.

```bash
# 전체 공유 그룹 구독: 원격 추가, 삭제 및 수정 사항이 로컬에서 실시간으로 동기화되고 자동으로 시드됩니다.
sync0 하위 데이터 세트:// ./local_mirror -p <노드 주소>

# 주문형 다중 선택 구독: 지정된 단일 파일 및 하위 디렉터리만 실시간으로 동기화하고 시드합니다.
sync0 하위 데이터 세트://models/llama.onnx,configs ./local_mirror -p <노드 주소>

# 다중 시스템 피어 그룹 양방향 실시간 동기화(전체 또는 쉼표 다중 선택 경로도 지원)
sync0 그룹 team-docs:// ./docs -p <노드 주소>
```

### 4. 팀 다중 공유 그룹 및 구성원 권한 구성(`.nt` 구성)

기본 구성 디렉터리는 최소한의 [NestedText](https://nestedtext.org) (`.nt`) 형식을 사용하여 `~/.config/sync0`(`-c <directory>`를 통해 전환 가능)입니다.
- **공용 네트워크 읽기 제한 지원(승인된 사용자만 읽을 수 있음)**: 공유 그룹이 `users:` 구성원 목록으로 구성되어 있는 한(또는 명령줄에서 `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`를 지정) 시스템은 **자동으로 개인 인증(`auth: true`)을 켜고** 공용 네트워크 익명 노드 열거 또는 읽기 및 P2P 구독을 금지합니다. 시딩 노드는 화이트리스트도 동시에 상속하므로 승인된 사용자만 읽을 수 있습니다. `users`로 구성되지 않은 공유 그룹은 기본적으로 공개 및 읽기 전용입니다. 공개 및 읽기 전용으로 설정하고 지정된 구성원에게만 업로드할 수 있도록 하려면 `auth: false`을 명시적으로 설정할 수 있습니다.
- **세분화된 읽기-쓰기 및 하위 디렉터리 전달 권한**: 구성원은 기본적으로 읽기 전용이며(`r` 명시적으로 작성할 필요 없음) `r`(읽기 전용), `w`(드롭 상자에만 쓰기, 읽을 수 없음), `rw`(읽기-쓰기) 및 `write_prefix`(업로드에 허용되는 하위 디렉터리 접두사 제한)를 지원합니다.

**멤버 구성 예(`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (기본 읽기 전용, 속도 제한 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt(읽기 및 쓰기 권한, 지정된 하위 디렉터리에만 업로드 가능)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (쓰기 전달 권한만, 읽기는 금지)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**공유 그룹 구성 예(`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # 구성되지 않은 사용자: 기본 공용 네트워크 읽기 전용
  dataset:
    path: ./data
    rate: 50MB

  # 구성된 사용자: 공용 네트워크 읽기를 자동으로 제한합니다(alice와 bob만 읽을 수 있고 charlie는 전달 및 업로드만 가능).
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

서비스를 시작합니다(구성 파일을 로드하거나 명령줄 매개변수를 직접 사용하여 공용 네트워크 읽기를 제한하고 구성원에게 권한 부여).

```bash
# 시작하려면 ~/.config/sync0/config.nt를 로드하세요.
sync0 share --region SHA

# 또는 순수 명령줄을 통해 개인 공유 그룹을 게시합니다(공용 네트워크 읽기를 자동으로 제한하고 승인된 사용자만 액세스할 수 있도록 --allow-* 지정).
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. 노드 주소, 명함 및 다국어

```bash
# 로컬 IP가 없는 노드 주소 보기(첫 번째 실행 시 키가 자동 생성됨)
sync0 id

# Ed25519 자체 서명 노드 명함 생성(닉네임, 도시 코드, 이메일, 웹사이트, 소개)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# 기본적으로 시스템 언어를 따르며 환경 변수를 통해 전환할 수 있는 75개의 내장 언어가 있습니다.
SYNC0_LANG=en sync0 --help
```

## 성능 및 핵심 기능

### 대륙 간 WAN 실제 측정(비교 `rsync`)

실제 측정 환경: 미국 `c1` → 유럽 `n1` (RTT 65ms), 데이터 세트는 Linux 커널 `linux-7.3.3`:

#### 1) 단품요리 모드와 `rsync`

| 데이터 세트 | 크기 | `sync0` 단일 지점<br>(Mbps) | `rsync`<br>(Mbps) | 속도 향상(`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(압축 불가능) | 155 MB | **236.48** | 108.74 | **2.17×** |
| `linux-7.3.3.tar`(압축 가능) | 1.6 GB | **843.83** | 385.06 | **2.19×** |
| `linux-7.3.3.tar`(로컬 변경 증분) | 1.6 GB | **8,014.15** | 1,361.72 | **5.89×** |
| `linux-7.3.3/` (95,979개의 작은 파일) | 1.5 GB | **627.58** | 347.80 | **1.80×** |
| **기하평균** | — | **1,000.91** | 375.26 | **2.67×** |

#### 2) P2P 듀얼 소스 모드와 `rsync`

| 데이터 세트 | 크기 | `sync0` P2P 듀얼 소스<br>(Mbps) | `rsync`<br>(Mbps) | 속도 향상(`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(압축 불가능) | 155 MB | **330.09** | 108.74 | **3.04×** |
| `linux-7.3.3.tar`(압축 가능) | 1.6 GB | **1,551.86** | 385.06 | **4.03×** |
| `linux-7.3.3.tar`(로컬 변경 증분) | 1.6 GB | **5,474.17** | 1,361.72 | **4.02×** |
| `linux-7.3.3/` (95,979개의 작은 파일) | 1.5 GB | **706.56** | 347.80 | **2.03×** |
| **기하평균** | — | **1,186.42** | 375.26 | **3.16×** |

> 참고: P2P 이중 소스 모드에서 유럽 노드는 `s1` 시드를 위해 협력하며 대륙 간 백본 RTT는 65ms입니다.

### 핵심 제품 기능

- **공개 키 주소 지정 자동 홀 펀칭**: 중앙 서버 및 공용 네트워크 주소가 필요 없으며 분산 네트워크 공개 키 주소를 기반으로 자동 NAT 홀 펀칭이 가능합니다.
- **밀리초 수준의 실시간 동기화 및 메타데이터 인식**: 기본 파일 이벤트 모니터링(`FSEvents` / `inotify` / `ReadDirectoryChangesW`), 파일 추가, 삭제, POSIX 권한(`mode`) 및 밀리초 수준 수정 시간(`mtime`)의 실시간 푸시를 기반으로 합니다. 권한이나 시간만 수정되면 데이터 블록 전송이 발생하지 않습니다.
- **BT 스타일 동시 다운로드 및 업로드 및 지역적 유사성 스케줄링**: 다운로드 노드는 전체 양이 다운로드될 때까지 기다릴 필요가 없습니다. 128비트 해시 검사를 통과한 모든 블록 간격(`Op::Have`)은 다른 노드가 동시에 가져올 수 있도록 메모리/임시 풀에 즉시 잠깁니다. 동적 PEX 노드 교환 및 느린 노드 절반 선점(작업 도용)과 함께 클러스터 처리량이 최대화됩니다.
- **악성 노드 변조 방지 및 클러스터 중독 방지**: 신뢰할 수 있는 소스 목록 `root_hash` 일관성 있는 잠금 + 필수 하드웨어 가속 `gxhash128` 각 블록이 디스크에 배치되고 외부에 시드되기 전 다이제스트 확인. 변조된 블록이 발견되면 밀리초 수준의 회로 차단기가 악성 노드를 차단하고 정직한 소스에서 자동으로 복구합니다.
- **FastCDC 현장 증분 및 작은 파일 집계**: 대용량 파일의 부분 수정을 위해 차등 블록만 전송되고 디스크에 배치됩니다. 대용량 소형 파일 메모리 패키징 및 접두어 차등 압축은 파일별 왕복 오버헤드를 제거합니다.
- **정전 후 자가 복구 및 재시작 후 재개**: Redis와 유사한 RDB + AOF 하이브리드 형식(`.s0_subs.bin`)을 사용하여 시드 상태 및 파일 목록을 유지하고 일일 변경 사항을 마이크로초 단위로 추가하며 정기적으로 자동으로 다시 작성되고 구성됩니다. 서버가 다시 시작되면 오프라인 변경 사항이 시드 노드에 자동으로 푸시됩니다.

## 기술 아키텍처 및 문서

- **이중 평면 분리 프로토콜**:
  - **제어 및 실시간 변경 표면(`iroh` QUIC / TCP, 첫 번째 바이트 `PROTO_VERSION` 버전 핸드셰이크) **: Ed25519 명함 확인, 권한 확인, Swarm 시드 검색, `u64::MAX` 레벨 대량 변경 스트리밍 일괄 처리 및 `mzstd` 압축 `SubPush` 실시간 푸시 지원(`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` 3개의 프리미티브).
  - **데이터 배포 표면(네이티브 UDP + `compio` 비동기 I/O) **: 20B 컴팩트 헤더, 18B TACK 주기적 피드백, BBRv3/Copa 하이브리드 혼잡 제어, RACK-TLP 패킷 손실 복구, 첫 번째 블록 Shannon 엔트로피 적응형 Zstd 압축 우회 및 `gxhash128` 블록 엔드 투 엔드 검증.
