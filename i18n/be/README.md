# sync0

`sync0` - гэта дэцэнтралізаваны інструмент абмену файламі P2P, сінхранізацыі ў рэальным часе і размеркавання з некалькіх крыніц, які выкарыстоўваецца замест `rsync` - вымераная хуткасць транскантынентальнай глабальнай сеткі складае да **6,95×** з `rsync` (сярэдняя геаметрычная хуткасць у адной кропцы **2,01×**, сярэдняя геаметрычная хуткасць P2P з двума крыніцамі **3,33×**), і сінхранізацыя вялікіх невялікіх файлаў праз акіяны такая ж хуткая, як **7.19×**.

Кожная машына з'яўляецца і серверам, і кліентам: няма неабходнасці ў цэнтральным серверы або агульнадаступным сеткавым адрасе, аўтаматычнае прабіванне дзірак заснавана на адрасе адкрытага ключа размеркаванай сеткі і падтрымлівае прамую перадачу паміж дзвюма машынамі, хостынг дазволаў для групы сумеснага выкарыстання, некалькі выбараў падкаталогаў па патрабаванні, мілісекундную сінхранізацыю ў рэжыме рэальнага часу і адначасовае паскарэнне з некалькіх крыніц P2P.

## Усталяваць

### Спосаб 1: Ўстаноўка грузу

```bash
cargo install sync0
```

### Спосаб 2: загрузка папярэдне скампіляваных двайковых файлаў

Перайдзіце да [Выпускі GitHub](https://github.com/webc-site/sync0/releases), каб спампаваць сціснуты пакет `.tar.xz`, які адпавядае сістэме (падтрымлівае Linux, macOS, Windows, Android, iOS, FreeBSD), распакаваць і змясціць у `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Пачніце хутка

### 1. Прамая перадача нулявой канфігурацыі паміж двума машынамі (`send` / `recv`)

Няма неабходнасці наладжваць групу абмену, непасрэдна перадаваць файлы або каталогі паміж дзвюма машынамі на высокай хуткасці:

```bash
# Прыёмны бок праслухоўвае порт і запісвае ў ./backup
sync0 recv 0.0.0.0:9000 ./backup

# Прамая перадача ад адпраўніка (неабавязкова --delete люстэрка, каб ачысціць лішнія файлы, --rate абмежаванне хуткасці 50MB)
sync0 send ./project 192.168.1.10:9000
```

### 2. Абагульванне паведамленняў і спампоўванне/запампоўка па патрабаванні (`share` / `pull` / `push`)

```bash
# Сервер: апублікаваць групу сумеснага выкарыстання з дапамогай аднаго радка каманды (пасля запуску вывесці адрас вузла iroh без IP)
sync0 share dataset:./data

# Кліент: выцягніце ўсю групу сумеснага выкарыстання набору даных у лакальны ./local_data
sync0 выцягнуць набор даных:// ./лакальныя_даныя -p <адрас вузла>

# Кліент: Выцягвайце некалькі выбраных элементаў па патрабаванні (сінхранізуйце толькі пэўныя асобныя файлы і падкаталогі)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <адрас вузла>

# Кліент: загружайце файлы або каталогі ў аўтарызаваныя групы абмену
sync0 push dataset://releases/v1 ./build_output -p <адрас вузла>
```

### 3. Высадка падпіскі ў рэжыме рэальнага часу і двухбаковая сінхранізацыя з некалькімі машынамі (`sub` / `group`)

Пасля ўстанаўлення доўгага злучэння, калі які-небудзь файл **дадае, мадыфікуе, выдаляе, змяняе дазволы або час мадыфікацыі** адбываецца на аддаленым канцы, лакальны каталог будзе сінхронна абнаўляцца за мілісекунды ў рэжыме рэальнага часу (новыя/мадыфікаваныя вялікія файлы будуць выцягваць толькі блокі адрозненняў і абнаўляць іх на месцы, выдаленне файлаў аўтаматычна ачышчае лакальныя файлы і пустыя каталогі, і толькі змяняе дазволы або пазначае час нулявымі блокамі даных непасрэдна):

- **`sync0 sub`(Аднабаковае адлюстраванне ў рэжыме рэальнага часу + аўтаматычнае запаўненне)**: Лакальны рэжым у рэжыме рэальнага часу сочыць за дабаўленнямі, выдаленнямі і мадыфікацыямі з боку абагульвання і аўтаматычна служыць у якасці крыніцы P2P-пачатку для забеспячэння адначасовага паскарэння для іншых выцягваючых вузлоў.
- **`sync0 group`(Шматмашынная аднарангавая двухбаковая сінхранізацыя ў рэжыме рэальнага часу)**: калі файлы дадаюцца, выдаляюцца або мадыфікуюцца на любой машыне ў групе, усе іншыя онлайн-вузлы будуць абнаўляцца сінхронна ў рэжыме рэальнага часу і служаць адзін для аднаго пачатковымі.

```bash
# Падпішыцеся на ўсю групу абмену: аддаленыя дабаўленні, выдаленні і мадыфікацыі сінхранізуюцца лакальна ў рэжыме рэальнага часу і аўтаматычна запаўняюцца
sync0 sub dataset:// ./local_mirror -p <адрас вузла>

# Падпіска з множным выбарам па патрабаванні: сінхранізаваць і запаўняць толькі асобныя файлы і падкаталогі ў рэжыме рэальнага часу
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <адрас вузла>

# Двухбаковая сінхранізацыя ў рэжыме рэальнага часу з групай аднагодкаў з некалькімі машынамі (таксама падтрымлівае поўныя шляхі або шляхі множнага выбару праз коску)
sync0 group team-docs:// ./docs -p <адрас вузла>
```

### 4. Канфігурацыя дазволаў для некалькіх груп і членаў каманды (`.nt`)

Стандартны каталог канфігурацыі `~/.config/sync0` (можна пераключыць праз `-c <directory>`), выкарыстоўваючы мінімалістычны фармат [NestedText](https://nestedtext.org) (`.nt`):
- **Падтрымка абмежавання чытання ў агульнадаступнай сетцы (толькі аўтарызаваныя карыстальнікі могуць чытаць)**: пакуль група абагульвання настроена са спісам членаў `users:` (або камандны радок вызначае `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`), сістэма **аўтаматычна ўключае прыватную аўтэнтыфікацыю (`auth: true`)** і забараняе пералік або чытанне ананімных вузлоў публічнай сеткі, і P2P-падпіска на вузлы пасева таксама будзе адначасова ўспадкоўваць белы спіс, дазваляючы чытаць толькі аўтарызаваным карыстальнікам; групы абагульвання, для якіх не настроена `users`, па змаўчанні з'яўляюцца агульнадаступнымі і даступнымі толькі для чытання (калі вы хочаце быць агульнадаступнымі і даступнымі толькі для чытання і адкрытымі для запампоўкі толькі вызначаным удзельнікам, вы можаце відавочна ўсталяваць `auth: false`).
- **Падрабязныя дазволы на чытанне-запіс і дастаўку падкаталогаў**: удзельнікі па змаўчанні даступныя толькі для чытання (`r` не трэба пісаць яўна) і падтрымліваюць `r` (толькі для чытання), `w` (толькі для запісу ў выпадальнае поле, не чытаецца), `rw` (чытанне-запіс) і `write_prefix` (абмежаванне прэфікс падкаталога, дазволены для загрузкі).

**Прыклад канфігурацыі ўдзельніка (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (па змаўчанні толькі для чытання, абмежаванне хуткасці 80 МБ)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (дазволы на чытанне і запіс, дазволена загружаць толькі ў вызначаны падкаталог)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (толькі дазвол на дастаўку запісу, чытанне забаронена)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**Прыклад канфігурацыі групы абагульвання (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # Ненастроеныя карыстальнікі: агульнадаступная сетка па змаўчанні толькі для чытання
  dataset:
    path: ./data
    rate: 50MB

  # Наладжаныя карыстальнікі: аўтаматычна абмяжоўваць чытанне публічнай сеткі (толькі Аліса і Боб могуць чытаць, Чарлі можа толькі дастаўляць і загружаць)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

Запусціце службу (загрузіце файл канфігурацыі або непасрэдна выкарыстоўвайце параметры каманднага радка, каб абмежаваць чытанне публічнай сеткі і аўтарызаваць удзельнікаў):

```bash
# Загрузіце ~/.config/sync0/config.nt, каб пачаць
sync0 share --region SHA

# Або апублікаваць прыватную групу абагульвання праз чысты камандны радок (укажыце --allow-*, каб аўтаматычна абмежаваць чытанне агульнадаступнай сеткі і атрымаць да яе доступ толькі аўтарызаваныя карыстальнікі)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. Адрас вузла, візітоўка і шматмоўнасць

```bash
# Прагляд лакальнага адраса вузла без IP (ключ генеруецца аўтаматычна для першага запуску)
sync0 id

# Стварыце самападпісваную візітную картку вузла Ed25519 (псеўданім, код горада, адрас электроннай пошты, вэб-сайт, увядзенне)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# Ёсць 75 убудаваных моў, якія па змаўчанні ідуць за мовай сістэмы і могуць быць пераключаны з дапамогай зменных асяроддзя.
SYNC0_LANG=en sync0 --help
```

### Асноўныя характарыстыкі прадукту

- **Адрасаванне адкрытых ключоў з аўтаматычным прабіваннем дзірак**: Няма неабходнасці ў цэнтральным серверы і адрасе агульнадаступнай сеткі, аўтаматычнае прабіванне дзірак NAT на аснове адраса адкрытага ключа размеркаванай сеткі.
- **Мілісекундная сінхранізацыя ў рэжыме рэальнага часу і інфармаванасць аб метададзеных**: на аснове ўласнага маніторынгу файлавых падзей (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), адпраўкі файлаў у рэжыме рэальнага часу, выдаленняў, дазволаў POSIX (`mode`) і часу мадыфікацыі на ўзроўні мілісекунд (`mtime`); нулявая перадача блока даных, калі зменены толькі дазволы або час.
- **Адначасовая загрузка і загрузка ў стылі BT і планаванне рэгіянальнай блізкасці**: вузлу загрузкі не трэба чакаць, пакуль будзе спампавана поўная колькасць. Усе інтэрвалы блокаў (`Op::Have`), якія прайшлі праверку 128-бітнага хэша, неадкладна блакіруюцца ў памяці/часовым пуле, каб іншыя вузлы маглі адначасова атрымліваць іх. Разам з дынамічным абменам вузламі PEX і павольным пераадоленнем вузла напалову (крадзеж працы) прапускная здольнасць кластара максімальна павялічваецца.
- **Супрацьшкодны ўмяшанне ў вузлы і імунітэт да атручвання кластараў**: аўтарытэтны спіс крыніц `root_hash` Самаузгодненая блакіроўка + абавязковае апаратнае паскарэнне `gxhash128` праверка дайджэста перад тым, як кожны блок будзе змешчаны на дыск і будзе загружаны знешне; калі знойдзены сапсаваны блок, аўтаматычны выключальнік на ўзроўні мілісекунд адключыць шкоднасны вузел і аўтаматычна аднавіць яго з сумленнай крыніцы.
- **FastCDC in-situ increment and small file agregation**: толькі дыферэнцыяльныя блокі перадаюцца для частковай мадыфікацыі вялікіх файлаў і змяшчаюцца на дыск; вялізная ўпакоўка памяці для невялікіх файлаў і дыферэнцыяльнае сцісканне прэфіксаў пазбаўляюць ад накладных выдаткаў на файл за файлам.
- **Самааднаўленне пасля адключэння электраэнергіі і аднаўленне пасля перазагрузкі**: падобны на Redis гібрыдны фармат RDB + AOF (`.s0_subs.bin`) выкарыстоўваецца для захавання стану запаўнення і спісу файлаў, штодзённыя змены дадаюцца за мікрасекунды і аўтаматычна перапісваюцца і рэгулярна арганізоўваюцца. Пасля перазапуску сервера змены ў аўтаномным рэжыме аўтаматычна адпраўляюцца ў вузел запаўнення.

## Тэхнічная архітэктура і дакументацыя

- **Пратакол развязкі падвойнай плоскасці**:
  - **Паверхня кіравання і змяненняў у рэальным часе (`iroh` QUIC / TCP, першы байт `PROTO_VERSION` рукапацісканне версіі) **: адказвае за праверку візітнай карткі Ed25519, праверку дазволаў, выяўленне пачатковага элемента Swarm і падтрымку пакетавання масавых змяненняў узроўню `u64::MAX` і `mzstd` сціснутага `SubPush` штуршка ў рэальным часе (`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` Тры прымітывы).
  - **Паверхня размеркавання даных (уласны UDP + `compio` асінхронны ўвод-вывад) **: кампактны загаловак 20B, перыядычная зваротная сувязь 18B TACK, гібрыдны кантроль перагрузкі BBRv3/Copa, аднаўленне страты пакетаў RACK-TLP, абыход сціску Zstd, адаптаваны да энтрапіі першага блока Шэнана, і скразная праверка блока `gxhash128`.
