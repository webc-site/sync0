# sync0

`sync0` - гэта інструмент каманднага радка для перадачы файлаў па сетках, паступовай сінхранізацыі каталогаў і адначасовага размеркавання даных на некалькі машын.

## Арыгінальная задума дызайну

У розных машынных залах, краінах або асяроддзях з затрымкамі ў сетцы і стратай пакетаў такія інструменты, як `rsync` і `scp` заснаваны на пацверджанні адной паслядоўнасці злучэння, што абмяжоўвае выкарыстанне паласы прапускання; калі некалькі машын адначасова атрымліваюць дадзеныя з аднаго сервера, сеткавая карта зыходнага сервера можа лёгка стаць вузкім месцам.

Мэта `sync0` - вырашыць дзве праблемы:

1. Дазвольце сінхранізацыі файлаў і каталогаў паміж дзвюма машынамі працаваць з поўнай фізічнай прапускной здольнасцю і перадаваць змененую частку толькі тады, калі файл будзе часткова зменены.
2. Некалькі машын могуць перадаваць блокі даных адна адной пры сінхранізацыі аднаго каталога, зніжаючы нагрузку на зыходны сервер і скарачаючы агульны час сінхранізацыі.

## Параўнанне хуткасці з rsync

Тэставае асяроддзе: еўрапейскі вузел $\leftrightarrow$ паўночнаамерыканскі вузел, затрымка туды-назад 86 мс, вымярэнне поўнага часу, уключаючы сканіраванне каталога, параўнанне дэдуплікацыі, сеткавую перадачу і праверку размяшчэння дыска:

| Сцэнар перадачы | Памер дадзеных | `sync0` | `rsync` | множны |
| :--- | :---: | :---: | :---: | :---: |
| 10 000 невялікіх файлаў | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| Пакеты кода і архіва (`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| Відэафайл (`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| Паступовая сінхранізацыя (змяніць 1% кантэнту) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## Метады паляпшэння прадукцыйнасці

- **Адначасовая перадача UDP**: Адпраўляйце блокі даных праз UDP і паўторна перадавайце толькі страчаныя фрагменты, каб пазбегнуць блакіроўкі адзінкавай страты пакета пры наступнай перадачы файлаў.
- **Сегментацыя змесціва і дэдуплікацыя**: падзяліце файл на блокі даных у адпаведнасці з зместам і вылічыце кантрольнае значэнне. Тое ж змесціва, якое ўжо знаходзіцца на прыёмным канцы, выкарыстоўваецца паўторна непасрэдна лакальна без дубліравання ў сетцы.
- **Аўтаматычнае рэгуляванне сціску ў залежнасці ад хуткасці сеткі**: уключыце сціск для сцісканага змесціва, такога як тэкст і код; аўтаматычна прапускаць сціск для відэа, малюнкаў, сціснутых пакетаў або пад высакахуткаснай лакальнай сеткай, каб паменшыць спажыванне працэсара.
- **Выцягванне некалькіх вузлоў паблізу**: калі некалькі машын выцягваюць адзін і той жа каталог, блокі даных будуць выцягвацца адначасова з загружаных вузлоў у тым жа горадзе або з меншай затрымкай.

## Усталяваць

### Спосаб 1: Усталёўка праз Cargo

```bash
cargo install sync0
```

### Спосаб 2: загрузка папярэдне скампіляваных двайковых файлаў

Перайдзіце да [Выпускі GitHub](https://github.com/webc-site/sync0/releases), каб спампаваць сціснуты пакет `.tar.xz` для адпаведнай сістэмы (падтрымлівае Linux x86_64/ARM64, macOS Apple Silicon/Intel, Windows x64/ARM64, Android ARM64/x86_64, FreeBSD, NetBSD). Пасля распакавання змесціце `sync0` у каталог `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Кіраўніцтва карыстальніка

### 1. Прамая перадача файлаў або каталогаў паміж двума машынамі

Пачніце маніторынг на прыёмнай машыне і ўкажыце шлях атрымання і захавання:

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

Адпраўце адзін файл або цэлы каталог з машыны-адпраўшчыка:

```bash
sync0 send ./project 192.168.1.10:9000
```

Часта выкарыстоўваюцца параметры:

```bash
# Выдаліць лішнія файлы, якія існуюць на прымаючым, але не на адпраўным баку (люстраная сінхранізацыя)
sync0 send ./project 192.168.1.10:9000 --delete

# Абмежаваць хуткасць адпраўкі (адзінка вымярэння: байты/секунду, напрыклад, 50 МБ/с)
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# Бясшумны рэжым (панэль прагрэсу не паказваецца)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. Публікацыя агульных каталогаў і выцягванне з некалькіх вузлоў

Апублікаваць агульны каталог (пад назвай `dataset`) на зыходным серверы:

```bash
sync0 share dataset ./data --region SHA
```

Выцягніце агульны каталог на іншых машынах (вы можаце запоўніць некалькі адрасоў вузлоў адначасова, падзяліўшы іх коскамі, каб атрымаць адначасова):

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

Выцягнуць толькі пэўны падкаталог у агульным каталогу:

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

Перанесці лакальныя змены ў аддалены агульны каталог:

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. Падпішыцеся на аўтаматычнае абнаўленне каталога

Падпішыцеся на агульны каталог зыходнага вузла. Калі файл дададзены або зменены ў зыходным каталогу, ён будзе аўтаматычна сінхранізаваны з лакальным кампутарам. У той жа час лакальная машына будзе аўтаматычна служыць вузлом для іншых машын:

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. Двухбаковая сінхранізацыя шматмашынных груп

Некалькі машын далучаюцца да адной групы, і змены ў любым каталогу вузлоў будуць аўтаматычна сінхранізаваны з іншымі вузламі ў групе:

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. Ідэнтычнасць вузла і асабістая візітная картка

Кожны вузел падтрымлівае ўстаноўку імя карыстальніка, горада, электроннай пошты, вэб-сайта і персаналізаванай подпісы (максімум 256 сімвалаў), а таксама праходзіць аўтэнтыфікацыю подпісу лакальнага закрытага ключа:

```bash
# Прагляд ідэнтыфікатара лакальнага адкрытага ключа (укажыце каталог канфігурацыі, каб захаваць ключ)
sync0 id -c ~/.config/sync0

# Стварайце і паказвайце візітныя карткі вузлоў з персанальнымі подпісамі
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`, `pull`, `sub`, `group` таксама могуць быць запушчаны з гэтымі параметрамі профілю:

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. Шматмоўнае пераключэнне

`sync0` Падтрымлівае 75 моў. Па змаўчанні даведка каманднага радка і падказкі на адпаведнай мове аўтаматычна адлюстроўваюцца ў адпаведнасці з моўным асяроддзем аперацыйнай сістэмы; калі сістэмнай мовы няма ў спісе падтрымоўваных, па змаўчанні выкарыстоўваецца англійская.

Каб задаць мову ўручную, усталюйце зменную асяроддзя `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
