# sync0

`sync0` - гэта аднарангавы (P2P) інструмент сумеснага выкарыстання файлаў і шматмашыннай сінхранізацыі, які канкуруе з Resilio Sync.

Кожная машына адначасова з'яўляецца серверам і кліентам: любы вузел можа публікаваць некалькі груп абмену файламі. Пасля далучэння іншых вузлоў яны могуць аўтаматычна атрымліваць даступныя пачатковыя вузлы з аднарангавага сервера і атрымліваць іх адначасова з некалькіх крыніц. Пасля завяршэння сінхранізацыі будуць аўтаматычна створаны пачатковыя элементы для большай колькасці вузлоў для паскарэння загрузкі.

## Асноўныя моманты

- **Кожны адначасова і сервер, і кліент**: параўнальна з Resilio Sync, без залежнасці ад цэнтральнага сервера. Любы вузел можа ствараць некалькі груп абмену файламі, а таксама можа далучацца да груп абмену іншымі людзьмі; вузлы аўтаматычна абменьваюцца і атрымліваюць даступныя пачатковыя вузлы для дасягнення адначасовага выцягвання і сінхранізацыі некалькіх машын у рэжыме рэальнага часу.
- **Адрас вузла без IP**: па змаўчанні ключ вузла і `base64url` закадаваны адрас `iroh` аўтаматычна ствараюцца ў `~/.config/sync0` без неабходнасці запамінання або раскрыцця публічнага IP.
- **Сінхранізацыя з некалькімі выбарамі па патрабаванні**: падтрымлівае сінхранізацыю ўсёй групы абмену, а таксама падтрымлівае сінхранізацыю па патрабаванні шляхам выбару некалькіх файлаў або падкаталогаў адначасова.
- **Іерархічныя дазволы членаў групы і кіраванне каталогам загрузкі**: падтрымлівае дазволы толькі для чытання (`ro`), загрузкі для чытання і запісу (`rw`) і кіравання (`admin`), а таксама можа індывідуальна вызначаць прэфікс шляху, які кожнаму ўдзельніку дазволена загружаць (па змаўчанні дазволена запампоўка ў каранёвы каталог агульнага доступу).
- **Поўнахуткасная і паступовая сінхранізацыя ў сетках**: адначасовая перадача вялікіх файлаў, аб'яднанне вялікіх малых файлаў у памяці і сінхранізаваныя блокі даных толькі пры частковым змяненні файлаў.

## Усталяваць

### Спосаб 1: Усталёўка праз Cargo

```bash
cargo install sync0
```

### Спосаб 2: загрузка папярэдне скампіляваных двайковых файлаў

Перайдзіце на [GitHub Releases](https://github.com/webc-site/sync0/releases), каб спампаваць сціснуты пакет `.tar.xz` для адпаведнай сістэмы (падтрымлівае Linux, macOS, Windows, Android, FreeBSD, NetBSD), распакуйце і змясціце яго ў каталог `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Пачніце хутка

`sync0` выкарыстоўвае `~/.config/sync0` у якасці каталога канфігурацыі па змаўчанні (калі вам трэба пераключыцца на іншыя каталогі, вы можаце дадаць `-c <каталог>`).

### 1. Праглядзіце адрас лакальнага вузла і наладку візітнай карткі

```bash
# Прагляд лакальнага адраса вузла (ключ аўтаматычна генеруецца ў ~/.config/sync0 у першы раз)
sync0 id

# Стварэнне асабістай візітнай карткі вузла (падтрымлівае імя карыстальніка, горад, адрас электроннай пошты, вэб-сайт і подпіс у межах 256 слоў)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. Публікацыя некалькіх груп абмену файламі і ўстаноўка дазволаў членам групы (`.nt` Канфігурацыя)

`sync0` наладжаны ў фармаце [NestedText](https://nestedtext.org) (`.nt`). Кожны карыстальнік мае асобны файл канфігурацыі `.nt`. Вы можаце вызначыць каталог профілю карыстальніка праз `users_dir` у `config.nt` (што аўтаматычна ўключае ўсе `.nt` файлы ў гэтым каталогу). Як карыстальнік, так і прэфікс шляху, які можа быць загружаны, выкарыстоўваюць неўпарадкаваны спіс (`-`). **Калі прэфікс шляху загрузкі не запоўнены, загрузка ў каранёвы каталог агульнага доступу дазволена па змаўчанні**.

1. Стварыце асобныя файлы канфігурацыі `.nt` для кожнага ўдзельніка ў каталогу `~/.config/sync0/users/`:

`~/.config/sync0/users/alice.nt` (удзельнік толькі для чытання, хуткасць абмежаваная `80MB`, `rate` падтрымлівае `GB`, `MB`, `KB` адзінак):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (удзельнікі з абмежаванай загрузкай: дазволена загружаць толькі ў `uploads/bob` і `shared/common` каталогі):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (Загрузка члена па змаўчанні: калі `write_prefix` апушчаны, запампоўка ў каранёвы каталог агульнага доступу дазволена па змаўчанні):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. Наладзьце каталог карыстальніка і некалькі груп сумеснага выкарыстання файлаў у `~/.config/sync0/config.nt`:

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

Пачаць службу абмену:

```bash
# Прамы запуск (аўтаматычна загружае ўсе карыстальніцкія канфігурацыі .nt у каталогах ~/.config/sync0/config.nt і users_dir)
sync0 share --region SHA

# Або хутка апублікуйце некалькі груп абагульвання і аўтарызуйце членаў групы непасрэдна праз камандны радок
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. Выцягнуць увесь кантэнт або выбраць некалькі файлаў і каталогаў (`sync0 pull`)

Падключыцеся да любога аднарангавага вузла, каб аўтаматычна атрымаць усе даступныя пачатковыя вузлы ў групе абагульвання і атрымліваць з некалькіх пачатковых вузлоў адначасова:

```bash
# Перанясіце ўсю групу сумеснага выкарыстання набору даных у лакальны ./local_data
sync0 выцягнуць набор даных:// ./лакальныя_даныя -p <адрас вузла>

# Сінхранізацыя з некалькімі выбарамі: адначасова выцягвайце адзіны файл docs/readme.md і падкаталогі assets/icons, src/core
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <адрас вузла>
```

### 4. Загрузіць файл або каталог у групу абагульвання (`sync0 push`)

Удзельнікі з дазволам на запампоўку (`rw` або `admin`) могуць загружаць лакальныя файлы або каталогі ў групы аддаленага абагульвання:

```bash
# Удзельнікі з дазволам на загрузку ў каранёвы каталог: загружаць непасрэдна ў агульны каранёвы каталог
sync0 push team-vault:// ./new_release -p <адрас вузла>

# Толькі ўдзельнікі, упаўнаважаныя на пэўны прэфікс (напрыклад, uploads/bob): загружаць на дазволены прэфікс шляху
sync0 push team-vault://uploads/bob/report.pdf ./report.pdf -p <адрас вузла>
```

### 5. Падпісацца на аўтаматычную сінхранізацыю і запаўненне (`sync0 sub`)

Пасля падпіскі на групу сумеснага выкарыстання пэўнага вузла лакальны сервер адначасова з'яўляецца прымаючым кліентам і новым серверам пасева; калі файл зыходнага вузла абнаўляецца, ён аўтаматычна сінхранізуецца і забяспечвае спампоўку кавалкамі для іншых вузлоў:

```bash
# Падпішыцеся на ўсю групу абагульвання і аўтаматычна запусціце яе
sync0 sub dataset:// ./local_mirror -p <адрас вузла>

# Толькі множны выбар, каб падпісацца на ўказаныя файлы і падкаталогі і задаць іх
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <адрас вузла>
```

### 6. Шматмашынная групавая аднарангавая сінхранізацыя (`sync0 group`)

Некалькі машын далучаюцца да адной групы сумеснага выкарыстання, адна адна аўтаматычна выяўляе даступныя пачатковыя вузлы і падтрымлівае двухбаковую сінхранізацыю (падтрымлівае поўную сінхранізацыю або множны выбар файлаў і каталогаў):

```bash
# Поўнае далучэнне да групы і двухбаковая сінхранізацыя
sync0 group team-docs:// ./docs -p <адрас вузла>

# Толькі каталог wal і файл meta.json у групе сінхранізацыі з множным выбарам
sync0 group team-docs://wal,meta.json ./docs -p <адрас вузла>
```

### 7. Прамая перадача "кропка-кропка" паміж двума машынамі (`send` / `recv`)

Няма неабходнасці папярэдне наладжваць групу, і вы можаце часова перадаваць файлы або каталогі непасрэдна паміж двума машынамі:

```bash
# Маніторынг прыёмніка
sync0 recv 0.0.0.0:9000 ./backup

# Адпраўляючы бок непасрэдна перадае файлы або каталогі (неабавязкова --delete люстэрка, каб ачысціць лішнія файлы, --rate абмежаванне хуткасці)
sync0 send ./project 192.168.1.10:9000
```

### 8. Шматмоўнае пераключэнне

`sync0` падтрымлівае 75 моў і аўтаматычна пераключаецца ў залежнасці ад моўнага асяроддзя сістэмы па змаўчанні; яго таксама можна ўказаць уручную праз `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
