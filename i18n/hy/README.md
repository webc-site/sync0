# sync0

`sync0`-ը ապակենտրոնացված P2P ֆայլերի փոխանակման, իրական ժամանակի համաժամացման և բազմաղբյուրի բաշխման գործիք է, որն օգտագործվում է `rsync`-ին փոխարինելու համար. անդրմայրցամաքային լայնածավալ ցանցի չափված արագությունը մինչև **6,95×** է `rsync`-ից (մեկ կետային երկրաչափական միջին արագություն **, P2geP միջին արագություն **, P2geP* միջին արագություն **-2,01P): **3.33×**), և օվկիանոսներում հսկայական փոքր ֆայլերի համաժամացումը նույնքան արագ է, որքան **7.19×**:

Յուրաքանչյուր մեքենա և՛ սերվեր է, և՛ հաճախորդ. կարիք չկա կենտրոնական սերվերի կամ հանրային ցանցի հասցեի, անցքերի ավտոմատ փչումը հիմնված է բաշխված ցանցի հանրային բանալու հասցեի վրա և աջակցում է ուղիղ փոխանցմանը երկու մեքենաների միջև, բազմաբաշխման խմբային թույլտվությունների հոսթինգին, ենթադիրեկտորների բազմակի ընտրությունը ըստ պահանջի, միլիվայրկյան մակարդակի իրական ժամանակում աճող բազմակի համաժամացման և P2P:

## Տեղադրեք

### Մեթոդ 1. Բեռների տեղադրում

```bash
cargo install sync0
```

### Մեթոդ 2. Ներբեռնեք նախապես կազմված երկուականները

Գնացեք [GitHub Releases](https://github.com/webc-site/sync0/releases)՝ համակարգին համապատասխան `.tar.xz` սեղմված փաթեթը ներբեռնելու համար (աջակցում է Linux, macOS, Windows, Android, iOS, FreeBSD), ապազիպացրեք և դրեք `PATH` մեջ:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Շտապեք սկսել

### 1. Զրոյական կոնֆիգուրացիայի ուղիղ փոխանցում երկու մեքենաների միջև (`send` / `recv`)

Կարիք չկա կարգավորել համօգտագործման խումբը, ուղղակիորեն փոխանցել ֆայլերը կամ գրացուցակները երկու մեքենաների միջև բարձր արագությամբ.

```bash
# Ստացողը լսում է պորտին և գրում է ./backup
sync0 recv 0.0.0.0:9000 ./backup

# Ուղիղ փոխանցում ուղարկողից (ըստ ցանկության – ջնջել հայելին՝ ավելորդ ֆայլերը մաքրելու համար, - 50 ՄԲ արագության սահմանաչափ)
sync0 send ./project 192.168.1.10:9000
```

### 2. Գրառումների համօգտագործում և ըստ պահանջի ձգում/վերբեռնում (`share` / `pull` / `push`)

```bash
# Սերվեր. Հրապարակեք համօգտագործման խումբը մեկ հրամանի տողով (արտադրեք IP-ից զերծ iroh հանգույցի հասցեն գործարկումից հետո)
sync0 share dataset:./data

# Հաճախորդ. Քաշեք տվյալների համօգտագործման ամբողջ խումբը դեպի տեղական ./local_data
sync0 pull database:// ./local_data -p <հանգույցի հասցե>

# Հաճախորդ. Քաշեք մի քանի ընտրություն ըստ պահանջի (համաժամեցրեք միայն նշված առանձին ֆայլերը և ենթագրքերերը)
sync0 pull տվյալների հավաքածու://docs/readme.md,assets/icons,src/core ./local_data -p <հանգույցի հասցե>

# Հաճախորդ. Վերբեռնեք ֆայլեր կամ գրացուցակներ լիազորված համօգտագործման խմբերում
sync0 push Dataset://releases/v1 ./build_output -p <հանգույցի հասցե>
```

### 3. Իրական ժամանակում բաժանորդագրության սերմանում և բազմաֆունկցիոնալ երկկողմանի համաժամացում (`sub` / `group`)

Երկար կապ հաստատելուց հետո, եթե որևէ ֆայլ **ավելացնելու, փոփոխելու, ջնջելու, փոխելու թույլտվությունները կամ փոփոխման ժամանակը** տեղի է ունենում հեռավոր ծայրում, տեղական գրացուցակը սինխրոն կերպով կթարմացվի միլիվայրկյաններով իրական ժամանակում (նոր/փոփոխված մեծ ֆայլերը միայն կհանեն տարբերությունների բլոկները և կթարմացնեն դրանք տեղում, ջնջեք ֆայլերը ինքնաբերաբար կմաքրեն կամ կփոխեն միայն տեղական ֆայլերը և կփոխեն դատարկ տնօրենը):

- **`sync0 sub`(Միակողմանի իրական ժամանակի հայելավորում + ավտոմատ սերմացում)**. Տեղական իրական ժամանակում հետևում է համօգտագործման վերջի ավելացումներին, ջնջումներին և փոփոխություններին և ավտոմատ կերպով ծառայում է որպես P2P սերմի աղբյուր` միաժամանակ արագացում ապահովելու այլ ձգվող հանգույցների համար:
- **`sync0 group`(Բազմաֆունկցիոնալ իրական ժամանակում երկկողմանի համաժամանակացում)**. Եթե խմբի որևէ մեքենայի վրա ֆայլեր ավելացվեն, ջնջվեն կամ փոփոխվեն, մյուս բոլոր առցանց հանգույցները համաժամանակաբար կթարմացվեն իրական ժամանակում և կծառայեն որպես սերմեր միմյանց համար:

```bash
# Բաժանորդագրվեք համօգտագործման ամբողջ խմբին. հեռակա հավելումները, ջնջումները և փոփոխությունները համաժամացվում են տեղում իրական ժամանակում և ավտոմատ կերպով սերմացվում են:
sync0 sub databas:// ./local_mirror -p <հանգույցի հասցե>

# Բազմընտրական բաժանորդագրություն ըստ պահանջի. միայն իրական ժամանակում համաժամացրեք և տեղադրեք նշված առանձին ֆայլեր և ենթագրքեր
sync0 ենթախմբի տվյալների հավաքագրում://models/llama.onnx,configs ./local_mirror -p <հանգույցի հասցե>

# Բազմամեքենաների հասակակիցների խմբի երկկողմանի իրական ժամանակի համաժամացումը (նաև աջակցում է ամբողջական կամ ստորակետով բազմակի ընտրության ուղիները)
sync0 group team-docs:// ./docs -p <հանգույցի հասցե>
```

### 4. Թիմի բազմաֆունկցիոնալ խմբի և անդամների թույլտվության կազմաձևում (`.nt` կազմաձևում)

Կանխադրված կազմաձևման գրացուցակը `~/.config/sync0` է (կարելի է փոխարկել `-c <directory>`-ի միջոցով), օգտագործելով մինիմալիստական ​​[NestedText](https://nestedtext.org) (`.nt`) ձևաչափը.
- **Աջակցում է հանրային ցանցի ընթերցումը սահմանափակող (միայն լիազորված օգտվողները կարող են կարդալ)**: Քանի դեռ համօգտագործման խումբը կազմաձևված է `users:` անդամների ցուցակով (կամ հրամանի տողում նշվում է `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`), համակարգը միանում է մասնավոր կերպով (`--auth`): id="6">)** և արգելում է հանրային ցանցի անանուն հանգույցների թվարկումը կամ ընթերցումը, և P2P Բաժանորդագրվելը սերմանող հանգույցներին նույնպես կժառանգի սպիտակ ցուցակը միաժամանակ՝ թույլ տալով կարդալ միայն լիազորված օգտվողներին; համօգտագործվող խմբերը, որոնք կազմաձևված չեն `users`-ով, լռելյայն հրապարակային են և միայն կարդալու համար (եթե ցանկանում եք լինել հանրային և միայն կարդալու և բաց վերբեռնումների համար միայն նշված անդամների համար, կարող եք բացահայտորեն սահմանել `auth: false`):
- **Կարդալ-գրելու նուրբ և ենթատեղեկատուի առաքման թույլտվություններ**. Անդամները լռելյայնորեն միայն կարդալու են (`r` պետք չէ հստակ գրել), և աջակցում են `r` (միայն կարդալու), `w` (միայն գրել բացման տուփում, ոչ ընթեռնելի), <b>re <5">"b-wr": (սահմանափակել ենթագրքի նախածանցը, որը թույլատրվում է վերբեռնման համար):

**Անդամի կազմաձևման օրինակ (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (կանխադրված միայն կարդալու համար, արագության սահմանափակում 80 ՄԲ)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (կարդալու և գրելու թույլտվություններ, թույլատրվում է վերբեռնել միայն նշված ենթագրքում)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (միայն գրելու առաքման թույլտվություն, ընթերցումն արգելված է)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**Խմբի կոնֆիգուրացիայի համօգտագործման օրինակ (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # Չկազմաձևված օգտվողներ. լռելյայն հանրային ցանց միայն կարդալու համար
  dataset:
    path: ./data
    rate: 50MB

  # Կազմաձևված օգտվողներ. ավտոմատ կերպով սահմանափակել հանրային ցանցի ընթերցումը (միայն Ալիսն ու Բոբը կարող են կարդալ, Չարլին կարող է միայն մատուցել և վերբեռնել)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

Սկսեք ծառայությունը (բեռնեք կազմաձևման ֆայլը կամ ուղղակիորեն օգտագործեք հրամանի տողի պարամետրերը՝ հանրային ցանցի ընթերցումը սահմանափակելու և անդամներին լիազորելու համար).

```bash
# Բեռնել ~/.config/sync0/config.nt՝ սկսելու համար
sync0 share --region SHA

# Կամ հրապարակեք անձնական համօգտագործման խումբ մաքուր հրամանի տողի միջոցով (նշեք --allow-* ավտոմատ կերպով սահմանափակելու հանրային ցանցի ընթերցումը, և միայն լիազորված օգտվողները կարող են մուտք գործել այն)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
```

### Ապրանքի հիմնական հատկանիշները

- **Հանրային բանալու հասցեագրման ավտոմատ անցքերի դակիչ**. Կենտրոնական սերվերի և հանրային ցանցի հասցեի կարիք չկա, NAT անցքի ավտոմատ դակիչ` բաշխված ցանցի հանրային բանալու հասցեի հիման վրա:
- **Միլիվայրկյանական մակարդակի իրական ժամանակի համաժամացում և մետատվյալների իրազեկում**. հիմնված է բնօրինակ ֆայլերի իրադարձությունների մոնիտորինգի վրա (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), ֆայլերի հավելումների, ջնջումների իրական ժամանակում, POSIX թույլտվությունների (`mode`) և millisement="d) փոփոխության (`mode`) և millisement="d); զրոյական տվյալների բլոկի փոխանցում, երբ փոփոխվում են միայն թույլտվությունները կամ ժամանակը:
- **BT ոճի միաժամանակյա ներբեռնում և վերբեռնում և տարածաշրջանային մերձեցման ժամանակացույց**. Ներբեռնման հանգույցը կարիք չունի սպասել ամբողջ գումարի ներբեռնմանը: Բոլոր բլոկների միջակայքերը (`Op::Have`), որոնք անցել են 128-բիթանոց հեշ ստուգումը, անմիջապես արգելափակվում են հիշողության/ժամանակավոր լողավազանում, որպեսզի մյուս հանգույցները միաժամանակ քաշեն: Դինամիկ PEX հանգույցների փոխանակման և դանդաղ հանգույցի կիսամյակային կանխարգելման (Work-Stealing) հետ միասին կլաստերի թողունակությունը առավելագույնի է հասցվում:
- **Վնասակար հանգույցների խախտում և կլաստերային թունավորման անձեռնմխելիություն**. հեղինակավոր աղբյուրների ցանկ `root_hash` Ինքնահաստատ կողպում + ապարատային պարտադիր արագացում `gxhash128` մարսողական ստուգում, նախքան յուրաքանչյուր բլոկի տեղադրումը սկավառակի վրա և դրսից սերմանվում է; եթե հայտնաբերվի կեղծված բլոկ, միլիվայրկյան մակարդակի անջատիչը կմարի վնասակար հանգույցը և ինքնաբերաբար կվերականգնվի ազնիվ աղբյուրից:
- **FastCDC in-situ ավելացում և փոքր ֆայլերի համախմբում**. Միայն դիֆերենցիալ բլոկները փոխանցվում են մեծ ֆայլերի մասնակի փոփոխության համար և տեղադրվում սկավառակի վրա; Փոքր ֆայլերի հիշողության զանգվածային փաթեթավորումը և նախածանցի դիֆերենցիալ սեղմումը վերացնում են ֆայլ առ ֆայլ շրջագայությունը վերևից:
- **Հոսանքազրկումից հետո ինքնաբուժում և վերագործարկումից հետո վերսկսում**. Redis-ի նման RDB + AOF հիբրիդային ձևաչափը (`.s0_subs.bin`) օգտագործվում է սերմանման կարգավիճակը և ֆայլերի ցանկը պահպանելու համար, ամենօրյա փոփոխությունները կցվում են միկրովայրկյաններով և ավտոմատ կերպով վերագրվում և կանոնավոր կերպով կազմակերպվում: Սերվերի վերագործարկումից հետո անցանց փոփոխություններն ավտոմատ կերպով տեղափոխվում են սերմնավորման հանգույց:

## Տեխնիկական ճարտարապետություն և փաստաթղթեր

- **Երկակի հարթության անջատման արձանագրություն**.
  - **Վերահսկող և իրական ժամանակի փոփոխության մակերեսը (`iroh` QUIC / TCP, առաջին բայթ `PROTO_VERSION` տարբերակի ձեռքսեղմում) **: Պատասխանատու է Ed25519 այցեքարտի ստուգման, թույլտվության հաստատման, Swarm սերմերի հայտնաբերման և `u64::MAX` մակարդակի զանգվածային փոփոխության հոսքի փաթեթավորման և <b> compressed"-ի համար: (`FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` Երեք պարզունակ):
  - **Տվյալների բաշխման մակերեսը (բնական UDP + `compio` ասինխրոն I/O) **. 20B կոմպակտ վերնագիր, 18B TACK պարբերական արձագանք, BBRv3/Copa հիբրիդային գերբնակվածության վերահսկում, RACK-TLP փաթեթների կորստի վերականգնում, առաջին-բլոկ Shannon entropy adaptive Zstd-ի կողմից: վերջից մինչև վերջ ստուգում.
