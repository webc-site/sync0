# sync0

`sync0`သည် ဗဟိုချုပ်ကိုင်မှု လျှော့ချထားသော P2P ဖိုင်မျှဝေခြင်း၊ အချိန်နှင့်တပြေးညီ ထပ်တူပြုခြင်းနှင့် အရင်းအမြစ်ပေါင်းစုံ ဖြန့်ဖြူးရေးတူးလ်တစ်ခုဖြစ်ပြီး `rsync` - အစားထိုးရန်အသုံးပြုသည့် ဖြတ်ကျော် WAN ၏ တိုင်းတာသည့်အမြန်နှုန်းသည် `rsync` ၏ **5.89×** အထိ (တစ်ခုတည်းသော အမှတ်ဂျီဩမေတြီ ပျမ်းမျှအမြန်နှုန်း ** 2.67×6-**)၊ P2P ပျမ်းမျှအမြန်နှုန်း ** 12 × နှင့် P2P transoceanic high-latency link P2P acceleration သည် **7.68×** အထိ (အပြည့်အစုံ-လင့်ခ် 24-scenario ကျယ်ကျယ်ပြန့်ပြန့် ဂျီဩမေတြီ ပျမ်းမျှအမြန်နှုန်း **2.56×**) အထိ။

စက်တစ်ခုစီသည် ဆာဗာနှင့် ဖောက်သည် နှစ်ခုလုံးဖြစ်သည်- ဗဟိုဆာဗာ သို့မဟုတ် အများသူငှာ ကွန်ရက်လိပ်စာအတွက် မလိုအပ်ပါ၊ အလိုအလျောက် အပေါက်ဖောက်ခြင်းကို ဖြန့်ဝေထားသော ကွန်ရက် အများသူငှာသော့လိပ်စာအပေါ် အခြေခံပြီး ၎င်းသည် စက်နှစ်လုံးကြား တိုက်ရိုက် ထုတ်လွှင့်မှုကို ပံ့ပိုးပေးသည်၊ ၎င်းသည် စက်နှစ်လုံးကြား တိုက်ရိုက် ထုတ်လွှင့်မှု၊ မျှဝေမှုအုပ်စု ခွင့်ပြုချက်ရယူခြင်း၊ လိုအပ်ချက်ပေါ်ရှိ လမ်းညွှန်ခွဲများစွာကို ရွေးချယ်မှု၊ မီလီစက္ကန့်အဆင့် အချိန်နှင့်တပြေးညီ ထပ်လောင်းထပ်တူပြုခြင်း နှင့် P2P အရင်းအမြစ်ပေါင်းစုံ ကိုက်ညီမှုရှိသည်။

## တပ်ဆင်ပါ။

### နည်းလမ်း 1- ကုန်တင်တပ်ဆင်ခြင်း။

```bash
cargo install sync0
```

### နည်းလမ်း 2- precompiled binaries ကို ဒေါင်းလုဒ်လုပ်ပါ။

စနစ်နှင့်သက်ဆိုင်သော ချုံ့ထားသော ပက်ကေ့ဂျ်ကို ဒေါင်းလုဒ်လုပ်ရန် [GitHub Releases](https://github.com/webc-site/sync0/releases) သို့သွားပါ (Linux၊ macOS၊ Windows၊ Android၊ iOS၊ FreeBSD) ကို ဇစ်ဖွင့်ပြီး `PATH`တွင် ထည့်သွင်းပါ-

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## အမြန်စတင်လိုက်ပါ။

### 1. စက်နှစ်လုံးကြားမှ တိုက်ရိုက်ထုတ်လွှင့်မှု သုည (`send` / `recv`)

မျှဝေသည့်အဖွဲ့ကို စီစဉ်သတ်မှတ်ရန် မလိုအပ်ဘဲ၊ စက်နှစ်လုံးကြားတွင် ဖိုင်များ သို့မဟုတ် လမ်းညွှန်များကို တိုက်ရိုက်လွှဲပြောင်းရန် မလိုအပ်ပါ။

```bash
# လက်ခံသည့်အဆုံးသည် ဆိပ်ကမ်းပေါ်တွင် နားထောင်ပြီး ./backup သို့ စာရေးသည်။
sync0 recv 0.0.0.0:9000 ./backup

# ပေးပို့သူထံမှ တိုက်ရိုက်ထုတ်လွှင့်ခြင်း (ချန်လှပ်ထားနိုင်သည် -- ဖိုင်များကို ရှင်းလင်းရန် မှန်ကို ဖျက်ပါ၊ -- 50MB မြန်နှုန်းကန့်သတ်မှုနှုန်းထား)
sync0 send ./project 192.168.1.10:9000
```

### 2. ပို့စ်မျှဝေခြင်းနှင့် လိုအပ်သလောက်ဆွဲ/အပ်လုဒ် (`share` / `pull` / `push`)

```bash
# ဆာဗာ- အမိန့်စာတစ်ကြောင်းဖြင့် မျှဝေသည့်အုပ်စုကို ထုတ်ဝေပါ (စတင်ပြီးနောက် IP-အခမဲ့ iroh node လိပ်စာကို ထုတ်ပါ)
sync0 share dataset:./data

# ကလိုင်းယင့်- ဒေတာအစုံမျှဝေခြင်းအဖွဲ့တစ်ခုလုံးကို ဒေသတွင်း ./local_data သို့ ဆွဲထုတ်ပါ။
sync0 pull dataset:// ./local_data -p <node address>

# Client- လိုအပ်ချက်အရ ရွေးချယ်မှုအများအပြားကို ဆွဲယူပါ (သတ်မှတ်ထားသော ဖိုင်များနှင့် ဖိုင်တွဲခွဲများကိုသာ တစ်ပြိုင်တည်းလုပ်ဆောင်ပါ)
ထပ်တူပြုခြင်း0 ဆွဲယူဒေတာအတွဲ://docs/readme.md၊assets/icons,src/core ./local_data -p <node လိပ်စာ>

# သုံးစွဲသူ- ခွင့်ပြုထားသော မျှဝေမှုအုပ်စုများသို့ ဖိုင်များ သို့မဟုတ် လမ်းညွှန်များကို အပ်လုဒ်လုပ်ပါ။
sync0 push dataset://releases/v1 ./build_output -p <node address>
```

### 3. အချိန်နှင့်တပြေးညီ စာရင်းသွင်းခြင်း မျိုးစေ့ချခြင်း နှင့် စက်ပေါင်းစုံ နှစ်လမ်း ပေါင်းစပ်ခြင်း (`sub` / `group`)

ရှည်လျားသောချိတ်ဆက်မှုတစ်ခုကို တည်ဆောက်ပြီးနောက်၊ အကယ်၍ ဖိုင် **ထည့်သွင်းခြင်း၊ ပြုပြင်ခြင်း၊ ဖျက်ခြင်း၊ ခွင့်ပြုချက်ပြောင်းလဲခြင်း သို့မဟုတ် ပြုပြင်မွမ်းမံချိန်** သည် အဝေးမှအဆုံးတွင် ဖြစ်ပေါ်ပါက၊ စက်တွင်းလမ်းညွှန်ကို အချိန်နှင့်တပြေးညီ မီလီစက္ကန့်အတွင်း ထပ်တူပြု၍ အပ်ဒိတ်လုပ်မည် (အသစ်/မွမ်းမံထားသော ဖိုင်ကြီးများသည် မတူညီသောပိတ်ဆို့မှုများကိုသာ ဆွဲထုတ်ပြီး ၎င်းတို့ကို အပ်ဒိတ်လုပ်မည်၊ ဖိုင်များကို ဖျက်ပစ်မည်)၊ ဖိုင်များကို ဖျက်လိုက်သည် ဒေသဆိုင်ရာဖိုင်များနှင့် ဗလာကျင်းထားသောဒေတာများကို တိုက်ရိုက်ရှင်းလင်းပေးလိမ့်မည် သို့မဟုတ် ပိတ်ဆို့သည့်အကြိမ်များသာ ပြောင်းလဲသွားပါမည်။

- **`sync0 sub`(တစ်ကြောင်းတည်းဖြင့် အချိန်နှင့်တပြေးညီ ပုံတူကူးချခြင်း + အလိုအလျောက် မျိုးစေ့ထုတ်ခြင်း)**- ဒေသန္တရအချိန်သည် မျှဝေခြင်းအဆုံး၏ ထပ်တိုးမှုများ၊ ဖျက်ခြင်းနှင့် ပြုပြင်မွမ်းမံမှုများကို လိုက်နာပြီး အခြားဆွဲတင်သည့်နေရာများအတွက် တစ်ပြိုင်နက်တည်း အရှိန်မြှင့်ပေးရန်အတွက် P2P မျိုးစေ့အရင်းအမြစ်အဖြစ် အလိုအလျောက်ဆောင်ရွက်ပေးပါသည်။
- **`sync0 group`(Multi-machine peer-to-peer two-way real-time synchronization)**- ဖိုင်များကို အဖွဲ့တွင်းရှိ မည်သည့်စက်တွင်မဆို ထည့်သွင်းခြင်း၊ ဖျက်ပစ်ခြင်း သို့မဟုတ် ပြုပြင်ပါက၊ အခြားအွန်လိုင်း node အားလုံးကို အချိန်နှင့်တပြေးညီ အပ်ဒိတ်လုပ်မည်ဖြစ်ပြီး တစ်ခုနှင့်တစ်ခု အစေ့များအဖြစ် ဆောင်ရွက်ပါသည်။

```bash
# မျှဝေမှုအုပ်စုတစ်ခုလုံးကို စာရင်းသွင်းပါ- အဝေးမှ ထပ်လောင်းမှုများ၊ ဖျက်မှုများနှင့် ပြုပြင်မွမ်းမံမှုများကို စက်တွင်းအချိန်နှင့် တစ်ပြေးညီ ထပ်တူပြုပြီး အလိုအလျောက် မျိုးစေ့ချပါသည်။
sync0 sub dataset:// ./local_mirror -p <node address>

# လိုအပ်ချက်အလိုက် ရွေးချယ်မှုများစွာသော စာရင်းသွင်းမှု- အချိန်နှင့်တပြေးညီ သတ်မှတ်ထားသော ဖိုင်များနှင့် ဖိုင်တွဲခွဲများကိုသာ တစ်ပြိုင်တည်းလုပ်ဆောင်ပြီး မျိုးစေ့ချပါ
ထပ်တူပြုခြင်း0 ခွဲဒေတာအတွဲ://models/llama.onnx၊configs ./local_mirror -p <node လိပ်စာ>

# စက်အစုံပါသော သက်တူရွယ်တူအုပ်စုနှစ်စုကို အချိန်နှင့်တစ်ပြေးညီ ထပ်တူပြုခြင်း (အပြည့်အဝ သို့မဟုတ် ကော်မာ အစုံရွေးချယ်သောလမ်းကြောင်းများကိုလည်း ပံ့ပိုးပေးသည်)
sync0 အဖွဲ့ team-docs:// ./docs -p <node address>
```

### 4. အဖွဲ့ပေါင်းစုံ မျှဝေသည့်အဖွဲ့နှင့် အဖွဲ့ဝင်ခွင့်ပြုချက်ဖွဲ့စည်းပုံ (`.nt`ဖွဲ့စည်းပုံ)

ပုံသေဖွဲ့စည်းပုံလမ်းညွှန်သည် `~/.config/sync0` (`-c <directory>`) မှတဆင့် ပြောင်းနိုင်သည်)၊ အနည်းငယ်မျှသာသော [NestedText](https://nestedtext.org) (`.nt`) ဖော်မတ်-
- ** အများသူငှာ ကွန်ရက်ဖတ်ရှုခြင်းကို ကန့်သတ်ခြင်းကို ပံ့ပိုးပေးသည် (ခွင့်ပြုထားသော အသုံးပြုသူများသာ ဖတ်နိုင်သည်)**: မျှဝေသည့်အဖွဲ့အား `users:`အဖွဲ့ဝင်စာရင်းဖြင့် ပြင်ဆင်သတ်မှတ်ထားသရွေ့ (သို့မဟုတ် အမိန့်ပေးစာကြောင်းက `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`၊ စနစ်သည် ** အများသူငှာ သီးသန့်ကွန်ရက်ကို အလိုအလျောက် ဖွင့်ပေးသည်**** အမည်မသိ node စာရင်းကောက်ယူခြင်း သို့မဟုတ် ဖတ်ခြင်း နှင့် P2P သည် seeding node များကို စာရင်းသွင်းခြင်းဖြင့် whitelist ကို တစ်ပြိုင်နက်တည်း အမွေဆက်ခံရမည်ဖြစ်ပြီး၊ ခွင့်ပြုထားသောအသုံးပြုသူများကိုသာ ဖတ်ခွင့်ပြုမည်ဖြစ်သည်။ `users` ဖြင့် ပုံသေသတ်မှတ်မထားသော မျှဝေခြင်းအုပ်စုများသည် အများသူငှာ ဖတ်ရှုရန်သာဖြစ်သည် (ပုံမှန်အားဖြင့် အများသူငှာ ဖတ်ရှုရန်သာဖြစ်ပြီး သတ်မှတ်ထားသောအဖွဲ့ဝင်များသို့သာ အပ်လုဒ်လုပ်ရန် ဖွင့်ထားလိုပါက၊ သင်သည် အတိအလင်းသတ်မှတ်နိုင်သည် `auth: false`)။
- **အနုစိတ်ဖတ်-ရေးခြင်းနှင့် လမ်းညွှန်ချက်ခွဲခွဲပေးပို့ခြင်းခွင့်ပြုချက်များ**: အဖွဲ့ဝင်များသည် ပုံမှန်အားဖြင့် ဖတ်ရန်သာဖြစ်သည် (`r` အတိအလင်းရေးထားရန် မလိုအပ်ပါ)၊ နှင့် ပံ့ပိုးပေးခြင်း `r` (ဖတ်ရန်သာ)၊ `w` (ဖတ်ရန်မဖြစ်နိုင်သော drop box တွင်သာရေးပါ) <b id="4iteid"> (direct-bry) ရှေ့တန်းတင်ရန် ခွင့်ပြုထားသည်။)

**အဖွဲ့ဝင်ဖွဲ့စည်းပုံဥပမာ (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (မူရင်းဖတ်ရန်သာ၊ အမြန်နှုန်းကန့်သတ်ချက် 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (စာဖတ်ခြင်းနှင့် ရေးခြင်းခွင့်ပြုချက်များ၊ သတ်မှတ်ထားသော လမ်းကြောင်းခွဲများသို့သာ အပ်လုဒ်လုပ်ခွင့်ပြုသည်)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (ပေးပို့ခြင်းခွင့်ပြုချက်ဖြင့်သာ ရေးသားခြင်း၊ စာဖတ်ခြင်းကို တားမြစ်ထားသည်)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**အဖွဲ့ဖွဲ့စည်းပုံဥပမာကို မျှဝေခြင်း (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # သတ်မှတ်မထားသော အသုံးပြုသူများ- ပုံသေ အများသူငှာ ကွန်ရက် ဖတ်ရန်သာ
  dataset:
    path: ./data
    rate: 50MB

  # စီစဉ်သတ်မှတ်ထားသော အသုံးပြုသူများ- အများသူငှာ ကွန်ရက်ဖတ်ရှုခြင်းကို အလိုအလျောက်ကန့်သတ်သည် (alice နှင့် bob တို့သာ ဖတ်နိုင်သည်၊ charlie ကသာ ပေးပို့နိုင်ပြီး အပ်လုဒ်လုပ်နိုင်သည်)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

ဝန်ဆောင်မှုကို စတင်ပါ (ဖွဲ့စည်းပုံဖိုင်ကို တင်ပါ သို့မဟုတ် အများသူငှာ ကွန်ရက်ဖတ်ရှုခြင်းကို ကန့်သတ်ရန်နှင့် အဖွဲ့ဝင်များကို ခွင့်ပြုရန် အမိန့်ပေးလိုင်းဘောင်များကို တိုက်ရိုက်အသုံးပြုပါ)

```bash
# စတင်ရန် ~/.config/sync0/config.nt ကို တင်ပါ။
sync0 share --region SHA

# သို့မဟုတ် သီးသန့်ခွဲဝေမှုအဖွဲ့အား သန့်ရှင်းသော အမိန့်ပေးစာကြောင်းမှတစ်ဆင့် ထုတ်ဝေပါ (--allow-* အား အများသူငှာ ကွန်ရက်ဖတ်ရှုခြင်းကို အလိုအလျောက်ကန့်သတ်ရန်နှင့် ခွင့်ပြုထားသည့် အသုံးပြုသူများသာ ၎င်းကို ဝင်ရောက်ကြည့်ရှုနိုင်သည်)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

```bash
# ဒေသတွင်း IP မပါသော node လိပ်စာကိုကြည့်ပါ (ပထမ run အတွက် သော့ကို အလိုအလျောက်ထုတ်ပေးသည်)

# Ed25519 ကိုယ်တိုင်ရေးထိုးထားသော node လုပ်ငန်းကတ် (အမည်ပြောင်၊ မြို့ကုဒ်၊ အီးမေးလ်၊ ဝဘ်ဆိုက်၊ မိတ်ဆက်) ကို ထုတ်လုပ်ပါ
```

### အဓိကထုတ်ကုန်အင်္ဂါရပ်များ

- ** အလိုအလျောက် အပေါက်ဖောက်ခြင်းကို ဖြေရှင်းသည့် အများသူငှာသော့ **- ဗဟိုဆာဗာနှင့် အများသူငှာ ကွန်ရက်လိပ်စာ၊ ဖြန့်ဝေထားသော ကွန်ရက် အများသူငှာသော့လိပ်စာအပေါ် အခြေခံ၍ အလိုအလျောက် NAT အပေါက်ဖောက်ခြင်း မလိုအပ်ပါ။
- **Millisecond-level real-time synchronization and metadata awareness**- ဇာတိဖိုင်ဖြစ်ရပ်စောင့်ကြည့်မှုအပေါ်အခြေခံ၍ (`FSEvents` / `inotify` / `ReadDirectoryChangesW`)၊ ဖိုင်ထည့်သွင်းမှု၊ ဖျက်မှု၊ POSIX ခွင့်ပြုချက်များ (`mode`) နှင့် millisecond-level မွမ်းမံမှုအချိန် (<b); ခွင့်ပြုချက်များ သို့မဟုတ် အချိန်များကိုသာ ပြုပြင်သည့်အခါတွင် ဒေတာပိတ်ဆို့ခြင်းအား သုညထုတ်လွှင့်ခြင်း
- ** BT-စတိုင် တပြိုင်နက်တည်း ဒေါင်းလုဒ်လုပ်ခြင်းနှင့် အပ်လုဒ်လုပ်ခြင်းနှင့် ဒေသဆိုင်ရာ ရင်းနှီးမှုအချိန်ဇယားဆွဲခြင်း**- ဒေါင်းလုဒ်ဆွဲသည့်နေရာသည် ဒေါင်းလုဒ်လုပ်ရန် ပမာဏပြည့်သည်အထိ စောင့်ရန် မလိုအပ်ပါ။ 128-bit hash check ကိုကျော်သွားသော ပိတ်ဆို့သည့်ကြားကာလများအားလုံးကို (`Op::Have`) သည် အခြား node များကို တစ်ပြိုင်နက်ဆွဲယူနိုင်စေရန် memory/temporary pool တွင် ချက်ချင်းသော့ခတ်ထားသည်။ ပြောင်းလဲနေသော PEX node လဲလှယ်ခြင်းနှင့် နှေးကွေးသော node တစ်ဝက်ကြိုတင်ပြင်ဆင်ခြင်း (Work-Stealing) တို့နှင့်အတူ၊ အစုလိုက်အပြုံလိုက်ထုတ်လွှင့်မှုကို ချဲ့ထွင်ထားပါသည်။
- **မလိုလားအပ်သော node များကို လက်ဆော့ခြင်းနှင့် အစုလိုက်အဆိပ်သင့်စေသော ကိုယ်ခံစွမ်းအား**: တရားဝင်အရင်းအမြစ်စာရင်း `root_hash`ကိုယ်တိုင် တစ်သမတ်တည်းသော့ခတ်ခြင်း + မဖြစ်မနေ ဟာ့ဒ်ဝဲ အရှိန်မြှင့်ခြင်း `gxhash128` ဘလောက်တစ်ခုစီကို ဒစ်ပေါ်တွင် ချထားပြီး ပြင်ပတွင် မျိုးစေ့ချခြင်းမပြုမီ ချေဖျက်အတည်ပြုခြင်း၊ ခိုးယူထားသော ဘလောက်တစ်ခုကို တွေ့ရှိပါက၊ မီလီစက္ကန့်အဆင့် circuit breaker သည် အန္တရာယ်ရှိသော node ကို မီးပိတ်ပြီး ရိုးသားသော အရင်းအမြစ်မှ အလိုအလျောက် ပြန်လည်ရယူမည်ဖြစ်သည်။
- **FastCDC in-site increment increment and small file aggregation**- ဖိုင်ကြီးများကို တစ်စိတ်တစ်ပိုင်း ပြုပြင်မွမ်းမံရန်အတွက် ကွဲပြားသော ဘလောက်များကိုသာ လွှဲပြောင်းပြီး disk ပေါ်တွင် ထားရှိပါ။ ကြီးမားသော သေးငယ်သော ဖိုင်မှတ်ဉာဏ် ထုပ်ပိုးမှုနှင့် ရှေ့ဆုံး ကွဲပြားမှု ချုံ့မှုတို့သည် ဖိုင်တစ်ဖိုင်မှ အသွားအပြန် ပေါ်လာခြင်းကို ဖယ်ရှားပေးသည်။
- **ဓာတ်အားပြတ်တောက်ပြီး ပြန်လည်စတင်ပြီးနောက် ပြန်လည်စတင်ပြီးနောက် မိမိကိုယ်ကို ကုသခြင်း**- Redis-like RDB + AOF ပေါင်းစပ်ဖော်မတ် (`.s0_subs.bin`) ကို မျိုးစေ့အခြေအနေနှင့် ဖိုင်စာရင်းကို ဆက်လက်ထိန်းသိမ်းထားရန်အတွက် အသုံးပြုထားပြီး၊ နေ့စဉ်ပြောင်းလဲမှုများကို မိုက်ခရိုစက္ကန့်များဖြင့် ပေါင်းထည့်ကာ အလိုအလျောက် ပြန်လည်ပြင်ဆင်ပြီး ပုံမှန်လုပ်ဆောင်ပါသည်။ ဆာဗာကို ပြန်လည်စတင်ပြီးနောက်၊ အော့ဖ်လိုင်းပြောင်းလဲမှုများကို မျိုးစေ့ထုတ် node သို့ အလိုအလျောက် တွန်းပို့ပါသည်။

## နည်းပညာဗိသုကာနှင့် စာတမ်းပြုစုခြင်း။

- ** လေယာဉ်နှစ်စင်း ခွဲထုတ်ခြင်း ပရိုတိုကော**-
  - **ထိန်းချုပ်မှုနှင့် အချိန်နှင့်တပြေးညီ ပြောင်းလဲမှု မျက်နှာပြင် (`iroh` QUIC / TCP, first byte `PROTO_VERSION`ဗားရှင်း လက်ဆွဲနှုတ်ဆက်ခြင်း) **- Ed25519 လုပ်ငန်းကတ် အတည်ပြုခြင်း၊ ခွင့်ပြုချက် အတည်ပြုခြင်း၊ Swarm seed ရှာဖွေတွေ့ရှိခြင်းနှင့် `u64::MAX`အဆင့် အစုလိုက်အပြုံလိုက် ပြောင်းလဲခြင်း ထုတ်လွှင့်ခြင်း batching နှင့် <b <b <b> အချိန်နှင့်တစ်ပြေးညီ ပြောင်းလဲခြင်း > (ချုံ့ 5) <b <bid="4"> id="6"> / `FsOp::Remove` / `FsOp::Meta` ရှေးရိုးသုံးဆင့်)။
  - **ဒေတာဖြန့်ချီရေးမျက်နှာပြင် (ဇာတိ UDP + `compio` အညီအမျှ I/O) **- 20B ကျစ်လစ်သော ခေါင်းစီး၊ 18B TACK အချိန်အပိုင်းအခြားအလိုက် တုံ့ပြန်ချက်၊ BBRv3/Copa ပေါင်းစပ်ပိတ်ဆို့ခြင်း ထိန်းချုပ်မှု၊ RACK-TLP ပက်ကက်ဆုံးရှုံးမှု ပြန်လည်ရယူရေး၊ first-block Shannon entropy adaptive Zstd verification blockid.to-end၊ နှင့်
