# sync0

`sync0` е инструмент за команден ред за прехвърляне на файлове през мрежи, постепенно синхронизиране на директории и едновременно разпространение на данни към множество машини.

## Оригинално дизайнерско намерение

В различни машинни зали, държави или среди със закъснения в мрежата и загуба на пакети, инструменти като `rsync` и `scp` се основават на потвърждение на единична последователност на свързване, което ограничава използването на честотната лента; когато няколко машини изтеглят данни от един и същи сървър едновременно, мрежовата карта на сървъра източник може лесно да се превърне в тясно място.

Целта на `sync0` е да разреши два проблема:

1. Оставете синхронизирането на файлове и директории между двете машини да работи с пълна физическа честотна лента и прехвърляйте променената част само когато файлът е частично модифициран.
2. Множество машини могат да прехвърлят блокове данни една към друга, когато синхронизират една и съща директория, намалявайки натоварването на сървъра източник и съкращавайки общото време за синхронизиране.

## Сравнение на скоростта с rsync

Тестова среда: Европейски възел $\leftrightarrow$ Северноамерикански възел, двупосочно забавяне 86 ms, измерване на пълното отнемане на време, включително сканиране на директория, сравнение на дедупликация, мрежово предаване и проверка на разположението на диска:

| Сценарий на предаване | Размер на данните | `sync0` | `rsync` | множество |
| :--- | :---: | :---: | :---: | :---: |
| 10 000 малки файла | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| Пакети с код и архив (`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| Видео файл (`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| Постепенна синхронизация (промяна на 1% съдържание) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## Методи за подобряване на производителността

- **UDP едновременно предаване**: Изпращайте блокове данни чрез UDP и препредавайте само загубени фрагменти, за да избегнете загуба на единичен пакет, блокиращ последващи прехвърляния на файлове.
- **Сегментиране на съдържанието и дедупликация**: Разделете файла на блокове данни според съдържанието и изчислете стойността за проверка. Същото съдържание, което вече е на приемащия край, се използва повторно директно локално, без да се дублира мрежата.
- **Автоматично регулиране на компресията според скоростта на мрежата**: Включете компресията за компресируемо съдържание като текст и код; автоматично пропускане на компресията за видеоклипове, снимки, компресирани пакети или при високоскоростна LAN, за да намали потреблението на процесора.
- **Изтегляне на много възли наблизо**: Когато няколко машини изтеглят една и съща директория, блоковете данни ще бъдат изтеглени едновременно от изтеглени възли в същия град или с по-ниска латентност.

## Инсталирайте

### Метод 1: Инсталирайте чрез Cargo

```bash
cargo install sync0
```

### Метод 2: Изтеглете предварително компилирани двоични файлове

Отидете на [GitHub Releases](https://github.com/webc-site/sync0/releases), за да изтеглите `.tar.xz` компресирания пакет за съответната система (поддържа Linux x86_64/ARM64, macOS Apple Silicon/Intel, Windows x64/ARM64, Android ARM64/x86_64, FreeBSD, NetBSD). След като разархивирате, поставете `sync0` в директорията `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Ръководство за потребителя

### 1. Директно прехвърляне на файлове или директории между две машини

Стартирайте наблюдението на приемащата машина и посочете пътя за получаване и запис:

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

Изпратете един файл или цяла директория от изпращащата машина:

```bash
sync0 send ./project 192.168.1.10:9000
```

Често използвани параметри:

```bash
# Изтриване на излишни файлове, които съществуват в получаващата страна, но не и в изпращащата (огледална синхронизация)
sync0 send ./project 192.168.1.10:9000 --delete

# Ограничете скоростта на изпращане (единица: байтове/секунда, например 50 MB/s)
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# Тих режим (не се показва лента за напредък)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. Публикуване на споделени директории и изтегляне от множество възли

Публикувайте споделена директория (с име `dataset`) на началния сървър:

```bash
sync0 share dataset ./data --region SHA
```

Изтеглете споделената директория на други машини (можете да попълните множество адреси на възли едновременно, разделени със запетаи, за да изтеглите едновременно):

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

Изтеглете само определена поддиректория в споделената директория:

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

Избутайте локалните промени обратно в отдалечената споделена директория:

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. Абонирайте се за автоматични актуализации на каталога

Абонирайте се за споделената директория на изходния възел. Когато файл се добави или модифицира в изходната директория, той автоматично ще се синхронизира с локалния компютър. В същото време локалната машина автоматично ще служи като възел за изтегляне на други машини:

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. Двупосочна синхронизация на многомашинни групи

Няколко машини се присъединяват към едно и също име на група и промените във всяка директория на възел ще бъдат автоматично синхронизирани с други възли в групата:

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. Идентификация на възела и лична визитка

Всеки възел поддържа задаване на потребителско име, град, имейл, уебсайт и персонализиран подпис (максимум 256 знака) и преминава удостоверяване на подписа на локалния частен ключ:

```bash
# Вижте идентификатора на локалния публичен ключ (посочете конфигурационната директория, за да запазите ключа)
sync0 id -c ~/.config/sync0

# Генерирайте и покажете визитки на възли с персонализирани подписи
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`, `pull`, `sub`, `group` също могат да бъдат стартирани с тези параметри на профила:

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. Многоезично превключване

`sync0` Поддържа 75 езика. По подразбиране помощта и подканите на командния ред на съответния език се показват автоматично според езиковата среда на операционната система; ако системният език не е в поддържания списък, по подразбиране се използва английски.

За да посочите езика ръчно, задайте променливата на средата `SYNC0_LANG`:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
