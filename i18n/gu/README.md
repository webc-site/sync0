# sync0

`sync0` એ વિકેન્દ્રિત P2P ફાઇલ શેરિંગ, રીઅલ-ટાઇમ સિંક્રોનાઇઝેશન અને મલ્ટિ-સોર્સ ડિસ્ટ્રિબ્યુશન ટૂલ છે જેનો ઉપયોગ `rsync`ને બદલવા માટે થાય છે - ટ્રાન્સકોન્ટિનેન્ટલ WAN ની માપેલી ઝડપ `rsync`ની **5.89×** (સિંગલ પોઈન્ટ ભૌમિતિક સરેરાશ ઝડપ **2.67 × 2.67 પી. 2.67-સોર્સ સરેરાશ ઝડપ) સુધીની છે. **3.16×**), અને ટ્રાન્સસેનિક હાઇ-લેટન્સી લિંક P2P પ્રવેગક **7.68×** (સંપૂર્ણ-લિંક 24-પરિદ્રશ્ય વ્યાપક ભૌમિતિક સરેરાશ ઝડપ **2.56×**) સુધી છે.

દરેક મશીન સર્વર અને ક્લાયંટ બંને છે: સેન્ટ્રલ સર્વર અથવા જાહેર નેટવર્ક સરનામાંની કોઈ જરૂર નથી, ઓટોમેટિક હોલ પંચિંગ ડિસ્ટ્રિબ્યુટેડ નેટવર્ક પબ્લિક કી એડ્રેસ પર આધારિત છે, અને તે બે મશીનો વચ્ચે ડાયરેક્ટ ટ્રાન્સમિશનને સપોર્ટ કરે છે, મલ્ટિ-શેરિંગ ગ્રૂપ પરમિશન હોસ્ટિંગ, ડિમાન્ડ પર સબડિરેક્ટરીઝની બહુવિધ પસંદગી, મિલિસેકન્ડ-લેવલ રીઅલ-ટાઇમ ઇન્ક્રીમેન્ટલ પીસી-2 સિંક્રનાઇઝેશન મલ્ટિ-સોર્સ સિંક્રનાઇઝેશન.

## ઇન્સ્ટોલ કરો

### પદ્ધતિ 1: કાર્ગો ઇન્સ્ટોલેશન

```bash
cargo install sync0
```

### પદ્ધતિ 2: પૂર્વસંકલિત દ્વિસંગી ડાઉનલોડ કરો

સિસ્ટમને અનુરૂપ `.tar.xz` સંકુચિત પેકેજ ડાઉનલોડ કરવા માટે [GitHub Releases](https://github.com/webc-site/sync0/releases) પર જાઓ (Linux, macOS, Windows, Android, iOS, FreeBSD ને સપોર્ટ કરે છે), અનઝિપ કરો અને `PATH` માં મૂકો:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## ઝડપથી શરૂ કરો

### 1. બે મશીનો વચ્ચે ઝીરો-કોન્ફિગરેશન ડાયરેક્ટ ટ્રાન્સમિશન (`send` / `recv`)

શેરિંગ જૂથને ગોઠવવાની જરૂર નથી, બે મશીનો વચ્ચે સીધી ફાઇલો અથવા ડિરેક્ટરીઓ ઉચ્ચ ઝડપે સ્થાનાંતરિત કરો:

```bash
# પ્રાપ્ત કરનાર અંત પોર્ટ પર સાંભળે છે અને ./backup પર લખે છે
sync0 recv 0.0.0.0:9000 ./backup

# પ્રેષક તરફથી ડાયરેક્ટ ટ્રાન્સમિશન (વૈકલ્પિક --વધારાની ફાઇલોને સાફ કરવા માટે મિરર કાઢી નાખો, --રેટ 50MB ઝડપ મર્યાદા)
sync0 send ./project 192.168.1.10:9000
```

### 2. પોસ્ટ શેરિંગ અને માંગ પર ખેંચો/અપલોડ કરો (`share` / `pull` / `push`)

```bash
# સર્વર: આદેશની એક લાઇન સાથે શેરિંગ જૂથ પ્રકાશિત કરો (સ્ટાર્ટઅપ પછી IP-ફ્રી ઇરોહ નોડ સરનામું આઉટપુટ કરો)
sync0 share dataset:./data

# ક્લાયંટ: સમગ્ર ડેટાસેટ શેરિંગ જૂથને સ્થાનિક ./local_data પર ખેંચો
sync0 પુલ ડેટાસેટ:// ./local_data -p <નોડ સરનામું>

# ક્લાયંટ: માંગ પર બહુવિધ પસંદગીઓ ખેંચો (ફક્ત ઉલ્લેખિત સિંગલ ફાઇલો અને સબડિરેક્ટરીઝને સિંક્રનાઇઝ કરો)
sync0 પુલ ડેટાસેટ://docs/readme.md,assets/icons,src/core ./local_data -p <નોડ સરનામું>

# ક્લાયન્ટ: અધિકૃત શેરિંગ જૂથોમાં ફાઇલો અથવા ડિરેક્ટરીઓ અપલોડ કરો
sync0 push dataset://releases/v1 ./build_output -p <નોડ સરનામું>
```

### 3. રીઅલ-ટાઇમ સબ્સ્ક્રિપ્શન સીડીંગ અને મલ્ટિ-મશીન ટુ-વે સિંક્રોનાઇઝેશન (`sub` / `group`)

લાંબુ કનેક્શન સ્થાપિત કર્યા પછી, જો કોઈ ફાઇલ **ઉમેરવું, સંશોધિત કરવું, કાઢી નાખવું, પરવાનગીઓ બદલવી અથવા ફેરફાર કરવાનો સમય** રીમોટ છેડે થાય, તો સ્થાનિક ડિરેક્ટરી રીઅલ ટાઇમમાં મિલિસેકન્ડ્સમાં સિંક્રનસ રીતે અપડેટ કરવામાં આવશે (નવી/સંશોધિત મોટી ફાઇલો માત્ર તફાવતના બ્લોક્સને ખેંચશે અને તેને સ્થાને અપડેટ કરશે, ફાઇલો કાઢી નાખવાથી આપોઆપ સ્થાનિક ફાઇલો સાફ થશે અને માત્ર ડાયરેક્ટર ડેટામાં ફેરફાર થશે. સીધા બ્લોક્સ):

- **`sync0 sub`(વન-વે રીઅલ-ટાઇમ મિરરિંગ + ઓટોમેટિક સીડીંગ)**: સ્થાનિક રીઅલ-ટાઇમ શેરિંગ એન્ડના ઉમેરાઓ, કાઢી નાખવા અને ફેરફારોને અનુસરે છે અને અન્ય પુલિંગ નોડ્સ માટે સમવર્તી પ્રવેગક પ્રદાન કરવા માટે આપમેળે P2P બીજ સ્ત્રોત તરીકે સેવા આપે છે.
- **`sync0 group`(મલ્ટી-મશીન પીઅર-ટુ-પીઅર ટુ-વે રીઅલ-ટાઇમ સિંક્રોનાઇઝેશન)**: જો જૂથમાં કોઈપણ મશીન પર ફાઇલો ઉમેરવામાં આવે છે, કાઢી નાખવામાં આવે છે અથવા સંશોધિત કરવામાં આવે છે, તો અન્ય તમામ ઑનલાઇન નોડ્સ રીઅલ ટાઇમમાં સિંક્રનસ રીતે અપડેટ કરવામાં આવશે અને એકબીજા માટે બીજ તરીકે સેવા આપશે.

```bash
# સમગ્ર શેરિંગ જૂથમાં સબ્સ્ક્રાઇબ કરો: રિમોટ ઉમેરાઓ, કાઢી નાખવા અને ફેરફારો સ્થાનિક રીતે રીઅલ ટાઇમમાં સિંક્રનાઇઝ થાય છે અને આપમેળે સીડ થાય છે
sync0 સબ ડેટાસેટ:// ./local_mirror -p <નોડ સરનામું>

# ઑન-ડિમાન્ડ મલ્ટિ-સિલેક્ટ સબ્સ્ક્રિપ્શન: રીઅલ ટાઇમમાં ફક્ત સિંક્રનાઇઝ અને ઉલ્લેખિત સિંગલ ફાઇલો અને સબડિરેક્ટરીઝને સીડ કરો
sync0 સબ ડેટાસેટ://models/llama.onnx,configs ./local_mirror -p <નોડ સરનામું>

# મલ્ટી-મશીન પીઅર ગ્રૂપ ટુ-વે રીઅલ-ટાઇમ સિંક્રોનાઇઝેશન (સંપૂર્ણ અથવા અલ્પવિરામ મલ્ટિ-સિલેક્ટ પાથને પણ સપોર્ટ કરે છે)
sync0 group team-docs:// ./docs -p <node address>
```

### 4. ટીમ મલ્ટિ-શેરિંગ જૂથ અને સભ્ય પરવાનગી ગોઠવણી (`.nt` ગોઠવણી)

ડિફૉલ્ટ રૂપરેખાંકન નિર્દેશિકા છે `~/.config/sync0` (`-c <directory>` દ્વારા સ્વિચ કરી શકાય છે), ઓછામાં ઓછા [NestedText](https://nestedtext.org) (`.nt`) ફોર્મેટનો ઉપયોગ કરીને:
- **સાર્વજનિક નેટવર્ક વાંચનને પ્રતિબંધિત કરવાનું સમર્થન કરે છે (ફક્ત અધિકૃત વપરાશકર્તાઓ જ વાંચી શકે છે)**: જ્યાં સુધી શેરિંગ જૂથ `users:` સભ્ય સૂચિ સાથે ગોઠવાયેલ હોય (અથવા આદેશ વાક્ય `--allow-r` / `--allow-rw` / `--allow-w` / `--auth` નિર્દિષ્ટ કરે છે ત્યાં સુધી, સિસ્ટમ ** આપોઆપ ચાલુ થાય છે અને `--auth` આપમેળે ચાલુ થાય છે. સાર્વજનિક નેટવર્ક અનામી નોડની ગણતરી અથવા વાંચન પર પ્રતિબંધ મૂકે છે, અને P2P સીડિંગ નોડ્સ માટે સબ્સ્ક્રાઇબ કરવાથી વારાફરતી વ્હાઇટલિસ્ટ પણ પ્રાપ્ત થશે, ફક્ત અધિકૃત વપરાશકર્તાઓને વાંચવાની મંજૂરી આપશે; શેરિંગ જૂથો કે જે `users` સાથે રૂપરેખાંકિત નથી તે ડિફૉલ્ટ રૂપે સાર્વજનિક છે અને ફક્ત વાંચવા માટે છે (જો તમે સાર્વજનિક અને ફક્ત વાંચવા માટે અને ફક્ત ઉલ્લેખિત સભ્યો માટે અપલોડ કરવા માટે ખુલ્લા રહેવા માંગતા હો, તો તમે સ્પષ્ટપણે `auth: false` સેટ કરી શકો છો).
- **ફાઇન-ગ્રેઇન્ડ રીડ-રાઇટ અને સબડાયરેક્ટરી ડિલિવરી પરવાનગીઓ**: સભ્યો ડિફૉલ્ટ રૂપે ફક્ત વાંચવા માટે હોય છે (`r` સ્પષ્ટ રીતે લખવાની જરૂર નથી), અને સમર્થન `r` (ફક્ત વાંચવા માટે), `w` (માત્ર ડ્રોપ બોક્સ પર લખો, વાંચી શકાય નહીં), <b <b-id="limit"> (5) વાંચો (5) સબડિરેક્ટરી ઉપસર્ગ અપલોડ કરવા માટે માન્ય છે).

**સભ્ય ગોઠવણીનું ઉદાહરણ (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (ડિફોલ્ટ ફક્ત વાંચવા માટે, ઝડપ મર્યાદા 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (વાંચવા અને લખવાની પરવાનગી, માત્ર ઉલ્લેખિત સબડિરેક્ટરી પર અપલોડ કરવાની મંજૂરી)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (ફક્ત ડિલિવરીની પરવાનગી લખો, વાંચન પ્રતિબંધિત છે)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**શેરિંગ જૂથ ગોઠવણીનું ઉદાહરણ (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # રૂપરેખાંકિત વપરાશકર્તાઓ નથી: ડિફૉલ્ટ સાર્વજનિક નેટવર્ક ફક્ત વાંચવા માટે
  dataset:
    path: ./data
    rate: 50MB

  # રૂપરેખાંકિત વપરાશકર્તાઓ: આપમેળે જાહેર નેટવર્ક વાંચનને પ્રતિબંધિત કરો (ફક્ત એલિસ અને બોબ વાંચી શકે છે, ચાર્લી ફક્ત વિતરિત અને અપલોડ કરી શકે છે)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

સેવા શરૂ કરો (રૂપરેખાંકન ફાઇલ લોડ કરો અથવા જાહેર નેટવર્ક વાંચનને પ્રતિબંધિત કરવા અને સભ્યોને અધિકૃત કરવા માટે સીધા આદેશ વાક્ય પરિમાણોનો ઉપયોગ કરો):

```bash
# શરૂ કરવા માટે ~/.config/sync0/config.nt લોડ કરો
sync0 share --region SHA
```

### મુખ્ય ઉત્પાદન સુવિધાઓ

- **પબ્લિક કી એડ્રેસિંગ ઓટોમેટિક હોલ પંચિંગ**: સેન્ટ્રલ સર્વર અને પબ્લિક નેટવર્ક એડ્રેસની જરૂર નથી, વિતરિત નેટવર્ક પબ્લિક કી એડ્રેસ પર આધારિત ઓટોમેટિક NAT હોલ પંચિંગ.
- **મિલિસેકન્ડ-લેવલ રીઅલ-ટાઇમ સિંક્રનાઇઝેશન અને મેટાડેટા જાગરૂકતા**: મૂળ ફાઇલ ઇવેન્ટ મોનિટરિંગ (`FSEvents` / `inotify` / `ReadDirectoryChangesW`) પર આધારિત, ફાઇલ ઉમેરણો, કાઢી નાખવા, POSIX પરવાનગીઓ (`mode`) અને મિલિસેકન્ડ-સમય (`mode`) અને મિલિસેકન્ડ-સમય (5); શૂન્ય ડેટા બ્લોક ટ્રાન્સમિશન જ્યારે માત્ર પરવાનગીઓ અથવા સમય સંશોધિત કરવામાં આવે છે.
- **BT-શૈલી એકસાથે ડાઉનલોડ અને અપલોડ અને પ્રાદેશિક એફિનિટી શેડ્યુલિંગ**: ડાઉનલોડિંગ નોડને સંપૂર્ણ રકમ ડાઉનલોડ કરવા માટે રાહ જોવાની જરૂર નથી. તમામ બ્લોક અંતરાલ (`Op::Have`) કે જેણે 128-બીટ હેશ ચેક પસાર કર્યો છે તે અન્ય નોડ્સને એકસાથે ખેંચવા માટે તરત જ મેમરી/ટેમ્પરરી પૂલમાં લૉક કરવામાં આવે છે. ગતિશીલ PEX નોડ એક્સચેન્જ અને ધીમા નોડ હાફ પ્રિમમ્પશન (વર્ક-સ્ટીલિંગ) સાથે, ક્લસ્ટર થ્રુપુટ મહત્તમ કરવામાં આવે છે.
- **એન્ટિ-મેલિશિયસ નોડ ટેમ્પરિંગ અને ક્લસ્ટર પોઈઝનિંગ ઈમ્યુનિટી**: અધિકૃત સ્ત્રોત સૂચિ `root_hash` સ્વ-સતત લોકીંગ + ફરજિયાત હાર્ડવેર પ્રવેગક `gxhash128` દરેક બ્લોકને ડિસ્ક પર મૂકવામાં આવે અને બાહ્ય રીતે સીડ કરવામાં આવે તે પહેલાં ડાયજેસ્ટ વેરિફિકેશન; જો ચેડાં કરેલ બ્લોક મળી આવે, તો મિલીસેકન્ડ-લેવલ સર્કિટ બ્રેકર દૂષિત નોડને બ્લેકઆઉટ કરશે અને પ્રમાણિક સ્ત્રોતમાંથી આપમેળે પુનઃપ્રાપ્ત થશે.
- **ફાસ્ટસીડીસી ઇન-સીટુ ઇન્ક્રીમેન્ટ અને નાની ફાઇલ એકત્રીકરણ**: મોટી ફાઇલોના આંશિક ફેરફાર માટે માત્ર વિભેદક બ્લોક્સ ટ્રાન્સફર કરવામાં આવે છે અને ડિસ્ક પર મૂકવામાં આવે છે; વિશાળ નાની ફાઇલ મેમરી પેકેજિંગ અને ઉપસર્ગ વિભેદક કમ્પ્રેશન ફાઇલ-બાય-ફાઇલ રાઉન્ડ-ટ્રીપ ઓવરહેડને દૂર કરે છે.
- **પાવર આઉટેજ પછી સ્વ-હીલિંગ અને પુનઃપ્રારંભ કર્યા પછી પુનઃપ્રાપ્તિ**: રેડિસ-જેવા RDB + AOF હાઇબ્રિડ ફોર્મેટ (`.s0_subs.bin`) નો ઉપયોગ બીજની સ્થિતિ અને ફાઇલ સૂચિને ચાલુ રાખવા માટે થાય છે, દૈનિક ફેરફારો માઇક્રોસેકન્ડ્સમાં ઉમેરવામાં આવે છે, અને તે આપમેળે ફરીથી લખવામાં આવે છે અને નિયમિતપણે ગોઠવાય છે. સર્વર પુનઃપ્રારંભ થયા પછી, ઑફલાઇન ફેરફારો આપમેળે સીડિંગ નોડ પર ધકેલાય છે.

## ટેકનિકલ આર્કિટેક્ચર અને દસ્તાવેજીકરણ

- **ડ્યુઅલ પ્લેન ડીકપલિંગ પ્રોટોકોલ**:
  - **કંટ્રોલ અને રીઅલ-ટાઇમ ચેન્જ સરફેસ (`iroh` QUIC / TCP, ફર્સ્ટ બાઇટ `PROTO_VERSION` વર્ઝન હેન્ડશેક) **: Ed25519 બિઝનેસ કાર્ડ વેરિફિકેશન, પરમીશન વેરિફિકેશન, સ્વર્મ સીડ ડિસ્કવરી અને `u64::MAX` લેવલ ચેન્જ સ્ટ્રીમિંગ બેચિંગ માટે જવાબદાર અને <bid="4"> રીઅલ ટાઇમ પ્રેસ અને `FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` ત્રણ આદિમ).
  - **ડેટા વિતરણ સપાટી (મૂળ UDP + `compio` અસુમેળ I/O) **: 20B કોમ્પેક્ટ હેડર, 18B TACK સામયિક પ્રતિસાદ, BBRv3/કોપા હાઇબ્રિડ કન્જેશન કંટ્રોલ, RACK-TLP પેકેટ નુકશાન પુનઃપ્રાપ્તિ, ફર્સ્ટ-બ્લોક શેનોન એન્ટ્રોપી અને <bdpdstression <bd દ્વારા બ્લોક અંત-થી-અંત ચકાસણી.
