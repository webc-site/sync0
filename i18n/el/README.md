# sync0

Το `sync0` είναι ένα αποκεντρωμένο εργαλείο κοινής χρήσης αρχείων P2P, συγχρονισμού σε πραγματικό χρόνο και διανομής πολλαπλών πηγών που χρησιμοποιείται για την αντικατάσταση του `rsync` - η μετρούμενη ταχύτητα του διηπειρωτικού WAN είναι έως το `rsync`'s **5,89×** (μονό σημείο γεωμετρικής μέσης ταχύτητας πηγών ** μέση ταχύτητα 2,62P×** **3,16×**), και η επιτάχυνση P2P της ζεύξης υψηλής καθυστέρησης υπερωκεάνιας είναι έως **7,68×** (πλήρης σύνδεση 24 σεναρίων συνολικής γεωμετρικής μέσης ταχύτητας **2,56×**).

Κάθε μηχάνημα είναι ταυτόχρονα διακομιστής και πελάτης: δεν υπάρχει ανάγκη για κεντρικό διακομιστή ή δημόσια διεύθυνση δικτύου, η αυτόματη διάτρηση οπών βασίζεται στη διεύθυνση δημόσιου κλειδιού του κατανεμημένου δικτύου και υποστηρίζει απευθείας μετάδοση μεταξύ δύο μηχανών, φιλοξενία αδειών ομάδας πολλαπλής κοινής χρήσης, πολλαπλή επιλογή υποκαταλόγων κατά παραγγελία, πολλαπλασιαστικό συγχρονισμό πολλαπλών πηγών σε πραγματικό χρόνο σε επίπεδο χιλιοστών του δευτερολέπτου και P2P.

## Εγκαθιστώ

### Μέθοδος 1: Εγκατάσταση φορτίου

```bash
cargo install sync0
```

### Μέθοδος 2: Λήψη προμεταγλωττισμένων δυαδικών αρχείων

Μεταβείτε στο [GitHub Releases](https://github.com/webc-site/sync0/releases) για λήψη του `.tar.xz` συμπιεσμένου πακέτου που αντιστοιχεί στο σύστημα (υποστηρίζει Linux, macOS, Windows, Android, iOS, FreeBSD), αποσυμπιέστε και βάλτε το στο `PATH`:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## Ξεκινήστε γρήγορα

### 1. Απευθείας μετάδοση μηδενικής διαμόρφωσης μεταξύ δύο μηχανών (`send` / `recv`)

Δεν χρειάζεται να διαμορφώσετε μια ομάδα κοινής χρήσης, να μεταφέρετε απευθείας αρχεία ή καταλόγους μεταξύ δύο μηχανών με υψηλή ταχύτητα:

```bash
# Το άκρο λήψης ακούει στη θύρα και γράφει στο ./backup
sync0 recv 0.0.0.0:9000 ./backup

# Απευθείας μετάδοση από τον αποστολέα (προαιρετικό -- διαγραφή καθρέφτη για τον καθαρισμό των περιττών αρχείων, -- ρυθμός όριο ταχύτητας 50 MB)
sync0 send ./project 192.168.1.10:9000
```

### 2. Κοινή χρήση αναρτήσεων και λήψη/μεταφόρτωση κατ' απαίτηση (`share` / `pull` / `push`)

```bash
# Διακομιστής: Δημοσιεύστε την ομάδα κοινής χρήσης με μία γραμμή εντολών (εξαγωγή της διεύθυνσης κόμβου iroh χωρίς IP μετά την εκκίνηση)
sync0 share dataset:./data

# Πελάτης: Τραβήξτε ολόκληρη την ομάδα κοινής χρήσης δεδομένων στο τοπικό ./local_data
sync0 pull σύνολο δεδομένων:// ./local_data -p <διεύθυνση κόμβου>

# Πελάτης: Τραβήξτε πολλαπλές επιλογές κατ' απαίτηση (συγχρονίστε μόνο καθορισμένα μεμονωμένα αρχεία και υποκαταλόγους)
sync0 pull σύνολο δεδομένων://docs/readme.md,assets/icons,src/core ./local_data -p <διεύθυνση κόμβου>

# Πελάτης: Μεταφορτώστε αρχεία ή καταλόγους σε εξουσιοδοτημένες ομάδες κοινής χρήσης
sync0 σύνολο δεδομένων push://releases/v1 ./build_output -p <διεύθυνση κόμβου>
```

### 3. Δημιουργία συνδρομής σε πραγματικό χρόνο και αμφίδρομος συγχρονισμός πολλαπλών μηχανών (`sub` / `group`)

Μετά τη δημιουργία μιας μακράς σύνδεσης, εάν κάποιο αρχείο **προσθήκη, τροποποίηση, διαγραφή, αλλαγή δικαιωμάτων ή χρόνος τροποποίησης** εμφανιστεί στο απομακρυσμένο άκρο, ο τοπικός κατάλογος θα ενημερώνεται συγχρονισμένα σε χιλιοστά του δευτερολέπτου σε πραγματικό χρόνο (τα νέα/τροποποιημένα μεγάλα αρχεία θα τραβήξουν μόνο τα μπλοκ διαφοράς και θα τα ενημερώσουν στη θέση τους, η διαγραφή αρχείων θα καθαρίσει αυτόματα και θα αλλάξει αυτόματα αρχεία δεδομένων zeromp και θα αλλάξει απευθείας ανά τοπικό φάκελο.

- **`sync0 sub`(Μονόδρομος κατοπτρισμός σε πραγματικό χρόνο + αυτόματη σπορά)**: Ο τοπικός πραγματικός χρόνος ακολουθεί τις προσθήκες, διαγραφές και τροποποιήσεις του τέλους κοινής χρήσης και χρησιμεύει αυτόματα ως πηγή εκκίνησης P2P για την παροχή ταυτόχρονης επιτάχυνσης για άλλους κόμβους έλξης.
- **`sync0 group`(Αμφίδρομος συγχρονισμός peer-to-peer σε πραγματικό χρόνο από πολλές μηχανές)**: Εάν προστεθούν, διαγραφούν ή τροποποιηθούν αρχεία σε οποιοδήποτε μηχάνημα της ομάδας, όλοι οι άλλοι διαδικτυακοί κόμβοι θα ενημερώνονται συγχρονισμένα σε πραγματικό χρόνο και θα χρησιμεύουν ως σπόροι ο ένας για τον άλλον.

```bash
# Εγγραφείτε σε ολόκληρη την ομάδα κοινής χρήσης: οι απομακρυσμένες προσθήκες, διαγραφές και τροποποιήσεις συγχρονίζονται τοπικά σε πραγματικό χρόνο και τοποθετούνται αυτόματα
sync0 sub σύνολο δεδομένων:// ./local_mirror -p <διεύθυνση κόμβου>

# Συνδρομή πολλαπλών επιλογών κατ' απαίτηση: μόνο συγχρονισμός και δημιουργία μεμονωμένων αρχείων και υποκαταλόγων καθορισμένων σε πραγματικό χρόνο
sync0 δευτερεύον σύνολο δεδομένων://models/llama.onnx,configs ./local_mirror -p <διεύθυνση κόμβου>

# Αμφίδρομος συγχρονισμός σε πραγματικό χρόνο ομάδας ομότιμων πολλών μηχανών (υποστηρίζει επίσης διαδρομές πολλαπλής επιλογής πλήρους ή με κόμμα)
sync0 group team-docs:// ./docs -p <διεύθυνση κόμβου>
```

### 4. Ομάδα πολλαπλής κοινής χρήσης ομάδας και διαμόρφωση δικαιωμάτων μελών (διαμόρφωση`.nt`)

Ο προεπιλεγμένος κατάλογος διαμόρφωσης είναι `~/.config/sync0` (μπορεί να γίνει εναλλαγή μέσω `-c <directory>`), χρησιμοποιώντας τη μινιμαλιστική μορφή [NestedText](https://nestedtext.org) (`.nt`):
- **Υποστηρίζει τον περιορισμό της ανάγνωσης του δημόσιου δικτύου (μόνο οι εξουσιοδοτημένοι χρήστες μπορούν να διαβάσουν)**: Εφόσον η ομάδα κοινής χρήσης έχει διαμορφωθεί με μια λίστα μελών `users:` (ή η γραμμή εντολών καθορίζει `--allow-r` / `--allow-rw` / `--allow-w` / `--auth` / `--auth`, το σύστημα ενεργοποιείται αυτόματα (b id="5">) id="6">)** και απαγορεύει την απαρίθμηση ή την ανάγνωση ανώνυμων κόμβων στο δημόσιο δίκτυο, και η εγγραφή P2P σε κόμβους σποράς θα κληρονομήσει επίσης τη λίστα επιτρεπόμενων ταυτόχρονα, επιτρέποντας μόνο στους εξουσιοδοτημένους χρήστες να διαβάζουν. οι ομάδες κοινής χρήσης που δεν έχουν διαμορφωθεί με `users` είναι δημόσιες και μόνο για ανάγνωση από προεπιλογή (εάν θέλετε να είναι δημόσιες και μόνο για ανάγνωση και ανοιχτές σε μεταφορτώσεις μόνο σε καθορισμένα μέλη, μπορείτε να ορίσετε ρητά το `auth: false`).
- ** Λεπτές άδειες ανάγνωσης-εγγραφής και παράδοσης υποκαταλόγου**: Τα μέλη είναι μόνο για ανάγνωση από προεπιλογή (`r` δεν χρειάζεται να γραφτεί ρητά) και υποστηρίζουν `r` (μόνο για ανάγνωση), `w` (μόνο εγγραφή στο αναπτυσσόμενο πλαίσιο, όχι αναγνώσιμο), <b>re <id="1"> και "id="b4" (περιορίστε το πρόθεμα υποκαταλόγου που επιτρέπεται για μεταφόρτωση).

**Παράδειγμα διαμόρφωσης μέλους (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (προεπιλογή μόνο για ανάγνωση, όριο ταχύτητας 80 MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

```yaml
# ~/.config/sync0/users/bob.nt (δικαιώματα ανάγνωσης και εγγραφής, επιτρέπεται μόνο η μεταφόρτωση σε καθορισμένο υποκατάλογο)
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

```yaml
# ~/.config/sync0/users/charlie.nt (μόνο άδεια παράδοσης εγγραφής, η ανάγνωση απαγορεύεται)
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: w
```

**Παράδειγμα διαμόρφωσης ομάδας κοινής χρήσης (`~/.config/sync0/config.nt`):**

```yaml
users_dir: ./users

groups:
  # Μη διαμορφωμένοι χρήστες: προεπιλεγμένο δημόσιο δίκτυο μόνο για ανάγνωση
  dataset:
    path: ./data
    rate: 50MB

  # Διαμορφωμένοι χρήστες: περιορίζει αυτόματα την ανάγνωση του δημόσιου δικτύου (μόνο η alice και ο bob μπορούν να διαβάσουν, ο Charlie μπορεί μόνο να παραδώσει και να ανεβάσει)
  team-vault:
    path: ./vault
    users:
      - alice
      - bob
      - charlie
```

Εκκινήστε την υπηρεσία (φορτώστε το αρχείο διαμόρφωσης ή χρησιμοποιήστε απευθείας τις παραμέτρους της γραμμής εντολών για να περιορίσετε την ανάγνωση του δημόσιου δικτύου και να εξουσιοδοτήσετε μέλη):

```bash
# Φορτώστε το ~/.config/sync0/config.nt για έναρξη
sync0 share --region SHA

# Ή δημοσιεύστε μια ομάδα ιδιωτικής κοινής χρήσης μέσω καθαρής γραμμής εντολών (καθορίστε --allow-* να περιορίζει αυτόματα την ανάγνωση του δημόσιου δικτύου και μόνο εξουσιοδοτημένοι χρήστες μπορούν να έχουν πρόσβαση)
sync0 share team-vault:./vault \
  --allow-r 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-w 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 5. Διεύθυνση κόμβου, επαγγελματική κάρτα και πολύγλωσση

```bash
# Προβολή της τοπικής διεύθυνσης κόμβου χωρίς IP (το κλειδί δημιουργείται αυτόματα για την πρώτη εκτέλεση)
sync0 id

# Δημιουργία επαγγελματικής κάρτας κόμβου με αυτο-υπογραφή Ed25519 (ψευδώνυμο, κωδικός πόλης, email, ιστότοπος, εισαγωγή)
sync0 profile -u alice --region SHA --email alice@example.com -b "Shanghai node"

# Υπάρχουν 75 ενσωματωμένες γλώσσες, οι οποίες ακολουθούν τη γλώσσα συστήματος από προεπιλογή και μπορούν να εναλλάσσονται μέσω μεταβλητών περιβάλλοντος.
SYNC0_LANG=en sync0 --help
```

## Απόδοση και βασικά χαρακτηριστικά

### Πραγματική μέτρηση διαηπειρωτικού WAN (Σύγκριση `rsync`)

Πραγματικό περιβάλλον μέτρησης: Ηνωμένες Πολιτείες `c1` → Ευρώπη `n1` (RTT 65 ms), το σύνολο δεδομένων είναι πυρήνας Linux `linux-7.3.3`:

#### 1) A la carte λειτουργία έναντι `rsync`

| Σύνολο δεδομένων | μέγεθος | `sync0` Μονό σημείο<br>(Mbps) | `rsync`<br>(Mbps) | Επιτάχυνση (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(μη συμπιέσιμο) | 155 MB | **236.48** | 108.74 | **2,17×** |
| `linux-7.3.3.tar`(συμπιεστή) | 1.6 GB | **843.83** | 385.06 | **2,19×** |
| `linux-7.3.3.tar`(τοπική αύξηση αλλαγής) | 1.6 GB | **8,014.15** | 1,361.72 | **5,89×** |
| `linux-7.3.3/` (95.979 μικρά αρχεία) | 1.5 GB | **627.58** | 347.80 | **1,80×** |
| **γεωμετρική μέση** | — | **1,000.91** | 375.26 | **2,67×** |

#### 2) Λειτουργία διπλής πηγής P2P έναντι `rsync`

| Σύνολο δεδομένων | μέγεθος | `sync0` Διπλή πηγή P2P<br>(Mbps) | `rsync`<br>(Mbps) | Επιτάχυνση (`sync0` / `rsync`) |
| :--- | ---: | ---: | ---: | ---: |
| `linux-7.3.3.tar.xz`(μη συμπιέσιμο) | 155 MB | **330.09** | 108.74 | **3,04×** |
| `linux-7.3.3.tar`(συμπιεστή) | 1.6 GB | **1,551.86** | 385.06 | **4,03×** |
| `linux-7.3.3.tar`(τοπική αύξηση αλλαγής) | 1.6 GB | **5,474.17** | 1,361.72 | **4,02×** |
| `linux-7.3.3/` (95.979 μικρά αρχεία) | 1.5 GB | **706.56** | 347.80 | **2,03×** |

> Σημείωση: Στη λειτουργία διπλής πηγής P2P, οι ευρωπαϊκοί κόμβοι `s1` συνεργάζονται για τη σπορά, και η διηπειρωτική ραχοκοκαλιά RTT είναι 65 ms.

### Βασικά χαρακτηριστικά προϊόντος

- **Αυτόματη διάτρηση οπών με διευθυνσιοδότηση δημόσιου κλειδιού**: Δεν χρειάζεται κεντρικός διακομιστής και διεύθυνση δημόσιου δικτύου, αυτόματη διάτρηση οπών NAT με βάση τη διεύθυνση δημόσιου κλειδιού του κατανεμημένου δικτύου.
- **Συγχρονισμός σε πραγματικό χρόνο σε επίπεδο χιλιοστών του δευτερολέπτου και ευαισθητοποίηση μεταδεδομένων**: Με βάση την παρακολούθηση συμβάντων εγγενών αρχείων (`FSEvents` / `inotify` / `ReadDirectoryChangesW`), ώθηση σε πραγματικό χρόνο προσθηκών αρχείων, διαγραφών, αδειών POSIX (`mode`) και χρόνου τροποποίησης (millisecon) (`mode`) μηδενική μετάδοση μπλοκ δεδομένων όταν τροποποιούνται μόνο τα δικαιώματα ή ο χρόνος.
- **Ταυτόχρονη λήψη και μεταφόρτωση τύπου BT και προγραμματισμός περιφερειακής συνάφειας**: Ο κόμβος λήψης δεν χρειάζεται να περιμένει για τη λήψη ολόκληρου του ποσού. Όλα τα διαστήματα μπλοκ (`Op::Have`) που έχουν περάσει τον έλεγχο κατακερματισμού των 128 bit κλειδώνονται αμέσως στη μνήμη/προσωρινή πισίνα για να τραβήξουν άλλοι κόμβοι ταυτόχρονα. Μαζί με τη δυναμική ανταλλαγή κόμβων PEX και τη μισή προκοπή αργού κόμβου (Κλοπή εργασίας), η απόδοση του συμπλέγματος μεγιστοποιείται.
- **Ανοσία παραβίασης και δηλητηρίασης συμπλέγματος κατά των κακόβουλων κόμβων**: έγκυρη λίστα πηγών `root_hash` Αυτοσυνεπές κλείδωμα + υποχρεωτική επιτάχυνση υλικού `gxhash128` επαλήθευση πέψης πριν από την τοποθέτηση κάθε μπλοκ στο δίσκο και την εξωτερική σπορά. Εάν εντοπιστεί ένα παραποιημένο μπλοκ, ο διακόπτης κυκλώματος επιπέδου χιλιοστού του δευτερολέπτου θα απενεργοποιήσει τον κακόβουλο κόμβο και θα ανακτήσει αυτόματα από την ειλικρινή πηγή.
- **Επί τόπου προσαύξηση FastCDC και συγκέντρωση μικρών αρχείων**: Μόνο μπλοκ διαφορικών μεταφέρονται για μερική τροποποίηση μεγάλων αρχείων και τοποθετούνται στο δίσκο. Η μαζική συσκευασία μνήμης μικρών αρχείων και η διαφορική συμπίεση του προθέματος εξαλείφουν την επιβάρυνση της επιστροφής από αρχείο προς αρχείο.
- **Αυτοίαση μετά από διακοπή ρεύματος και επανέναρξη μετά την επανεκκίνηση**: Η υβριδική μορφή RDB + AOF που μοιάζει με Redis (`.s0_subs.bin`) χρησιμοποιείται για τη διατήρηση της κατάστασης σποράς και της λίστας αρχείων, οι καθημερινές αλλαγές προστίθενται σε μικροδευτερόλεπτα και ξαναγράφονται και οργανώνονται αυτόματα τακτικά. Μετά την επανεκκίνηση του διακομιστή, οι αλλαγές εκτός σύνδεσης προωθούνται αυτόματα στον κόμβο σποράς.

## Τεχνική αρχιτεκτονική και τεκμηρίωση

- **Πρωτόκολλο αποσύνδεσης διπλού επιπέδου**:
  - **Έλεγχος και επιφάνεια αλλαγής σε πραγματικό χρόνο (`iroh` QUIC / TCP, πρώτο byte `PROTO_VERSION` χειραψία έκδοσης) **: Υπεύθυνος για την επαλήθευση επαγγελματικής κάρτας Ed25519, την επαλήθευση αδειών, την ανακάλυψη σμήνων και την υποστήριξη για `u64::MAX` μαζική αλλαγή επιπέδου ροής και <b> ώθηση σε πραγματικό χρόνο `FsOp::Upsert` / `FsOp::Remove` / `FsOp::Meta` Τρεις πρωτόγονοι).
  - **Επιφάνεια διανομής δεδομένων (εγγενής UDP + `compio` ασύγχρονη I/O) **: συμπαγής κεφαλίδα 20B, περιοδική ανάδραση 18B TACK, υβριδικός έλεγχος συμφόρησης BBRv3/Copa, ανάκτηση απώλειας πακέτων RACK-TLP, first-block Shannon entropy adaptive <bid compred="2 και Zstd" επαλήθευση από άκρο σε άκρο.
