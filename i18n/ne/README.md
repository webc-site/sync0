# sync0

`sync0` एक पियर-टू-पीयर (P2P) फाइल साझेदारी र बहु-मेसिन सिङ्क्रोनाइजेसन उपकरण हो जसले Resilio Sync सँग प्रतिस्पर्धा गर्छ।

प्रत्येक मेसिन सर्भर र क्लाइन्ट दुवै हो: कुनै पनि नोडले धेरै फाइल साझेदारी समूहहरू प्रकाशित गर्न सक्छ। अन्य नोडहरू सामेल भएपछि, तिनीहरूले स्वचालित रूपमा सहकर्मी सर्भरबाट उपलब्ध बीज नोडहरू प्राप्त गर्न सक्छन् र तिनीहरूलाई धेरै स्रोतहरूबाट एकैसाथ तान्न सक्छन्। सिंक्रोनाइजेसन पूरा भएपछि, डाउनलोडहरू गति बढाउन थप नोडहरूका लागि बीजहरू स्वचालित रूपमा सिर्जना हुनेछन्।

## कोर हाइलाइटहरू

- **सबैजना दुबै सर्भर र ग्राहक हुन्**: Resilio Sync सँग तुलनात्मक, कुनै केन्द्रीय सर्भर निर्भरता छैन। कुनै पनि नोडले धेरै फाइल साझेदारी समूहहरू सिर्जना गर्न सक्छ, र अन्य व्यक्तिहरूको साझेदारी समूहहरूमा पनि सामेल हुन सक्छ; नोडहरू स्वचालित रूपमा आदानप्रदान र उपलब्ध बीउ नोडहरू प्राप्त गर्नका लागि समवर्ती पुलिङ र धेरै मेसिनहरूको वास्तविक-समय सिङ्क्रोनाइजेसन प्राप्त गर्न।
- **IP-मुक्त नोड ठेगाना**: पूर्वनिर्धारित रूपमा, नोड कुञ्जी र `base64url` एन्कोड गरिएको `iroh` ठेगाना स्वचालित रूपमा `~/.config/sync0` मा उत्पन्न हुन्छन् सार्वजनिक आईपी सम्झन वा खुलासा गर्न आवश्यक छैन।
- **मागमा बहु-चयन सिंक्रोनाइजेसन**: सम्पूर्ण साझेदारी समूहको सिङ्क्रोनाइजेसनलाई समर्थन गर्दछ, र एकै समयमा धेरै फाइलहरू वा उपनिर्देशिकाहरू चयन गरेर मागमा सिङ्क्रोनाइजेसनलाई समर्थन गर्दछ।
- **समूह सदस्य पदानुक्रमिक अनुमतिहरू र अपलोड डाइरेक्टरी नियन्त्रण**: पढ्न-मात्र समर्थन गर्दछ (`ro`), पढ्ने-लेखन अपलोड (`rw`), र व्यवस्थापन (`admin`) अनुमतिहरू, र व्यक्तिगत रूपमा प्रत्येक सदस्यलाई अपलोड गर्न अनुमति दिइएको मार्ग उपसर्ग निर्दिष्ट गर्न सक्छ (पूर्वनिर्धारित रूपमा, साझा डाइरेक्टरी अपलोड गर्न अनुमति दिइएको छ)।
- **सञ्जालहरूमा पूर्ण-गति र वृद्धिशील सिङ्क्रोनाइजेसन**: ठूला फाइलहरूको समवर्ती प्रसारण, मेमोरीमा ठूलो साना फाइलहरूको एकत्रीकरण, र फाइलहरू आंशिक रूपमा परिमार्जन हुँदा मात्र सिङ्क्रोनाइज गरिएको डेटा ब्लकहरू।

## स्थापना गर्नुहोस्

### विधि १: कार्गो मार्फत स्थापना गर्नुहोस्

```bash
cargo install sync0
```

### विधि २: पूर्वकम्पाइल गरिएको बाइनरीहरू डाउनलोड गर्नुहोस्

[GitHub Releases](https://github.com/webc-site/sync0/releases) मा जानुहोस् `.tar.xz` सम्बन्धित प्रणालीको लागि कम्प्रेस गरिएको प्याकेज डाउनलोड गर्न (लिनक्स, macOS, Windows, Android, FreeBSD, NetBSD समर्थन गर्दछ), अनजिप गर्नुहोस् र यसलाई `PATH` डाइरेक्टरीमा राख्नुहोस्:

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## छिटो सुरु गर्नुहोस्

`sync0` पूर्वनिर्धारित रूपमा कन्फिगरेसन डाइरेक्टरीको रूपमा `~/.config/sync0` प्रयोग गर्दछ (यदि तपाइँ अन्य निर्देशिकाहरूमा स्विच गर्न आवश्यक छ भने, तपाइँ `-c <directory>` थप्न सक्नुहुन्छ)।

### 1. स्थानीय नोड ठेगाना र व्यापार कार्ड सेटिङ हेर्नुहोस्

```bash
# स्थानीय नोड ठेगाना हेर्नुहोस् (कुञ्जी पहिलो पटक ~/.config/sync0 मा स्वचालित रूपमा उत्पन्न हुन्छ)
sync0 id

# व्यक्तिगत नोड व्यापार कार्ड उत्पन्न गर्नुहोस् (प्रयोगकर्ता नाम, शहर, इमेल, वेबसाइट र 256 शब्द भित्र हस्ताक्षर समर्थन गर्दछ)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. बहु फाइल साझेदारी समूहहरू प्रकाशित गर्नुहोस् र समूह सदस्य अनुमतिहरू सेट गर्नुहोस् (`.nt` कन्फिगरेसन)

`sync0` [NestedText](https://nestedtext.org) (`.nt`) ढाँचामा कन्फिगर गरिएको छ। प्रत्येक प्रयोगकर्तासँग छुट्टै `.nt` कन्फिगरेसन फाइल हुन्छ। तपाईले प्रयोगकर्ता प्रोफाइल डाइरेक्टरीलाई `users_dir` मार्फत `config.nt` मा निर्दिष्ट गर्न सक्नुहुन्छ (जसले स्वचालित रूपमा यस डाइरेक्टरीमा सबै `.nt` फाइलहरू समावेश गर्दछ)। अपलोड गर्न अनुमति दिइएको प्रयोगकर्ता र मार्ग उपसर्ग दुवै एक अक्रमित सूची (`-`) प्रयोग गर्नुहोस्। **जब अपलोड पथ उपसर्ग भरिएको छैन, पूर्वनिर्धारित रूपमा सेयरको रूट डाइरेक्टरीमा अपलोड गर्न अनुमति दिइन्छ**।

1. `~/.config/sync0/users/` निर्देशिकामा प्रत्येक सदस्यको लागि छुट्टै `.nt` कन्फिगरेसन फाइलहरू सिर्जना गर्नुहोस्:

`~/.config/sync0/users/alice.nt` (पढ्ने मात्र सदस्य, दर सीमित `80MB`, `rate` समर्थन गर्दछ `GB`, `MB`, `KB` एकाइहरू):

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (प्रतिबन्धित अपलोड सदस्यहरू: `uploads/bob` र `shared/common` निर्देशिकाहरूमा मात्र अपलोड गर्न अनुमति दिइएको छ):

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (पूर्वनिर्धारित सदस्य अपलोड: जब `write_prefix` हटाइएको छ, साझाको मूल डाइरेक्टरीमा अपलोड गर्न पूर्वनिर्धारित रूपमा अनुमति छ):

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. `~/.config/sync0/config.nt` मा प्रयोगकर्ता डाइरेक्टरी र बहु ​​फाइल साझेदारी समूहहरू कन्फिगर गर्नुहोस्:

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

साझेदारी सेवा सुरु गर्नुहोस्:

```bash
# प्रत्यक्ष स्टार्टअप (स्वचालित रूपमा सबै .nt प्रयोगकर्ता कन्फिगरेसनहरू ~/.config/sync0/config.nt र user_dir डाइरेक्टरीहरूमा लोड हुन्छ)
sync0 share --region SHA

# वा चाँडै धेरै साझा समूहहरू प्रकाशित गर्नुहोस् र समूह सदस्यहरूलाई सीधा आदेश रेखा मार्फत अधिकृत गर्नुहोस्
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. सबै सामग्री तान्नुहोस् वा धेरै फाइलहरू र निर्देशिकाहरू चयन गर्नुहोस् (`sync0 pull`)

साझेदारी समूहमा सबै उपलब्ध बीउ नोडहरू स्वतः प्राप्त गर्नका लागि कुनै पनि पियर नोडमा जडान गर्नुहोस्, र एकसाथ धेरै बीज नोडहरूबाट तान्नुहोस्:

```bash
# सम्पूर्ण डेटासेट साझेदारी समूहलाई स्थानीय ./local_data मा तान्नुहोस्
sync0 पुल डेटासेट:// ./local_data -p <नोड ठेगाना>

# बहु-चयन सिंक्रोनाइजेसन: एकल फाइल कागजात/readme.md र उपनिर्देशिका सम्पत्ति/आइकनहरू, src/core लाई एकै साथ तान्नुहोस्
sync0 पुल डेटासेट://docs/readme.md,assets/icons,src/core ./local_data -p <नोड ठेगाना>
```

### 4. साझेदारी समूहमा फाइल वा डाइरेक्टरी अपलोड गर्नुहोस् (`sync0 push`)

अपलोड अनुमति (`rw` वा `admin`) भएका सदस्यहरूले टाढाको साझेदारी समूहहरूमा स्थानीय फाइलहरू वा डाइरेक्टरीहरू अपलोड गर्न सक्छन्:

```bash
# रूट डाइरेक्टरी अपलोड अनुमति भएका सदस्यहरू: साझा रूट डाइरेक्टरीमा सीधा अपलोड गर्नुहोस्
sync0 push team-vault:// ./new_release -p <node address>

# कुनै खास उपसर्ग (जस्तै अपलोड/बब) मा अधिकृत सदस्यहरू मात्र: अनुमति दिइएको पथ उपसर्गमा अपलोड गर्नुहोस्
sync0 push team-vault://uploads/bob/report.pdf ./report.pdf -p <नोड ठेगाना>
```

### 5. स्वचालित सिंक र सीडिङको सदस्यता लिनुहोस् (`sync0 sub`)

एक निश्चित नोडको साझेदारी समूहमा सदस्यता लिएपछि, स्थानीय सर्भर प्राप्त गर्ने ग्राहक र नयाँ सीडिङ ​​सर्भर दुवै हो; जब स्रोत नोड फाइल अद्यावधिक हुन्छ, यो स्वचालित रूपमा सिङ्क्रोनाइज हुन्छ र अन्य नोडहरूको लागि chunked डाउनलोड प्रदान गर्दछ:

```bash
# सम्पूर्ण साझा समूहको सदस्यता लिनुहोस् र स्वचालित रूपमा बीज गर्नुहोस्
sync0 sub dataset:// ./local_mirror -p <नोड ठेगाना>

# निर्दिष्ट फाइलहरू र उपनिर्देशिकाहरूमा सदस्यता लिन र तिनीहरूलाई सीड गर्न केवल बहु-चयन गर्नुहोस्
sync0 sub dataset://models/llama.onnx,configs ./local_mirror -p <नोड ठेगाना>
```

### 6. बहु-मेसिन समूह पियर सिंक्रोनाइजेसन (`sync0 group`)

धेरै मेसिनहरू एउटै साझेदारी समूहमा सामेल हुन्छन्, एकअर्काले स्वचालित रूपमा उपलब्ध बीज नोडहरू पत्ता लगाउँछन् र दुई-तर्फी सिंक्रोनाइजेसन कायम गर्दछ (पूर्ण सिंक्रोनाइजेसन वा फाइलहरू र डाइरेक्टरीहरूको बहु चयनलाई समर्थन गर्दछ):

```bash
# पूर्ण रूपमा समूह र दुई-तर्फी सिंक्रोनाइजेसनमा सामेल हुनुहोस्
sync0 group team-docs:// ./docs -p <node address>

# बहु-चयन सिङ्क्रोनाइजेसन समूहमा केवल wal डाइरेक्टरी र meta.json फाइल
sync0 group team-docs://wal,meta.json ./docs -p <node address>
```

### 7. दुई मेसिनहरू (`send` / `recv`) बीच बिन्दु-देखि-बिन्दु प्रत्यक्ष प्रसारण

त्यहाँ समूह पूर्व-कन्फिगर गर्न आवश्यक छैन, र तपाईं अस्थायी रूपमा फाइलहरू वा डाइरेक्टरीहरू सीधा दुई मेसिनहरू बीच स्थानान्तरण गर्न सक्नुहुन्छ:

```bash
# रिसीभर निगरानी
sync0 recv 0.0.0.0:9000 ./backup

# पठाउने अन्तले प्रत्यक्ष रूपमा फाइलहरू वा डाइरेक्टरीहरू स्थानान्तरण गर्दछ (वैकल्पिक -- अतिरिक्त फाइलहरू सफा गर्न मिरर मेटाउनुहोस्, --रेट गति सीमा)
sync0 send ./project 192.168.1.10:9000
```

### 8. बहु-भाषा स्विचिङ

`sync0` ले ७५ भाषाहरूलाई समर्थन गर्छ, र स्वचालित रूपमा प्रणाली भाषा वातावरण अनुसार पूर्वनिर्धारित रूपमा स्विच गर्छ; यो पनि `SYNC0_LANG` मार्फत म्यानुअल रूपमा निर्दिष्ट गर्न सकिन्छ:

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
