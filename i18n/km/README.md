# sync0

`sync0`គឺ​ជា​ការ​ចែក​រំលែក​ឯកសារ​ពី​គ្នា​ទៅ​ម្នាក់ (P2P) និង​ឧបករណ៍​ធ្វើ​សមកាលកម្ម​ច្រើន​ម៉ាស៊ីន​ដែល​ប្រកួតប្រជែង​ជាមួយ Resilio Sync។

ម៉ាស៊ីននីមួយៗគឺទាំងម៉ាស៊ីនមេ និងម៉ាស៊ីនភ្ញៀវ៖ ថ្នាំងណាមួយអាចបោះពុម្ពក្រុមចែករំលែកឯកសារច្រើន។ បន្ទាប់ពីថ្នាំងផ្សេងទៀតចូលរួម ពួកគេអាចទទួលបានថ្នាំងគ្រាប់ពូជដែលមានដោយស្វ័យប្រវត្តិពីម៉ាស៊ីនមេ និងទាញពួកវាក្នុងពេលតែមួយពីប្រភពជាច្រើន។ បន្ទាប់ពីការធ្វើសមកាលកម្មត្រូវបានបញ្ចប់ គ្រាប់ពូជនឹងត្រូវបានបង្កើតដោយស្វ័យប្រវត្តិសម្រាប់ថ្នាំងបន្ថែមទៀតដើម្បីពន្លឿនការទាញយក។

## គំនួសពណ៌ស្នូល

- **អ្នក​រាល់​គ្នា​គឺ​ទាំង​ម៉ាស៊ីន​មេ និង​ម៉ាស៊ីន​ភ្ញៀវ**៖ អាច​ប្រៀប​ធៀប​ទៅ​នឹង Resilio Sync មិន​មាន​ការ​ពឹង​ផ្អែក​លើ​ម៉ាស៊ីន​មេ​កណ្តាល​ទេ។ ថ្នាំងណាមួយអាចបង្កើតក្រុមចែករំលែកឯកសារច្រើន ហើយក៏អាចចូលរួមក្រុមចែករំលែករបស់អ្នកដទៃផងដែរ។ ថ្នាំងផ្លាស់ប្តូរដោយស្វ័យប្រវត្តិ និងទទួលបានថ្នាំងគ្រាប់ពូជដែលមាន ដើម្បីសម្រេចបាននូវការទាញស្របគ្នា និងការធ្វើសមកាលកម្មតាមពេលវេលាជាក់ស្តែងនៃម៉ាស៊ីនច្រើន។
- **អាសយដ្ឋានថ្នាំងគ្មាន IP**៖ តាមលំនាំដើម លេខកូដថ្នាំង និង `base64url`អាសយដ្ឋានដែលបានអ៊ិនកូដ `iroh`ត្រូវបានបង្កើតដោយស្វ័យប្រវត្តិនៅក្នុង `~/.config/sync0` ដោយមិនចាំបាច់ចងចាំ ឬបង្ហាញ IP សាធារណៈទេ។
- **ជ្រើសរើសការធ្វើសមកាលកម្មច្រើនតាមតម្រូវការ**៖ គាំទ្រការធ្វើសមកាលកម្មនៃក្រុមចែករំលែកទាំងមូល ហើយក៏គាំទ្រការធ្វើសមកាលកម្មតាមតម្រូវការដោយជ្រើសរើសឯកសារច្រើន ឬថតរងក្នុងពេលតែមួយ។
- **ការអនុញ្ញាតតាមឋានានុក្រមសមាជិកក្រុម និងការគ្រប់គ្រងបញ្ជីផ្ទុកឡើង**៖ គាំទ្រការអានបានតែ (`ro`) អាន-សរសេរបង្ហោះ (`rw`) និងការគ្រប់គ្រង (`admin`) ការអនុញ្ញាត ហើយអាចបញ្ជាក់ជាលក្ខណៈបុគ្គលនូវបុព្វបទផ្លូវដែលសមាជិកនីមួយៗត្រូវបានអនុញ្ញាតឱ្យបង្ហោះ (តាមលំនាំដើម ការផ្ទុកឡើងទៅកាន់ថត root នៃការចែករំលែកត្រូវបានអនុញ្ញាត)។
- ** ការធ្វើសមកាលកម្មល្បឿនពេញលេញ និងបន្ថែមលើបណ្តាញនានា **៖ ការបញ្ជូនឯកសារធំដំណាលគ្នា ការប្រមូលផ្តុំឯកសារតូចៗដ៏ធំនៅក្នុងអង្គចងចាំ ហើយមានតែប្លុកទិន្នន័យដែលបានធ្វើសមកាលកម្មនៅពេលដែលឯកសារត្រូវបានកែប្រែដោយផ្នែក។

## ដំឡើង

### វិធីសាស្រ្តទី 1: ដំឡើងតាមរយៈទំនិញ

```bash
cargo install sync0
```

### វិធីទី 2: ទាញយកប្រព័ន្ធគោលពីរដែលបានចងក្រងជាមុន

ចូលទៅកាន់ [GitHub Releases](https://github.com/webc-site/sync0/releases) ដើម្បីទាញយក `.tar.xz`កញ្ចប់ដែលបានបង្ហាប់សម្រាប់ប្រព័ន្ធដែលត្រូវគ្នា (គាំទ្រ Linux, macOS, Windows, Android, FreeBSD, NetBSD) ពន្លា ហើយដាក់វាទៅក្នុងថត `PATH`៖

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## ចាប់ផ្តើមយ៉ាងឆាប់រហ័ស

`sync0` ប្រើ `~/.config/sync0` ជា​ថត​កំណត់​រចនាសម្ព័ន្ធ​តាម​លំនាំដើម (ប្រសិន​បើ​អ្នក​ត្រូវ​ប្ដូរ​ទៅ​ថត​ផ្សេង អ្នក​អាច​បន្ថែម `-c <directory>`)។

### 1. មើលអាសយដ្ឋានថ្នាំងមូលដ្ឋាន និងការកំណត់នាមប័ណ្ណ

```bash
# មើលអាសយដ្ឋានថ្នាំងមូលដ្ឋាន (សោត្រូវបានបង្កើតដោយស្វ័យប្រវត្តិក្នុង ~/.config/sync0 ជាលើកដំបូង)
sync0 id

# បង្កើតកាតអាជីវកម្មថ្នាំងផ្ទាល់ខ្លួន (គាំទ្រឈ្មោះអ្នកប្រើប្រាស់ ទីក្រុង អ៊ីមែល គេហទំព័រ និងហត្ថលេខាក្នុងរយៈពេល 256 ពាក្យ)
sync0 profile -u alice --region SHA --email alice@example.com --url https://example.com -b "Shanghai node"
```

### 2. បោះផ្សាយក្រុមចែករំលែកឯកសារជាច្រើន និងកំណត់ការអនុញ្ញាតសមាជិកក្រុម (`.nt`ការកំណត់រចនាសម្ព័ន្ធ)

`sync0`ត្រូវបានកំណត់រចនាសម្ព័ន្ធក្នុងទម្រង់ [NestedText](https://nestedtext.org) (`.nt`)។ អ្នកប្រើប្រាស់នីមួយៗមានឯកសារកំណត់រចនាសម្ព័ន្ធ `.nt`ដាច់ដោយឡែក។ អ្នកអាចបញ្ជាក់បញ្ជីឈ្មោះអ្នកប្រើប្រាស់តាមរយៈ `users_dir`ក្នុង `config.nt` (ដែលរួមបញ្ចូលឯកសារ `.nt` ទាំងអស់ដោយស្វ័យប្រវត្តិនៅក្នុងថតឯកសារនេះ)។ ទាំង​អ្នក​ប្រើ និង​បុព្វបទ​ផ្លូវ​ដែល​ត្រូវ​បាន​អនុញ្ញាត​ឱ្យ​ផ្ទុក​ឡើង​ប្រើ​បញ្ជី​ដែល​មិន​បាន​តម្រៀប (`-`)។ **នៅពេលដែលបុព្វបទផ្លូវផ្ទុកឡើងមិនត្រូវបានបំពេញទេ ការបង្ហោះទៅកាន់ថតឫសនៃការចែករំលែកត្រូវបានអនុញ្ញាតតាមលំនាំដើម**។

1. បង្កើត​ឯកសារ​កំណត់​រចនាសម្ព័ន្ធ `.nt`ដាច់ដោយឡែក​សម្រាប់​សមាជិក​នីមួយៗ​ក្នុង​ថត `~/.config/sync0/users/`៖

`~/.config/sync0/users/alice.nt` (សមាជិកបានតែអាន អត្រាមានកំណត់ `80MB`, `rate`គាំទ្រ `GB`, `MB`, `KB` គ្រឿង)៖

```yaml
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
perm: ro
rate: 80MB
```

`~/.config/sync0/users/bob.nt` (សមាជិក​ផ្ទុក​ឡើង​ដែល​បាន​ដាក់​កម្រិត៖ អនុញ្ញាត​ឱ្យ​ផ្ទុក​ឡើង​តែ​ក្នុង `uploads/bob` និង `shared/common` ថត៖

```yaml
id: 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f
perm: rw
write_prefix:
  - uploads/bob
  - shared/common
```

`~/.config/sync0/users/charlie.nt` (ការអាប់ឡូតសមាជិកលំនាំដើម៖ នៅពេលដែល `write_prefix`ត្រូវបានលុបចោល ការបង្ហោះទៅកាន់ថត root នៃការចែករំលែកត្រូវបានអនុញ្ញាតតាមលំនាំដើម៖

```yaml
id: 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
perm: rw
```

2. កំណត់រចនាសម្ព័ន្ធថតអ្នកប្រើប្រាស់ និងក្រុមចែករំលែកឯកសារច្រើនក្នុង `~/.config/sync0/config.nt`៖

```yaml
users_dir: ./users

groups:
  dataset:
    path: ./data
    auth: false
    perm: ro
    rate: 50MB

  models:
    path: ./models
    auth: false
    perm: ro
    rate: 1GB

  team-vault:
    path: ./vault
    auth: true
    perm: ro
    rate: 512KB
    users:
      - alice
      - bob
      - charlie
```

ចាប់ផ្តើមសេវាកម្មចែករំលែក៖

```bash
# ការចាប់ផ្តើមដោយផ្ទាល់ (ផ្ទុកដោយស្វ័យប្រវត្តិនូវការកំណត់រចនាសម្ព័ន្ធអ្នកប្រើប្រាស់ .nt ទាំងអស់នៅក្នុងបញ្ជី ~/.config/sync0/config.nt និងusers_dir)
sync0 share --region SHA

# ឬបោះផ្សាយក្រុមចែករំលែកច្រើនយ៉ាងរហ័ស និងអនុញ្ញាតសមាជិកក្រុមដោយផ្ទាល់តាមរយៈបន្ទាត់ពាក្យបញ្ជា
sync0 share dataset:./data team-vault:./vault \
  --auth \
  --allow-ro 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c \
  --allow-rw 7K8bCdEfGhIjKlMnOpQrStUvWxYz0123456789de_f:uploads/bob,shared/common \
  --allow-rw 9M0cDeFgHiJkLmNoPqRsTuVwXyZ0123456789gh_i
```

### 3. ទាញមាតិកាទាំងអស់ ឬជ្រើសរើសឯកសារ និងថតច្រើន (`sync0 pull`)

ភ្ជាប់ទៅ node peer ណាមួយ ដើម្បីទទួលបានថ្នាំងគ្រាប់ពូជដែលមានទាំងអស់ដោយស្វ័យប្រវត្តិនៅក្នុងក្រុមចែករំលែក ហើយទាញពីថ្នាំងគ្រាប់ពូជច្រើនក្នុងពេលដំណាលគ្នា៖

```bash
# ទាញក្រុមចែករំលែកសំណុំទិន្នន័យទាំងមូលទៅមូលដ្ឋាន ./local_data
sync0 pull dataset:// ./local_data -p <node address>

# ការធ្វើសមកាលកម្មជ្រើសរើសច្រើន៖ ទាញឯកសារតែមួយ docs/readme.md ក្នុងពេលដំណាលគ្នា និងទ្រព្យសម្បត្តិថតរង/រូបតំណាង src/core
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <node address>
```

### 4. ផ្ទុកឡើងឯកសារ ឬថតទៅកាន់ក្រុមចែករំលែក (`sync0 push`)

សមាជិក​ដែល​មាន​សិទ្ធិ​ផ្ទុក​ឡើង (`rw` ឬ `admin`) អាច​ផ្ទុក​ឯកសារ​មូលដ្ឋាន ឬ​ថត​ទៅ​ក្រុម​ចែករំលែក​ពី​ចម្ងាយ៖

```bash
# សមាជិកដែលមានសិទ្ធិបង្ហោះថតឫស៖ បង្ហោះដោយផ្ទាល់ទៅថតឫសដែលបានចែករំលែក
sync0 push team-vault:// ./new_release -p <node address>

# មាន​តែ​សមាជិក​ដែល​បាន​អនុញ្ញាត​ឱ្យ​មាន​បុព្វបទ​ជាក់លាក់​មួយ (ដូចជា​ការ​ផ្ទុក​ឡើង/bob)៖ ផ្ទុក​ឡើង​ទៅ​បុព្វបទ​ផ្លូវ​ដែល​បាន​អនុញ្ញាត
sync0 push team-vault://uploads/bob/report.pdf ./report.pdf -p <node address>
```

### 5. ជាវការធ្វើសមកាលកម្មដោយស្វ័យប្រវត្តិ និងការបណ្តុះ (`sync0 sub`)

បន្ទាប់​ពី​បាន​ជាវ​ក្រុម​ចែក​រំលែក​នៃ​ថ្នាំង​ជាក់លាក់​មួយ ម៉ាស៊ីន​បម្រើ​មូលដ្ឋាន​គឺ​ទាំង​ម៉ាស៊ីន​ភ្ញៀវ​ទទួល និង​ម៉ាស៊ីន​បម្រើ​គ្រាប់ពូជ​ថ្មី​។ នៅពេលដែលឯកសារថ្នាំងប្រភពត្រូវបានធ្វើបច្ចុប្បន្នភាព វាត្រូវបានធ្វើសមកាលកម្មដោយស្វ័យប្រវត្តិ និងផ្តល់នូវការទាញយកបណ្តុំសម្រាប់ថ្នាំងផ្សេងទៀត៖

```bash
# ជាវទៅក្រុមចែករំលែកទាំងមូល និងគ្រាប់ពូជដោយស្វ័យប្រវត្តិ
sync0 sub dataset:// ./local_mirror -p <node address>

# មានតែការជ្រើសរើសច្រើនប៉ុណ្ណោះ ដើម្បីជាវឯកសារ និងថតរងដែលបានបញ្ជាក់ ហើយជ្រើសរើសពួកវា
sync0 sub dataset://models/llama.onnx,config ./local_mirror -p <node address>
```

### 6. ការធ្វើសមកាលកម្មក្រុមពហុម៉ាស៊ីន (`sync0 group`)

ម៉ាស៊ីនជាច្រើនចូលរួមក្រុមចែករំលែកដូចគ្នា គ្នាទៅវិញទៅមករកឃើញថ្នាំងគ្រាប់ពូជដែលមានដោយស្វ័យប្រវត្តិ និងរក្សាការធ្វើសមកាលកម្មពីរផ្លូវ (គាំទ្រការធ្វើសមកាលកម្មពេញលេញ ឬការជ្រើសរើសឯកសារ និងថតច្រើន):

```bash
# ចូលរួមយ៉ាងពេញលេញជាមួយក្រុម និងការធ្វើសមកាលកម្មពីរផ្លូវ
sync0 ក្រុម team-docs:// ./docs -p <node address>

# មានតែថត wal និងឯកសារ meta.json នៅក្នុងក្រុមធ្វើសមកាលកម្មជ្រើសរើសច្រើនប៉ុណ្ណោះ។
sync0 ក្រុម team-docs://wal,meta.json ./docs -p <node address>
```

### 7. ការបញ្ជូនដោយផ្ទាល់ពីចំណុចមួយទៅចំណុចរវាងម៉ាស៊ីនពីរ (`send` / `recv`)

មិនចាំបាច់កំណត់រចនាសម្ព័ន្ធក្រុមជាមុនទេ ហើយអ្នកអាចផ្ទេរឯកសារ ឬថតឯកសារជាបណ្តោះអាសន្នដោយផ្ទាល់រវាងម៉ាស៊ីនពីរ៖

```bash
# ការត្រួតពិនិត្យអ្នកទទួល
sync0 recv 0.0.0.0:9000 ./backup

# ចុងបញ្ចប់បញ្ជូនដោយផ្ទាល់ផ្ទេរឯកសារ ឬថតឯកសារ (ស្រេចចិត្ត --លុបកញ្ចក់ដើម្បីសម្អាតឯកសារលើស --អត្រាល្បឿនកំណត់)
sync0 send ./project 192.168.1.10:9000
```

### 8. ការប្តូរពហុភាសា

`sync0` គាំទ្រ 75 ភាសា ហើយប្តូរដោយស្វ័យប្រវត្តិទៅតាមបរិស្ថានភាសាប្រព័ន្ធតាមលំនាំដើម។ វាក៏អាចត្រូវបានបញ្ជាក់ដោយដៃតាមរយៈ `SYNC0_LANG`៖

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
