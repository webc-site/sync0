# sync0

`sync0` គឺជាឧបករណ៍បន្ទាត់ពាក្យបញ្ជាសម្រាប់ផ្ទេរឯកសារឆ្លងកាត់បណ្តាញ បង្កើនការធ្វើសមកាលកម្មថត និងចែកចាយទិន្នន័យក្នុងពេលដំណាលគ្នាទៅកាន់ម៉ាស៊ីនជាច្រើន។

## គោលបំណងនៃការរចនាដើម

នៅក្នុងបន្ទប់ឆ្លងម៉ាស៊ីន ប្រទេស ឬបរិស្ថានដែលមានការពន្យារពេលបណ្តាញ និងការបាត់បង់កញ្ចប់ព័ត៌មាន ឧបករណ៍ដូចជា `rsync` និង `scp` គឺផ្អែកលើការបញ្ជាក់លំដាប់នៃការតភ្ជាប់តែមួយ ដែលកំណត់ការប្រើប្រាស់កម្រិតបញ្ជូន។ នៅពេលដែលម៉ាស៊ីនជាច្រើនទាញទិន្នន័យពីម៉ាស៊ីនមេតែមួយក្នុងពេលតែមួយ កាតបណ្តាញម៉ាស៊ីនមេប្រភពអាចក្លាយជាឧបសគ្គយ៉ាងងាយស្រួល។

គោលដៅនៃ `sync0`គឺដើម្បីដោះស្រាយបញ្ហាពីរ៖

1. អនុញ្ញាតឱ្យការធ្វើសមកាលកម្មឯកសារ និងថតឯកសាររវាងម៉ាស៊ីនទាំងពីរដំណើរការកម្រិតបញ្ជូនរាងកាយពេញលេញ ហើយគ្រាន់តែផ្ទេរផ្នែកដែលបានផ្លាស់ប្តូរនៅពេលដែលឯកសារត្រូវបានកែប្រែដោយផ្នែក។
2. ម៉ាស៊ីនជាច្រើនអាចផ្ទេរប្លុកទិន្នន័យទៅគ្នាទៅវិញទៅមកនៅពេលធ្វើសមកាលកម្មថតដូចគ្នា កាត់បន្ថយការផ្ទុកនៅលើម៉ាស៊ីនមេប្រភព និងកាត់បន្ថយពេលវេលាធ្វើសមកាលកម្មទាំងមូល។

## ការប្រៀបធៀបល្បឿនជាមួយ rsync

បរិយាកាសសាកល្បង៖ ថ្នាំងអ៊ឺរ៉ុប $\leftrightarrow$ ថ្នាំងអាមេរិកខាងជើង ការពន្យាពេលធ្វើដំណើរទៅមក 86 ms វាស់ពេលវេលាប្រើប្រាស់ពេញលេញ រួមទាំងការស្កេនថត ការប្រៀបធៀបការផ្ដាច់ ការបញ្ជូនបណ្តាញ និងការផ្ទៀងផ្ទាត់ការដាក់ថាស៖

| :--- | :---: | :---: | :---: | :---: |
| 10,000 ឯកសារតូច | 77.6 MB | 0.90 s (688 Mbps) | 4.86 s (128 Mbps) | 5.4x |
| កញ្ចប់កូដ និងបណ្ណសារ (`.tar`) | 512 MB | 1.94 s (2111 Mbps) | 9.36 s (438 Mbps) | 4.8x |
| ឯកសារវីដេអូ (`.mp4`) | 512 MB | 7.36 s (556 Mbps) | 12.11 s (338 Mbps) | 1.6x |
| បង្កើនសមកាលកម្ម (កែប្រែមាតិកា 1%) | 512 MB | 0.12 s | 1.85 s | 15.4x |

## វិធីសាស្រ្តកែលម្អការអនុវត្ត

- **ការបញ្ជូន UDP ដំណាលគ្នា**៖ ផ្ញើប្លុកទិន្នន័យតាមរយៈ UDP ហើយបញ្ជូនតែបំណែកដែលបាត់បង់ឡើងវិញ ដើម្បីជៀសវាងការបាត់បង់កញ្ចប់ព័ត៌មានតែមួយដែលរារាំងការផ្ទេរឯកសារជាបន្តបន្ទាប់។
- **ការបែងចែកខ្លឹមសារ និងការដកស្ទួន**៖ បំបែកឯកសារទៅជាប្លុកទិន្នន័យដោយយោងតាមខ្លឹមសារ និងគណនាតម្លៃពិនិត្យ។ មាតិកាដូចគ្នាដែលមានរួចហើយនៅលើចុងទទួលគឺត្រូវប្រើឡើងវិញដោយផ្ទាល់ក្នុងមូលដ្ឋានដោយមិនចម្លងបណ្តាញ។
- **កែសម្រួលការបង្ហាប់ដោយស្វ័យប្រវត្តិតាមល្បឿនបណ្តាញ **៖ បើកការបង្ហាប់សម្រាប់មាតិកាដែលអាចបង្ហាប់បាន ដូចជាអត្ថបទ និងកូដ។ រំលងការបង្ហាប់ដោយស្វ័យប្រវត្តិសម្រាប់វីដេអូ រូបភាព កញ្ចប់ដែលបានបង្ហាប់ ឬនៅក្រោម LAN ល្បឿនលឿន ដើម្បីកាត់បន្ថយការប្រើប្រាស់ស៊ីភីយូ។
- **ពហុថ្នាំងដែលនៅជិតទាញ**៖ នៅពេលដែលម៉ាស៊ីនជាច្រើនទាញថតដូចគ្នា ប្លុកទិន្នន័យនឹងត្រូវបានទាញក្នុងពេលដំណាលគ្នាពីថ្នាំងដែលបានទាញយកនៅក្នុងទីក្រុងតែមួយ ឬជាមួយនឹងភាពយឺតយ៉ាវទាប។

## ដំឡើង

### វិធីសាស្រ្តទី 1: ដំឡើងតាមរយៈទំនិញ

```bash
cargo install sync0
```

### វិធីទី 2: ទាញយកប្រព័ន្ធគោលពីរដែលបានចងក្រងជាមុន

សូមចូលទៅកាន់ [GitHub Releases](https://github.com/webc-site/sync0/releases) ដើម្បីទាញយក `.tar.xz`កញ្ចប់ដែលបានបង្ហាប់សម្រាប់ប្រព័ន្ធដែលត្រូវគ្នា (គាំទ្រ Linux x86_64/ARM64, macOS Apple Silicon/Intel, Windows x64/ARM64, Android ARM64/x86_64, FreeBSD, NetBSD)។ បន្ទាប់​ពី​ពន្លា សូម​ដាក់ `sync0` ទៅ​ក្នុង​ថត `PATH`៖

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## ការណែនាំអ្នកប្រើប្រាស់

### 1. ផ្ទេរឯកសារ ឬថតដោយផ្ទាល់រវាងម៉ាស៊ីនពីរ

ចាប់ផ្តើមត្រួតពិនិត្យនៅលើម៉ាស៊ីនទទួល ហើយបញ្ជាក់ផ្លូវទទួល និងរក្សាទុក៖

```bash
sync0 recv 0.0.0.0:9000 ./backup
```

ផ្ញើឯកសារតែមួយ ឬថតទាំងមូលពីម៉ាស៊ីនផ្ញើ៖

```bash
sync0 send ./project 192.168.1.10:9000
```

ប៉ារ៉ាម៉ែត្រដែលប្រើជាទូទៅ៖

```bash
# លុបឯកសារដែលលែងត្រូវការតទៅទៀតដែលមាននៅលើចុងទទួល ប៉ុន្តែមិនមែននៅលើចុងផ្ញើទេ (ការធ្វើសមកាលកម្មកញ្ចក់)
sync0 send ./project 192.168.1.10:9000 --delete

# កំណត់អត្រាផ្ញើ (ឯកតា៖ បៃ/វិនាទី ឧទាហរណ៍ ៥០ មេកាបៃ/វិនាទី)
sync0 send ./project 192.168.1.10:9000 --rate 50000000

# របៀបស្ងាត់ (មិនបង្ហាញរបារវឌ្ឍនភាពទេ)
sync0 send ./project 192.168.1.10:9000 -q
```

### 2. ការបោះពុម្ពថតដែលបានចែករំលែក និងការទាញយកពីថ្នាំងច្រើន។

បោះផ្សាយ​ថត​ដែល​បាន​ចែករំលែក (ឈ្មោះ `dataset`) នៅលើ​ម៉ាស៊ីនមេ​ដើម៖

```bash
sync0 share dataset ./data --region SHA
```

ទាញថតដែលបានចែករំលែកនៅលើម៉ាស៊ីនផ្សេងទៀត (អ្នកអាចបំពេញអាសយដ្ឋានថ្នាំងច្រើនក្នុងពេលតែមួយ បំបែកដោយសញ្ញាក្បៀស ដើម្បីទាញក្នុងពេលដំណាលគ្នា)៖

```bash
sync0 pull 10.0.0.1:9000,10.0.0.2:9000 dataset ./local_data
```

ទាញតែថតរងជាក់លាក់មួយនៅក្នុងថតដែលបានចែករំលែក៖

```bash
sync0 pull 10.0.0.1:9000 dataset ./local_data --subpath 2026/logs
```

រុញការផ្លាស់ប្តូរក្នុងតំបន់ត្រឡប់ទៅថតដែលបានចែករំលែកពីចម្ងាយវិញ៖

```bash
sync0 push 10.0.0.1:9000 dataset ./local_data
```

### 3. ជាវប្រចាំទៅកាតាឡុកបច្ចុប្បន្នភាពដោយស្វ័យប្រវត្តិ

ជាវប្រចាំទៅថតដែលបានចែករំលែកនៃថ្នាំងប្រភព។ នៅពេលដែលឯកសារត្រូវបានបន្ថែម ឬកែប្រែនៅក្នុងថតប្រភព វានឹងត្រូវបានធ្វើសមកាលកម្មដោយស្វ័យប្រវត្តិទៅកុំព្យូទ័រមូលដ្ឋាន។ ក្នុងពេលជាមួយគ្នានេះ ម៉ាស៊ីនមូលដ្ឋាននឹងបម្រើជាថ្នាំងដោយស្វ័យប្រវត្តិសម្រាប់ម៉ាស៊ីនផ្សេងទៀតដើម្បីទាញ៖

```bash
sync0 sub 10.0.0.1:9000 dataset ./local_mirror
```

### 4. ការធ្វើសមកាលកម្មពីរផ្លូវនៃក្រុមពហុម៉ាស៊ីន

ម៉ាស៊ីនជាច្រើនចូលរួមជាមួយឈ្មោះក្រុមដូចគ្នា ហើយការផ្លាស់ប្តូរនៅក្នុងថត node ណាមួយនឹងត្រូវបានធ្វើសមកាលកម្មដោយស្វ័យប្រវត្តិទៅថ្នាំងផ្សេងទៀតនៅក្នុងក្រុម៖

```bash
sync0 group team-docs ./docs 10.0.0.1:9000,10.0.0.2:9000
```

### 5. អត្តសញ្ញាណប័ណ្ណ និងនាមប័ណ្ណផ្ទាល់ខ្លួន

ថ្នាំងនីមួយៗគាំទ្រការកំណត់ឈ្មោះអ្នកប្រើប្រាស់ ទីក្រុង អ៊ីមែល គេហទំព័រ និងហត្ថលេខាផ្ទាល់ខ្លួន (អតិបរមា 256 តួអក្សរ) និងឆ្លងកាត់ការផ្ទៀងផ្ទាត់ហត្ថលេខាឯកជនក្នុងតំបន់៖

```bash
# មើលលេខសម្គាល់សោសាធារណៈក្នុងតំបន់ (បញ្ជាក់ថតកំណត់រចនាសម្ព័ន្ធដើម្បីបន្តសោ)
sync0 id -c ~/.config/sync0

# បង្កើត និងបង្ហាញនាមប័ណ្ណដែលមានហត្ថលេខាផ្ទាល់ខ្លួន
sync0 profile -c ~/.config/sync0 \
  -u alice \
  --region SHA \
  --email alice@example.com \
  --url https://example.com \
  -b "Shanghai backup node"
```

`share`, `pull`, `sub`, `group` ក៏អាចត្រូវបានដាក់ឱ្យដំណើរការជាមួយនឹងប៉ារ៉ាម៉ែត្រទម្រង់ទាំងនេះផងដែរ៖

```bash
sync0 share dataset ./data -c ~/.config/sync0 -u alice --region SHA -b "Shanghai backup node"
```

### 6. ការប្តូរពហុភាសា

`sync0` គាំទ្រ 75 ភាសា។ តាមលំនាំដើម ជំនួយបន្ទាត់ពាក្យបញ្ជា និងប្រអប់បញ្ចូលក្នុងភាសាដែលត្រូវគ្នាត្រូវបានបង្ហាញដោយស្វ័យប្រវត្តិយោងទៅតាមបរិយាកាសភាសានៃប្រព័ន្ធប្រតិបត្តិការ។ ប្រសិនបើភាសាប្រព័ន្ធមិនស្ថិតនៅក្នុងបញ្ជីដែលគាំទ្រទេ ភាសាអង់គ្លេសត្រូវបានប្រើតាមលំនាំដើម។

ដើម្បីបញ្ជាក់ភាសាដោយដៃ កំណត់អថេរបរិស្ថាន `SYNC0_LANG`៖

```bash
SYNC0_LANG=en sync0 --help
SYNC0_LANG=ja sync0 --help
SYNC0_LANG=de sync0 --help
```
