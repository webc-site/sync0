# sync0

`sync0`គឺជាការចែករំលែកឯកសារ P2P វិមជ្ឈការ ការធ្វើសមកាលកម្មតាមពេលវេលាជាក់ស្តែង និងឧបករណ៍ចែកចាយពហុប្រភពដែលប្រើដើម្បីជំនួស `rsync` - ល្បឿនវាស់វែងនៃបណ្តាញតំបន់ធំទូលាយឆ្លងទ្វីបគឺរហូតដល់ **6.95×** នៃ `rsync` (ល្បឿនមធ្យមធរណីមាត្រតែមួយចំណុច ** 2.01×****** និង geometric speed.**, 3.01 × មធ្យម។ ការធ្វើសមកាលកម្មនៃឯកសារតូចៗដ៏ធំនៅទូទាំងមហាសមុទ្រគឺលឿនដូចជា **7.19×**។

ម៉ាស៊ីននីមួយៗគឺទាំងម៉ាស៊ីនមេ និងម៉ាស៊ីនភ្ញៀវ៖ មិនចាំបាច់មានម៉ាស៊ីនមេកណ្តាល ឬអាសយដ្ឋានបណ្តាញសាធារណៈទេ ការខួងរន្ធដោយស្វ័យប្រវត្តិគឺផ្អែកលើអាសយដ្ឋានសោសាធារណៈបណ្តាញដែលបានចែកចាយ ហើយវាគាំទ្រការបញ្ជូនដោយផ្ទាល់រវាងម៉ាស៊ីនពីរ ការបង្ហោះការអនុញ្ញាតជាក្រុមច្រើន ការជ្រើសរើសថតរងច្រើនតាមតម្រូវការ ការធ្វើសមកាលកម្មបន្ថែមពេលជាក់ស្តែងកម្រិតមីលីវិនាទី និង P2P ភាពស្របគ្នានៃប្រភពច្រើន។

## ដំឡើង

### វិធីសាស្រ្តទី 1: ការដំឡើងទំនិញ

```bash
cargo install sync0
```

### វិធីទី 2: ទាញយកប្រព័ន្ធគោលពីរដែលបានចងក្រងជាមុន

សូមចូលទៅកាន់ [GitHub Releases](https://github.com/webc-site/sync0/releases) ដើម្បីទាញយក `.tar.xz`កញ្ចប់ដែលបានបង្ហាប់ដែលត្រូវនឹងប្រព័ន្ធ (គាំទ្រ Linux, macOS, Windows, Android, iOS, FreeBSD) ពន្លា ហើយដាក់ចូលទៅក្នុង `PATH`៖

```bash
tar -xJf sync0-*.tar.xz
sudo mv sync0 /usr/local/bin/
```

## ចាប់ផ្តើមយ៉ាងឆាប់រហ័ស

### 1. ការបញ្ជូនដោយផ្ទាល់តាមការកំណត់សូន្យរវាងម៉ាស៊ីនពីរ (`send` / `recv`)

មិនចាំបាច់កំណត់រចនាសម្ព័ន្ធក្រុមចែករំលែកទេ ផ្ទេរឯកសារ ឬថតដោយផ្ទាល់រវាងម៉ាស៊ីនពីរក្នុងល្បឿនលឿន៖

```bash
# ចុងទទួលស្តាប់នៅលើច្រក ហើយសរសេរទៅ ./backup
sync0 recv 0.0.0.0:9000 ./backup

# ការបញ្ជូនដោយផ្ទាល់ពីអ្នកផ្ញើ (ជាជម្រើស --លុបកញ្ចក់ដើម្បីសម្អាតឯកសារលើស --អត្រាដែនកំណត់ល្បឿន 50MB)
sync0 send ./project 192.168.1.10:9000
```

### 2. ការចែករំលែកការបង្ហោះ និងការទាញ/បង្ហោះតាមតម្រូវការ (`share` / `pull` / `push`)

```bash
# ម៉ាស៊ីនមេ៖ បោះផ្សាយក្រុមចែករំលែកជាមួយបន្ទាត់ពាក្យបញ្ជាមួយ (បញ្ចេញអាសយដ្ឋាន IP គ្មាន iroh node បន្ទាប់ពីចាប់ផ្តើម)
sync0 share dataset:./data

# ម៉ាស៊ីនភ្ញៀវ៖ ទាញក្រុមចែករំលែកសំណុំទិន្នន័យទាំងមូលទៅមូលដ្ឋាន ./local_data
sync0 pull dataset:// ./local_data -p <node address>

# ម៉ាស៊ីនភ្ញៀវ៖ ទាញជម្រើសច្រើនតាមតម្រូវការ (ធ្វើសមកាលកម្មឯកសារតែមួយ និងថតរងដែលបានបញ្ជាក់)
sync0 pull dataset://docs/readme.md,assets/icons,src/core ./local_data -p <node address>

# អតិថិជន៖ បង្ហោះឯកសារ ឬថតទៅកាន់ក្រុមចែករំលែកដែលមានការអនុញ្ញាត
sync0 push dataset://releases/v1 ./build_output -p <node address>
```

### 3. ការបន្តពូជនៃការជាវតាមពេលវេលាជាក់ស្តែង និងការធ្វើសមកាលកម្មពីរផ្លូវរបស់ម៉ាស៊ីនច្រើន (`sub` / `group`)

បន្ទាប់ពីបង្កើតការភ្ជាប់ដ៏យូរ ប្រសិនបើឯកសារណាមួយ **ការបន្ថែម កែប្រែ លុប ផ្លាស់ប្តូរការអនុញ្ញាត ឬពេលវេលាកែប្រែ** កើតឡើងនៅលើផ្នែកដាច់ស្រយាល ថតមូលដ្ឋាននឹងត្រូវបានធ្វើបច្ចុប្បន្នភាពសមកាលកម្មគិតជាមិល្លីវិនាទីក្នុងពេលវេលាជាក់ស្តែង (ឯកសារធំថ្មី/ដែលបានកែប្រែនឹងទាញតែភាពខុសគ្នា ហើយធ្វើបច្ចុប្បន្នភាពពួកវានៅកន្លែងនោះ លុបឯកសារនឹងសម្អាតឯកសារមូលដ្ឋានដោយស្វ័យប្រវត្តិ និងទិន្នន័យទទេរផ្ទាល់) ហើយមានតែការផ្លាស់ប្តូរការអនុញ្ញាតតែប៉ុណ្ណោះ។

- **`sync0 sub`(ការឆ្លុះពេលវេលាជាក់ស្តែងមួយផ្លូវ + ការបណ្តុះដោយស្វ័យប្រវត្តិ)**៖ ពេលវេលាពិតក្នុងតំបន់ធ្វើតាមការបន្ថែម ការលុប និងការកែប្រែនៃចុងបញ្ចប់នៃការចែករំលែក ហើយដំណើរការដោយស្វ័យប្រវត្តិជាប្រភពគ្រាប់ពូជ P2P ដើម្បីផ្តល់ការបង្កើនល្បឿនដំណាលគ្នាសម្រាប់ថ្នាំងទាញផ្សេងទៀត។
- **`sync0 group`(ការធ្វើសមកាលកម្មតាមពេលវេលាជាក់ស្តែងពីរផ្លូវរវាងម៉ាស៊ីនច្រើននាក់)**៖ ប្រសិនបើឯកសារត្រូវបានបន្ថែម លុប ឬកែប្រែនៅលើម៉ាស៊ីនណាមួយក្នុងក្រុម នោះថ្នាំងអនឡាញផ្សេងទៀតទាំងអស់នឹងត្រូវបានអាប់ដេតក្នុងពេលជាក់ស្តែង ហើយបម្រើជាគ្រាប់ពូជសម្រាប់គ្នាទៅវិញទៅមក។

```bash
# ជាវក្រុមចែករំលែកទាំងមូល៖ ការបន្ថែមពីចម្ងាយ ការលុប និងការកែប្រែត្រូវបានធ្វើសមកាលកម្មក្នុងមូលដ្ឋានក្នុងពេលវេលាជាក់ស្តែង និងបង្កើតគ្រាប់ពូជដោយស្វ័យប្រវត្តិ
sync0 sub dataset:// ./local_mirror -p <node address>

# ការជាវច្រើនជ្រើសរើសតាមតម្រូវការ៖ ធ្វើសមកាលកម្ម និងគ្រាប់ពូជដែលបានបញ្ជាក់ឯកសារតែមួយ និងថតរងក្នុងពេលវេលាជាក់ស្តែង
sync0 sub dataset://models/llama.onnx,config ./local_mirror -p <node address>

# ការ​ធ្វើ​សមកាលកម្ម​តាម​ពេល​ជាក់ស្តែង​ពីរ​ផ្លូវ​ក្រុម​ម៉ាស៊ីន​ច្រើន​ (ក៏​គាំទ្រ​ផ្លូវ​ជ្រើសរើស​ច្រើន​ពេញ​ឬ​សញ្ញាក្បៀស​ផង​ដែរ)
sync0 ក្រុម team-docs:// ./docs -p <node address>
```

### 4. ក្រុមចែករំលែកច្រើនក្រុម និងការកំណត់រចនាសម្ព័ន្ធការអនុញ្ញាតសមាជិក (`.nt`ការកំណត់រចនាសម្ព័ន្ធ)

ថតការកំណត់រចនាសម្ព័ន្ធលំនាំដើមគឺ `~/.config/sync0` (អាចប្តូរបានតាមរយៈ `-c <directory>`) ដោយប្រើទម្រង់ [NestedText](https://nestedtext.org) (`.nt`)៖
- **គាំទ្រការរឹតបន្តឹងការអានបណ្តាញសាធារណៈ (មានតែអ្នកប្រើប្រាស់ដែលមានការអនុញ្ញាតប៉ុណ្ណោះអាចអានបាន)**៖ ដរាបណាក្រុមចែករំលែកត្រូវបានកំណត់រចនាសម្ព័ន្ធដោយ `users:`បញ្ជីសមាជិក (ឬបន្ទាត់ពាក្យបញ្ជាបញ្ជាក់ `--allow-r` / `--allow-rw` / `--allow-w` / `--auth`) ប្រព័ន្ធ ** បើកដោយស្វ័យប្រវត្តិនូវបណ្តាញសាធារណៈ (6) និងហាមឃាត់** ការរាប់បញ្ចូល ឬអានថ្នាំងអនាមិក ហើយ P2P ជាវថ្នាំងបណ្ដុះក៏នឹងទទួលមរតកបញ្ជីសក្នុងពេលដំណាលគ្នាដែរ ដោយអនុញ្ញាតឲ្យអ្នកប្រើប្រាស់ដែលមានសិទ្ធិអានតែប៉ុណ្ណោះ។ ក្រុមចែករំលែកដែលមិនត្រូវបានកំណត់រចនាសម្ព័ន្ធជាមួយ `users`គឺសាធារណៈ និងបានតែអានតាមលំនាំដើម (ប្រសិនបើអ្នកចង់បង្ហាញជាសាធារណៈ និងបានតែអាន ហើយបើកឱ្យផ្ទុកឡើងសម្រាប់តែសមាជិកដែលបានបញ្ជាក់ អ្នកអាចកំណត់យ៉ាងច្បាស់ `auth: false`)។
- **ការអនុញ្ញាតការចែកចាយការអាន និងថតរងដែលមានលក្ខណៈល្អិតល្អន់**៖ សមាជិកត្រូវបានអានបានតែតាមលំនាំដើម (`r`មិនចាំបាច់សរសេរច្បាស់លាស់ទេ) និងគាំទ្រ `r` (បានតែអាន) `w` (គ្រាន់តែសរសេរទៅប្រអប់ទម្លាក់ប៉ុណ្ណោះ មិនអាចអានបាន) <b id="4iteid" > (read-only) បុព្វបទអនុញ្ញាតសម្រាប់ការផ្ទុកឡើង) ។

**ឧទាហរណ៍ការកំណត់រចនាសម្ព័ន្ធសមាជិក (`~/.config/sync0/users/`):**

```yaml
# ~/.config/sync0/users/alice.nt (បានតែអានលំនាំដើម ដែនកំណត់ល្បឿន 80MB)
id: 8J9aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ab_c
rate: 80MB
```

### លក្ខណៈពិសេសនៃផលិតផលស្នូល

- ** លេខសោសាធារណៈដែលដោះស្រាយការដាល់រន្ធដោយស្វ័យប្រវត្តិ**៖ មិនត្រូវការម៉ាស៊ីនមេកណ្តាល និងអាសយដ្ឋានបណ្តាញសាធារណៈទេ ការវាយរន្ធ NAT ដោយស្វ័យប្រវត្តិដោយផ្អែកលើអាសយដ្ឋានសោសាធារណៈបណ្តាញដែលបានចែកចាយ។
- **ការធ្វើសមកាលកម្មតាមពេលវេលាជាក់ស្តែងកម្រិតមីលីវិនាទី និងការយល់ដឹងអំពីទិន្នន័យមេតា**៖ ផ្អែកលើការត្រួតពិនិត្យព្រឹត្តិការណ៍ឯកសារដើម (`FSEvents` / `inotify` / `ReadDirectoryChangesW`) ពេលវេលាពិតប្រាកដនៃការបន្ថែមឯកសារ ការលុប ការអនុញ្ញាត POSIX (`mode`) និងពេលវេលាកែប្រែកម្រិតមិល្លីវិនាទី (<b); ការបញ្ជូនប្លុកទិន្នន័យសូន្យនៅពេលដែលមានតែការអនុញ្ញាត ឬពេលវេលាប៉ុណ្ណោះដែលត្រូវបានកែប្រែ។
- **ការទាញយក និងអាប់ឡូតក្នុងពេលដំណាលគ្នាតាមរចនាប័ទ្ម BT និងការកំណត់កាលវិភាគភាពស្និទ្ធស្នាលក្នុងតំបន់**៖ ថ្នាំងទាញយកមិនចាំបាច់រង់ចាំសម្រាប់ចំនួនពេញលេញដើម្បីទាញយកនោះទេ។ ចន្លោះពេលប្លុកទាំងអស់ (`Op::Have`) ដែលបានឆ្លងកាត់ការត្រួតពិនិត្យសញ្ញា 128 ប៊ីតត្រូវបានចាក់សោភ្លាមៗនៅក្នុងអង្គចងចាំ/បណ្តុំបណ្តោះអាសន្នដើម្បីឱ្យថ្នាំងផ្សេងទៀតទាញក្នុងពេលដំណាលគ្នា។ រួមជាមួយនឹងការផ្លាស់ប្តូរថ្នាំង PEX ថាមវន្ត និងថ្នាំងយឺតពាក់កណ្តាល preemption (Work-Stealing) លំហូរនៃចង្កោមត្រូវបានពង្រីកអតិបរមា។
- **ការជ្រៀតជ្រែកថ្នាំងប្រឆាំងព្យាបាទ និងអភ័យឯកសិទ្ធិនៃការពុលចង្កោម**៖ បញ្ជីប្រភពអនុញ្ញាត `root_hash`ការចាក់សោដោយខ្លួនឯង + ការបង្កើនល្បឿនផ្នែករឹងជាកាតព្វកិច្ច `gxhash128`ការផ្ទៀងផ្ទាត់រំលាយ មុនពេលប្លុកនីមួយៗត្រូវបានដាក់នៅលើថាស និងគ្រាប់ពូជខាងក្រៅ។ ប្រសិនបើរកឃើញប្លុករំខាន នោះឧបករណ៍បំបែកសៀគ្វីកម្រិតមិល្លីវិនាទីនឹងបិទថ្នាំងព្យាបាទ និងសង្គ្រោះដោយស្វ័យប្រវត្តិពីប្រភពស្មោះត្រង់។
- **ការបន្ថែម FastCDC នៅក្នុងកន្លែង និងការប្រមូលផ្តុំឯកសារតូច**៖ មានតែប្លុកឌីផេរ៉ង់ស្យែលប៉ុណ្ណោះដែលត្រូវបានផ្ទេរសម្រាប់ការកែប្រែផ្នែកខ្លះនៃឯកសារធំ និងដាក់នៅលើថាស។ ការវេចខ្ចប់អង្គចងចាំឯកសារតូចដ៏ធំ និងការបង្ហាប់ឌីផេរ៉ង់ស្យែលបុព្វបទ លុបបំបាត់ឯកសារដោយឯកសារ ដំណើរវិលជុំ។
- **ការព្យាបាលដោយខ្លួនឯងបន្ទាប់ពីការដាច់ចរន្តអគ្គិសនី និងការបន្តបន្ទាប់ពីការចាប់ផ្តើមឡើងវិញ**៖ ទម្រង់កូនកាត់ RDB + AOF ស្រដៀងនឹង Redis (`.s0_subs.bin`) ត្រូវបានប្រើដើម្បីបន្តស្ថានភាពគ្រាប់ពូជ និងបញ្ជីឯកសារ ការផ្លាស់ប្តូរប្រចាំថ្ងៃត្រូវបានបន្ថែមជាមីក្រូវិនាទី ហើយត្រូវបានសរសេរឡើងវិញដោយស្វ័យប្រវត្តិ និងរៀបចំជាទៀងទាត់។ បន្ទាប់​ពី​ម៉ាស៊ីន​មេ​ត្រូវ​បាន​ចាប់​ផ្តើ​ម​ឡើង​វិញ​ការ​ផ្លាស់​ប្តូ​រ​ក្រៅ​បណ្ដាញ​ត្រូវ​បាន​ជំរុញ​ដោយ​ស្វ័យ​ប្រវត្តិ​ទៅ​ថ្នាំង​គ្រាប់ពូជ​។

  - **ផ្ទៃចែកចាយទិន្នន័យ (ដើម UDP + `compio`អសមកាល I/O) **៖ បឋមកថាបង្រួម 20B, មតិកែលម្អតាមកាលកំណត់ 18B TACK, ការគ្រប់គ្រងការកកស្ទះកូនកាត់ BBRv3/Copa, ការស្ដារឡើងវិញនូវការបាត់បង់កញ្ចប់ព័ត៌មាន RACK-TLP, ប្លុកទីមួយ = "Shannon entropy adaptive Zstd verification bypass-2" > និងបញ្ចប់។
